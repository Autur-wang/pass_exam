一、注意力核心公式

缩放点积注意力(除以 $\sqrt{d_k}$ 防 softmax 饱和):

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V,\qquad d_k=d_{model}/h$$

多头:$\operatorname{MultiHead}=\operatorname{Concat}(\text{head}_1,\dots,\text{head}_h)W_O$,时间/空间复杂度 $O(n^2 d)$(瓶颈在 $n\times n$ 分数矩阵)。

二、注意力变体 & KV Cache

变体K/V 头KV Cache质量代表
MHA每头独立最大最好原始 Transformer
MQA全部共享 1 组最小略降PaLM
GQA分组共享折中接近 MHALLaMA 2/3
MLA压成低维 latent很小好DeepSeek

KV Cache 显存 $\approx 2\times L_{\text{层}}\times n_{\text{序列}}\times h\times d_{\text{head}}\times \text{bytes}$。压它的三条路:变体(MQA/GQA/MLA)、PagedAttention(消碎片)、prefix caching(复用前缀)。FlashAttention 不改显存量级但省 HBM 读写、更快,且是精确非近似。

四、对齐算法

算法要奖励模型?要价值网络?一句话
PPO要要(critic)clip 限制新旧策略比 + KL 惩罚
DPO不要不要偏好对直接做分类式损失,隐式奖励
GRPO要(或规则奖励)不要组内相对优势,省 critic(推理模型)

RLHF 三阶段:SFT → 训 RM(成对偏好 chosen/rejected)→ RL(PPO)最大化 RM 打分。为什么用 RL 不用 SFT:偏好是相对的、难监督单条最优、需要探索。

五、RAG 链路与检索

① 文档解析 → 预处理
↓
② 分块 chunking(定长+重叠 / 语义 / 结构)
↓
③ 向量化 embedding → 建索引(HNSW/IVF)
↓
④ 检索召回:混合(向量 + BM25,RRF 融合)
↓
⑤ Rerank 精排(cross-encoder)
↓
⑥ 拼进 prompt → 生成(带引用溯源)

BM25 三要素:词频饱和(TF)× 逆文档频率(IDF)× 文档长度归一。召回 vs 精排:召回求不漏、精排求排得准。降幻觉:RAG 给证据 + prompt 约束 + 结构化校验 + RLHF/DPO + 引用溯源。

vLLM 为什么快:PagedAttention(像 OS 分页管 KV Cache、消碎片)+ continuous batching(动态插入请求)。推理显存 ≈ 权重 + KV Cache + 激活。延迟指标:TTFT(首 token)/ TPOT(每 token)。

七、评估

分类/抽取:$\text{Precision}=\dfrac{TP}{TP+FP}$,$\text{Recall}=\dfrac{TP}{TP+FN}$,$F_1=\dfrac{2PR}{P+R}$。生成类:BLEU/ROUGE 有局限 → 人评 / LLM-as-judge。RAG:检索命中率 + 答案忠实度(faithfulness)/相关度。

让业务相信:把效果对齐到业务 KPI、做 A/B、可解释 + 抽样人审。这是评估类问题的高频落点。

八、高频「会被追问」清单

  • 为什么除以 $\sqrt{d_k}$?→ 点积方差随维度增大,防 softmax 饱和/梯度消失。
  • Q、K 为什么用不同权重?→ 否则注意力对称退化、只关注自己。
  • 为什么现在都是 decoder-only?→ 训练高效、zero-shot 泛化、KV Cache 友好、生成天然自回归。
  • LoRA 为什么不增推理延迟?→ $BA$ 可合并回 $W$。r=8 vs 16 看任务难度/数据量权衡。
  • DPO 为什么比 PPO 省?→ 跳过显式 RM 与 critic,单阶段优化偏好。
  • 这个需求微调还是 RAG?→ 改知识 RAG、改能力微调,常结合。
  • 微调/RAG 效果怎么评?怎么让业务相信?→ 可量化指标 + A/B + 人审(极高频)。
  • vLLM/PagedAttention 解决什么?→ KV Cache 显存碎片与利用率。
