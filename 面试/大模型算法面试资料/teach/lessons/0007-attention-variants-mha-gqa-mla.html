注意力变体:MHA / MQA / GQA / MLA

上节课我们发现 KV Cache 是自回归生成的救命稻草,但它会随「层数 × 头数 × 序列长度」线性膨胀,成为长上下文推理的显存黑洞。这节课的四个名字——MHA、MQA、GQA、MLA——其实是同一场战争的四种打法:如何在省 KV Cache 显存和不掉效果之间找平衡。面试里这是「多头注意力」之后最高频的追问,几乎逢大模型岗必考。

上节课(KV Cache)我们算过一笔账:推理时每生成一个 token,都要缓存它在每一层、每个头上的 K 和 V,好让后面的 token 不必重算。先别往下看,试着回忆:这份缓存的大小和哪几个量成正比?如果显存快满了,你最想砍掉哪一项?

一、一根主线:所有变体都在和 KV Cache 讨价还价

先把要省的东西写清楚。一次推理里,KV Cache 的总大小大致是:

$$\text{KV Cache} \;=\; \underbrace{2}_{K,\,V}\times n_{\text{layer}}\times \underbrace{n_{kv}}_{\text{K/V 头数}}\times d_h \times L \times b$$

$n_{\text{layer}}$ 层数,$d_h$ 每头维度,$L$ 序列长度,$b$ 每个数的字节数。除了 $n_{kv}$,其余几项要么是模型定死的、要么是任务给定的——唯一好动手脚的,就是「每层要缓存几组 K/V」这个 $n_{kv}$。

注意一个关键前提:Q 的头数 $n_h$ 从头到尾都不变。四种变体动的都是 K/V 的头数 $n_{kv}$,以及 K/V 到底以什么形式存进 cache。把这条主线记牢,四种方法就串成了一条从「不省」到「极省」的光谱:

二、MHA:每头独立 K/V,cache 最大

Multi-Head Attention 就是原始 Transformer 的做法:有几个 Q 头,就配几个独立的 K 头和 V 头,一一对应。表达能力最强,但每个 token 每一层要缓存 $n_h$ 组 K 和 $n_h$ 组 V。

问题正是那句「每头独立」:头越多、上下文越长,cache 越吃显存。这就是后面所有变体想解决的痛点。

三、MQA:所有头共享一组 K/V,省显存但质量降

Multi-Query Attention(Shazeer, 2019)把节流做到极致:Q 仍然是 $n_h$ 个头各自独立,但全部头共享同一组 K 和同一组 V。于是 $n_{kv}=1$,KV Cache 直接缩到 MHA 的 $1/n_h$。

代价是什么?K/V 的表达自由度被砍到只剩一份,不同头再也无法「各看各的」,通常会带来一定的质量损失,长文推理时尤为明显。所以 MQA 是「省显存优先」的激进选择,常见于对推理吞吐极敏感的场景(如 PaLM、Falcon 等报告采用)。

四、GQA:分组共享,MHA 与 MQA 的折中

MHA 效果好但太耗显存,MQA 省显存但掉点——Grouped-Query Attention(Ainslie et al., 2023)干脆取中间值:把 $n_h$ 个 Q 头分成 $g$ 组,每组内部共享一组 K/V,组与组之间不共享。于是 $n_{kv}=g$,cache 是 MHA 的 $g/n_h$。

GQA 的漂亮之处在于它是一根连续的「旋钮」:

  • $g=n_h$(每头一组)→ 退化成 MHA;
  • $g=1$(全体一组)→ 退化成 MQA;
  • 取中间(比如 8 组)→ 显存省了大半,质量却几乎追平 MHA。

正因为这种「几乎不掉点又省显存」的性价比,GQA 成了当前开源大模型的主流做法——LLaMA 2 的大模型(如 70B)、LLaMA 3 系列、Mistral 等都采用它。GQA 论文还给了个实用点:可以从已训好的 MHA checkpoint 通过少量「uptraining」转成 GQA,不必从零重训。

五、MLA:把 K/V 压成低维 latent,只缓存 latent

MQA/GQA 是「减头数」——直接砍掉信息通道。DeepSeek-V2 提出的 Multi-head Latent Attention(MLA)换了个思路:头数一个不减,但把庞大的 K/V 信息联合压缩成一个极低维的隐向量(latent)$c_t$。推理时显存里只存这个小小的 $c_t$,真正算注意力时再把它动态「解压」回各个头的 K 和 V。

用公式看得更清楚。设隐藏向量 $h_t$,压缩维度 $d_c \ll n_h d_h$:

$$c_t^{KV}=W^{DKV}h_t,\qquad k_t^{C}=W^{UK}c_t^{KV},\qquad v_t^{C}=W^{UV}c_t^{KV}$$

缓存里只存 $c_t^{KV}\in\mathbb{R}^{d_c}$,不存解压后的 $k_t,v_t$。原来要缓存 $2 n_h d_h$ 个数,现在只需 $d_c$ 个,显存大幅下降。

为什么这比 GQA 更聪明?GQA 是「粗暴地让若干头共用一份」,信息瓶颈是硬约束;MLA 的压缩矩阵 $W^{DKV}$ 是可学习的,模型能自己学到「哪些信息该留在 latent 里」,理论上能在同等 cache 预算下保住更接近 MHA 的表达力。

MLA 的隐藏难点:和 RoPE 打架

这是面试的深水区。RoPE(旋转位置编码)要按位置 $m$ 给每个 K 施加一个旋转;而 MLA 想在推理时把上投影 $W^{UK}$ 「吸收」进 $W^Q$ 里、直接拿 latent 算注意力(这样才真省算力)。但旋转是位置相关的,夹在 $W^{UK}$ 中间就没法预先吸收——两者不兼容。DeepSeek 的解法是解耦 RoPE(decoupled RoPE):额外拿出一小段专门承载位置信息的 key(所有头共享)去做旋转,其余部分走无位置的 latent 压缩。所以 MLA 的 cache 实际是「低维 latent + 一小段共享的 RoPE key」。

KV Cache 头数 $n_{kv}$
每层每 token 需要缓存的 K/V 组数。MHA:$n_{kv}=n_h$;GQA:$n_{kv}=g$($1<g<n_h$);MQA:$n_{kv}=1$。Q 的头数 $n_h$ 在所有变体里保持不变。
MLA 的 latent $c_t$
$$c_t^{KV}=W^{DKV}h_t\in\mathbb{R}^{d_c},\quad d_c\ll n_h d_h$$ 联合压缩后的低维隐向量,是 MLA 唯一进 KV Cache 的主体(外加一段共享 RoPE key)。K、V 由它经上投影动态还原,不进 cache。

六、一张表对齐四者

变体K/V 组数 $n_{kv}$相对 MHA 的 KV Cache特点代表模型
MHA$n_h$$1\times$(基准)每头独立,质量上限,最费显存原始 Transformer、GPT、BERT、LLaMA 1

GQA$g$$g/n_h$分组共享,质量与显存的折中旋钮LLaMA 2(70B)、LLaMA 3、Mistral

数量级上 MHA > GQA > MQA;MLA 走的是另一条轴,用「压缩」而非「减头」达到接近 MQA/小组 GQA 的显存,同时力图保住 MHA 级的效果。

GQA 的实现核心只有一步:K/V 只算 $n_{kv}$ 个头,注意力前用 repeat_interleave 把它们「广播」到 $n_h$ 个 Q 头上。自己敲一遍就懂它省在哪:

import torch

# Q:  [B, n_h,  T, d_h]   —— query 头数不变
# K,V:[B, n_kv, T, d_h]   —— 只算/只缓存 n_kv 组 (MQA 时 n_kv=1)
def expand_kv(K, V, n_h):
    n_kv = K.size(1)
    rep = n_h // n_kv                 # 每组要复制几份
    K = K.repeat_interleave(rep, dim=1)  # -> [B, n_h, T, d_h]
    V = V.repeat_interleave(rep, dim=1)
    return K, V                        # 之后就是普通多头注意力

# 关键:进 KV Cache 的是 [B, n_kv, T, d_h],省显存的正是这个 n_kv
# repeat 只发生在计算时,不落进 cache

MLA 则把「省」放在缓存的形态上——缓存 latent,计算时才解压:

# 预填充/解码时:只把 c_kv 存进 KV Cache
c_kv = h @ W_DKV.T          # [B, T, d_c]   <- cache 里就存它
# 算注意力时再动态解压回各头 K / V(推理可把 W_UK 吸收进 W_Q)
K = (c_kv @ W_UK.T).view(B, T, n_h, d_h).transpose(1, 2)
V = (c_kv @ W_UV.T).view(B, T, n_h, d_h).transpose(1, 2)

面试官会怎么问:

  • 「MHA / MQA / GQA 的 KV Cache 大小怎么比?」——写出 $2\,n_{\text{layer}}\,n_{kv}\,d_h\,L\,b$,指出差别全在 $n_{kv}$:$n_h$ vs $g$ vs $1$,量级 MHA > GQA > MQA。
  • 「GQA 为什么是折中?$g$ 怎么取?」——$g=n_h$ 是 MHA、$g=1$ 是 MQA,中间取值兼顾显存与质量;强调它是连续旋钮,还能从 MHA checkpoint uptraining 得到。
  • 「谁用哪种?」——原始 Transformer/GPT/LLaMA 1 用 MHA;PaLM、Falcon 等用 MQA;LLaMA 2(70B)/LLaMA 3、Mistral 用 GQA;DeepSeek-V2/V3 用 MLA。
  • 「MLA 缓存的到底是什么?比 GQA 强在哪?」——缓存低维 latent $c_t$(计算时解压),压缩矩阵可学习,能在小 cache 下逼近 MHA 质量。
  • 「MLA 和 RoPE 有什么冲突,怎么解决?」——旋转位置相关,无法预先吸收进上投影;用 decoupled RoPE,拿一小段共享 key 单独承载位置。答得出这个能拉开差距。

易错点:

  • 四种变体动的都是 K/V 头数,Q 头数 $n_h$ 始终不变。说「MQA 减少了 Q 头」是错的。
  • MQA/GQA 省的是 K/V 的缓存与参数,不是省注意力的头数——Q 仍是 $n_h$ 个头各自 attend,计算量的减少主要来自更小的 K/V 投影,而非更少的头。
  • MLA 缓存的是压缩后的 latent,不是解压后的 K/V。如果把解压后的 K/V 也缓存下来,就一点没省。
  • $g=1$ 时 GQA 就是 MQA,$g=n_h$ 时就是 MHA——别把 GQA 说成和它们「完全不同的第三种东西」。
  • 别忽略 MLA 里的 RoPE 处理:latent 不能直接旋转,需要解耦出共享 RoPE key,否则位置信息丢失。

自测 1:关于 MQA(Multi-Query Attention),下列哪项描述正确?

A. 所有注意力头共享同一组 K 和 V,而 Q 仍是各头独立 ✅正确。MQA 只把 K/V 缩成一组($n_{kv}=1$),Q 头数不变,cache 变成 MHA 的 $1/n_h$。
B. 所有头共享同一组 Q、K、V 三者错。Q 从不共享,各头独立;被共享的只有 K 和 V。
C. 通过减少 Q 头的数量来省显存错。省的是 K/V 头数,Q 头数保持 $n_h$。
D. 把 K、V 联合压缩成低维 latent 再缓存错,这是 MLA 的做法,不是 MQA。

自测 2:MLA 在 KV Cache 里实际缓存的主体是什么?

A. 每个头解压后的完整 K 和 V错。若缓存解压后的 K/V 就等于没压缩,失去 MLA 的意义。
B. 一个低维联合 latent $c_t$(计算时再解压回各头 K/V),外加一小段共享的 RoPE key ✅正确。只有小小的 $c_t$ 进 cache,K/V 由它动态还原;位置信息由解耦出的共享 RoPE key 承载。
C. 只缓存 K,不缓存 V错。K 和 V 都由同一个 latent 解压得到,缓存的是 latent 本身。
D. $g$ 组共享的 K/V错,这是 GQA 的分组共享,不是 MLA 的压缩思路。
