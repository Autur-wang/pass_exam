SFT 数据构建与格式:微调的燃料长什么样

前几课把「怎么改参数」讲透了(LoRA / QLoRA / Prefix)。但真正决定 SFT 效果上限的,往往不是你用哪种 PEFT,而是喂进去的数据。这节课把 SFT 数据拆到你能答清楚三件事:数据长什么格式、为什么只对回答部分算 loss、以及「要多少条才起效」。这几点几乎是每场大模型面试都会落到的送分/送命题。

上节课(QLoRA / Adapter / Prefix)解决的是「用尽量少的显存和参数把模型调过来」。但方法再省,喂的数据是垃圾,调出来的也是垃圾。先别往下看,试着回忆:你见过的 SFT 训练样本长什么样?模型在这一条样本上,到底该「学」哪一段文字?

一、SFT 到底在做什么

SFT(Supervised Fine-Tuning,有监督微调)做的事一句话讲清:给模型一堆「输入 → 期望回答」的示范,让它学会「拿到这种输入,就该这样回」。它仍然是语言模型的老本行——预测下一个 token——只是训练数据从「海量无标注网页」换成了「精心组织的问答/指令示范」。

所以 SFT 数据的核心单元永远是一对:提示(prompt)+ 期望回答(response)。区别只在于你用什么外壳把这一对包起来。

二、两种主流数据格式

格式 A:instruction / input / output(Alpaca 风)

把每条样本拆成三个字段,适合单轮指令任务:

{
  "instruction": "把下面的句子翻译成英文。",
  "input": "今天天气很好。",
  "output": "The weather is nice today."
}

instruction 是任务描述,input 是这次的具体输入(可以为空,比如「写一首关于秋天的诗」就没有 input),output 是期望回答。训练时框架会按一个固定模板把 instruction+input 拼成 prompt,把 output 当作要学的回答。

格式 B:messages / role(对话风)

用带角色的消息列表,天然支持多轮对话和 system 提示,是当下 Chat 模型的通用做法:

{
  "messages": [
    {"role": "system",    "content": "你是一个乐于助人的中文助手。"},
    {"role": "user",      "content": "把这句话翻译成英文:今天天气很好。"},
    {"role": "assistant", "content": "The weather is nice today."}
  ]
}

训练前会用模型自带的 chat template(如 tokenizer.apply_chat_template)把这个列表渲染成一串带特殊标记的纯文本,再交给模型。关键约束:训练用的模板必须和推理时用的模板一致——否则模型学的格式和你部署时喂的格式对不上,效果会明显下滑。

两种格式并非对立:instruction/input/output 常常只是 messages 的一种「单轮特例」,很多训练框架会在内部把前者转成后者再处理。多轮、需要 system 角色、要贴合线上对话形态时,优先用 messages 格式。

三、核心机制:只对 assistant 部分算 loss

这是本课最该背下来、也最常被追问的一点。一条样本里,prompt(system+user)和 response(assistant)会被拼成同一个序列喂进去,但计算损失时,要把 prompt 部分的 token 全部屏蔽(mask)掉,只在 assistant 回答的 token 上计算交叉熵。

用公式说,自回归语言模型的损失本是对整条序列每个位置求和;SFT 把求和范围限制在 response 的 token 上:

$$\mathcal{L}(\theta)=-\!\!\sum_{t\,\in\,\text{response}}\!\!\log p_\theta\!\left(y_t \mid y_{<t},\,x\right)$$

$x$ 是 prompt,$y_t$ 是回答里第 $t$ 个 token。求和号只跑 response 里的位置,prompt 位置不贡献梯度。

为什么要这么做?因为我们想让模型学的是「给定这个指令,该怎么回答」,而不是「怎么把用户的指令原样生成一遍」。如果不 mask,模型会花一半力气去拟合用户的提问文本——那既没意义,还会稀释它对「如何作答」的学习信号。屏蔽 prompt 后,梯度全部集中在「回答」上,学习信号更干净、更高效。

工程上怎么实现?PyTorch 的交叉熵有个约定:标签值等于 -100 的位置会被自动忽略(ignore_index=-100)。所以做法就是——把 prompt 段对应的 label 全部置为 -100:

序列 token你 是 助手请翻译:今天天气很好The weather is nice today
属于system(prompt)user(prompt)assistant(response)
label-100 -100 …-100 -100 …真实 token id(参与 loss)

多轮对话同理:每一轮的 user 提问都置 -100,只在每一轮的 assistant 回答上算 loss。TRL 的 SFTTrainer 配合 completion-only 的 collator、或各家训练脚本里的「mask prompt」选项,做的就是这件事。

四、质量 > 数量:数据怎么算「好」

面试官问「你怎么构建 SFT 数据」,想听的绝不是「爬了很多」。真正决定效果的是三个维度:

多样性
覆盖足够多的任务类型、指令风格、领域
别让模型只见过一种题
去重
剔除重复 / 高度相似样本
重复样本 = 变相过拟合
难度分布
简单到复杂都有,梯度合理
全是简单题学不到硬能力

还要盯住:回答本身的正确性与风格一致性(错误示范会被模型忠实学走)、标签噪声(源材料反复强调:样本里噪声过大,模型会去记噪声特征而过拟合)。对中文任务,源材料给的经验还包括适当的清洗/预处理,以及在数据有限时用同义替换、语序重组等做数据增强来扩充多样性——但增强要克制,别把噪声也放大了。

五、到底需要多少条数据

这题没有唯一答案,标准的答法是「看目标」,并给出量级而非拍死的数字。综合源材料的经验口径:

  • 小规模模型 / 窄任务:几千到几万条常常就够。
  • 大规模模型 / 宽覆盖:数十万到数百万条是常见范围。

另一条重要的行业观察是「少即是多」:当目标只是对齐回答风格与格式(而非灌输新知识)时,少量、极高质量的示范可能就足够——LIMA 这篇工作用约 1000 条精选样本,就得到了相当能打的指令遵循效果,并提出「对齐主要是在激活预训练已有能力、教它用什么格式表达」的假设。

把这两条统一起来的正确直觉是:如果是教模型「怎么说话/什么格式」,少而精可能够;如果是教它「一项它原本不会的新技能或新知识」,通常需要更多、更集中的数据。无论哪种,盲目堆量都不如提高质量与多样性。注意别把话说死——「越多一定越好」是错的,超过某个点后,低质量数据的边际收益会转负。

六、正样本、负样本与基座选择(多来源经验的统一)

面试里常有个陷阱:「你 SFT 用了正负样本吗?」——标准 SFT 只用正样本,也就是「好的示范回答」,通过上面的 loss 让模型去模仿它们。负样本(被拒绝的回答)不属于 SFT,而属于后面的偏好对齐阶段:奖励模型(RM)吃的是「输入 → 一个实数奖励分」或「优选/被拒」成对数据,DPO 直接吃 (chosen, rejected) 偏好对。把这条界线说清楚,是区分「背过流程」和「真懂 pipeline」的分水岭(RM / 偏好对齐见后续部分)。

还有一个高频实操题——基座该选 Base 还是 Chat?源材料的经验:任务是多轮对话/对话生成相关,选已经对齐过的 Chat 模型更省事;任务是单轮文本生成或非对话任务,从 Base 起手更干净、可控。选错基座会让「数据没问题但效果就是别扭」。

SFT(Supervised Fine-Tuning)
用「输入 → 期望回答」示范做有监督微调,仍是「预测下一个 token」,但 loss 只算在回答上。
指令微调(Instruction Tuning)
SFT 的典型形态:数据组织成 instruction/input/output 或 messages,让模型学会遵循自然语言指令。
Loss mask / ignore_index=-100
把 prompt 段的 label 置为 $-100$,交叉熵自动跳过这些位置,使梯度只来自 assistant 回答的 token。
Chat template
把 messages 列表渲染成带特殊标记纯文本的模板;训练与推理必须用同一套。

自己写一遍「构造带 mask 的 label」——这是理解 SFT 数据的关键动作:

from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("your-base-model")

# 一条对话样本(用模型自带的 chat template 渲染)
msgs = [
    {"role": "user", "content": "把这句话翻译成英文:今天天气很好。"},
    {"role": "assistant", "content": "The weather is nice today."},
]

# 分两次编码:prompt 段 vs prompt+response 全段
prompt_text = tok.apply_chat_template(
    msgs[:1], tokenize=False, add_generation_prompt=True)   # 到 assistant 起始
full_text   = tok.apply_chat_template(
    msgs, tokenize=False, add_generation_prompt=False)

prompt_ids = tok(prompt_text, add_special_tokens=False).input_ids
full_ids   = tok(full_text,   add_special_tokens=False).input_ids

input_ids = full_ids
labels    = list(full_ids)
# 关键:把 prompt 段的 label 全部置 -100,只保留 assistant 回答参与 loss
for i in range(len(prompt_ids)):
    labels[i] = -100
# 训练时:loss = CrossEntropyLoss(ignore_index=-100)(logits, labels)

面试官会怎么问:

  • 「SFT 数据长什么样、有哪些格式?」——instruction/input/output(单轮)与 messages/role(多轮、带 system);后者是 Chat 模型主流。
  • 「训练时 loss 算在哪一段?为什么?」——只算 assistant 回答,prompt 段 label 置 $-100$;为的是学「怎么答」而非「重复问题」。这是必答点。
  • 「SFT 需要多少条数据?」——看目标给量级:窄任务几千~几万,宽覆盖数十万~数百万;对齐风格可「少而精」(举 LIMA 约千条)。别报死数字。
  • 「你怎么保证数据质量?」——多样性 + 去重 + 难度分布 + 回答正确性/风格一致 + 控噪声。
  • 「SFT 用负样本吗?」——不用,SFT 只用正示范;负样本/偏好对属于 RM 与 DPO 阶段。
  • 「基座选 Base 还是 Chat?」——对话任务倾向 Chat,单轮/非对话倾向 Base。

易错点:

  • 忘了 mask prompt,把整条序列都算 loss——模型会分心去拟合用户提问,学习信号被稀释。
  • 训练用的 chat template 和推理时不一致——特殊标记对不上,线上效果莫名变差。
  • 把「正负样本」当成 SFT 的输入——负样本是 RM / DPO 的活儿,不是 SFT。
  • 迷信数据量,只堆量不去重、不控质量——重复与噪声会把模型推向过拟合,反而「越调越傻」(下一课细讲)。
  • 多轮对话只在最后一轮算 loss——通常应在每一轮的 assistant 回答上都算(除非有意只学最后一轮)。

自测 1:SFT 训练一条「user 提问 + assistant 回答」拼成的序列时,为什么要把 prompt 段的 label 置为 -100?

A. 为了节省显存,减少要存的 token置 $-100$ 不改变序列长度或显存占用,只影响哪些位置计入 loss。
B. 因为 prompt 段没有对应的 token不对,prompt 段同样被 tokenize 进了序列,只是不参与损失计算。
C. 让 loss 只落在 assistant 回答上,模型学「怎么答」而不是去重复用户的提问 ✅正确。ignore_index=-100 会跳过这些位置,梯度全部集中在回答 token,学习信号更干净。
D. 为了让 tokenizer 跑得更快与 tokenization 速度无关,mask 发生在算 loss 阶段。

自测 2:关于「SFT 需要多少条数据」,下面哪种回答最稳妥?

A. 越多越好,几百万条一定比一千条效果好「一定」太绝对;超过某点后低质量数据边际收益会转负,LIMA 的少而精就是反例。
B. 取决于目标:对齐风格/格式,少量高质量(如 LIMA 约千条)可能就够;教新技能/知识通常需要更多,质量与多样性比单纯堆量更关键 ✅正确。标准答法是给量级 + 看目标,而不是拍一个固定数字。
C. 固定就是 1 万条,和模型规模、任务都无关数据量与模型规模、任务宽窄、目标强相关,没有放之四海的固定值。
D. 只要过一千条,再多都没有意义过头了;教新知识/宽覆盖任务往往仍需要数十万到数百万条。

这节课的一手出处与深挖方向:

  • InstructGPT(Ouyang et al., 2022)——「Training language models to follow instructions with human feedback」,SFT 是其三阶段的第一步,示范数据的组织方式可对照本课。
  • Stanford Alpaca(Taori et al., 2023)与 Self-Instruct(Wang et al., 2022)——instruction/input/output 格式与「用模型自造指令数据」的来源。
  • LIMA: Less Is More for Alignment(Zhou et al., 2023)——用约 1000 条精选样本论证「质量 > 数量」与「对齐主要在激活预训练能力」的假设,本课第五节的直接依据。
  • 下一步:数据没构建好会怎样?SFT 之后「变傻」的数据偏移与过拟合问题,见第 0016 课。

一句话记忆:SFT 数据 = 「prompt → 好回答」的示范;只在 assistant 段算 loss(prompt 置 -100);质量、多样性、去重比堆量更重要,数据量看目标给量级。
