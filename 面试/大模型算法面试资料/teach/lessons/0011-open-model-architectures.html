开源架构对比与 Tokenizer / BPE

2017 年的原始 Transformer 和今天的 LLaMA、Qwen、DeepSeek,骨架是同一具:注意力 + FFN + 残差。但几乎每一个零件都被换过一遍——位置编码、归一化、注意力、激活、FFN 结构。面试官特别爱在这里追问「你说说 DeepSeek 和 LLaMA 到底差在哪」「为什么现在都用 RMSNorm 而不是 LayerNorm」。这节课把这套「现代化改造清单」讲清楚,再补上模型的入口——Tokenizer 与 BPE。

上节课我们把预训练分成三种范式(encoder-only / decoder-only / encoder-decoder),并看到主流开源大模型几乎都收敛到了 decoder-only。那么新问题来了:既然骨架都是 decoder-only 的 Transformer,为什么 LLaMA、Qwen、DeepSeek 还是各不相同?它们到底动了哪些零件、又为什么这么动? 先自己列几个你知道的差异点,再往下看。

一、直觉:骨架没变,零件全换了一遍

把原始 Transformer 想成一辆 2017 年的车:发动机(注意力)、变速箱(FFN)、车架(残差连接)这套底盘至今没变。但发动机换了涡轮(RoPE),换了更省油的机油(RMSNorm),多缸共享了油路(GQA/MLA),变速箱换了更平顺的挡位(SwiGLU),甚至给你并联了好几台按需启动的发动机(MoE)。逐个零件都是一次「针对性优化」,每次优化都对应一个明确的痛点。

组件原始 Transformer(2017)现代主流 LLM 常见做法升级动机(要能一句话答出)
位置编码正弦绝对编码 / 可学习绝对编码RoPE(部分用 ALiBi 等)表达相对位置、对更长序列外推更友好
归一化LayerNorm(且多为 Post-Norm)RMSNorm + Pre-Norm更省算、深层训练更稳
注意力MHA(多头)GQA / MLA压缩推理时的 KV Cache 显存
FFN 激活ReLUSwiGLU(门控 GLU 家族)门控带来更强的表达/更好的经验效果
FFN 结构稠密(每 token 走全部参数)MoE(稀疏,每 token 只走 Top-K 专家)总参数量放大而单 token 算力不成比例增长

注意用词:这是「主流/常见」而非「所有」。ALiBi、不同的激活变体、稠密与 MoE 并存,都真实存在;别在面试里把某一种说成「唯一」。

为什么是 RoPE,不是绝对位置编码?

原始的正弦绝对编码给「第 5 个位置」一个固定向量,模型看到的是绝对坐标;可语言里真正重要的往往是相对距离(「这个词离那个动词几步」)。而且训练时序列长度有隐含假设,推到远更长的序列时表现容易掉。

RoPE 的做法是把每一对特征维度看成二维平面上的点,按位置 $m$ 旋转一个角度:

$$\begin{pmatrix} \tilde{x}^{(2i-1)}\\ \tilde{x}^{(2i)} \end{pmatrix}=\begin{pmatrix} \cos m\theta_i & -\sin m\theta_i\\ \sin m\theta_i & \cos m\theta_i \end{pmatrix}\begin{pmatrix} x^{(2i-1)}\\ x^{(2i)} \end{pmatrix},\qquad \theta_i=10000^{-2i/d}$$

$m$ 是 token 的绝对位置,$\theta_i$ 控制每一维的旋转速度(低维转得快、高维转得慢)。

妙处在于:query 和 key 各自旋转后再做点积,结果只依赖二者的位置差 $m-n$:

$$\langle R_m q,\;R_n k\rangle=g(q,k,\;m-n)$$

旋转是正交变换,不改变向量长度;相对位置被「免费」编进了注意力分数里。这也是它外推更友好的原因。

为什么是 RMSNorm + Pre-Norm?

LayerNorm 要先减均值再除标准差,还带偏置:$\hat{x}=\frac{x-\mu}{\sigma}\odot g+b$。RMSNorm 砍掉了「减均值」这一步,只用均方根做缩放:

$$\operatorname{RMSNorm}(x)=\frac{x}{\sqrt{\dfrac{1}{d}\sum_{i=1}^{d}x_i^2+\epsilon}}\odot g$$

$g$ 是可学习的逐维缩放增益,$\epsilon$ 防止除零。没有减均值、通常也没有偏置,少一批统计量和参数,算得更快。经验上,去掉重新居中(re-centering)对效果影响很小,而重新缩放(re-scaling)才是稳定训练的关键。

而 Pre-Norm(把归一化放在子层之前、残差之外)相比原始的 Post-Norm,让梯度有一条不被反复归一化「挤压」的干净通路,深层网络更容易训练稳定。代价是最终表示可能需要一个额外的收尾 Norm,且极深时表达力略有讨论——但工程上,大模型堆几十上百层时,Pre-Norm 的稳定性收益压倒一切。

SwiGLU:把激活换成「门控」

原始 FFN 是 $\operatorname{ReLU}(xW_1)W_2$,两个权重矩阵。SwiGLU 属于 GLU(门控线性单元)家族,用一路信号去「开关」另一路:

$$\operatorname{FFN}_{\text{SwiGLU}}(x)=\big(\operatorname{Swish}(xW_{\text{gate}})\odot xW_{\text{up}}\big)W_{\text{down}},\qquad \operatorname{Swish}(z)=z\,\sigma(z)$$

注意它用了三个权重矩阵(gate / up / down),比原始 FFN 多一个;为了保持参数量可比,SwiGLU 的隐藏维通常取得比 ReLU-FFN 小一些。门控让网络能更灵活地控制信息通过。

MoE:总参数放大,单 token 算力不放大

MoE 把一层稠密 FFN 换成 $N$ 个并列的「专家」FFN,外加一个路由器(Router)。每个 token 只被送去得分最高的 Top-K 个专家,输出是它们的加权和:

$$y=\sum_{i\in\text{TopK}(x)} g_i\,E_i(x)$$

$g_i$ 是路由器给专家 $i$ 的门控权重,$E_i$ 是第 $i$ 个专家。关键点:总参数量(所有专家)可以很大,但每个 token 实际激活的只有 K 个专家,算力(FLOPs)按激活量算,不按总量算。这就是「大而不贵」。

MoE 最大的工程麻烦是负载均衡:路由器容易「偏心」,把大多数 token 塞给少数几个专家,其余专家吃不饱、训不动(马太效应)。两条主流对策:

  • 辅助损失(Auxiliary Loss):在主损失外加一个惩罚项,监控每个专家的负载频率 $f_i$ 与路由概率 $P_i$,逼它们趋于均匀——$L_{aux}=\alpha\,N\sum_{i=1}^{N} f_i\,P_i$。缺点:这个额外梯度会干扰主任务的学习。
  • 无辅助损失均衡(Auxiliary-Loss-Free):给每个专家配一个可动态调整的偏置,Top-K 选人时用「路由分数 + 偏置」;哪个专家过载就调低它的偏置,欠载就调高。偏置只影响「选谁」,不直接进主损失的梯度,避免了干扰。这是 DeepSeek 系列采用的思路。

二、家族取舍:同一套零件,不同的组合

把上面的零件当成「可选配件」,各家的差异其实就是选配清单不同。下面是概念层面的对比(不钉死具体版本号/参数,那些会随迭代变):

家族可以记住的「性格」
LLaMA把「现代配方」做成了开源标准模板:RoPE + RMSNorm(Pre-Norm) + SwiGLU,较大模型上用 GQA,主体是稠密结构。很多后来者都是在这份配方上做增删。
Qwen整体沿用同一类 decoder-only 现代配方(RoPE / RMSNorm / SwiGLU / GQA 这一系),并同时提供稠密与 MoE 两条产品线。可理解为「同一底盘上的一个成熟、覆盖面广的家族」。
DeepSeek差异化最鲜明:注意力用 MLA(把 KV 压成低维隐向量再动态解压,极致省 KV Cache),FFN 用细粒度 MoE(更多、更小的专家 + 共享专家),并采用无辅助损失的偏置式负载均衡。面试常拿它和 LLaMA 对比。
GLM早期最大特色不在零件而在预训练目标:自回归空白填充(autoregressive blank infilling),用一套目标同时兼顾「理解」与「生成」,不是纯 causal LM;后续版本逐步向主流 decoder-only 风格靠拢。

面试高频题:DeepSeek 和 LLaMA 架构差在哪?

别背版本号,答「设计选择」的差异,分两条主线最清楚:

  • 注意力:LLaMA(较大模型)用 GQA——让多个 query 头共享一组 K/V 头来省显存;DeepSeek 用 MLA——把 K/V 联合压缩成一个低维隐向量 $c_t$ 存进 Cache,计算时再解压回各头。二者目标一致(省 KV Cache),机制不同:GQA 是「共享」,MLA 是「压缩+解压」。
  • FFN:LLaMA 主体是稠密 FFN(SwiGLU);DeepSeek 用细粒度 MoE + 无辅助损失均衡。前者「每 token 走全部参数」,后者「每 token 只走少数专家」。
KV Cache 怎么一步步变小(概念示意,不代表具体倍数):

  MHA:  每个 Q 头都有自己的 K、V           →  Cache 最大
  GQA:  若干 Q 头共享一组 K、V(分组)      →  Cache 中等
  MLA:  只缓存压缩后的低维隐向量 c_t,      →  Cache 最小
        用时再投影解压回多头 K、V

三、模型的入口:Tokenizer 与 BPE

模型不吃字符串,吃的是整数 ID。把文本切成一串 token、再映射成 ID,这一步就是 Tokenizer。切分的粒度有三种选择,子词(subword)是折中出来的甜点区:

字符级
切成单字/字节
没有 OOV,但序列超长、单 token 语义太弱、算得慢
词级
切成整词
语义强,但词表爆炸、新词/稀有词直接 OOV、无法拆词形
子词级(BPE 等)
常见词整块、罕见词拆片
词表可控、几乎无 OOV、能拼出没见过的词

为什么不用字级、也不用词级?

  • 词级的死穴是 OOV(未登录词):词表一旦固定,遇到没收录的新词/拼写/专有名词就只能标成 <unk>,信息全丢;而要覆盖所有词,词表会大到无法承受。
  • 字级没有 OOV,但把「language」拆成 8 个字符,序列长度暴涨——注意力是 $O(n^2)$,序列越长越贵,而且单个字符几乎不携带语义,模型要花更多层去「重新拼词」。
  • 子词两头取好处:高频词(the、ing)保留成整块,低频词拆成有意义的片段(如 token + ization),既压住了序列长度和词表大小,又能用已有片段拼出训练时没见过的词。

BPE(字节对编码)在做什么?

BPE 是一种无监督的子词构建法:从最细的单位起步,不断把「出现最频繁的相邻单位对」合并成一个新单位,直到达到预设的合并次数(即目标词表大小)。以 hello world 为例的迭代:

初始(字符):  h e l l o   w o r l d
统计相邻对频率 → 'l'+'l'... 最高频的相邻对被合并
合并 "e"+"l" → "el":   h el l o   w o r l d
继续合并 "el"+"l" ...:  逐步长出 "ell"、"ello" 之类子词
… 重复,直到达到设定的合并次数 / 词表大小

训练结束后得到一张「合并规则表」+ 词表。推理时对新文本按同样的规则贪心地切分。工业上常用的是它的变体 byte-level BPE——在字节而非字符上做 BPE,这样任何 Unicode 文本(中文、emoji、乱码)都能被表示,彻底消除 OOV。

词表大小怎么权衡?

这是面试爱追的点,记住它是一把双刃剑:

  • 词表越大:同一段文本切出的 token 越少(序列更短、单位算力覆盖的信息更多),但 embedding 矩阵和输出层 softmax 都随词表线性变大(更多显存、更大末层计算),且很多罕见 token 见得少、训练不充分。
  • 词表越小:embedding/输出层省,但序列变长、注意力更贵。

所以词表大小是显存、序列长度、训练充分度之间的折中,不存在「越大越好」。多语言/代码场景往往需要更大的词表来把非英文、符号切得不那么碎。

BPE(Byte-Pair Encoding)
一种子词分词算法:从字符(或字节)开始,反复合并语料中最高频的相邻单位对,直到达到目标词表大小。兼顾「几乎无 OOV」与「词表可控」。
RMSNorm
只做均方根缩放、不减均值的归一化:$\operatorname{RMSNorm}(x)=\dfrac{x}{\sqrt{\frac1d\sum_i x_i^2+\epsilon}}\odot g$。比 LayerNorm 少算均值、通常无偏置,更省更稳。
MoE 的激活参数 vs 总参数
总参数 = 所有专家参数之和(很大);激活参数 = 单个 token 实际经过的参数(仅 Top-K 专家,较小)。算力按激活参数走。
# 一个玩具级 BPE:反复合并最高频相邻对(展示思想,非工业实现)
from collections import Counter

def get_pairs(tokens):
    return Counter(zip(tokens, tokens[1:]))   # 统计相邻对频率

def bpe_train(tokens, num_merges):
    merges = []
    for _ in range(num_merges):
        pairs = get_pairs(tokens)
        if not pairs:
            break
        best = max(pairs, key=pairs.get)      # 频率最高的相邻对
        merges.append(best)
        # 把序列里所有 best 相邻对合并成一个新单位
        merged, i = [], 0
        while i < len(tokens):
            if i < len(tokens) - 1 and (tokens[i], tokens[i+1]) == best:
                merged.append(tokens[i] + tokens[i+1])
                i += 2
            else:
                merged.append(tokens[i]); i += 1
        tokens = merged
    return tokens, merges

seq = list("hello world hello")   # 从字符起步
print(bpe_train(seq, num_merges=5))

面试官会怎么问:

  • 「现代 LLM 相比原始 Transformer 改了哪些地方?」——按清单答:RoPE(位置)、RMSNorm+Pre-Norm(归一化)、GQA/MLA(注意力省 KV)、SwiGLU(激活)、MoE(稀疏 FFN),每条都能说出动机。
  • 「DeepSeek 和 LLaMA 架构差别?」——两条主线:注意力(GQA「共享」vs MLA「压缩解压」)、FFN(稠密 vs 细粒度 MoE + 无辅助损失均衡)。
  • 「为什么用 RMSNorm 而不是 LayerNorm?为什么 Pre-Norm?」——省去减均值、少参数更快,重新缩放才是稳定关键;Pre-Norm 给梯度留干净通路,深层更稳。
  • 「为什么用 RoPE?绝对编码有什么问题?」——绝对编码只给绝对坐标、外推差;RoPE 用旋转把相对位置编进点积,外推更友好且无额外可学习参数。
  • 「为什么用 BPE 子词,不用字/词级?词表大小怎么定?」——词级 OOV+词表爆炸,字级序列太长语义弱;子词折中。词表越大序列越短但末层越大、罕见 token 训不充分。
  • 「MoE 怎么做负载均衡?」——辅助损失(会干扰主任务)vs 无辅助损失偏置法(DeepSeek);还有专家容量、噪声路由等。

易错点:

  • 别说「所有大模型都用 RoPE」。ALiBi 等相对位置方案真实存在,措辞用「主流/多数」。
  • RMSNorm 不是「没有可学习参数」——它去掉了减均值和偏置,但保留逐维缩放增益 $g$。
  • Pre-Norm 与 Post-Norm 是归一化相对残差的位置之别(之前 vs 之后),不是换了别的 Norm;两者可以和任意 Norm 组合。
  • MLA 不等于 GQA。GQA 是「多头共享同一组 K/V」;MLA 是「把 K/V 压成低维隐向量再解压」——机制不同,别混为一谈。
  • MoE 的「总参数量」不等于「单 token 算力」。看到「几百 B 参数的 MoE」别脑补成同规模稠密模型的算力。
  • SwiGLU 用三个权重矩阵(比原始 FFN 多一个),为保参数量可比通常把隐藏维调小,别忘了这一点。
  • 不要在答案里报没把握的具体数字(某模型词表多大、KV 省几倍、专家几个)。说不准就讲「量级 / 权衡方向」。

RMSNorm 短到可以默写,面试白板题常见。自己敲一遍,顺便对照 LayerNorm 想想少了哪一步:

import torch, torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.g = nn.Parameter(torch.ones(d))   # 可学习缩放增益,注意保留
        self.eps = eps

    def forward(self, x):                       # x: [..., d]
        rms = x.pow(2).mean(dim=-1, keepdim=True).add(self.eps).sqrt()
        return x / rms * self.g                 # 只缩放,不减均值、无偏置

自测 1:为什么现代 LLM 大多用 RoPE 取代原始的正弦绝对位置编码?

A. RoPE 引入了更多可学习参数,拟合能力更强错。RoPE 本身没有可学习参数,它靠固定的旋转把位置编进 Q/K。
B. RoPE 让模型不再需要注意力就能建模位置错。RoPE 恰恰是作用在注意力的 Q/K 上,离不开注意力。
C. RoPE 用旋转把位置编进 Q/K,点积后天然表达相对位置,且对更长序列外推更友好 ✅正确。旋转是正交变换不改变模长,点积结果只依赖位置差 $m-n$,相对位置「免费」得到,外推也更友好。
D. RoPE 只能和 RMSNorm 搭配使用错。RoPE 与归一化方案相互独立,可自由组合。

自测 2:关于 BPE 词表大小的权衡,下面哪个说法是对的?

A. 词表越大,同一段文本切出的 token 越少(序列更短),但 embedding/输出层更大、稀有 token 训练不充分 ✅正确。这正是词表大小的双刃剑:序列变短省注意力算力,但末层随词表线性变大,长尾 token 见得少训不透。
B. 词表越大,序列一定越长,显存一定越省错。词表越大序列反而越短;且末层显存随词表增大,不是「一定越省」。
C. 字符级切分没有 OOV,所以一定比子词更好错。字级虽无 OOV,但序列过长、单 token 语义弱,并非「一定更好」。
D. 词表大小对模型的显存和计算没有任何影响错。embedding 与输出 softmax 都随词表大小线性变化,影响显著。

这节课的一手出处与深挖方向:

  • RoFormer: Enhanced Transformer with Rotary Position Embedding(Su et al., 2021)——RoPE 原始论文,本课旋转矩阵与相对位置性质出自此。
  • Root Mean Square Layer Normalization(Zhang & Sennrich, 2019)——RMSNorm 原始论文,论证去掉 re-centering 的可行性。
  • GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints(Ainslie et al., 2023)——分组共享 K/V。
  • GLU Variants Improve Transformer(Shazeer, 2020)——SwiGLU 等门控激活的来源。
  • Neural Machine Translation of Rare Words with Subword Units(Sennrich et al., 2016)——把 BPE 引入 NLP 的经典论文。
  • Outrageously Large Neural Networks: The Sparsely-Gated MoE Layer(Shazeer et al., 2017)与 Switch Transformer(Fedus et al., 2021)——MoE 与负载均衡辅助损失。
  • LLaMA: Open and Efficient Foundation Language Models(Touvron et al., 2023)与 DeepSeek-V2 / V3 技术报告——MLA、细粒度 MoE、无辅助损失均衡的一手出处。
  • GLM: General Language Model Pretraining with Autoregressive Blank Infilling(Du et al., 2022)——GLM 空白填充预训练目标。
