对齐与 RLHF 全流程

预训练 + SFT 之后,模型已经会说人话、能听懂指令,可它未必会说「该说的话」——回答可能有用但危险、诚实但冒犯,或者礼貌地一本正经胡编。RLHF(基于人类反馈的强化学习)做的事,就是把「人类更喜欢哪种回答」这件写不成规则的事压进一个奖励模型,再用强化学习把模型往那个方向推。这是 ChatGPT 之所以「好用」的关键工序,也是对齐岗面试的必考主线:面试官几乎一定会让你把三个阶段从头讲一遍。

上一课(微调的坑)讲过:微调能让模型学会某种格式、语气、领域腔调,但它本质是行为克隆——把训练集里的回答尽量照着学「像」。先别往下看,想一个问题:如果我手上有两条回答,一条「有用但啰嗦」、一条「简洁但漏了关键点」,SFT 该把哪一条当作唯一标准答案喂进去?你会发现,「哪条更好」这件事,常常没法压成一条唯一的金标准。RLHF 正是从这个裂缝里长出来的。

一、为什么要对齐:SFT 教「像」,对齐教「好」

把训练分成两种目标最容易看清区别:

  • SFT 教「像」——给它一堆 (prompt, 人写回答),让它模仿人的说话方式。它学到的是「回答长这样」,是对形式与指令跟随的模仿。
  • 对齐教「好」——让它在无数种「都说得通」的回答里,倾向于人类真正偏好的那一种。这里的「好」通常拆成三条,业界常写作 HHH:有用(helpful)、无害(harmless)、诚实(honest)。

关键在于:「好」这个信号难以写成监督标签。你没法给每条回答标一个客观正确的答案,也难给每条回答打一个稳定的绝对分。但人类比较两条回答「哪个更好」却相对容易、相对一致。RLHF 的整套设计,都是围绕「把这种相对偏好用起来」展开的。

二、RLHF 三阶段:从模仿到偏好优化

经典 RLHF(以 InstructGPT 为代表)是三段流水线,每一阶段的产出是下一阶段的输入:

阶段 ①:SFT(监督微调)

用高质量的 (prompt, 人写回答) 教模型听懂指令、给出合理格式的回答。产出一个 SFT 模型,它是后两阶段的共同起点——既当策略的初始化,也当 RM 的骨干,还当 KL 惩罚里的参考模型 $\pi_{\text{ref}}$。

阶段 ②:训练奖励模型 RM

对同一个 prompt 采样多条回答,让人标注两两之间谁更好,得到成对偏好数据 $(x,\,y_w,\,y_l)$($y_w$ 是被选中的 chosen,$y_l$ 是被拒绝的 rejected)。用这些偏好训练一个打分模型 $r_\phi(x,y)$,把「人类偏好」变成一个可以求导的标量奖励。RM 的骨干通常就是 SFT 模型,把最后那层词表投影换成一个输出标量的头。

阶段 ③:RL 优化策略(PPO)

让策略 $\pi_\theta$(从 SFT 模型初始化)针对 prompt 现场生成回答,用 RM 给这条回答打分当奖励,再用 PPO 更新策略,让高分回答的概率上升。同时加一项 KL 惩罚,拴住策略别离参考模型 $\pi_{\text{ref}}$ 太远。这一阶段是 on-policy 的:被打分和被纠正的,是模型自己此刻采样出来的回答。

SFTRLHF(阶段 ②③)
信号来源人写的标准答案人对两条回答的相对偏好
学到什么模仿单条回答(「像」)倾向人类偏好的方向(「好」)
能否给负例否,只能「照这条学」能,分数高低都是反馈
训练数据的分布固定的人写语料模型自己采样(on-policy)

三、奖励模型 RM 到底怎么训

RM 吃一对回答,输出两个标量分数,训练目标是让优选回答的分数高于劣选。这套用成对比较拟合一个分数的做法,数学上就是经典的 Bradley-Terry 模型:

奖励模型的成对偏好损失(Bradley-Terry)
$$\mathcal{L}_{\text{RM}}(\phi)=-\,\mathbb{E}_{(x,\,y_w,\,y_l)\sim\mathcal{D}}\Big[\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\Big]$$
$\sigma$ 是 sigmoid;$r_\phi(x,y_w)-r_\phi(x,y_l)$ 是优选与劣选的分差。$\sigma(\cdot)$ 把分差映射成「$y_w$ 胜过 $y_l$ 的概率」,最小化负对数似然就是把这个概率往 1 推。它只约束相对高低,不约束绝对分值。

为什么用成对比较而不是让人直接打绝对分?让人判断「这条值 0.8 还是 0.7」既慢又难前后一致;判断「A 和 B 哪个更好」稳定得多、也更省力。源材料里 RM 数据被简写成 Input,Reward 的绝对分示意,那是便于理解的简化——工业界主流(如 InstructGPT)训练 RM 用的是成对偏好数据。面试里这一点常被追,别答错。

四、为什么用 RL,不直接 SFT?

这是本课最高频的追问。三条理由,层层递进:

  1. 偏好是相对的,没有唯一金标准。SFT 需要一条「标准答案」照着学,但很多任务里「更好」只能在两条回答之间比较,你写不出那条唯一最优——正是开头 recall 里那个「啰嗦 vs 漏关键点」的困境。
  2. RL 能给负例信号。SFT 只会说「照这条学」,没法说「别像那条」;RM 给出连续分数,好和坏都能反馈,模型知道要远离什么。
  3. 需要在模型自己的分布上探索纠错(on-policy)。RL 阶段是对模型当前采样出来的回答打分再更新,它在自己真实会犯错的地方被纠正;SFT 只在固定的人写数据上模仿,覆盖不到模型自己真实的输出分布。

阶段 ③ 要最大化的目标,一行写清:

$$\max_{\pi_\theta}\;\; \mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\big[\,r_\phi(x,y)\,\big]\;-\;\beta\,\mathbb{E}_{x}\Big[\operatorname{KL}\big(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\text{ref}}(\cdot\mid x)\big)\Big]$$

前一项:让 RM 打分越高越好。后一项(KL 惩罚,系数 $\beta$):拴住策略别离参考模型 $\pi_{\text{ref}}$ 太远,防止为了刷高分把语言能力练崩。PPO 只是求解这个目标的优化器——重要性采样比、截断 $\epsilon$、优势估计等机制留到下一课 0018 展开。

五、RLHF 的软肋,与它催生的 DPO

RLHF 强,但代价不小,这些不足几乎每一条都能被面试官拿来往深里问:

  • 奖励黑客(reward hacking)。RM 只是人类偏好的近似,不是真理。策略会钻 RM 的漏洞去刷高分——比如变得更长、更谄媚、堆套话——但人并不真喜欢。KL 惩罚能缓解,难根治。
  • 标注贵。偏好数据要人一对一对地比较,慢且烧钱(源材料原话:人类反馈的代价高昂)。
  • 训练不稳、工程复杂。PPO 阶段常要在显存里同时放策略、参考模型、奖励模型,还有价值网络,再叠加在线采样;超参敏感,错误的反馈会被放大(源材料:错误反馈的影响)。

正是这些痛点催生了 DPO(第 0020 课):它跳过显式的 RM 训练和 RL 循环,直接拿成对偏好用一个分类式损失优化策略,把三段流水线压成一步。理解了 RLHF 为什么这么绕、绕在哪,才能听懂 DPO 到底省掉了什么。

奖励模型的成对损失,核心就几行(把上面 Bradley-Terry 公式直接翻译过来):

import torch.nn.functional as F

# reward_model: 读入 (prompt, response) 输出一个标量分数
# 骨干通常是 SFT 模型,把词表输出层换成 1 维的打分头
def rm_loss(reward_model, prompt, chosen, rejected):
    r_w = reward_model(prompt, chosen)     # 优选回答的分数,标量
    r_l = reward_model(prompt, rejected)   # 劣选回答的分数,标量
    # 最大化 σ(r_w - r_l)  ⇔  最小化下面的负对数似然
    return -F.logsigmoid(r_w - r_l).mean()  # 只看分差,不看绝对值

面试官会怎么问:

  • 「把 RLHF 三阶段讲一遍,每步在干什么、产出什么?」——SFT 给起点 → RM 把偏好压成标量 → PPO 用 RM 当奖励优化策略并用 KL 拴住参考模型。
  • 「奖励模型怎么训?数据长什么样?」——SFT 模型换标量头,吃成对偏好 $(x, y_w, y_l)$,用 Bradley-Terry 损失让 chosen 的分高于 rejected。
  • 「为什么不直接 SFT 把好回答喂进去,非要上 RL?」——偏好是相对的没有唯一答案、需要负例信号、需要在模型自己的采样分布上探索纠错。
  • 「阶段 ③ 那个 KL 惩罚干嘛的?$\beta$ 调大调小会怎样?」——拴住策略别离参考太远;$\beta$ 大 → 更保守、更接近原模型但难提升,$\beta$ 小 → 更激进、更易奖励黑客甚至崩坏(源:$\beta$ 调大调小的影响)。
  • 「RLHF 有什么问题?你会怎么替代?」——奖励黑客 / 标注贵 / 训练不稳,顺势引出 DPO。

易错点:

  • RM 输出的是相对分数,绝对值本身没意义——同一 RM 的分只在同一 prompt 下比较才有意义,别把不同 prompt 的 RM 分直接比大小。
  • 别把 RM 数据说成「每条回答一个人打的绝对分」;主流是成对偏好比较(chosen / rejected)。
  • 参考模型 $\pi_{\text{ref}}$ 一般是 SFT 模型的冻结副本,不是预训练裸模型;KL 是相对它算的。
  • 「RLHF 就是 PPO」不准确:PPO 只是阶段 ③ 的优化器,RLHF 是整条三阶段流水线;阶段 ③ 也可换成别的 RL 算法(如 GRPO)。
  • 别说「RL 不需要人工标注」——偏好标注恰恰是 RLHF 里最贵的人力成本。

自测 1:RLHF 的第二阶段(训练奖励模型)用的是什么形式的数据?

A. 单条 (prompt, 唯一标准答案) 的监督对那是 SFT(阶段 ①)的数据形式,不是 RM。
B. 每条回答由人打一个绝对分数(如 0.8)这是便于理解的简化示意;主流做法是成对比较,因为人打绝对分既慢又不一致。
C. 成对偏好数据 (prompt, chosen, rejected),标注谁比谁好 ✅正确。RM 用 Bradley-Terry 损失让 chosen 的分高于 rejected,只约束相对高低。
D. 大量无标注的纯文本那是预训练用的数据,与偏好无关。

自测 2:为什么 RLHF 要绕道 RL,而不直接用 SFT 把「好回答」喂进去?

A. RL 训练更快、更省显存相反,PPO 阶段要同时放策略/参考/奖励/价值多个模型,更慢更吃显存。
B. 偏好是相对的、没有唯一最优答案;RL 能对模型自己采样的回答按相对好坏打分并探索,SFT 只能模仿单一参考答案 ✅正确。这三点(相对偏好、负例信号、on-policy 探索)正是要上 RL 的核心理由。
C. SFT 无法处理长文本,RL 才可以处理长文本靠上下文长度与架构,与 SFT/RL 的选择无关。
D. RL 完全不需要人工标注恰恰相反,偏好标注是 RLHF 最贵的人力成本。

这节课的一手出处与深挖方向:

  • Training language models to follow instructions with human feedback(Ouyang et al., 2022)——InstructGPT,经典三阶段 RLHF 的标准参考,SFT → RM → PPO 的流程与图都出自这里。
  • Learning to summarize from human feedback(Stiennon et al., 2020)——更早地把成对偏好 RM + PPO 跑通,读它能看清 RM 训练细节。
  • Deep reinforcement learning from human preferences(Christiano et al., 2017)——偏好驱动 RL 的源头,Bradley-Terry 式成对建模的出处之一。
  • Proximal Policy Optimization(Schulman et al., 2017)——阶段 ③ 用的 PPO 优化器,细节留到下一课 0018。
  • 下一步:强化学习基础与 PPO 机制(第 0018 课);跳过显式 RM/RL 循环的 DPO(第 0020 课)。

一句话记忆:RLHF = SFT 起步 → 用成对偏好训一个打分的奖励模型 → 再用 RL(PPO)把策略往高分推、用 KL 拴住参考模型;SFT 教「像」,RLHF 教「好」。
