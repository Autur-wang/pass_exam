Transformer 整体结构与数据流

几乎所有大模型都长在 Transformer 这棵树上。面试第一问往往就是「讲讲 Transformer 的结构」——它是判断你到底是背过图还是看懂了数据怎么流的分水岭。这节课不抠注意力的公式细节(留给 0002/0003),只把全景讲透:数据从输入到输出走了哪几步、encoder 和 decoder 各干什么、它凭什么比 RNN 又快又强。

这是本课的第一节,没有上一课。先自己想一个问题热身:假设让你把「我爱你」翻译成英文,模型得先「读懂」整句、再逐词吐出译文。如果用 RNN 一个词一个词地读,离得远的词要「互相看到」会有什么麻烦?整句能不能一次性并行处理?带着这个疑问往下看。

一、从 RNN 的困境说起:Transformer 要解决什么

Transformer 之前,序列建模主流是 RNN / LSTM 搭的 seq2seq:一个编码器把输入句子逐词读进去、压成一个(或一串)隐状态,一个解码器再逐词吐出译文。它有两个结构性的痛点:

  • 算不快:RNN 第 $t$ 步的隐状态依赖第 $t-1$ 步的输出,时间步之间是串行递推,天然无法在序列维度上并行,喂不饱 GPU。
  • 看不远:两个相距 $n$ 的词要「互相影响」,信号得沿着递推链走大约 $n$ 步,一路上不断被覆盖、衰减——这就是长程依赖难学、梯度容易消失的根源。

Transformer 的答案很激进:彻底扔掉循环和卷积,只靠注意力(attention)。注意力让序列里任意两个位置一步直连,而且这一步是一次大矩阵乘法——既解决「看不远」,又解决「算不快」。

维度RNN / seq2seqTransformer
序列内计算方式逐时间步串行递推一次矩阵运算,全部位置并行
任意两位置的连接路径长度约 $O(n)$ 步$O(1)$ 步(直接相连)
长程依赖易衰减、难学天然可达
训练能否并行(序列维)难能(见第五节)

「路径长度」指信息从一个位置传到另一个位置要经过多少次计算——越短,越容易学到长程关系。这张对比是面试答「Transformer 相比 RNN 好在哪」的骨架。

二、全景:Encoder 与 Decoder 两大块

原始 Transformer 是为机器翻译设计的编码器-解码器(encoder-decoder)架构,左半是 encoder,右半是 decoder。原论文里两边各堆叠 $N$ 层相同的结构(原文取 $N=6$)。先看数据整体怎么流:

三句话记住分工:

  • Encoder(编码器):把输入序列编码成一串富含上下文的向量表示。它能同时看到输入的所有词(双向),每一层只有两个子层:多头自注意力 + 前馈网络(FFN)。
  • Decoder(解码器):自回归地生成输出序列。它也有输入——训练时是「已知的、右移一位的目标序列」,推理时是「到目前为止已生成的词」。每一层有三个子层:带掩码的多头自注意力 → cross-attention(编码器-解码器注意力) → FFN。
  • 最后 decoder 顶部接一个线性层 + softmax,输出词表上的概率分布,取概率最高(或采样)的词作为下一个输出。

为什么 decoder 的自注意力要「带掩码」?因为生成第 $i$ 个词时,模型只能看到第 $1$ 到 $i-1$ 个词,不能偷看未来的词(否则训练时就作弊了)。掩码把「未来位置」的注意力分数设成 $-\infty$,softmax 后权重为 0——细节留到后面讲注意力的课。

为什么要残差连接(Residual Connection)?

子层的计算写成 $\operatorname{LayerNorm}(x+\operatorname{Sublayer}(x))$,那个 $+x$ 就是残差。它给梯度开了一条高速公路:反向传播时梯度可以绕过子层直接回流,缓解深层网络的梯度消失、让几十层也能训得动。直觉上,子层只需要学「在 $x$ 基础上要改动什么(残差)」,而不是从零重建整个映射,优化更容易。

为什么用 LayerNorm 而不是 BatchNorm?

NLP 里句子长度可变、同一 batch 里句子长短不一,BatchNorm 依赖「跨样本、同一特征维」的统计量,遇到变长序列很别扭。LayerNorm 对单个样本自己的所有特征维做归一化(把均值拉到约 0、方差拉到约 1),不跨样本,天然适配变长序列,也让训练更稳、收敛更快。

四、Encoder 与 Decoder 如何交互:cross-attention

两大块的唯一信息桥梁,就是 decoder 每层中间那个 cross-attention 子层(相对地,decoder 的另外两个子层只在自己内部流转)。它和自注意力用的是同一套「缩放点积注意力」机制,区别只在 Q、K、V 的来源:

Cross-Attention(编码器-解码器注意力)
Query 来自 decoder(下层的输出),Key 和 Value 来自 encoder 的最终输出:$$\operatorname{Attention}(Q_{\text{dec}},\,K_{\text{enc}},\,V_{\text{enc}})=\operatorname{softmax}\!\left(\frac{Q_{\text{dec}}K_{\text{enc}}^\top}{\sqrt{d_k}}\right)V_{\text{enc}}$$
直觉:decoder 拿着「我现在想生成什么」这个问题($Q$),去 encoder 编码好的源句子记忆里($K,V$)检索最相关的信息。这就是翻译时「对齐原文」的能力所在。注意 encoder 的输出对 decoder 的每一步是同一份,只需算一次。

这也回答了源材料里那个常考点:Encoder 端和 Decoder 端到底怎么交互?——就靠 cross-attention,decoder 出 $Q$、encoder 出 $K$ 和 $V$。

前馈网络(Feed-Forward Network, FFN)
每层里紧跟注意力的两层全连接,逐位置独立作用,中间夹一个非线性激活:$$\operatorname{FFN}(x)=\max(0,\,xW_1+b_1)\,W_2+b_2$$
注意力负责「在位置之间搬运、混合信息」,FFN 负责「在每个位置上做非线性变换、加工特征」——一个横向、一个纵向,配合起来。原文 FFN 用 ReLU,许多现代大模型换成了 GeLU / SwiGLU 等变体。

五、为什么整体能并行训练

这是 Transformer 相对 RNN 最关键的工程胜利,也是高频追问。原因有两层:

  • 层内无递推:一层里所有位置的自注意力和 FFN 都是一次性的大矩阵运算,不存在「第 $t$ 步等第 $t-1$ 步」的依赖,序列维天然并行,能吃满 GPU。
  • 训练时目标序列整段并行(teacher forcing):训练时正确的目标序列是已知的,把它右移一位喂给 decoder,配合因果掩码让每个位置只能看到自己左边——于是所有目标位置的预测可以在一次前向里同时算完,而不必像推理那样一个词一个词生成。

但要小心这个反例:

  • 「并行」说的是训练。推理(自回归生成)时,decoder 仍然是逐 token 串行的——每生成一个词都要把它接回输入再算下一步。别在面试里说成「Transformer 生成也能并行」。(推理慢正是后面 KV Cache 等课要优化的问题。)

面试官会怎么问:

  • 「讲一下 Transformer 的整体结构。」——encoder / decoder 各堆 $N$ 层;encoder 层 2 个子层、decoder 层 3 个子层;每个子层都套残差 + LayerNorm。别只背图,要说清数据怎么流。
  • 「相比 RNN,Transformer 解决了什么?」——并行(层内无递推)+ 长程依赖(任意两位置路径长度 $O(1)$)。把第一节那张对比表说出来。
  • 「Encoder 和 Decoder 怎么交互?」——cross-attention:decoder 提供 $Q$,encoder 输出提供 $K$、$V$。
  • 「一个 encoder block 里子层的顺序?」——自注意力 → 残差+Norm → FFN → 残差+Norm;decoder 中间多一层 cross-attention。
  • 「为什么 Transformer 能并行训练而 RNN 不能?」——无时间步递推 + teacher forcing + 因果掩码;记得补一句「推理仍是串行」。

易错点:

  • decoder 也有输入。常见误解是「只有 encoder 吃输入」;实际 decoder 训练时吃右移一位的目标序列,推理时吃已生成的前缀。
  • 原始论文是 Post-LN(残差之后再 LayerNorm:$\operatorname{LayerNorm}(x+\operatorname{Sublayer}(x))$);很多现代大模型改用 Pre-LN(先 Norm 再进子层),训练更稳。别一口咬定「Transformer 都是先残差后 Norm」。
  • decoder 的自注意力是带因果掩码的,cross-attention 一般不带因果掩码(它要看全部源句子)。
  • 「Transformer 完全没有顺序信息」不对——自注意力本身对位置无感,顺序是靠位置编码补进去的(后续课专门讲)。

用 PyTorch 把「一个 encoder block」的数据流写出来,感受子层顺序(注意力和 FFN 的内部实现留到后面的课):

import torch.nn as nn

class EncoderBlock(nn.Module):
    def __init__(self, d_model, n_head, d_ff):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, n_head, batch_first=True)
        self.ffn  = nn.Sequential(
            nn.Linear(d_model, d_ff), nn.ReLU(), nn.Linear(d_ff, d_model)
        )
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)

    def forward(self, x):
        # 子层1:自注意力 → 残差 + Norm(此处为 Post-LN 写法)
        a, _ = self.attn(x, x, x)          # Q=K=V=x,故称"自"注意力
        x = self.norm1(x + a)
        # 子层2:FFN → 残差 + Norm
        x = self.norm2(x + self.ffn(x))
        return x

自测 1:Transformer 中 Encoder 和 Decoder 是通过什么完成信息交互的?

A. Decoder 把自己的输出直接拼回 Encoder 的输入端不对,两块没有这种回接;交互只发生在 decoder 内部的 cross-attention 子层。
B. Encoder 和 Decoder 共享同一套权重不对,两者参数独立;而且共享权重也不构成「交互」。
C. cross-attention:Decoder 提供 Query,Encoder 的输出提供 Key 和 Value ✅正确。decoder 拿 $Q$ 去 encoder 记忆($K,V$)里检索相关信息,这是唯一的信息桥梁。
D. Encoder 最后一层直接当作 Decoder 的第一层堆上去不对,两块是并列的两个栈,不是首尾相接堆叠。

自测 2:为什么 Transformer 训练时能并行,而 RNN 不能?

A. 自注意力对所有位置一次性做矩阵运算、无时间步递推;配合 teacher forcing 与因果掩码,整段目标序列可在一次前向里同时算完 ✅正确。并行来自「层内无递推」+「训练时目标已知、右移+掩码」。注意这说的是训练;推理仍是逐 token 串行。
B. 因为 Transformer 参数比 RNN 少,所以算得快不对,并行与否是结构问题,不是参数量;Transformer 参数往往更多。
C. 因为 Transformer 不需要位置编码,省掉了顺序计算不对,Transformer 恰恰需要位置编码来补顺序信息;这与并行无关。
D. 因为 Transformer 只能在 GPU 上运行不对,能否并行是算法结构决定的,与跑在什么硬件上无关。
