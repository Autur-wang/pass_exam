位置编码:从正弦到 RoPE

自注意力有一个「先天缺陷」:它根本不知道词的先后顺序。「狗咬人」和「人咬狗」在它眼里可能是同一件事。这节课把位置信息怎么补进去讲透——从原始 Transformer 的正弦编码,到今天几乎所有主流大模型(LLaMA、Qwen、DeepSeek)都在用的 RoPE(旋转位置编码)。这是面试里「位置编码细讲一下」的标准答法。

上节课(多头注意力)我们把 $\operatorname{softmax}(QK^\top/\sqrt{d_k})V$ 并行成了 $h$ 个头。先别往下看,盯着这个公式想一想:如果我把输入序列的词序打乱,再打乱回来,这个公式算出的注意力权重会变吗?换句话说,公式里有任何一处用到了「谁在前、谁在后」吗?

一、问题:注意力对顺序「视而不见」

答案是——公式里没有任何一处依赖位置。$QK^\top$ 只看两个词的内容向量点积,softmax 只做归一化,加权求和只按权重取值。如果你把输入 $X$ 的行(token)重新排列,输出也只是跟着同样地重排,内容的对应关系一点不变。这个性质叫置换等变(permutation-equivariant)。

直觉后果:对纯注意力而言,「狗 咬 人」和「人 咬 狗」的 token 集合完全一样,它算不出「谁是主语、谁是宾语」。而 RNN 靠一步步递推天然带着顺序,CNN 靠卷积核的相对位置也带顺序——唯独注意力把顺序信息丢了。所以必须显式地把位置注入进去。

二、第一版答案:正弦/余弦绝对位置编码

原始 Transformer 的做法是:为每个位置 $pos$ 造一个和词向量等长的向量 $PE_{pos}$,直接加到词嵌入上。这个向量用一组不同频率的正弦、余弦函数生成:

$$PE_{(pos,\,2i)}=\sin\!\left(\frac{pos}{10000^{\,2i/d_{\text{model}}}}\right),\qquad PE_{(pos,\,2i+1)}=\cos\!\left(\frac{pos}{10000^{\,2i/d_{\text{model}}}}\right)$$

$pos$ 是位置序号,$i$ 是维度对的索引($0\le i<d_{\text{model}}/2$)。低维($i$ 小)频率高、转得快,负责刻画近距离差异;高维频率低、转得慢,负责跨越长距离。多个频率叠在一起,像时钟的秒针 / 分针 / 时针,一起把「第几位」编成一个唯一的向量。

为什么用三角函数而不是直接写个整数 $pos$?因为 $\sin/\cos$ 有界(不会随序列变长而数值爆炸),而且相邻位置的编码是平滑变化的,模型比较容易利用。但它有两个在面试里必须点出的局限:

  • 缺乏相对位置:它编的是「绝对第几位」。而语言里真正重要的往往是相对距离——「这个形容词修饰的是前面第 2 个名词」。绝对编码要靠模型自己从两个绝对位置里「减」出相对关系,并不直接。
  • 外推差:训练时只见过 $0\sim L$ 的位置组合。虽然 $\sin/\cos$ 对任意 $pos$ 都能算出数值,但模型从没学过如何使用那些更远位置的编码,推理时序列一旦变长,效果通常明显下滑。

三、RoPE 的核心思想:用「旋转」编码位置

RoPE(Rotary Position Embedding,旋转位置编码)换了个思路:不再把位置向量加到词向量上,而是把词向量按位置旋转一个角度。

具体做法:把 query / key 向量每相邻两维看作一个二维平面上的点 $(x^{(2i)}, x^{(2i+1)})$,位置在 $m$ 的向量,就把这个二维点逆时针旋转 $m\theta_i$:

RoPE 二维旋转
$$\begin{pmatrix}x'^{(2i)}\\[2pt] x'^{(2i+1)}\end{pmatrix}=\underbrace{\begin{pmatrix}\cos m\theta_i & -\sin m\theta_i\\[2pt] \sin m\theta_i & \phantom{-}\cos m\theta_i\end{pmatrix}}_{R_m^{(i)}}\begin{pmatrix}x^{(2i)}\\[2pt] x^{(2i+1)}\end{pmatrix}$$
整个 $d$ 维向量被切成 $d/2$ 个二维平面,第 $i$ 个平面的旋转频率为 $\theta_i=10000^{-2i/d}$。低维($i$ 小)$\theta$ 大转得快,高维转得慢——和正弦编码一样是「多尺度」的设计,只是从「相加」换成了「旋转」。

为什么旋转能让点积「自动」变成相对位置?

这是 RoPE 最漂亮的地方,也是面试必考的一句「为什么」。旋转矩阵有一个关键性质:两个旋转的转置相乘,等于它们角度之差的旋转:

$$R_m^\top R_n = R_{n-m}$$

因为 $R_m^\top=R_{-m}$(转置 = 反向旋转),而两次旋转相加,角度相减为 $n-m$。

于是,位置 $m$ 的 query 和位置 $n$ 的 key 做点积时:

$$\langle R_m q,\; R_n k\rangle=(R_m q)^\top(R_n k)=q^\top R_m^\top R_n\, k=q^\top R_{n-m}\, k$$

结果只依赖 $n-m$,也就是相对位置,绝对位置 $m$、$n$ 各自是多少反而被消掉了。

这就是核心:RoPE 施加的是绝对位置的旋转,但注意力分数(点积)只依赖两个词的相对距离。相对位置不再需要模型费劲去「减」,而是由点积的数学结构自然导出。同时它不引入任何额外可学习参数,也几乎不增加计算量。

四、为什么 RoPE 利于长度外推

把上面两点串起来就懂了:

  • 它编的是相对距离,不是绝对坐标。训练时模型学到的是「相隔 $k$ 的两个词该怎么互相关注」这类相对模式。只要相对距离 $k$ 在训练见过的范围内,即使整段序列被平移到更靠后的位置,注意力模式依然成立。绝对编码做不到这一点——换个绝对位置,加进去的向量就变了。
  • 旋转带来自然的远程衰减。RoFormer 论文给出:随着相对距离增大,注意力分数的上界会逐渐衰减,符合「离得越远、关联通常越弱」的语言直觉,让模型对超长距离不至于乱抓。

需要诚实说明:朴素 RoPE 在远超训练长度时同样会退化,并非「无限外推」。真正把上下文从几 K 拉到几十上百 K,靠的是在 RoPE 基础上的位置插值类方法(Position Interpolation、NTK-aware scaling、YaRN 等)——它们调整旋转频率或缩放位置,让训练学到的相对模式覆盖更长的范围。RoPE 的相对位置结构,正是这些外推技巧能生效的前提。

五、对比一句 AliBi

ALiBi(Attention with Linear Biases)是另一条为外推设计的路线,思路更「省事」:它完全不加位置向量、也不旋转,而是在注意力分数上直接减去一个与相对距离成正比的惩罚——离得越远,分数被压得越低。一句话对比:RoPE 靠「旋转 Q/K」把相对位置藏进点积;ALiBi 靠「按距离加线性惩罚」直接压低远处注意力。两者都比正弦绝对编码更擅长处理比训练更长的序列,主流大模型目前更多选择 RoPE。

把 RoPE 敲一遍最能记住「旋转」到底怎么落到代码上(注意:只作用于 Q、K,不作用于 V):

import torch

def rope_tables(d, seq_len, base=10000.0):
    # θ_i = base^{-2i/d},i = 0..d/2-1
    i = torch.arange(0, d, 2).float()
    theta = base ** (-i / d)                  # [d/2]
    pos = torch.arange(seq_len).float()       # [L]
    angles = torch.outer(pos, theta)          # [L, d/2],元素 = m * θ_i
    return angles.cos(), angles.sin()

def apply_rope(x, cos, sin):
    # x: [L, d];把相邻两维当作一个二维平面来旋转
    x_even, x_odd = x[..., 0::2], x[..., 1::2]           # 偶/奇维
    x_rot_even = x_even * cos - x_odd * sin              # 旋转矩阵第一行
    x_rot_odd  = x_even * sin + x_odd * cos              # 第二行
    return torch.stack([x_rot_even, x_rot_odd], -1).flatten(-2)

# 用法:q, k 先各自 apply_rope,再照常算 softmax(qk^T/√d)v;v 保持原样

面试官会怎么问:

  • 「Transformer 为什么必须要位置编码?去掉会怎样?」——自注意力置换等变,不加位置就区分不了词序,「狗咬人 / 人咬狗」变得一样。
  • 「正弦编码和 RoPE 有什么区别?」——正弦是加在输入上的绝对编码;RoPE 是乘在 Q/K 上的旋转,相对位置由点积自然导出。
  • 「RoPE 凭什么能表达相对位置?写一下核心。」——就答 $R_m^\top R_n=R_{n-m}$,所以 $\langle R_m q,R_n k\rangle$ 只依赖 $m-n$。这一步答出来基本就过了。
  • 「$\theta_i=10000^{-2i/d}$ 为什么这样设计?」——不同维度不同频率,低维转得快抓近距离、高维转得慢抓远距离,是多尺度编码;base(10000)可调,长上下文常调大。
  • 「RoPE 和 ALiBi 谁更适合长序列?」——都为外推而生;ALiBi 加距离惩罚更简单,RoPE 靠相对旋转 + 插值(PI/NTK/YaRN)扩展,主流模型多用 RoPE。

易错点:

  • RoPE 只旋转 Q 和 K,不旋转 V——位置信息要进的是「打分」环节,不是「取值」环节。
  • 正弦编码是加在词嵌入上、只在输入层一次;RoPE 是乘旋转、作用在每一层注意力的 Q/K 上。两者施加位置的方式和位置完全不同。
  • 别说「正弦编码根本没法算更长的位置」——它是连续函数,任意 $pos$ 都能算出数值,问题在于模型没学过怎么用,所以外推效果差,不是「算不出」。
  • RoPE 作用的角度 $m\theta_i$ 仍是绝对位置;「相对位置」是在点积那一步才涌现出来的,别混为一谈。
  • 朴素 RoPE 不是「天生能无限外推」;超出训练长度太多同样退化,长上下文要靠插值/缩放技巧。绝对话术在面试里要留余地。

自测 1:为什么 Transformer 必须显式加入位置编码?

A. 因为词嵌入维度不够,装不下语义信息维度与位置无关,加大维度也补不出词序。
B. 因为 softmax 在长序列上会损失数值精度数值精度不是位置编码要解决的问题。
C. 自注意力是置换等变的,对输入顺序不敏感,不加位置就分不清词序 ✅正确。$QK^\top$ 只看内容点积,打乱 token 顺序输出只是跟着重排,内容对应不变——顺序信息被丢掉了,必须显式补入。
D. 因为 RNN 太慢,位置编码是为了加速注意力计算位置编码不改变计算量,和加速无关。

自测 2:RoPE 能让注意力分数依赖相对位置,根本原因是?

A. 旋转矩阵满足 $R_m^\top R_n=R_{n-m}$,于是 $\langle R_m q,R_n k\rangle$ 只依赖位置差 $m-n$ ✅正确。绝对旋转在点积里两两抵消,只剩相对距离,这正是 RoPE 的数学核心。
B. RoPE 给每个位置学习一个可训练的位置向量那是可学习绝对编码;RoPE 不引入额外可学习参数。
C. RoPE 把位置编码直接加到 V 上,让取值带上位置RoPE 只旋转 Q、K,不作用于 V。
D. RoPE 用更大的 embedding 维度来存储绝对坐标RoPE 不增加维度,靠旋转而非扩容编码位置。

这节课的一手出处与深挖方向:

  • Attention Is All You Need(Vaswani et al., 2017)——§3.5 正弦/余弦绝对位置编码的原始出处,本课第二节的公式即出自此。
  • RoFormer: Enhanced Transformer with Rotary Position Embedding(Su et al., 2021)——RoPE 的原始论文,旋转矩阵、$\theta_i=10000^{-2i/d}$ 与远程衰减性质都在其中。
  • Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation(Press et al., 2022)——ALiBi 的论文,可对照理解另一条外推路线。
  • 顺着深挖长上下文:Position Interpolation、NTK-aware scaling、YaRN 是在 RoPE 之上扩展上下文长度的代表方法。
  • 下一步:位置编码之外,Transformer block 里的残差、LayerNorm 与 FFN(第 0005 课)。

一句话记忆:注意力对顺序无感,必须补位置;正弦编码是「加」在输入的绝对坐标,RoPE 是「旋转」Q/K,让点积 $q^\top R_{n-m}k$ 只依赖相对距离,因而更利于外推。
