QLoRA 与 Adapter / Prefix / P-Tuning

上一课的 LoRA 已经把「可训练参数」砍到很小,但那张冻结的 16-bit 基座还是稳稳占着显存的大头。QLoRA 的一招就是把这块也压掉——4-bit 量化基座 + 在其上训 LoRA,于是单卡微调大模型成为可能。这节课把 QLoRA 讲透,再横向串起 Adapter / Prefix-Tuning / P-Tuning 这几条并列的 PEFT 路线。面试里它们几乎必然被摆在一起对比:改哪里、加不加结构、参数量、推理有没有额外开销。

上节课(LoRA)的核心:冻结预训练权重 $W$,在旁边挂一条低秩旁路 $BA$,前向变成 $h=Wx+BAx=(W+BA)x$,训练时只更新 $A$、$B$,推理时把 $BA$ 合并回 $W$、零额外开销。先别往下看:LoRA 已经不训练 $W$ 了,可为什么显存还是下不去?那块显存到底花在哪?

一、QLoRA:把冻结的基座也压到 4-bit

先想清楚:LoRA 省了什么、没省什么

微调时的显存大致分四块:基座权重、梯度、优化器状态(如 AdamW 的一阶、二阶动量,通常是参数量的好几倍)、激活值。LoRA 让可训练参数骤减,于是梯度和优化器状态几乎清零——这是它省显存的主战场。但那张冻结基座仍然以 16-bit 原封不动地躺在显存里,而它恰恰是最大的一块。

QLoRA 的思路顺理成章:既然基座只用来做前向(不更新),那就没必要用 16-bit 存它——压成 4-bit,用的时候临时反量化算一算就行。基座这块显存直接缩到约四分之一,腾出的空间足以把上百亿参数的模型塞进单张 GPU。

把这条前向写成一行,和 LoRA 只差一个「反量化」:

$$h=\operatorname{dequant}(W_{\text{NF4}})\,x+\frac{\alpha}{r}\,BA\,x$$

$\operatorname{dequant}$ 把 4-bit 权重临时还原成计算精度(如 BF16),用完即弃;$\alpha/r$ 是 LoRA 的缩放系数。梯度只流进 $A,B$。

QLoRA 的三件套(一句话各记住)

  • NF4(4-bit NormalFloat):一种为「近似正态分布」的权重量身定制的 4-bit 数据类型。神经网络权重大多零均值、近正态,NF4 用分位数把 16 个可用量化格点分配到概率密度高的区间,信息利用率比普通 INT4 更高,量化误差更小。
  • 双重量化(Double Quantization):分块量化会为每个块存一个缩放常数(absmax),这些常数本身也占空间;双重量化把这些量化常数再量化一次,进一步省下少量显存。是「省上加省」的边角料优化。
  • 分页优化器(Paged Optimizers):借助 NVIDIA 统一内存,在显存突然吃紧(如长序列 + 梯度检查点触发的峰值)时,把优化器状态自动「换页」到 CPU 内存,峰值过去再换回——本质就是操作系统里的虚拟内存分页搬到了 GPU,专治偶发 OOM。

关键要说清:量化的是冻结基座,LoRA 适配器仍以较高精度(BF16)训练。所以 QLoRA 是把「4-bit 冻结 + 高精度低秩微调」缝在一起,而不是把整个模型都拿去做 4-bit 训练。

二、另外三条并列路线:Adapter / Prefix / P-Tuning

LoRA/QLoRA 属于「往权重旁边加低秩旁路」这一派。历史上更早的 PEFT 还有另外几条思路,面试常拿来和 LoRA 对照,核心区别是把可训练参数塞在哪。

Adapter
在层之间插模块
动了网络结构
Prefix-Tuning
每层 K/V 前接虚拟 token
动了每层输入
P-Tuning
输入处的连续 prompt 嵌入
动了提示,不动权重

Adapter Tuning:层间插入小瓶颈模块

在 Transformer 每个子层后面塞进一个小小的瓶颈模块:先降维、过一个非线性、再升维,外加一条残差连接。训练时冻结原模型全部参数,只更新这些新增的 Adapter。用源材料的说法:固定 $W_0$ 不变,把可训练的适配器附加上去、只训适配器。

代价很明确:这些模块是串行插入网络主干的新层,推理时必须逐个跑过去,无法像 LoRA 那样把增量合并回原权重——因此会带来实打实的额外前向延迟。这正是后来 LoRA 主打「无额外推理延迟」的动机来源。

Prefix-Tuning:每层前缀加可训练虚拟 token

不动任何权重,而是在每一层真实序列表征的前面,插入若干个连续的可训练「virtual token」向量作为前缀(prefix)。它们不必是词表里的真实词,只是一组自由参数。注意源材料强调的细节:这些前缀加在每一层,且每层的前缀不是上一层传下来的,而是各自独立的可训练 embedding。

对自回归模型,拼成 $z=[\text{PREFIX};x;y]$;对 Encoder-Decoder,两端都加前缀。训练时只更新前缀,Transformer 原参数固定。直觉上,这相当于用一小段「可学习的开场白」去引导冻结的大模型进入某个任务状态。

P-Tuning v1 / v2:连续提示嵌入

P-Tuning(v1)与 Prefix-Tuning 同源于「把离散的人工模板换成连续、可训练的提示向量」这一思想:在输入侧引入一组连续 prompt 嵌入(常配一个小的 prompt 编码器来生成),只训这部分,基座冻结,主要面向理解类(NLU)任务。它和纯人工写 prompt 的区别是——提示不再是词表里的词,而是可以梯度优化的向量。

P-Tuning v2是改进版,借鉴 Prefix-Tuning 的做法,在每一层都加入可训练的连续前缀,而不只在输入层加一层。多层深度提示带来了更强的容量,使它在不同规模、不同任务上都能逼近全量微调的水平。一句话记住二者之别:v1 主要在输入层加提示,v2 每层都加。

记忆抓手:LoRA/QLoRA「加旁路可合并」、Adapter「加串行层不可合并」、Prefix/P-Tuning「加提示不碰权重」。QLoRA 相对 LoRA 的差异只在于「基座被 4-bit 量化了」。

四、关键定义

QLoRA
把基座量化到 4-bit(NF4)并冻结,在其上以较高精度训练 LoRA 适配器的微调方法,再配双重量化与分页优化器进一步压显存与防 OOM。前向 $h=\operatorname{dequant}(W_{\text{NF4}})x+\frac{\alpha}{r}BAx$。
NF4(4-bit NormalFloat)
针对近似正态分布权重设计的 4-bit 量化数据类型,用分位数把量化格点集中到高概率区间,量化误差通常小于同位宽的普通整型量化。
Adapter
插在 Transformer 子层之间的小瓶颈模块(降维→非线性→升维 + 残差),只训该模块。因串行于主干,推理有额外延迟。
连续提示 / 虚拟 token
不属于词表、不对应任何真实词的可训练向量,作为「软提示」引导冻结模型;Prefix-Tuning 与 P-Tuning 系列都建立在它之上。

五、代码:一份最小 QLoRA 配置

工程上 QLoRA 常用 transformers + bitsandbytes + peft 三件套拼出来:

from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
import torch

# 1) 4-bit NF4 量化基座 + 双重量化,计算时反量化到 bf16
bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",           # NF4
    bnb_4bit_use_double_quant=True,      # 双重量化
    bnb_4bit_compute_dtype=torch.bfloat16,
)
model = AutoModelForCausalLM.from_pretrained("<base-model>", quantization_config=bnb)
model = prepare_model_for_kbit_training(model)  # 让量化基座能配合梯度检查点等

# 2) 在量化基座上挂 LoRA,只有这部分是 bf16 可训练参数
lora = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05,
                  target_modules=["q_proj", "v_proj"], task_type="CAUSAL_LM")
model = get_peft_model(model, lora)
model.print_trainable_parameters()      # 可训练参数只占很小比例
# 训练时优化器可选 "paged_adamw_8bit"(分页优化器)

换个角度,看一次线性层前向在 QLoRA 里到底发生了什么(概念示意,非真实内核):

def qlora_linear(x, W_nf4, absmax, A, B, alpha, r):
    W = dequantize_nf4(W_nf4, absmax)       # 4-bit → bf16,临时权重,用完即弃
    base = x @ W.T                          # 冻结主干,W 不更新
    delta = (x @ A.T) @ B.T * (alpha / r)   # LoRA 旁路,只有 A、B 有梯度
    return base + delta
# 反向传播时,梯度进不了 W(它只是被反量化的常量),只更新 A、B

面试官会怎么问:

  • 「QLoRA 相对 LoRA 到底省在哪?」——省的是冻结基座本身的显存(4-bit 存 vs 16-bit 存);LoRA 省的是梯度/优化器状态,两者省的不是同一块。
  • 「QLoRA 的代价是什么?」——① 4-bit 量化带来精度损失(NF4 + LoRA 能挽回大部分质量,但不是无损);② 每次前向要反量化,单步训练通常比 BF16 的 LoRA 慢。拿显存换速度与一点精度。
  • 「NF4 / 双重量化 / 分页优化器各解决什么?」——见三件套:NF4 提高量化信息利用率、双重量化再省常数的显存、分页优化器防峰值 OOM。
  • 「Adapter 和 LoRA 的本质区别?」——Adapter 串行插层、推理有延迟且不可合并;LoRA 是并行旁路、可合并回权重、推理零额外开销。
  • 「Prefix-Tuning 和 P-Tuning v2 什么关系?」——v2 本质是把 Prefix-Tuning 的「每层加连续前缀」用到了理解类任务上;v1 主要在输入层加提示,v2 每层都加。

易错点:

  • 别说「QLoRA 是把整个模型做 4-bit 训练」——量化的只是冻结基座,LoRA 适配器仍是较高精度且可训练。
  • 别把 QLoRA 省的显存说成「优化器状态」——那是 LoRA 就已经省掉的;QLoRA 额外拿下的是基座权重那块。
  • QLoRA 主要是训练期省显存的技术。想推理零开销就得把适配器合并进 16-bit 权重,那样又会失去 4-bit 的显存优势;二者需要权衡,不是「既省显存又零开销」。
  • 别把 Adapter 说成「像 LoRA 一样可合并」——它是串行新模块,合不掉,推理有延迟。
  • 源材料里「P-Tuning 对整个模型参数进行微调」的说法要当心:P-Tuning 系列同样只训练少量提示/前缀参数、基座冻结,这才是它归入 PEFT 的原因。

自测 1:相比普通 LoRA,QLoRA 主要多省下了哪一块显存?

A. 优化器状态(AdamW 的一阶、二阶动量)那正是 LoRA 靠「可训练参数极少」已经省掉的部分,不是 QLoRA 的增量贡献。
B. 激活值显存激活值主要靠梯度检查点等手段处理,不是 QLoRA 量化基座直接针对的对象。
C. 冻结基座权重本身的显存(4-bit 存 vs 16-bit 存) ✅正确。LoRA 没动那张 16-bit 冻结基座,而它是显存大头;QLoRA 把它压到 4-bit,基座这块显存缩到约四分之一。
D. 推理时的 KV CacheKV Cache 是推理阶段的缓存,和 QLoRA 的训练期量化不是一回事。

自测 2:下列哪种 PEFT 方法因为在层间串行插入新模块,即使训练完也会带来额外推理延迟、无法像 LoRA 那样合并进原权重?

A. LoRA恰恰相反:LoRA 是并行旁路,可把 $BA$ 合并回 $W$,推理零额外开销。
B. Adapter Tuning ✅正确。Adapter 是插在子层之间的串行瓶颈模块,推理必须逐个跑过、合并不掉,这也是 LoRA 主打「无额外推理延迟」的动机。
C. P-Tuning v2它在每层加连续前缀,不往主干里插串行的新权重层。
D. QLoRAQLoRA 的适配器同样是 LoRA 式旁路,可合并;它的开销主要在训练期的反量化。

这节课的一手出处与深挖方向:

  • QLoRA: Efficient Finetuning of Quantized LLMs(Dettmers, Pagnoni, Holtzman, Zettlemoyer, 2023)——NF4、双重量化、分页优化器的原始来源;论文的标志性演示是在单张 48GB GPU 上微调 65B 量级模型。
  • LoRA: Low-Rank Adaptation of Large Language Models(Hu et al., 2021)——QLoRA 的适配器基础,详见第 0013 课。
  • Parameter-Efficient Transfer Learning for NLP(Houlsby et al., 2019)——Adapter Tuning 原论文。
  • Prefix-Tuning: Optimizing Continuous Prompts for Generation(Li & Liang, 2021);GPT Understands, Too(Liu et al., 2021,P-Tuning);P-Tuning v2(Liu et al., 2021/2022)。
  • 想弄清 4-bit 量化的更底层机理,可回溯 LLM.int8()(Dettmers et al., 2022)这条量化脉络;下一步:微调离不开数据,见第 0015 课 SFT 数据构造。

一句话记忆:QLoRA = 4-bit(NF4)冻结基座 + 其上训 LoRA,省的是「基座权重」那块显存,代价是精度与速度;Adapter 串行插层、Prefix/P-Tuning 加连续提示,区别就看「改哪里、改不改结构、推理有没有额外开销」。
