值/引用语义、可变性与那个默认参数坑

"Python 是传值还是传引用?"——这道经典陷阱题的正确答案是"都不是"。这一节把名字绑定、可变性、拷贝和那个几乎人人踩过的可变默认参数坑一次讲透,让你在面试里能当场演示,而不是背半个答案。

不查文档,先在心里预测两段代码的输出:

① def f(acc=[]): acc.append(1); return acc——连着调 f() 三次,分别返回什么?
② def g(lst): lst.append(9) 和 def h(lst): lst = [9],分别传同一个外部 list 进去,外部会不会变?

先给出你的答案,再往下看。这两个正是本节的核心。

一、直觉:变量是"贴在对象上的便利贴"

很多语言里,变量像一个"盒子",赋值是把值搬进盒子。Python 不是这样。在 Python 里,变量是名字(name),对象漂在内存里,赋值只是把名字这张便利贴贴到某个对象上。

x = [1, 2] 做了两件事:先造出一个 list 对象,再把名字 x 贴上去。y = x 不拷贝任何东西——它只是又拿一张写着 y 的便利贴,贴到同一个对象上。于是 x 和 y 指向同一份数据,通过任一个名字改动它,另一个都"看得见"。

理解了这一点,"传值还是传引用"这道题就迎刃而解了:调用函数时,Python 把实参对象的引用交给形参这个名字——形参是又一张贴在同一对象上的便利贴。这套机制的学名叫 call by object reference(也叫 call by sharing / 按共享传递)。它既不是纯粹的"传值"(没有拷贝对象),也不是 C++ 那种"传引用"(你无法在函数里替换掉调用方的变量本身)。

二、关键推论:同一个对象改得动,换个对象换不掉

"按共享传递"会分裂出两种截然不同的后果,取决于你在函数里做的是就地修改还是重新绑定:

def append_item(lst):
    lst.append(99)          # 就地修改:动的是同一个对象,外部看得见
    print("函数内(修改后):", lst)

def rebind(lst):
    lst = [1, 2, 3]         # 重新绑定:名字改贴到新对象,外部那张便利贴没动
    print("函数内(重绑定):", lst)

data = [1, 2]
append_item(data)
print("外部(被就地修改):", data)   # [1, 2, 99]  —— 变了!

data2 = [1, 2]
rebind(data2)
print("外部(重绑定不影响):", data2) # [1, 2]     —— 没变

为什么会这样?lst.append(99) 是在调用方和函数共享的那个对象上动手,自然双方都看到变化;而 lst = [1, 2, 3] 只是把函数内的 lst 这张便利贴撕下来贴到一个新对象上,调用方 data2 的便利贴还牢牢贴在老对象上,毫发无伤。

这也解释了为什么 x = 5; y = x; y += 1 之后 x 仍是 5:int 不可变,y += 1 无法就地改 5,只能造出新对象 6 再让 y 改贴过去——这本质上就是"重新绑定"。可变与不可变,决定了你能不能"就地"动一个对象。

可变 (Mutable) —— 能就地改不可变 (Immutable) —— 只能造新的
list、dict、set、大多数自定义对象int、float、str、tuple、frozenset、bool

小验证工具:id(obj) 给你对象的身份编号,a is b 判断两个名字是不是贴在同一对象上。想在面试里证明"没拷贝",当场打印 id() 前后一致即可。

名字绑定 (Name Binding)
Python 变量是名字,赋值 = 把名字绑定到一个对象,不拷贝对象。多个名字可绑定到同一对象。
按共享传递 (Call by Object Reference / Call by Sharing)
传参传的是对象引用(便利贴的复制,不是对象的复制)。就地修改可变对象 → 外部可见;重新绑定形参名 → 外部不受影响。
可变 vs 不可变 (Mutable vs Immutable)
可变对象能被就地改状态;不可变对象一旦创建就不能变,任何"修改"都会产生新对象。
浅拷贝 vs 深拷贝 (Shallow vs Deep Copy)
copy.copy 只新建最外层容器,内部元素仍与原对象共享;copy.deepcopy 递归复制,内外都是全新对象。

三、拷贝:= 根本不拷贝,浅拷贝只拷一层

既然 = 只复制便利贴,那真想要一份独立数据怎么办?这就引出三个层级——理解它们的差别几乎是可变性话题的必考延伸:

import copy

original = [[1, 2], [3, 4]]         # 一个嵌套 list:外层 + 两个内层子 list

alias   = original                  # 只是别名:同一个对象,连外层都共享
shallow = copy.copy(original)       # 浅拷贝:外层是新 list,内层子 list 仍共享
deep    = copy.deepcopy(original)   # 深拷贝:递归复制,内外都是全新对象

original[0].append(999)             # 改动最里层的那个子 list

print("original:", original)   # [[1, 2, 999], [3, 4]]
print("alias   :", alias)      # [[1, 2, 999], [3, 4]]  —— 本就是同一个
print("shallow :", shallow)    # [[1, 2, 999], [3, 4]]  —— 被连累!内层是共享的
print("deep    :", deep)       # [[1, 2], [3, 4]]       —— 独立,安全

浅拷贝之所以"被连累",是因为它只新建了外层这只"篮子",篮子里装的还是原来那几个子 list 的引用。改动子 list 时,原对象和浅拷贝都指向它,自然一起变。深拷贝则把篮子和篮子里的每个东西都递归造了一份新的,彻底切断关联——代价是更慢、更耗内存,所以别无脑 deepcopy,只在确实需要嵌套独立时才用。

四、面试最爱的一道坑:可变默认参数

下面这段代码,几乎每个 Python 面试官都会拿它试探你踩没踩过:

# ❌ 坑:默认值 [] 在函数「定义时」只创建一次,之后所有调用共享同一个 list
def add_task(task, acc=[]):
    acc.append(task)
    return acc

print(add_task("a"))   # ['a']
print(add_task("b"))   # ['a', 'b']       —— 竟然记住了上一次!
print(add_task("c"))   # ['a', 'b', 'c']  —— 跨调用不断累积

病根在于:默认参数的值对象,是在函数 def 执行(定义)那一刻创建的,只创建一次,之后被绑到函数对象上反复复用。它不是"每次调用都新建一个空 list"。于是这个 list 变成了一块跨调用的"隐形记忆",谁调用谁往里塞,越滚越大。你甚至能通过 add_task.__defaults__ 亲眼看到它被改。

标准修法:用 None 当哨兵值(sentinel),把"新建空容器"这件事挪进函数体——函数体是每次调用都会执行的:

# ✅ 修法:默认值用不可变的 None,进函数体再按需新建
def add_task_fixed(task, acc=None):
    if acc is None:
        acc = []           # 每次调用都是全新的 list
    acc.append(task)
    return acc

print(add_task_fixed("a"))   # ['a']
print(add_task_fixed("b"))   # ['b']   —— 各次调用互不干扰

反过来说,如果默认值是不可变对象(None、数字、字符串、tuple),就没有这个坑——因为你根本无法就地改它,不存在"被上次调用污染"的可能。这正是"不可变即安全"的一个具体体现。

五、为什么不可变对象是"好东西"

可变性不只是陷阱源,理解它另一面同样重要:不可变对象天生带三项红利。

  • 可哈希、能当 dict 键 / set 元素:哈希值在对象生命周期内必须稳定,可变对象改一下哈希就乱了,所以 list 不能当 dict 键,而 tuple / frozenset 可以。
  • 天然线程安全:没人能改它,多线程共享读就不用加锁,省掉一大类竞态。
  • 可安全缓存与共享:既然内容永不变,放心地缓存、复用、到处传,不怕被谁悄悄改坏(小整数、短字符串驻留就是靠这个)。

想让自己的类也享受这些红利?常用手段:用 tuple / frozenset 存数据、collections.namedtuple、或 @dataclass(frozen=True) 把一个类冻结成不可变值对象。这也是"值/引用语义"和上一节"相等与哈希"衔接的地方——可哈希对象的相等与哈希必须一致且稳定。

高频追问链(这一簇几乎必被连环追问):

  • "Python 是传值还是传引用?" → 都不是,是按共享传递(call by object reference)。传的是对象引用的副本:就地改可变对象外部可见,重新绑定形参名外部不受影响。别只答半句。
  • "那为什么 x=5; y=x; y+=1 后 x 还是 5,list 就不一样?" → 因为 int 不可变,y+=1 造新对象再重绑;list 可变,append 是就地改同一对象。差别在可变性,不在传参方式。
  • "可变默认参数你踩过吗?为什么会这样、怎么修?" → 默认值定义时只建一次被复用;修法是默认写 None,函数体内 if x is None: x = []。
  • "浅拷贝和深拷贝差在哪?什么时候一定要 deepcopy?" → 浅拷贝只新建最外层、内层共享;数据是嵌套且你要改内层又不想影响原件时,才需要 deepcopy。
  • "怎么当场证明两个变量指向同一对象?" → a is b 或比较 id(a) == id(b)。

坑一:张口就答"Python 传引用"(或"传值")。两个都是错的半答案。准确说法是按共享传递 / 传对象引用——传的是引用的副本。你无法像 C++ 引用那样在函数里替换掉调用方的变量本身(重绑定不影响外部),但你能改它指向的可变对象(就地修改外部可见)。把这两句话都说全,才算答对。

坑二:可变默认参数。def f(acc=[]) 的 [] 只在定义时创建一次、被所有调用共享,导致状态跨调用累积。这是面试官最爱的"你踩过吗"。修法固定:默认 None + 函数体内新建。

坑三:以为浅拷贝就"拷了一份"。浅拷贝只新建最外层容器,嵌套的子对象仍与原件共享;改子对象时原件和拷贝一起变,造成意外共享。数据有嵌套且要独立修改时,得用 copy.deepcopy。

"这门语言参数是怎么传的?"是跨语言必问题。三种语言的模型对照:

语言参数传递模型"改对象内容"影响外部?"让形参指向新对象"影响外部?
Python统一按共享传递(传对象引用副本)可变对象:会否(只是重绑本地名字)
Java一律传值:基本类型传值副本,对象传"引用的副本"会(通过引用副本改对象字段)否(改的是引用副本)
C++显式区分:值传递 / 引用传递 & / 指针值传递:否;引用/指针:会引用传递:会(能替换调用方变量本身)

一句话记忆:Python 和 Java 都"传引用的副本"(所以能改对象、不能换对象);C++ 是唯一能靠引用参数在函数里连调用方变量本身都替换掉的。理解这一层,跨语言的参数传递题就都能答稳。

自测 1:预测下面这段的三行输出,并说明原因。 
def collect(x, bucket=[]):
    bucket.append(x)
    return bucket

print(collect(1))
print(collect(2))
print(collect(3))

输出:[1] → [1, 2] → [1, 2, 3]。

原因:默认值 [] 在函数定义时只创建一次,三次调用共享同一个 list,所以 append 不断往里累积。想让每次独立,改成 bucket=None,函数体里 if bucket is None: bucket = []。

自测 2:下面哪句最准确地回答"Python 是传值还是传引用"?

准确答案:都不是——Python 是"按共享传递 / 传对象引用"。传给函数的是对象引用的副本:在函数内就地修改可变对象(如 lst.append(x)),外部看得见;在函数内重新绑定形参名(如 lst = new),外部不受影响。

典型错误:只答"传引用"(那会让人以为能在函数里替换掉调用方的变量,Python 不能)或只答"传值"(那会让人以为对象被拷贝了,其实没有)。两个半句合起来才对。

自测 3:a = [[1], [2]]; b = copy.copy(a); a[0].append(99) 之后,b 是什么?换成 deepcopy 呢?

浅拷贝:b == [[1, 99], [2]]。因为 copy.copy 只新建了最外层 list,里面两个子 list 仍与 a 共享;改 a[0] 这个子 list,b[0] 是同一个对象,跟着变。

深拷贝:b == [[1], [2]]。deepcopy 递归复制了每一层,b 完全独立,不受 a 改动影响。

带走这一条:Python 变量是名字、赋值不拷贝对象,传参是"按共享传递"——就地改可变对象外部可见,重绑形参名外部不变。由此派生三件必答:可变默认参数(默认 None + 体内新建)、浅拷贝只拷一层(嵌套要独立就 deepcopy)、不可变对象因永不变而可哈希、线程安全、可安全缓存。
