多态:重写 vs 重载与动态分派

多态是四大支柱里"名字最唬人、答案最容易只答一半"的一个。很多人一开口就说"多态就是重写",漏掉了重载这一半;还有人张口就来"Python 支持方法重载",当场翻车。这一节把这两个坑一次填平。

先想一个场景:你有 Cat、Dog、Duck 三个类,都有一个 speak() 方法。现在要写一个函数,遍历一群动物、让每个都叫一声。你会给这个函数写几个 if isinstance(...) 分支?还是根本不用写?——先给个答案,再往下看。

一、直觉:同一个按钮,不同的对象各按各的

多态(Polymorphism)字面是"多种形态"。放到代码里,它的意思是:一段通用代码,面对不同类型的对象,能各自触发对的行为——而调用方不需要知道对方到底是哪个具体类型。

打个比方:你按下遥控器的"播放"键,电视放视频、音箱放音乐、扫地机开始扫地。按键的动作是统一的(共享接口),背后干什么由对象自己决定。你(调用方)不必为每种设备写一套不同的操作。多态干掉的就是那一大堆 if 是电视 / elif 是音箱 / elif 是扫地机 的分支。

源题一句话点题:多态让不同类型的对象通过共享接口被统一对待,抽象掉方法细节,从而提升灵活性与复用性。而它落地有两条完全不同的路——这正是面试的分水岭。

多态 (Polymorphism)
让不同类型的对象通过共享接口被统一调用,具体执行哪份实现由对象自己决定。它有两副面孔 ↓
① 重载 (Overloading) —— 编译期多态
同一个类里有多个同名方法,靠参数不同(签名不同)来区分。选哪个在编译期按签名定下来。也叫 ad-hoc / 静态多态。
② 重写 (Overriding) —— 运行时多态
子类为父类已有的同名方法提供新实现,替换父类版本。签名相同,选哪个在运行时按对象的真实类型定。也叫 subtype / 动态多态。
动态分派 / 后期绑定 (Dynamic Dispatch / Late Binding)
运行时才确定"这一次到底调哪份方法实现"的机制,是运行时多态的引擎。

二、重写(Overriding):运行时多态,Python 的主场

重写是你天天在写、却未必意识到的那种多态。子类把父类的方法"换一个实现",调用时按对象运行时的真实类型去找该调哪个:

class Animal:
    def speak(self):
        return "..."           # 父类的默认实现

class Cat(Animal):
    def speak(self):           # override:同名同签名,提供新实现
        return "Meow"

class Dog(Animal):
    def speak(self):
        return "Woof"

# 一段"通用代码":它只知道"这些东西都能 speak",不关心具体是猫是狗
def chorus(animals):
    for a in animals:
        print(a.speak())       # 动态分派:看 a 运行时的真实类型来决定调哪个 speak

chorus([Cat(), Dog(), Animal()])
# Meow
# Woof
# ...

注意 chorus 里一个 if isinstance 都没有。加一个 Duck 类,chorus 一行都不用改——这就是多态给的"开闭"(对扩展开放、对修改关闭)红利。这里的 a.speak() 具体调到哪份实现,是运行时才敲定的,即所谓动态分派 / 后期绑定。

canon 补充(必须讲,是加分点):Python 的方法查找天生就是运行时动态的——它不需要像 C++ 那样给方法加 virtual 关键字。每次 a.speak(),解释器都沿着对象的类型 → MRO(方法解析顺序)去字典里现查。所以在 Python 里,"重写"随处可见、无需任何声明;上面这段代码本身就是运行时多态。

三、重载(Overloading):编译期多态,以及 Python 的大坑

重载是另一半多态,漏掉它是最常见的失分点。它指同一个类里同名、但参数签名不同的多个方法,编译器按你传的参数在编译期挑一个:

// C++ 里的方法重载:同名 area,签名不同,编译器按参数选
int area(int side);              // 正方形
int area(int w, int h);          // 矩形
// area(5) 与 area(3, 4) 在编译期就被解析到不同函数

但到了 Python,情况完全不同——这是本节头号面试陷阱:

class Calc:
    def add(self, a, b):
        return a + b

    def add(self, a, b, c):      # 同名!Python 不会"重载"
        return a + b + c         # 而是直接用后者覆盖(replace)前者

Calc().add(1, 2)
# ❌ TypeError: add() missing 1 required positional argument: 'c'
# 第一个 add 已经不存在了 —— 类的字典里同名 key 只留最后一个

为什么?因为 Python 的类体本质是往一个字典里塞 {"add": 函数对象},同名 key 后写的覆盖先写的,没有"按签名共存多份"的机制。所以严格说:Python 不原生支持方法重载(method overloading)。要达到类似效果,Python 的地道做法是默认参数、*args/**kwargs,或 functools.singledispatch(按类型分派)——这留到 0020 专讲。

高频追问链(多态是四大支柱里追问最密的一个):

  • "重写和重载有什么区别?" → 三点对照:①时机——重载编译期定、重写运行时定;②位置——重载在同一个类内、重写跨父子类;③签名——重载靠签名不同区分、重写要求签名相同。一句话:重载是"同名不同参",重写是"同名同参换实现"。
  • "Python 支持方法重载吗?" → 不原生支持,同名方法后者覆盖前者;可用默认参数 / *args / singledispatch 模拟(0020)。但要区分:方法重载不支持,运算符重载(operator overloading,靠 __add__、__eq__ 等 dunder 方法)是支持的。别把这两个混为一谈。
  • "动态分派靠什么实现?" → C++/Java 靠虚方法表(vtable):对象里存一个指向函数指针表的指针,运行时查表跳转。Python 更"软"——靠运行时在实例 __dict__、类及其 MRO 里逐级查名字。点到 vtable 即可,别展开汇编(本课范围外)。
  • "为什么说重载也算多态?" → 因为"同一个名字 area 应对多种参数形态"本身就是"一名多态";学名 ad-hoc polymorphism(特设多态)。多态 ≠ 只有运行时那一种。

四、虚方法(virtual):C++ 为什么要多这个关键字?

源题特意点了 C++ 的 virtual,因为它揭示了动态分派"不是免费的"这层真相。在 C++ 里,基类方法默认不是虚的——通过基类引用/指针调用时,默认按静态类型调(即"你声明成什么类型就调谁的"),那就调不到派生类的重写版本。只有给基类方法标上 virtual,才启用动态分派,让基类引用也能调到正确的派生实现:

// C++:必须显式 virtual,基类引用才能调到派生类的实现
class Animal {
public:
    virtual void speak() { /* ... */ }   // 去掉 virtual,下面就调不到 Cat::speak
};
class Cat : public Animal {
public:
    void speak() override { /* "Meow" */ }
};

对照之下:Java 的实例方法默认就是虚的(除 static/private/final 外),不用写关键字就能重写;Python 更彻底,方法调用永远是动态查找,连"虚不虚"这个概念都不需要暴露给你。三种语言,三种默认。

翻车点一:"多态就是重写。" 这是最常见的半个答案。完整表述是:多态有编译期(重载、模板/泛型)与运行时(重写、虚函数)两种;只答重写等于丢掉一半分。面试官往往就等着追一句"那重载算不算多态?"来筛人。

翻车点二:"Python 支持方法重载。" 错。Python 同名方法后定义者覆盖先定义者,不存在按签名共存的多份实现。要 hedge 得准:①方法重载——不原生支持,用默认参数 / singledispatch 模拟;②运算符重载——支持,靠 dunder 方法。混着说就露怯。

翻车点三:把动态分派说成"编译期就定好了"。 恰恰相反——运行时多态的核心就是"编译时不知道、运行时才定"(late binding)。编译期定死的是重载。

两个维度先分清,再看三门语言的默认差异——这两张表几乎覆盖多态的所有跨语言追问。

维度编译期多态运行时多态

一句话:"虚不虚"这件事,Python 免谈、Java 默认给、C++ 要你自己开。

合上讲义,自己写一遍,验证你真的分得清两半:

  • 写 Shape 基类,方法 area(self) 返回 0;再写 Circle、Rectangle 各自重写 area。
  • 写一个通用函数 total_area(shapes),不用任何 isinstance,累加所有形状面积——体会运行时多态。
  • 然后故意在 Shape 里写两个同名 describe(self) 和 describe(self, verbose),调用 Shape().describe() 看会发生什么(想想为什么报错),亲手撞一次"Python 没有方法重载"的墙。
自测 1:下列哪一项属于编译期多态?

A. 子类 Cat 重写父类 Animal 的 speak()
B. 同一个类里 add(int) 与 add(int, int) 两个同名不同参的方法
C. 通过基类引用调用被 virtual 标记的方法
D. Python 里遍历一组对象调用它们各自的 speak()

答案:B。 方法重载(同名不同签名,编译期按参数选)是编译期多态。A、C、D 都是运行时多态(重写 / 虚方法 / 动态分派)。这题就是在筛"是不是只把多态等同于重写"。

自测 2:下面这段 Python 会输出什么?为什么? 
class Printer:
    def show(self, msg):
        print("one arg:", msg)
    def show(self, msg, times):
        print("two args:", msg * times)

Printer().show("hi")

答案:抛 TypeError(缺少参数 times),而不是打印 "one arg: hi"。

因为 Python 不支持方法重载:类体里同名 show 的第二个定义直接覆盖了第一个,类的字典里只剩接收两个参数的那份。调 show("hi") 少传一个参数,自然报错。想让一个方法应对不同参数个数,正解是默认参数(def show(self, msg, times=1))或 *args,而不是写多份同名方法。

带走这一条:多态 = 共享接口下"一名多态",有两半——重载(编译期,同名不同参,同一类内)和重写(运行时,同名同参,跨父子类,靠动态分派)。答题千万别只说重写。语言默认各异:Python 方法调用永远动态、但不原生支持方法重载(可支持运算符重载);Java 方法默认虚;C++ 要 virtual 才动态分派。
