对象的生命周期与身份:is vs ==

"对象是什么?"是最像送分题、其实最容易答浅的一问。这一节把它拆成两个能当场演示的硬核:对象的三特征 + 一生,以及 Python 里最常被写错的一行——is 和 == 到底比的是什么。

先别往下看。请你回答:a = [1, 2, 3] 和 b = [1, 2, 3],那么 a == b 是 True 还是 False?a is b 呢?为什么?把两个答案和理由都在心里说出来,再往下对。

一、直觉:一个对象,像一个"活着的东西"

面试官问"What is an object?",他想听的不是"类的实例"这句循环定义,而是你能不能说清一个对象由哪几件事构成、又经历了什么。把对象想成一个活物,它同时有三样东西:

它是谁
Identity
唯一身份
它现在怎样
State
状态 · 可变
它能做什么
Behavior
行为 · 方法

拿一只狗打比方:它有一张独一无二的身份证(identity,哪怕世上有另一只一模一样的狗,也不是它)、有此刻的状态(state:饿不饿、会哪些技能,会变)、还有一套能做的动作(behavior:坐下、握手,这些动作会改它的状态)。三样缺一不可——只有数据没行为是结构体,只有行为没身份是函数。

这三样合起来"活一辈子",就是对象的生命周期:

① 创建实例化
造出身份+初始状态
→
② 操作调方法 / 改状态
身份始终不变
→
③ 销毁GC 回收
或显式解除引用

注意中间一格:操作阶段状态在变,但身份从头到尾是同一个。狗学会了新技能,它还是那只狗——这正是 identity 和 state 的分野,也是下面 is 与 == 的全部根源。

对象 (Object)
一个同时拥有 identity(身份)+ state(状态)+ behavior(行为) 的运行时实体;类是它的模板,对象是类的实例。
Identity(身份)
对象在其生命期内唯一且不变的标记,回答"是不是同一个对象"。在 CPython 里由 id(obj) 表示。
State(状态)
对象此刻持有的数据(属性值),通常可变——操作阶段就是在改它。
Behavior(行为)
对象能响应的操作(方法),往往用来读或改状态。
生命周期 (Lifecycle)
创建(实例化)→ 操作(改状态/调方法)→ 销毁(垃圾回收或显式解除引用)。

二、创建那一步,内部发生了什么?

写 d = Dog("Rex") 看着是一步,实际是两步:先 __new__ 负责"造出一个空实例"(分配、拿到身份),再 __init__ 负责"给这个已存在的实例填初始状态"。日常你几乎只写 __init__,因为 __new__ 的默认行为已经够用了(这两者的分工与何时要重写 __new__,留到 0007 详讲)。

class Dog:
    def __init__(self, name):      # 初始化:给"已造出的"实例填状态
        self.name = name           # state(状态)
        self.tricks = []

    def learn(self, trick):        # behavior(行为):改状态
        self.tricks.append(trick)

d = Dog("Rex")     # ① 创建:先 __new__ 造壳拿身份,再 __init__ 填状态
d.learn("sit")     # ② 操作:调方法、改状态,d 还是同一个对象
del d              # ③ 解除一个引用;引用计数归零时才真正销毁

关于第 ③ 步要说准:del d 不等于"立刻销毁对象",它只是删掉 d 这个名字对对象的引用。CPython 的回收以引用计数为主——引用数归零就即时回收;对付"你引用我、我引用你"的循环引用,再叠一层分代垃圾回收(generational GC)兜底。所以对象何时真正消失,是运行时说了算,不是你 del 说了算。

三、身份 vs 值:is 和 == 的分水岭

有了"身份 / 状态"这对概念,Python 里两个比较运算就一目了然:

  • is 比 identity:两个名字是不是指向同一个对象(等价于 id(a) == id(b))。
  • == 比 value / equality:两个对象的值是否相等,可由 __eq__ 自定义(默认退化为按身份比;__eq__ 的定制留到 0022)。
a = [1, 2, 3]
b = [1, 2, 3]      # 内容一样,但是"另造"的一个 list 对象
c = a              # 没有新对象,c 只是 a 的另一个名字

print(a == b)      # True  —— 值相等(内容逐项一样)
print(a is b)      # False —— 不是同一个对象
print(a is c)      # True  —— 就是同一个对象

print(id(a), id(b))    # 两个不同的整数 → 身份不同
print(id(a) == id(c))  # True → a 和 c 身份相同

一句话记牢:== 问"长得一样吗",is 问"就是你吗"。上面 a 和 b 长得一样(== 为真),但不是同一个(is 为假);a 和 c 则是同一个对象的两个名字。

关于 id() 再补一刀准确性:CPython 里 id(obj) 恰好是对象的内存地址——但这是 CPython 的实现细节,不是 Python 语言的保证。语言只承诺:id() 在对象生命期内唯一且恒定。别把它当内存地址来写逻辑,换个解释器(如某些 PyPy 场景)就不成立。

高频追问链(这一簇几乎必被追到底):

  • "is 和 == 有什么区别?" → is 比身份(同一个对象?),== 比值(内容相等?,由 __eq__ 决定)。答不清这条基本出局。
  • "为什么 a = 256; b = 256; a is b 是 True,换成 257 却可能是 False?" → CPython 缓存了小整数(约 -5 到 256),同一个值复用同一个对象;这是实现细节,不是语言规则,别据此写逻辑。见下面易错点。
  • "判断一个变量是不是 None,该写 x is None 还是 x == None?" → 用 is None。因为 None 是全局单例,比身份最准最快;而 == None 可能被对方类重写的 __eq__ 骗到,给出意外结果。
  • "id() 返回的是内存地址吗?" → 在 CPython 里是,但那是实现细节;语言只保证生命期内唯一且恒定。
  • "对象什么时候被销毁?" → CPython 引用计数为主,归零即回收;分代 GC 兜底循环引用。del 只减引用,不保证立即销毁。

头号翻车点:拿 is 去判断值相等。初学者常写 if x is 0、if name is "admin",一开始"居然能跑",于是误以为对——那是因为 CPython 对小整数(约 -5 到 256)做了缓存、对部分短字符串做了驻留(interning),让不同来源的相同值"碰巧"是同一个对象。一旦值超出缓存范围、或字符串是运行时拼出来的,is 立刻翻脸:

x = 256; y = 256
print(x is y)   # True  —— 落在小整数缓存里,别当真

x = 257; y = 257
print(x is y)   # 可能 False —— 超出缓存,是两个对象了
print(x == y)   # True  —— 判断"值相等"永远用 ==

规矩:判断值是否相等,永远用 ==;只有判断"是不是同一个对象 / 是不是 None"这类身份问题,才用 is(if x is None)。把缓存行为当成语言保证来写逻辑,是最典型的"面试当场被反例打脸"。

"身份比较 / 值比较,你这门语言怎么分?"是跨语言必问。Python 的这对区分,在其它语言里对应得很整齐:

语言比身份(同一对象)比值(内容相等)生命周期特点
Pythonis==(__eq__)引用计数 + 分代 GC,回收时机由运行时定
Java==(比引用).equals()纯 GC,回收时机不确定
C++比指针 / 地址 &a == &b==(可重载)确定性析构:栈对象一出作用域立即析构

特别注意 Java 的坑正好和 Python 相反:Java 的 == 比的是引用(identity),值相等要用 .equals()——所以 Java 里 str1 == str2 判字符串内容是经典 bug,和 Python 里用 is 判内容是同一类错误。而 C++ 走的是另一条路:栈上对象离开作用域就确定性析构,不像 Python/Java 交给不确定时机的 GC。

合上讲义,打开解释器,亲手把这些区别跑出来:

  • 造两个内容相同的 dict,分别打印 a == b、a is b、id(a)、id(b),解释为什么。
  • 写 c = a 后再打印 a is c,说清"新对象"和"新名字"的差别。
  • 令 a.append(4),再看 c——为什么 c 也变了?这和"同一个对象"有什么关系?
  • 试 x = 256; y = 256; x is y 与 x = 257; y = 257; x is y,亲眼看缓存边界。(结论:这类结果别写进业务逻辑。)
自测 1:a = [1, 2]; b = a; c = [1, 2]。下面四个表达式,各是 True 还是 False?a == b、a is b、a == c、a is c。

答案:True / True / True / False。

  • a == b → True:值相等。
  • a is b → True:b = a 没造新对象,b 只是 a 的另一个名字,身份相同。
  • a == c → True:c 内容和 a 一样,值相等。
  • a is c → False:c 是"另造"的 list,身份不同(id(a) != id(c))。

要点:== 看内容,is 看"是不是同一个对象"。赋值 b = a 是共享引用,不是拷贝。

自测 2:同事把判空写成 if user == None:,你说应该改成 if user is None:。请给出两条理由。

理由一(正确性):None 是全局单例,判"是不是 None"本质是身份问题,is 直击要害;而 == 会走对象的 __eq__,如果 user 的类重写了 __eq__(比如某些 ORM、numpy 数组),== None 可能返回意外结果甚至抛异常。

理由二(约定与性能):is None 是 Python 社区一致的惯用法(PEP 8 也这么建议),可读性最好;身份比较也比可能触发 __eq__ 调用的 == 更直接。

带走这一条:对象 = identity(唯一身份)+ state(可变状态)+ behavior(行为),一生走"创建 → 操作 → 销毁"。身份贯穿始终,状态在变——这正是 is 与 == 的分水岭:is 比身份(是不是同一个对象),== 比值(内容相不相等)。判值相等永远用 ==,判 None/同一对象才用 is;小整数缓存与字符串驻留会让 is "看似"为真,那是 CPython 实现细节,别当语言保证。
