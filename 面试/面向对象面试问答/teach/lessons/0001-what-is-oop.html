什么是 OOP:对象、类与四大支柱

这是全课的开篇总览。目标不是把四大支柱一次讲满,而是让你先建立一张"地图":OOP 到底在解决什么、类和对象是什么关系、四根支柱各管一件什么事——每根支柱后面都有专节深挖。

开始前先自问:如果不用 class,只用一堆函数和全局变量,也能把程序写出来。那"面向对象"到底多出来了什么、值得单独拿出来讲?先给自己一个答案,再往下看。

一、直觉:把"数据"和"操作数据的代码"绑在一起

过程式编程里,数据是数据、函数是函数,两者分家。你有一堆变量描述一辆车(fuel、speed),再有一堆函数去操作它们(drive(car)、refuel(car))。程序一大,"哪个函数能改哪个变量"就没人说得清了。

OOP(Object-Oriented Programming,面向对象编程)换了个组织方式:把程序拆成一个个自包含的对象,每个对象把自己的数据、以及操作这些数据的方法捆在一起。一辆车对象既装着 fuel,也带着 drive()——想让车跑,就叫这辆车自己 car.drive(),而不是把车丢给外部函数处理。

这样带来四个好处(这四个词几乎是面试标准答案):模块化(每个对象是一个独立单元)、可复用(类可以被继承、被复用)、可扩展(加新类型不必推翻旧代码)、灵活(改内部实现不影响外部调用)。

二、两个最基本的名词:类 与 对象

OOP 里一切从这对概念开始,面试也几乎必问它俩的区别(源题 Q7、Q8)。

类 (Class)
创建对象的蓝图 / 模板。它定义两样东西:属性(attributes,数据,描述状态) 和 方法(methods,行为,操作数据)。类本身不占"具体那辆车"的内存,它只规定"车应该长什么样"。
对象 (Object)
类的一次具体实例(instance),把数据与行为真正装进内存。对象有三大特征:
① identity(身份)——独一无二,能和别的对象区分(即使内容一样);
② state(状态)——由属性的当前值定义,可变;
③ behavior(行为)——由方法定义,是它能做的动作。

一句话类比:类是设计图,对象是照着图盖出来的房子。一张图能盖很多栋房子,每栋房子有自己的门牌号(identity)和住户(state)。

用 Python 看清楚这层关系——注意 identity、state、behavior 分别对应哪一行:

class Dog:                     # 类:蓝图
    species = "Canis"          # 类属性:所有实例共享

    def __init__(self, name):  # 构造器:实例化时自动调用
        self.name = name       # 实例属性 → state(状态)

    def bark(self) -> str:     # 方法 → behavior(行为)
        return f"{self.name}: Woof!"

d1 = Dog("Rex")                # 对象 = 类的实例(instantiation)
d2 = Dog("Rex")                # 同名,但是另一个对象

print(d1.name)                 # Rex           —— state
print(d1.bark())               # Rex: Woof!    —— behavior
print(d1 is d2)                # False —— 名字一样,身份不同(identity)
print(id(d1) == id(d2))        # False —— 内存里是两个不同对象

对象的生命周期(源题 Q8 的追问点):创建(实例化,如 Dog("Rex"))→ 操作(改状态、调方法)→ 销毁。在 CPython 里,销毁靠引用计数为主 + 分代回收处理循环引用自动完成,你一般不用手动释放(这点后面还会再碰到)。

三、四大支柱:一句话地图

OOP 的能力集中在四根支柱上。先记住这张卡片,建立整体感;每根支柱都有独立一节做深挖:

Encapsulation
封装
捆绑数据+方法,藏起内部,只留受控接口 → 0002
Inheritance
继承
基于已有类建新类,复用+建立层次(is-a) → 0003
Polymorphism
多态
同一调用,子类各自表现(重载/重写) → 0004
Abstraction
抽象
只暴露必要功能,藏起复杂实现(抽象类/接口) → 0005

还有一个常被算作"第五点"的概念:关联(Association)——描述对象之间的关系,而不是对象内部。它有两种强度:聚合(Aggregation,has-a,部分能独立存在),比如"班级 has-a 学生",班级没了学生还在;组合(Composition,更强的 has-a,部分不能独立存在),比如"房子 has-a 房间",房子拆了房间也不复存在。这块本课先点到,后面讲"组合优于继承"时再展开。

四、一个例子,同时看见四根支柱

下面这段 Python 把四根支柱串在一起。看代码时对照右侧注释,想清楚"哪一行是哪根支柱"——这正是面试官喜欢让你逐行讲的题:

from abc import ABC, abstractmethod

# 抽象(Abstraction):Animal 是抽象基类,规定"动物必须会叫",但自己不能被实例化
class Animal(ABC):
    def __init__(self, name):
        self._name = name              # 封装(Encapsulation):状态藏进对象,前缀 _ 表"内部"

    @property                          # 受控访问:对外只读地暴露 name
    def name(self) -> str:
        return self._name

    @abstractmethod                    # 抽象方法:子类必须实现,否则子类也没法实例化
    def speak(self) -> str:
        ...

    def introduce(self):               # 复用:所有子类共享这段逻辑,不必各写一遍
        print(f"I am {self._name}. {self.speak()}")

# 继承(Inheritance):Lion 基于 Animal,是一种 Animal(is-a)
class Lion(Animal):
    def speak(self) -> str:            # 多态(Polymorphism):重写(override)成自己的行为
        return "Roar!"

class Parrot(Animal):
    def speak(self) -> str:
        return "Squawk!"

# a = Animal("???")   # ❌ TypeError:抽象类不能直接实例化

zoo = [Lion("Leo"), Parrot("Rio")]
for a in zoo:                          # 运行时多态:同一句 a.introduce(),各自表现不同
    a.introduce()
# I am Leo. Roar!
# I am Rio. Squawk!
  • 抽象:Animal(ABC) + @abstractmethod 让 Animal 只定义"契约"(必须会 speak),不能被直接 new 出来。
  • 封装:名字存进 self._name,只通过 @property 的 name 受控暴露。
  • 继承:Lion、Parrot 复用了 introduce(),不用重复写。
  • 多态:同一行 a.introduce(),遍历时对 Lion 打印 Roar、对 Parrot 打印 Squawk——调用方不需要知道 a 具体是谁。

高频追问链(开篇总览最容易被这样连环问):

  • "类和对象的区别?" → 类是蓝图/模板(定义结构与行为、不占具体内存);对象是按蓝图造出的实例(占内存、有独立身份和状态)。一个类能造出无数对象。
  • "能各用一句话说四大支柱吗?" → 封装=藏数据留接口;继承=复用+建层次;多态=同接口不同实现;抽象=只露必要功能。(能秒答这句,基本盘就稳了。)
  • "OOP 比过程式好在哪?一定更好吗?" → 好在模块化/复用/扩展/灵活;但不是银弹——小脚本、数据管道类任务里,过度 OOP 反而是负担(过度设计)。要按场景选,别为了 OOP 而 OOP。
  • "Python 里一切都是对象吗?" → 是——整数、函数、类本身都是对象,都能赋值/传参。这跟 Java 不同(Java 的 int 等基本类型不是对象)。
  • "对象什么时候被销毁?" → CPython 里引用计数归零即回收,循环引用由分代 GC 处理;可定义 __del__ 但不保证调用时机,别依赖它做关键清理(用 with / 上下文管理器更稳)。

坑一:把"类"和"对象"说反。紧张时最容易口误成"对象是蓝图、类是实例"。记死类比——类=设计图,对象=盖出来的房子,一图多房。

坑二:以为"用了 class 关键字 = 面向对象"。把一堆只有 getter/setter 的"贫血对象"配上一大坨面条式流程,本质还是过程式思维,只是穿了 class 的外衣。OOP 的精髓是用对象为"职责"和"协作"建模,而不是把变量塞进 class 里。

坑三:背得出四大支柱,却讲不清彼此关系。面试官几乎必追问区别(封装 vs 抽象、重载 vs 重写、继承 vs 组合)。本课先建地图,后面每节就是专攻这些"区别题"。

"OOP 是哪种语言的专利吗?"——不是。不同语言对 OOP 的定位差别很大,这是跨语言常考点:

语言范式定位说明
Java以 OOP 为中心代码几乎都得写在类里,连 main 都在类中;但基本类型(int 等)不是对象,所以并非严格意义的"一切皆对象"。
Python多范式支持 OOP,也支持过程式与函数式,可自由混用;而且一切皆对象(连函数、类都是)。
JavaScript多范式基于原型(prototype)的 OOP + 函数式;class 关键字是原型机制的语法糖。
C#多范式(强 OOP)强类型 OOP,同时支持泛型、函数式等。
C过程式无原生类;可用 struct 把数据分组、配函数指针来模拟部分 OOP,但语言本身不原生支持完整 OOP。

一句话:OOP 是一种思想/范式,不是某门语言的独家功能。想找"更纯粹一切皆对象"的语言,通常会举 Smalltalk、Ruby;Java 常被说"围绕 OOP",但也留了基本类型这个例外。

合上讲义,自己敲一个最小可跑的例子,把类/对象/四大支柱各点到一次:

  • 写一个抽象基类 Shape(用 abc.ABC + @abstractmethod),规定必须实现 area()。
  • 派生 Circle 和 Rectangle,各自实现 area()(多态)。
  • 半径/边长存成 self._r 这样的内部属性(封装),用 @property 只读暴露。
  • 放进一个列表遍历,统一调用 s.area(),验证同一句代码对不同形状给出不同结果。

自测:试着 Shape() 直接实例化,应当报 TypeError——想清楚这属于四大支柱里的哪一根。

自测 1:在上面的动物例子里,for a in zoo: a.introduce() 对狮子打印 Roar、对鹦鹉打印 Squawk。这最直接体现的是哪一根支柱?

答案:多态(Polymorphism),具体是运行时多态 / 方法重写(override)。

关键特征是"同一个调用接口,针对不同对象产生不同行为",而且调用方不必知道 a 具体是哪个子类。

这里当然也用到了继承(Lion/Parrot 继承 Animal)和抽象(speak 是抽象方法),但"同调用、异行为"这一现象本身,就是多态的定义。

自测 2:判断——"只要用了 class 关键字写代码,就算是在做面向对象编程。"这句话对吗?

答案:不对。

用 class 只是语法;是不是 OOP,取决于你有没有用对象去封装职责、组织协作、利用多态/抽象。如果只是把一堆全局变量塞进一个 class、逻辑仍写成一长串过程,那本质还是过程式,只是换了层壳(这类"贫血对象 + 面条逻辑"是常见反模式)。

反过来讲:OOP 是一种组织与建模的思路,语法只是承载它的工具。

带走这一条:OOP 把"数据 + 操作数据的方法"捆进自包含的对象,好处是模块化/复用/扩展/灵活。类是蓝图,对象是实例(有 identity/state/behavior)。四大支柱=封装(藏)、继承(复用)、多态(同接口异行为)、抽象(只露必要)。这一节是地图,后面 0002–0005 逐根钻透。
