继承:is-a、继承类型与 super

继承的定义谁都会背,面试真正筛人的是两问:"你凭什么用继承而不是复制粘贴?"和"你说的是哪一种继承?"。这一节把 is-a 关系、五种继承类型、以及 Python 里 super() 的正确用法一次讲透。

开始前先回忆:你有一个 Animal 类,现在要写 Dog、Cat,它们都有 name、都会 speak(),只是叫声不同。你会怎么复用 Animal 里已经写好的东西?如果直接把 Animal 的代码复制两份到 Dog 和 Cat 里,以后会踩什么坑?先给个答案,再往下看。

一、直觉:继承是"把共性提到上一层"

继承(Inheritance)就是基于一个已有的类,创建一个新类。新类自动"继承"旧类的属性和行为,然后在此基础上加自己的东西、或改写不合适的东西。

用一句话抓住它的本质:继承建立的是 "is-a"(是一种)关系。Dog is a Animal,Manager is a(n) Employee。当你能理直气壮地说出"X 是一种 Y"的时候,让 X 继承 Y 才是正当的。反过来——如果你只是"想用 Y 里现成的代码",那不是 is-a,那是为了偷懒而继承,后面会讲这为什么危险。

继承 (Inheritance)
基于已有类创建新类,新类获得已有类的属性与行为,并可扩展或重写。它表达的是 is-a 关系。
父类 (Base / Super / Parent class)
被继承的那个类。术语在不同语言里混用:base class(C++)、superclass(Java)、parent class(通俗说法)指的是同一个。
子类 (Derived / Sub / Child class)
继承别人的那个类:derived class(C++)、subclass(Java)、child class(通俗)。
重写 (Override)
子类用同名方法覆盖父类的实现,给出自己的版本(下一节 0004「多态」的核心机制)。
super()
子类里调用父类逻辑的入口,最常见于 super().__init__(...) 复用父类构造。注意它的语义有个坑,见易错点。

二、五种继承类型(源题的核心考点)

面试题常问 "Name some types of inheritance"。别只答"单继承和多继承",完整的五种要能报出名字、画出形状、举出语言:

类型形状一句话典型语言
① 单继承
Single		A ← B一个子类只继承一个基类,最常见、最安全Java(class B extends A)、Python、C++ 都支持
② 多继承
Multiple		A、B ← C一个子类同时继承多个基类C++、Python 支持;Java 不用类支持,改用 interface 达到类似效果
③ 多层继承
Multilevel		A ← B ← C链式:C 继承 B,B 又继承 A三种语言都支持
④ 层次继承
Hierarchical		B ← A → C一个基类被多个子类继承(A 被 B、C 共同继承)三种语言都支持
⑤ 混合继承
Hybrid		以上的组合多种形式叠加,容易变复杂C++ 可能出现;Java 不直接用类支持,可用接口模拟多继承那部分

为什么 Java 要把多继承和混合继承挡在门外?因为多继承会引出 菱形问题(diamond problem):如果两个父类都从同一个"祖父类"继承并各自改了某个方法,子类到底该用哪一份?Java 的选择是——类只能单继承,想要"多来源"就用 interface(接口只定契约、通常不带实现状态,冲突风险小得多)。C++ 允许真多继承,并用 virtual 继承来化解菱形冲突;Python 也允许多继承,靠 MRO(见下面跨语言对照)确定查找顺序。菱形问题的深水区我们放到 0019 用 MRO 专门讲,这里你只需要能说出"它叫菱形问题、Java 因此禁止类多继承"。

三、Python 单继承 + super() 实战

看代码。Dog is-a Animal,用 super() 复用父类构造,再重写 speak():

class Animal:
    def __init__(self, name):
        self.name = name              # self ≈ 其他语言里的 this

    def speak(self):
        return f"{self.name} 发出了某种声音"

    def describe(self):
        return f"我是 {self.name}"


class Dog(Animal):                    # 括号里写父类:Dog 单继承 Animal
    def __init__(self, name, breed):
        super().__init__(name)        # 复用父类构造,别手写 self.name = name
        self.breed = breed            # 子类自己新增的属性

    def speak(self):                  # override:给出 Dog 自己的版本
        return f"{self.name}({self.breed}) 说:汪汪"


d = Dog("旺财", "柴犬")
print(d.speak())                      # 旺财(柴犬) 说:汪汪   —— 用子类版本
print(d.describe())                   # 我是 旺财            —— 继承自父类,没重写
print(isinstance(d, Animal))          # True   —— Dog is-a Animal
print(isinstance(d, Dog))             # True

三个要点:

  • class Dog(Animal):括号里是父类,一行就建立了 is-a 关系。
  • super().__init__(name):让父类去初始化它负责的部分(name),子类只管自己新增的(breed)。不要在子类里重复写 self.name = name——那就是把父类逻辑复制了一份,父类一改你就漏改。
  • describe() 没重写却能用:这就是继承的复用——子类白得父类所有没被覆盖的方法。

高频追问链(继承几乎必被追问,顺着答能显出深度):

  • "继承和组合(composition)有什么区别?什么时候用哪个?" → 继承是 is-a(狗是动物),组合是 has-a(汽车有引擎)。判断口诀:能说通"X 是一种 Y"才用继承,否则用组合。业界更进一步有句名言"组合优于继承",原因见易错点,专题在 0010。
  • "super() 调用的一定是父类吗?" → 单继承下是的;但严格讲 super() 返回的是 MRO(方法解析顺序)里的下一个类,多继承时它未必是你写在括号里的那个直接父类。这点答准立刻区别于死记硬背的人。
  • "Java 为什么不支持(类的)多继承?" → 为了回避菱形问题带来的二义性与复杂度,改用 interface 提供"多来源"的能力。
  • "继承有什么代价 / 缺点?" → 父子强耦合与脆弱基类问题(fragile base class):改动父类可能悄悄破坏所有子类。见易错点。

头号翻车点:为了"复用代码"而继承。继承的正当理由只有一个——真实的 is-a 关系。如果你继承某个类仅仅因为"它刚好有我想要的几个方法",那是把复用误当成了继承。代价是:子类和父类被焊死成强耦合,父类暴露给子类的一切(包括你没打算用的方法)都成了子类对外承诺的一部分。

脆弱基类问题(fragile base class):继承让父类的实现细节泄漏给子类。父类作者哪天改了一个内部方法的调用方式,可能在完全不知情的情况下把远处某个子类弄崩——因为子类依赖了它本不该依赖的父类内部行为。这正是"组合优于继承"的动机:组合只依赖对方的公开接口,耦合面小得多。(这条会在 0010 展开。)

次级坑:说"super() 就是父类"。单继承下没错,但多继承里它是 MRO 的下一个,拿不准就这样表述,别把话说死。

"多继承在你这门语言里怎么处理?"是继承题的必考对照,记住这张表:

语言类的多继承菱形问题怎么办"多来源"的正道
Python支持用 MRO / C3 线性化定唯一查找顺序(Cls.__mro__ 可查)直接多继承,或 mixin
Java不支持(类只能单继承)从源头回避:类不能多继承interface 多实现(implements A, B)
C++支持(真多继承)用 virtual 继承合并共同基类子对象直接多继承

一句话:Java 从源头禁掉、C++ 用 virtual 打补丁、Python 用 MRO 排个确定顺序。三种哲学,MRO 的细节在 0019。

合上讲义,自己写一遍(先单继承,建立肌肉记忆):

  • 写一个父类 Employee,有 name、base_salary,以及方法 pay() 返回 base_salary。
  • 写子类 Manager(Employee):构造里用 super().__init__(...) 复用父类,新增属性 bonus;重写 pay(),返回 base_salary + bonus。
  • 自测:isinstance(m, Employee) 是不是 True?为什么?(因为 Manager is-a Employee。)
  • 进阶自问:如果需求变成"一个人既是 Manager 又是 Engineer",你会用多继承,还是用组合(让 Person 持有若干 Role)?哪个更不容易踩菱形?
自测 1:有人写 class Stack(list):,理由是"list 已经有 append/pop 了,继承过来省事"。这个设计好不好?为什么?

不好——这是典型的"为复用而继承"。问一句 is-a:Stack 是一种 list 吗?不是。栈只该暴露 push/pop/peek,但继承 list 会把 insert、__setitem__、按下标随机插入等破坏栈语义的方法全部暴露出去,调用方能绕过栈的规则乱改。

更好的做法是组合:让 Stack 内部持有一个 list(self._items = []),只对外开放栈该有的几个方法。这就是 has-a 而非 is-a——正是"组合优于继承"的经典场景(专题 0010)。

自测 2:下面关于 super() 的说法,哪个最准确?"在 Python 里 super() 指向的是……"

答案:MRO(方法解析顺序)中当前类的下一个类。在单继承下,这个"下一个"恰好就是直接父类,所以平时把它当"父类"用没问题;但在多继承下,super() 顺着 MRO 走,可能指向一个并非你直接父类的兄弟分支上的类。

常见错误答案是"super() 永远等于直接父类"——这在多继承里会失效。想彻底搞懂,看 0019 的 MRO / C3 线性化。

自测 3:把五种继承类型和它们的形状连起来——"A ← B ← C"是哪一种?"B ← A → C"又是哪一种?

"A ← B ← C" 是多层继承(Multilevel):链式,C 继承 B,B 继承 A。

"B ← A → C" 是层次继承(Hierarchical):一个基类 A 被多个子类 B、C 共同继承。

另外三种:单继承(A ← B,一对一)、多继承(多个基类 → 一个子类)、混合继承(以上组合)。面试报名字 + 画形状,比只说"有好几种"强得多。

带走这一条:继承表达的是 is-a 关系,唯一正当的理由是"X 确实是一种 Y",而不是"我想蹭 Y 的代码"——后者会招来强耦合与脆弱基类问题。五种类型(单/多/多层/层次/混合)要能报名字画形状;super().__init__() 复用父类构造,但它严格来说指向 MRO 的下一个而非死板的"父类"。想不清该不该继承时,先问 is-a,答不通就改用组合(0010)。
