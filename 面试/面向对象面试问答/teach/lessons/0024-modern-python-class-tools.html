现代 Python 建类:dataclass、slots、Enum

前面几节讲了封装、不可变、可变默认坑这些"机制"。这一节把它们落地成一件事——Pythonic 地写一个类。面试里当场用 @dataclass 消掉一屏样板,再顺手讲清它背后挡住的坑,是很稳的加分项。

你要写一个只装 x、y 两个字段的 Point 类,要求:打印出来好看、能用 == 比较相等、还能塞进 set。凭直觉,你得手写几个方法?分别是哪几个?先在心里列出来——这一节教你怎么一个都不写。

一、直觉:样板(boilerplate)是噪声

一个"纯数据容器"类,90% 的代码都是抄的:__init__ 把参数逐个塞进 self、__repr__ 拼一个好看的字符串、__eq__ 逐字段比较……字段一多,这些方法又长又容易漏、容易和字段列表不同步。这些代码不表达任何业务意图,纯粹是噪声。

现代 Python 的思路是:你只声明"有哪些字段",样板方法交给工具自动生成。你把注意力留给真正的业务逻辑。这一簇工具有四件,先建立地图,再逐个看。

@dataclass
装饰一个类,按你声明的字段自动生成 __init__ / __repr__ / __eq__ 等样板。可选 frozen=True(不可变)、slots=True(省内存)、order=True(可排序)。适合需要方法或可变状态的数据容器。
namedtuple / NamedTuple
带名字字段的元组:轻量、不可变、可解包。适合小型、只读的记录。collections.namedtuple 是老写法,typing.NamedTuple 支持类型注解。
__slots__
在类里声明 __slots__ = ('x', 'y'),限定实例只能有这几个属性。省内存(不给每个实例建 __dict__)、禁止动态加属性;代价是失去 __dict__、多继承与弱引用有坑。
Enum
定义一组具名常量(class Color(Enum): RED = 1)。比裸整数 / 裸字符串更安全、更可读、可用 is 比较。

二、@dataclass:从"手抄"到"声明"

先看手写一个 Point 要付出什么——注意里面没有一行是业务逻辑:

# ❌ 手写:三个魔术方法全靠抄,还容易和字段列表不同步
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point(x={self.x!r}, y={self.y!r})"

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

换成 @dataclass,你只写"有哪些字段",三个方法自动到位:

# ✅ @dataclass:声明字段即可,__init__/__repr__/__eq__ 全自动
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p = Point(1, 2)
print(p)                 # Point(x=1, y=2)   ← 自动 __repr__
print(p == Point(1, 2))  # True              ← 自动 __eq__

字段可以给默认值(x: int = 0)。但一旦默认值是可变对象,坑就来了——这正是上一节(值 / 引用 / 可变性)那个经典陷阱:

from dataclasses import dataclass, field

# ❌ 直接给可变默认:dataclass 在类定义时就报 ValueError
@dataclass
class Cart:
    items: list = []          # ValueError: mutable default ... is not allowed

# ✅ 用 default_factory:每个实例拿到一个"新建"的 list
@dataclass
class Cart:
    items: list = field(default_factory=list)

注意 dataclass 的贴心之处:它直接把这个坑变成报错,逼你写 default_factory,而不是让你悄悄踩进"所有实例共享同一个 list"的雷。这是它帮你挡下的第一个坑。

再看 frozen=True:让实例不可变,并因此自动可哈希——呼应"不可变才能安全地哈希"那一节:

from dataclasses import dataclass

@dataclass(frozen=True)
class Money:
    amount: int
    currency: str

m = Money(100, "CNY")
# m.amount = 200      # ❌ FrozenInstanceError:frozen 后不能再赋值
seen = {m}            # ✅ 可哈希 → 能进 set、能当 dict 的 key
print(m)              # Money(amount=100, currency='CNY')  ← __repr__ 照样有

三、slots、namedtuple、Enum

slots:海量实例要省内存时,让实例不再各自带一个 __dict__。Python 3.10+ 的 dataclass 可以直接 slots=True,等价于手写 __slots__:

from dataclasses import dataclass

@dataclass(slots=True)        # Python 3.10+
class Pixel:
    x: int
    y: int

# 手写等价物:
class Pixel:
    __slots__ = ('x', 'y')    # 不再为每个实例建 __dict__

px = Pixel(0, 0)
# px.z = 5   # ❌ AttributeError:slots 禁止动态加没声明过的属性

namedtuple:如果这条记录只读、还想像元组一样解包,namedtuple 比 dataclass 更轻:

from collections import namedtuple
from typing import NamedTuple

Point = namedtuple("Point", ["x", "y"])   # 老写法

class Point(NamedTuple):                   # 带类型注解的新写法
    x: int
    y: int

p = Point(1, 2)
print(p.x)          # 1        ← 按名字取字段
a, b = p            # (1, 2)   ← 还能像普通元组一样解包
# p.x = 9           # ❌ 元组不可变,不能改

Enum:一组固定取值(状态、颜色、方向……),用 Enum 而不是裸常量:

from enum import Enum

class Color(Enum):
    RED = 1
    GREEN = 2
    BLUE = 3

print(Color.RED)          # <Color.RED: 1>
print(Color.RED.name)     # 'RED'
print(Color.RED.value)    # 1
print(Color.RED is Color.RED)   # True  ← 成员是单例,可用 is 比较

为什么不用 RED = 1 这种裸常量?因为裸常量里 1 和别处的 1 没法区分,函数收到 color=5 也不报错;Enum 给了一个受约束的类型,拼错名字直接 AttributeError,可读性和安全性都更好。

四、到底用哪个?一张决策表

你的场景首选工具理由
需要方法 / 可变状态的数据类@dataclass普通类,能加方法、能继承,默认可变
小型、只读、还想解包的记录namedtuple / NamedTuple元组子类,最轻,天然不可变
不可变值对象、要进 set / dict@dataclass(frozen=True)不可变 + 自动可哈希
要创建海量实例、省内存__slots__ / slots=True去掉 per-instance __dict__
一组固定取值(状态 / 类别)Enum具名、可读、类型受约束

高频追问链(数据类几乎必被问):

  • "dataclass 和 namedtuple 有什么区别,该用哪个?" → namedtuple 是 tuple 子类:不可变、可解包、更轻,适合小型只读记录;dataclass 是普通类:默认可变(要不可变加 frozen)、加方法 / 继承更自然。要"不可变 + 解包"→ NamedTuple;要"行为 / 可变 / 灵活"→ dataclass。
  • "@dataclass 到底帮你生成了哪些方法?" → 默认 __init__、__repr__、__eq__;order=True 再加 __lt__ 等比较方法;frozen=True 加 __hash__ 并封锁赋值。每一项都能单独开关。
  • "为什么 dataclass 不让我写 items: list = []?" → 默认值在类定义时只求值一次,会被所有实例共享(上一节的可变默认坑);dataclass 检测到 list / dict / set 默认值直接抛 ValueError,逼你改用 default_factory。
  • "__slots__ 为什么省内存、是不是也更快?" → 主要收益是不给每个实例建 __dict__,实例一多内存下降明显(具体幅度看属性数量与实现,别背死数字);属性走描述符,常被说"略快",但这不是它的主卖点。

坑一:dataclass 里可变默认必须用 default_factory。直接写 x: list = [] 会在类定义时就 ValueError——这是 dataclass 主动帮你挡住"共享可变默认"的雷,别绕过它。

坑二:只有 frozen=True 才自动 __hash__。普通(可变)dataclass 的 __hash__ 被设为 None,进 set / 当 key 会 TypeError。要它可哈希,就得 frozen=True(且 eq 保持默认的 True)。而且即便 frozen,若某个字段本身不可哈希(如里面装了 list),哈希那一刻仍会报错。

坑三:__slots__ 遇上继承会"漏"。子类如果没有也定义 __slots__,它的实例又会冒出一个 __dict__,省内存的效果就没了。要完全生效,继承链上每一层都得声明 __slots__。

附赠坑:字段顺序。有默认值的字段不能排在没默认值的字段前面,否则 dataclass 生成的 __init__ 参数非法,直接 TypeError——和普通函数"默认参数必须靠后"是同一个道理。

"消除数据类样板"是各语言的共同诉求,记住这张对照:

语言消除样板的工具对应 Python 思路
Javarecord(16+)≈ frozen dataclass / NamedTuple:不可变值载体,自动 equals/hashCode/toString
JavaLombok @Data≈ @dataclass:生成构造器 / getter/setter / equals / toString(可变)
C#record≈ frozen dataclass:值语义、带 with 复制
C#struct值类型;语义上像"小的不可变记录",但底层机制与 Python 不同

一句话:Python 的 dataclass / namedtuple 和 Java record、Lombok、C# record 是同一类思路——把"纯数据类"的样板交给语言 / 库生成。

  • 把它改成不可变值对象:加 frozen=True,再试着把两个 Student 放进一个 set——会成功还是报错?为什么?(提示:字段里有 list。)
  • 用 Enum 定义 Grade(A/B/C),让 Student 多一个 grade: Grade 字段;打印实例看看 __repr__ 长什么样。
自测 1:下面这段代码会发生什么?为什么?@dataclass\nclass C:\n tags: list = []

答案:在类定义时就抛 ValueError(mutable default ... is not allowed),类根本创建不出来。

原因:默认值只在类定义时求值一次,如果允许,这个 [] 会被所有实例共享(上一节的可变默认坑)。dataclass 检测到 list / dict / set 这类可变默认就主动报错,正确写法是 tags: list = field(default_factory=list),让每个实例各拿一个新列表。

自测 2:四个场景配四件工具——① 表示"订单状态只能是 待付款/已付款/已发货" ② 要创建上千万个只有 x、y 的坐标点、内存吃紧 ③ 一个需要 total() 方法、字段还会变的购物车 ④ 一条只读、要解包成 lat, lng = pos 的经纬度记录

① → Enum:一组固定取值,具名且类型受约束。

② → __slots__ / @dataclass(slots=True):海量实例去掉 per-instance __dict__ 省内存。

③ → @dataclass(可变):要加方法、字段会变,普通 dataclass 最合适。

④ → NamedTuple / namedtuple:只读 + 可解包,元组子类最轻。

带走这一条:写纯数据类别再手抄样板——需要方法 / 可变用 @dataclass,只读小记录用 namedtuple,不可变值对象用 frozen=True(顺带可哈希),海量实例省内存用 __slots__,固定取值用 Enum。记住三个坑:可变默认要 default_factory、可哈希要 frozen、__slots__ 继承每层都要写。
