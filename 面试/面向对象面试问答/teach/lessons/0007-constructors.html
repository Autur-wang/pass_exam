构造器:初始化、__init__ 与 __new__

"构造器是什么"是送分题,但面试官紧接着一定会追:"Python 里 __init__ 到底构造了什么?__new__ 又是干嘛的?怎么做构造器重载?"这一节把这一簇讲透。

先想一个问题:你写 t = Temperature(25) 的时候,括号里的 25 到底喂给了谁?对象是先被"造出来",还是先被"初始化"——这两件事,是同一步吗?先在心里给个答案,再往下看。

一、直觉:构造器是对象的"开箱质检"

想象你网购了一台需要组装的家具。快递送到的是一个箱子——空间已经分配好了,但里面还是散件,不能直接用。你得按说明书把螺丝拧上、把板子对齐,它才变成一张能用的桌子。

构造器(Constructor)就是这份"开箱说明书":它在对象刚被创建出来的那一刻自动执行,负责把散件装成"一致、可用的初始状态"。没有它,你的对象就是一个字段全空、随时会崩的半成品。构造器的核心价值只有一句话:保证任何一个新对象,一诞生就是合法可用的。

构造器 (Constructor)
一种特殊方法,在创建对象时自动调用,用来把新对象初始化成一致、可用的初始状态。
三个经典特征(源题口径,主要描述 Java/C++/C#)
① 与类名关联(便于识别,如 Java 里方法名 = 类名);② 没有返回类型(连 void 都没有);③ 创建对象时自动被调用,不用你手动 call。
四种类型
① 默认构造器:无参;若你一个构造器都没写,语言自动提供一个空的。
② 参数化构造器:带参,用传入的值给字段赋初值(最常用)。
③ 拷贝构造器:用同类型的另一个对象来初始化当前对象(C++ 里常用于深拷贝)。
④ 静态构造器:初始化类级成员、做类级动作,不参与单个对象的创建;很多语言(含 Python)没有这个专门语法。

注意上面第②条"没有返回类型"是 Java/C++/C# 的口径。到了 Python,情况要精确一点——见下一节。

二、Python 的两步:__new__ 造壳,__init__ 填馅

回到开头那个问题。在 Python 里,Temperature(25) 背后其实是两步,由两个不同的方法接力完成:

Temperature(25)你写的调用
→
__new__(cls, 25)真正"造"出实例(空壳)
→
__init__(self, 25)往壳里"填"状态
→
t可用的对象
  • __new__ 才是真正的构造器:它负责分配并返回一个新实例(那个"空箱子")。
  • __init__ 是初始化器(initializer):它拿到 __new__ 已经造好的对象(self),往里填字段。所以 25 最终是喂给 __init__ 的。

这就解开了"没有返回类型"在 Python 里的真相:__init__ 必须返回 None——如果你在 __init__ 里写 return 42,Python 会抛 TypeError。而真正"返回新对象"的活儿,是 __new__ 干的。

99% 的日常代码只需要写 __init__,因为默认的 __new__(继承自 object)已经把壳造好了。那什么时候才需要动 __new__?主要是这几种场景:

  • 继承不可变类型(int/str/tuple):值必须在"造壳"那一刻就定死,等到 __init__ 时对象已经不可改了。
  • 实现单例或对象池:想控制"到底造不造新实例"。
  • 写元类(metaclass)等高级机制。
# 继承不可变类型 str,必须重写 __new__ 才能改值
class UpperStr(str):
    def __new__(cls, value):
        # str 不可变:值要在"造壳"时就定好,__init__ 阶段改不动
        return super().__new__(cls, value.upper())

s = UpperStr("hello")
print(s)          # HELLO
print(type(s))    # <class '__main__.UpperStr'>

三、没有构造器重载,怎么办?

Java/C++ 里你可以写好几个同名、不同参数签名的构造器,这叫构造器重载(overloading)。Python 不支持这种基于签名的重载:一个类里如果写了两个 __init__,后一个会静默覆盖前一个——不报错,但第一个直接失效。

Python 用两个更简洁的手段替代重载:

class Temperature:
    """一个温度类:参数化 __init__ + 备用(命名)构造器。"""

    def __init__(self, celsius: float = 0.0):   # 默认参数:一个 __init__ 顶多个重载
        # __init__ 是"初始化器":对象此刻已由 __new__ 造好,
        # 这里只负责把它填成"一致、可用"的初始状态。
        if celsius < -273.15:                    # 低于绝对零度 → 非法
            raise ValueError("温度不能低于绝对零度")
        self.celsius = celsius

    @classmethod
    def from_fahrenheit(cls, f: float) -> "Temperature":
        # 命名构造器(工厂方法):弥补"没有构造器重载"
        return cls((f - 32) * 5 / 9)            # 内部再回到 __init__,复用校验

    @classmethod
    def from_kelvin(cls, k: float) -> "Temperature":
        return cls(k - 273.15)


t1 = Temperature(25)                    # 走 __init__
t2 = Temperature.from_fahrenheit(98.6)  # 走命名构造器 → 内部回到 __init__
t3 = Temperature.from_kelvin(300)
  • 默认参数:一个 __init__ 配上默认值,就能覆盖"传/不传""传几个"等多种调用姿势。
  • @classmethod 命名构造器(工厂方法):像 from_fahrenheit 这样起个能读懂的名字,收进 cls(...) 去调真正的 __init__。标准库里的 dict.fromkeys()、datetime.fromtimestamp() 都是这个套路。它比"一个 __init__ 塞十个参数用 if 分流"清晰得多。

还有一件必须记住的事——子类的构造:子类若定义了自己的 __init__,父类的 __init__ 不会自动跑,你要用 super().__init__(...) 显式调用(super() 走的是 MRO 上的下一个,通常就是父类)。忘了调,父类那部分字段就没初始化,埋下坑。

高频追问链(构造器几乎必被深挖):

  • "构造器有返回值吗?" → Java/C++ 构造器没有返回类型(连 void 都没有);Python 的 __init__ 必须返回 None,返回别的会 TypeError;真正"返回新对象"的是 __new__。
  • "__init__ 和 __new__ 有什么区别?什么时候要重写 __new__?" → __new__ 造实例(返回对象)、__init__ 填状态(返回 None);只有不可变类型子类、单例/对象池、元类这类场景才需要重写 __new__。
  • "Python 怎么做构造器重载?" → 没有基于签名的重载,用默认参数 + @classmethod 命名构造器替代;同一个类写两个 __init__ 后者会覆盖前者。
  • "子类里怎么调父类构造器?不调会怎样?" → super().__init__(...);不调则父类的初始化被跳过,父类字段可能缺失。
  • "如果一个类什么构造器都不写呢?" → 语言提供默认(无参)构造器;Python 里就是继承 object.__init__,对象仍能创建,只是没有任何自定义初始化。

坑一:想"重载"而写了两个 __init__。Python 不按签名分派,后定义的方法直接覆盖前一个,不报错、静默失效——这类 bug 最难查。想要多种构造方式,请用 @classmethod 工厂方法,别堆 __init__。

坑二:可变默认参数(经典中的经典)。写 def __init__(self, items=[]) 会翻车:默认值 [] 只在函数定义时创建一次,之后所有"没传 items"的实例共享同一个列表。

# ❌ 陷阱:可变默认参数被所有实例共享
class Basket:
    def __init__(self, items=[]):
        self.items = items

a = Basket(); a.items.append("apple")
b = Basket()
print(b.items)   # ['apple'] —— b 从没加过东西,却有 apple!

# ✅ 正解:默认用 None,进函数体再新建
class Basket:
    def __init__(self, items=None):
        self.items = items if items is not None else []

这个坑本身是"可变默认参数"问题,会在 0023 节专门深讲;此处先记住构造器里的铁律:默认值别用可变对象,用 None 兜底。

"你这门语言的构造器怎么玩?"是跨语言必问。记住这张对照:

语言构造器重载拷贝构造命名构造器
Python不支持(用默认参数 + @classmethod)无专用语法,用 copy 模块 / __copy__惯用 @classmethod(from_xxx)
Java支持(多个不同签名)无内建,手写拷贝构造器 / clone()惯用静态工厂方法
C++支持(多个不同签名)有专门的拷贝构造器 Foo(const Foo&),与析构器 ~Foo() 成对出现常用静态工厂函数
C#支持(多个不同签名)无内建,手写静态工厂方法

一句话:Java/C++/C# 靠"多个签名的构造器"应对多种初始化;Python 靠"一个 __init__ + 默认参数 + 命名工厂"。C++ 尤其特殊——它把"拷贝怎么造""对象怎么销毁"都做成了语言一等公民(拷贝构造器 + 析构器),这也是 0008 节析构与资源管理要展开的话题。

合上讲义,自己写一个 Color 类:

  • __init__(self, r, g, b):三个通道都必须在 0 到 255 之间,否则 raise ValueError。
  • 加一个命名构造器 @classmethod from_hex(cls, s):接受 "#ff8800" 这样的字符串,解析成三个通道后回调 cls(...)(而不是重复写一遍校验)。
  • 写完自测:能不能再写第二个 __init__ 让它"支持字符串输入"?试一下,观察会发生什么——这正是"没有构造器重载"的现场体感。
自测 1:上面 Basket 的 ❌ 版本里,连续 a = Basket(); a.items.append("apple"); b = Basket() 后,b.items 是什么?为什么?

答案:['apple']。

items=[] 这个默认列表只在函数定义(def 执行)时创建一次,而不是每次调用都新建。于是所有"没传 items"的实例——a 和 b——都指向同一个列表对象。a 往里 append,b 自然也看得到。修法是默认写 items=None,进函数体再 [] 兜底。

自测 2:下面哪句关于 __new__ / __init__ 的说法最准确?A. __init__ 负责创建并返回新对象;B. __new__ 造出实例,__init__ 初始化它,日常大多只需写后者;C. 二者完全等价,写哪个都行;D. Python 每个类都必须同时重写这两个。

答案:B。

A 错:__init__ 只初始化、必须返回 None,真正返回新对象的是 __new__。C 错:职责不同,一个"造壳"一个"填馅"。D 错:默认的 __new__ 继承自 object 已够用,只有不可变类型子类、单例、元类等场景才需要重写 __new__;绝大多数类只写 __init__。

带走这一条:构造器 = 对象诞生时自动跑的"开箱质检",保证新对象一出生就合法可用。在 Python 里这是两步——__new__ 造壳(真构造器,返回实例)、__init__ 填馅(初始化器,返回 None);日常只写 __init__。Python 没有构造器重载,用默认参数 + @classmethod 命名工厂替代;默认参数千万别用可变对象,用 None 兜底。
