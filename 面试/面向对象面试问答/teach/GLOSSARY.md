# 面向对象(OOP)面试 术语表

这门课的标准语言。所有讲解、练习、学习记录都遵循这里的措辞。术语以 Python 为主锚点,跨语言差异在条目里点明。带 _避免_ 的是应当让位给标准术语的别名。

## 核心概念与四大支柱

**面向对象编程 (OOP)**:
把代码组织成一个个"自包含对象"的范式——每个对象把**数据**与操作数据的**方法**捆在一起。
_避免_:类式编程、对象式写法

**类 (Class)**:
创建对象的蓝图,定义对象的属性(数据)与方法(行为)。
_避免_:模板(易与 C++ template 混)、类型

**对象 / 实例 (Object / Instance)**:
类的一次具体实例化,拥有身份(identity)、状态(state)、行为(behavior)三要素。
_避免_:变量、结构体

**封装 (Encapsulation)**:
把数据与操作它的方法捆进一个单元,并**隐藏内部状态**,只通过受控接口(getter/setter/property)暴露。
_避免_:数据隐藏(那只是封装的一个方面)、私有化

**继承 (Inheritance)**:
基于已有类创建新类,子类获得父类的属性与方法,建立 **"is-a" 关系**。
_避免_:派生、扩展(extend 是 Java 关键字,不等于继承概念本身)

**多态 (Polymorphism)**:
让不同类型的对象通过**共享接口**被统一对待,同一方法调用在不同对象上表现不同行为。
_避免_:重写(overriding 只是多态的一种实现手段)

**抽象 (Abstraction)**:
只暴露必要的、相关的功能,隐藏实现细节;通过抽象类与接口实现。
_避免_:封装(两者常被混:封装是"藏起来",抽象是"只给必要的")

## 多态与绑定

**重写 (Overriding)**:
子类给出父类已有方法的新实现,**运行时**根据对象实际类型决定调用哪个——运行时多态。
_避免_:覆盖、override(中文语境用"重写")

**重载 (Overloading)**:
同一作用域内多个同名方法,靠参数个数/类型/顺序区分,**编译期**按签名选择——编译期多态。
_避免_:重定义;注意 **Python 不支持真正的重载**(后定义覆盖前者)

**动态分派 / 后期绑定 (Dynamic Dispatch / Late Binding)**:
运行时才确定该调用哪个具体方法实现的机制,是运行时多态的底层。
_避免_:虚调用(virtual call 是 C++ 说法)

**静态绑定 / 早期绑定 (Static / Early Binding)**:
编译期就确定调用目标(如重载解析、静态方法、非虚方法)。
_避免_:编译期绑定

**虚方法 (Virtual Method)**:
C++ 中用 `virtual` 标记、可被子类重写并参与动态分派的方法;Java 方法默认虚,Python 方法总是动态查找。
_避免_:抽象方法(virtual 可以有实现)

## 类与对象机制

**构造器 (Constructor)**:
创建对象时自动调用、用于初始化状态的特殊方法。Python 里是 `__init__`(严格说 `__new__` 才是"造",`__init__` 是"初始化")。
_避免_:初始化函数

**析构器 / 终结器 (Destructor / Finalizer)**:
对象销毁前用于释放资源的清理钩子。C++ 是 `~T()`(确定性);Python 是 `__del__`(不保证时机,靠 GC);Java 的 `finalize()` 已弃用。
_避免_:清理函数;**面试更该谈** `with`/context manager 与 `try-with-resources`

**垃圾回收 (Garbage Collection, GC)**:
自动回收不再被引用的对象内存的机制(Java/C#/Python 都有;C++ 靠 RAII 手动/确定性管理)。
_避免_:内存回收

**访问修饰符 (Access Specifier)**:
控制成员可见性的关键字:`private`(仅类内)、`protected`(类内+子类)、`public`(全局)。
_避免_:权限、可见性关键字

**getter / setter**:
封装下用于读/写私有属性的公开方法;Python 惯用 `@property` 把它们伪装成属性访问。
_避免_:存取器

**实例成员 / 类成员 (Instance / Class Member)**:
实例成员每个对象各一份;类成员(类变量、`@staticmethod`、`@classmethod`)全类共享。
_避免_:静态成员(Python 语境用"类成员"更准)

## 关系与耦合

**关联 (Association)**:
对象之间的一般性关系(A 用到 B),最弱的一种。
_避免_:引用关系

**聚合 (Aggregation)**:
"has-a" 关系的一种,整体拥有部分,但**部分可独立于整体存在**(如班级 has 学生)。
_避免_:组合(聚合更弱)

**组合 (Composition)**:
更强的 "has-a",**部分不能脱离整体存在**(如房子 has 房间),整体销毁部分随之销毁。
_避免_:聚合、包含

**Mixin(混入)**:
只提供方法、不独立成型的类,横向复用行为("can-do-this"),Python 靠多重继承落地。
_避免_:多继承、trait(概念相近但非等同)

**内聚 (Cohesion)**:
一个类内部方法与数据彼此相关的紧密程度;**高内聚**是目标(功能内聚最佳),对应单一职责。
_避免_:凝聚度

**耦合 (Coupling)**:
类/模块之间相互依赖的程度;**低耦合(松耦合)**是目标,消息耦合最松、内容耦合最紧。
_避免_:依赖度

**组合优于继承 (Composition over Inheritance)**:
设计准则:除非有明确 "is-a" 关系,否则优先用组合而非继承,以获得更灵活、可替换的设计。
_避免_:少用继承(过于笼统)

## SOLID 五原则

**单一职责原则 (SRP)**:
一个类应只有一个变化的理由(只承担一项职责)。对应高内聚。
_避免_:一个类只做一件事(不精确)

**开闭原则 (OCP)**:
对扩展开放、对修改关闭——加新功能靠新增代码(继承/实现接口),而非改动已有代码。
_避免_:可扩展原则

**里氏替换原则 (LSP)**:
子类对象必须能替换父类对象而不破坏程序正确性;经典反例是"正方形 is-a 矩形"。
_避免_:子类可替换(要强调"不破坏正确性")

**接口隔离原则 (ISP)**:
不应强迫类依赖它用不到的方法;宁可多个小接口,不要一个大而全的胖接口。
_避免_:接口最小化

**依赖倒置原则 (DIP)**:
高层模块与低层模块都应依赖**抽象**,而非具体实现;抽象不依赖细节。常与依赖注入配合。
_避免_:面向接口编程(DIP 更严格)

**依赖注入 (Dependency Injection, DI)**:
把对象所需的依赖从外部传入(构造器/方法/属性),而非在内部自行 new——DIP 的常见落地手段。
_避免_:控制反转(IoC 是更大的概念,DI 是其一种)

## 设计模式(GoF 三大类)

**设计模式 (Design Pattern)**:
针对反复出现的设计问题的、可复用的通用解法(源自 GoF《设计模式》)。分创建型/结构型/行为型。
_避免_:套路、框架

**单例 (Singleton)**:
保证一个类全局只有一个实例并提供全局访问点(创建型)。Python 可用模块级对象/`__new__`/元类实现。
_避免_:全局变量

**工厂方法 / 抽象工厂 (Factory)**:
把对象的创建过程封装起来,让调用方不必关心具体类(创建型)。
_避免_:构造器包装

**适配器 (Adapter)**:
把一个接口转换成客户端期望的另一个接口,让不兼容的类协作(结构型)。
_避免_:包装器(wrapper 更宽泛)

**装饰器 (Decorator)**:
不改原类、在运行时动态叠加职责(结构型)。**注意与 Python 语法 `@decorator` 相关但非同一回事**。
_避免_:Python 装饰器(要区分模式与语法糖)

**策略 (Strategy)**:
把可互换的算法各自封装成类,运行时选用(行为型)——常用来替代大量 if/else 分支。
_避免_:多态(策略是多态的一种应用)

**观察者 (Observer)**:
一对多依赖:被观察对象状态变化时自动通知所有观察者(行为型)。
_避免_:发布订阅(pub/sub 更解耦,概念相近)

## Python 特有机制(高频跨语言追问)

**name mangling(名称改写)**:
Python 对 `__attr`(双下划线开头)在类内改写为 `_ClassName__attr`,制造"伪私有";这是 Python "没有真 private"的真相。
_避免_:私有化、双下划线私有

**MRO / C3 线性化 (Method Resolution Order)**:
Python 多重继承下确定方法查找顺序的算法(C3 线性化),`super()` 沿 MRO 协作调用,是解决 diamond 问题的机制。
_避免_:继承顺序、查找链

**鸭子类型 (Duck Typing)**:
不看类型、只看对象"能不能做这个操作"("像鸭子叫就当鸭子")——Python 实现多态/抽象的方式之一。
_避免_:动态类型(范围更大)

**抽象基类 (ABC) / Protocol**:
Python 表达"接口/抽象类"的两种方式:`abc.ABC`(名义子类型,需显式继承)与 `typing.Protocol`(结构子类型,鸭子类型的静态版)。
_避免_:接口(Python 无 interface 关键字)

**`@property` / `@staticmethod` / `@classmethod`**:
分别把方法伪装成属性访问(承载 getter/setter)、定义与实例无关的静态方法、定义以类为首参 `cls` 的类方法。
_避免_:装饰器方法

## 通用设计术语

**接口 (Interface)**:
一组方法签名构成的契约,规定实现类"必须能做什么"而不规定"怎么做"。Java 有 `interface`;Python 用 ABC/Protocol/鸭子类型。
_避免_:抽象类(接口无实现,抽象类可有)

**抽象类 (Abstract Class)**:
不能被直接实例化的类,可含抽象方法(留给子类实现)与具体方法(提供默认实现),作为其他类的基础。
_避免_:接口、基类

**is-a / has-a**:
判断该用继承还是组合的经验法则:"是一种"(is-a)→ 继承;"拥有一个"(has-a)→ 组合。
_避免_:属于、包含

**SoC(关注点分离)**:
把系统按不同关注点拆成互不重叠的部分,是高内聚低耦合在架构层面的体现。
_避免_:模块化(更宽泛)
