# NOTES · 教学偏好与工作区说明

## 用户偏好(教学法)
- **交互式授课优先**:默认按仓库教学人设走——先让她复述当前理解 → 补缺 → 用 `AskUserQuestion` 出题校验(打乱正确项位置、答前不公布答案)→ 确认掌握再进下一节。**不要一次把 26 节灌完。**
- 支持 ELI5 / ELI14 / ELII 三档讲解,按她要求切换。
- 深挖"为什么":每个概念不止讲是什么、怎么做,更要讲为什么这样设计、边界情况、以及不这样会怎样(反例驱动)。
- **代码以 Python 为主**(用户明确选择),在"面试爱问的跨语言差异"处才对照 Java/C++/C#,用 `.crosslang` 装置承载。

## 这套课的骨架逻辑
- **骨 = 源里的 15 道真题**(Q1–Q15,已在 lessons 里被聚类覆盖);**肉 = OOP 面试必考 canon**(SOLID/设计模式/语言机制),锚定权威书与官方文档。
- 每节结构固定:`🔁先回忆 → 直觉/原理 → 关键定义 → 代码(Python 为主)→ 🎯面试怎么考(高频追问链)→ ⚠面试易错点 → 🐍跨语言对照(如相关)→ 自测 → 📚权威出处与延伸 → 上/下课导航`。
- 核心链条:**讲清是什么 → 讲透为什么 → 落到代码 → 落到面试 → 答得住追问**。

## 反幻觉纪律(本课特别注意)
- OOP 是稳定教科书知识,幻觉风险低于 AI,但仍须守:**绝对措辞("唯一/所有/永远")必须能举出反例**,否则改措辞。
- 语言机制断言要准:如"Python 没有真正 private""Java 用 interface 绕开多继承""C++ 用 virtual 做动态分派""Python 没有方法重载"——这些是送分点,但也最容易讲错细节,拿不准就 hedge 或标注。
- 补充的 canon 内容(SOLID、设计模式)标注权威出处;源里没写的,不假装是源里的。

## 样式与技术约定
- 全课唯一样式表 `assets/style.css`,每节只 link 这一个。**本课无数学,不加载 KaTeX**(与姊妹 AI 课的最大差异)。
- 代码块用 `<pre><code>`;HTML 源码里凡出现 `<`、`>`(如 C++ `vector<int>`、泛型、比较运算)**必须写 `&lt;`/`&gt;`**,否则被浏览器当标签吃掉。这是本课最需要盯的转义点(代替了 AI 课的 KaTeX `<` 陷阱)。
- 上/下课导航用精确文件名(`NNNN-dash-case-topic.html`),避免死链。

## 与其他课的边界
本工作区仅覆盖"OOP 面试问答"。仓库内另有《面向对象高级编程 advanced_oop》(是编程进阶课,非面试问答),两者不共用装置与术语,勿混。
