# Mission: 面向对象(OOP)面试问答冲刺

## Why
在技术面试里,OOP 是几乎绕不开的一环——无论投 Python 后端、Java 工程、还是通用软件岗,面试官都会用"什么是封装 / 继承 vs 组合 / SOLID / 设计模式"这类题快速探你的设计功底。目标不是背诵定义,而是**当场把每个概念讲清、讲出为什么、并扛得住追问**,把这一环从"可能翻车"变成"稳定拿分"。

## Success looks like
- 能用一句话讲清封装、继承、多态、抽象各是什么、解决什么问题,并当场写出最小代码示例(Python 为主)。
- 面对"Python 有 private 吗 / 有重载吗 / 有接口吗 / 多重继承怎么办"这类跨语言追问,能答出**机制真相**(name mangling、singledispatch、ABC/Protocol、MRO/C3),而不是含糊带过。
- 能讲透 SOLID 五原则各自的"坏味道 → 原则 → 重构方向",并举出 LSP 的经典反例(矩形/正方形)。
- 能在白板上就一道设计题(如"设计一个通知系统")选出合适的关系(is-a / has-a)与设计模式,并说清取舍。
- 遇到"组合 vs 继承怎么选""高内聚低耦合怎么落地"这类开放题,能给出有原则、有反例的回答。

## Constraints
- **代码以 Python 为主**(用户指定),在关键差异处对照 Java/C++/C#。
- 每节 10–12 分钟可读完,一节只攻一簇高频真题,自成一体、本地打开即可。
- 面试冲刺导向:每节都要落到"面试怎么考 + 易错点",不做学院派长篇。
- 无数学公式,不加载 KaTeX。

## Out of scope
- 具体框架/库的 OOP 用法(Django ORM、Spring 等)——只讲语言级 OOP 本身。
- 深入的编译原理 / 虚表内存布局(点到"动态分派靠 vtable"为止,不展开汇编)。
- UML 建模的完整规范(只用够面试白板画关系图的最小记号)。
- 函数式 / 并发编程范式的系统学习(仅在"OOP vs 其他范式"一课点到)。
