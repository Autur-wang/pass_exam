前端面试到底考什么:五道关卡与考察重点

"前端面试"听起来像一个统一的东西,但推开门才发现,它可能是简历筛选、trivia 问答、算法/JavaScript/UI 编码、系统设计、行为面试里的任意组合。这一课要回答的问题很具体:这几关到底分别在考什么,前端面试和普通软件工程面试的差异,又具体体现在哪一关上。

上一课结尾让你做过一次自评:对着"简历、编码、trivia、系统设计、行为"这几个方向,诚实标出哪一关你心里有底、哪一关没数。如果当时答得比较含糊,不用担心——这一课就是把"前端面试"这个笼统的名字拆开,看它到底由哪几关组成,每一关又在考什么,标完之后你的自评会更准。

一、先说清楚:前端面试和普通软件工程面试,差在哪

前端面试没有统一的标准结构。有些公司的前端面试流程,和普通软件工程师面试完全一样;另一些公司——源材料点名了 Google 和 Amazon——会把通用的软件工程环节和前端专属环节混在一起考。

更值得注意的一个动向是:行业正在逐渐减少对纯算法/数据结构(DSA)题目的依赖,转而要求候选人实现常见的前端库函数,或者搭建实际可用的 UI 组件/应用程序。源材料把这个转向形容为"令人鼓舞"的趋势,理由很直接:和大多数 DSA 题不同,这类前端专属问题和前端工程师的日常职责高度相关,是更准确的评估方式。

但"趋势"不等于"所有公司都这样"。往下看第三节的公司对照表就知道,Google、Amazon、ByteDance 在"算法"这一项上依然标着"是"。所以更准确的说法是:前端面试整体上更偏向领域知识、比传统 SWE 面试更少依赖纯算法,但具体某家公司考不考算法,还是要看这家公司自己的安排。

二、五道关卡分别考什么

简历关敲门砖,决定能不能进下一轮
→
Trivia 问答关1~2 分钟答完的领域知识小问题
→
编码关算法 / JS 函数 / UI 组件,三选一或都考
→
系统设计关通常只考资深候选人
→
行为面试关用过去经验判断是否适合这份工作

这五关不是每场面试都按这个顺序出现,也不是每场都全部考到——具体怎么排列,第三节会说清楚。这里先建立一张大局图:面试官问你的每一个问题,基本都能归到这五类里的某一类。

简历关。简历是给潜在雇主留下第一印象的机会,直接决定你能不能拿到候选资格。源材料特别提到一个容易被忽略的现实:够格但没被选中,很多时候不是因为能力不够,而是简历没能有效呈现你的成就。一旦过了简历筛选,你过去的履历就变得次要,接下来起决定作用的是可以学习和提高的技术技能。

Trivia 问答关。也叫测验问题,是一类"旨在测试你对该领域理解"的简短问题,每题一两分钟就该答完。源材料特别提醒:通常不会有整轮面试从头到尾只问你 trivia,但它会在其他轮次里突然冒出来——这一点在第四节的常见误区里会再展开。

编码关。"编码"这个词在前端面试里至少对应三种完全不同的活儿:

子类型考的是什么
算法编码解决通用算法题,评估你对数据结构、算法和时间复杂度的理解——通常不是前端专属领域
JavaScript 编码用 JS 实现前端开发里常用的函数或数据结构,直接对应前端日常工作
用户界面编码用 HTML/CSS/JS(有时还要求某个框架)搭建组件、小部件或完整应用

源材料的判断很明确:公司正在越来越倾向于用后两种"前端专属"编码题,而不是纯算法题,因为它们和前端工程师的实际工作更相关。

系统设计关。这是一种高度开放式的面试:面试官给一个模糊的问题或场景,你要把系统拆成更小的组件、画出架构图、设计 API、深入某个部分讨论权衡。源材料强调这一关通常只针对资深候选人,题目类型分三种——分布式系统(比如 Twitter 后端、URL 缩短器)、客户端应用程序(比如新闻信息流、照片共享应用)、复杂的用户界面组件(比如自动完成、下拉菜单、模态框)。前端工程师被问到的,大多数时候是后两种,而不是分布式后端系统。

行为面试关。面试官问你过去做过的具体事情、遇到的具体情况,用"过去的行为是未来行为的良好指标"这个假设,判断你是否适合这份工作、成熟度够不够——这一关考察的东西,超出了纯技术能力的范畴。源材料专门为这一关写了一整本手册,说明它的分量不比编码关轻。

三、招聘流程里,这五关怎么排列

把这五关按真实招聘流程的时间顺序摆一遍,大多数公司大致是这样三段:

阶段常见环节
初步筛选招聘人员电话(可能夹带 trivia 问题)、自动评分的在线评估或带回家项目
电话筛选编码(算法 / JavaScript 函数 / 搭 UI,三选一或组合)
全循环编码轮 + 系统设计轮 + 行为轮

源材料还给出一份"轮次类型矩阵",把每种问题类型在每个阶段出现的可能性标成高/中/低/无。核心结论可以简化成一句话:trivia 的强度多是低到中、但几乎覆盖每个阶段;系统设计几乎只集中在专门的系统设计轮,强度"高"。

更重要的是,具体某家公司考不考、考多重,差异很大。源材料给出的公司对照表里,同样是知名大厂,权重也完全不一样:

公司Trivia算法JavaScriptUI系统设计行为
Google是是是是是是
Meta / Facebook是否是否是是
ByteDance是是是是否是

这就是为什么"前端面试更偏领域知识、更轻算法"只能当成整体趋势,而不能套用到每一家公司头上——具体到你要面的那家公司,更可靠的做法是直接问清楚,而不是照搬行业整体趋势。

四、关键定义

前端 trivia 问答
测验/琐事式问题,考察你对 HTML/CSS/JS/浏览器等领域知识的即时理解,通常一两分钟内就该答完,不单独占满一整轮。避免把"通常没有专门的 trivia 轮次",理解成"trivia 不重要不用准备"——它会在编码轮、招聘人员电话甚至系统设计轮里随时冒出来。
前端编码面试
至少对应三种不同的活儿:解决通用算法题、用 JavaScript 实现前端相关的函数或数据结构、或用 HTML/CSS/JS 搭建可交互的 UI 组件,三者考察的技能并不相同。避免把"编码面试"直接等同于"刷算法题",而忽略了后两种更贴近前端日常工作、也是行业越来越倾向使用的形式。
前端系统设计面试
高度开放式的面试,要求把一个模糊的问题拆解成更小的组件、画架构图、设计 API 并讨论权衡,通常只针对资深候选人。避免拿后端系统设计那一套(分布式系统、URL 缩短器)去准备——前端候选人更常被要求设计的是客户端应用和复杂 UI 组件,比如自动完成、下拉菜单、照片共享应用。

现实中怎么用。拿到面试安排之后,别满足于招聘人员说的"技术面"这种笼统说法——直接追问每一轮具体是编码(算法/JS/UI 里的哪一种)、系统设计还是行为,再对照上面的招聘流程表决定复习优先级。如果对方含糊其辞,可以按目标公司的体量和业务去类推:规模和业务模式接近 Google、Amazon 的公司,大概率会混合考算法 + 系统设计 + 行为;更看重前端专属技能的团队,往往把重心放在 JavaScript/UI 编码和系统设计上。

一个容易踩的误区:看到"前端面试更偏领域知识、更轻算法"这个整体趋势,就直接推断"我要面的这家公司肯定不考算法",于是完全跳过算法复习。第三节的公司对照表说得很清楚:Google、Amazon、ByteDance 在"算法"这一栏依然标着"是"——趋势是行业整体在变,不代表每一家公司都已经变了,具体到你要面的那家,还是要单独确认。

本周就动手做的一件事:把你正在准备或即将投递的一家公司的面试流程,按"简历/trivia/算法/JS/UI/系统设计/行为"这七个标签逐轮标注清楚(哪怕暂时靠猜),而不是笼统写"技术面一轮、技术面二轮"。标注完你会立刻看出,自己该优先补的是哪一关。

带走这一条:前端面试不是"换了个名字的软件工程面试"——它可能由简历关、trivia 问答关、编码关(算法/JS/UI)、系统设计关、行为面试关中的若干项组成,行业整体在把重心从纯算法移向前端专属技能,但具体哪几项、权重多少因公司而异,拿到面试安排后第一件事就是把每一轮对应到这五关里的哪一种。

五、自测题

Q1:关于"前端面试和普通软件工程面试的区别",下面哪个说法最符合源材料? (A) 二者完全一样,不存在实质差异,只是叫法不同 (B) 行业正逐渐减少对纯算法/数据结构题的依赖,转而更多要求实现前端相关的 JS 函数或构建 UI 组件,但具体考什么因公司而异——比如 Amazon、Google、ByteDance 在算法这一项上仍标"是" (C) 前端面试已经完全弃用算法题,所有公司都只考 HTML/CSS/JS 基础知识

正确答案是 (B)。(A) 忽略了源材料"一些公司的前端面试流程与普通 SWE 相同,另一些则混合使用"的说法,把差异抹平了;(C) 把"行业正在逐渐放弃"这种趋势性描述,曲解成"已经完全不考",而公司对照表里 Amazon、Google、ByteDance 等在"算法"一栏仍标着"是"。

Q2:面试官连续问了你几个"这个 CSS 属性的默认值是什么""说说事件冒泡和捕获的区别"这类一两分钟就能答完的问题,这最可能属于源材料里的哪种题型? (A) trivia / 测验问题 (B) 系统设计问题 (C) 算法编码问题

正确答案是 (A)。源材料把 trivia 定义为"旨在测试你对该领域理解的简短问题,每题一两分钟就该答完",正好对应这种问法;(B) 系统设计面试是高度开放式的,需要拆解系统、画架构图,不会是几句话答完的小问题;(C) 算法编码要求真正动手写代码解决问题,不是纯口头的概念问答。

六、主推资源

本节内容主要对应源材料"准备一份很棒的简历"一节里提到的通用简历资源,以及"典型的招聘流程"一节里提到的、候选人常用来打探真实面经的两个平台:

  • Tech Interview Handbook · Resume —— 通用软件工程简历指南,源材料明确说它不是前端专属,但仍是打底的参考。
  • FAANG Tech Leads' Resume Handbook —— 另一份通用简历手册,和上面那份一起被源材料并列引用。
  • Glassdoor —— 候选人分享具体公司面试轮次和真实体验的平台之一。
  • Blind —— 同类的面经分享平台,常用来交叉核实某家公司实际考不考算法/系统设计。

有任何不清楚的,回到会话里问你的 AI 老师——可以让老师用 ELI5 讲清"trivia 问答关"和"算法编码关"到底差在哪,也可以让老师帮你对着你要面的公司,把每一轮标注成这五关里的哪一种。
