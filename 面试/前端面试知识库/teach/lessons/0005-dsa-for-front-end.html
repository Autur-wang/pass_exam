数据结构与算法面试:前端要刷题到什么程度

这节课要回答的问题很直接:前端工程师要不要刷算法题、和后端/通用软件岗比该刷到多深、常见题型长什么样、遇到动态规划和复杂图算法这类 Hard 难度的题该不该死磕——这几个问题,源材料 综合面试手册/algorithms 都给出了明确的判断标准,这节课把它拆开讲清楚。

回忆一下上一课(0004)的分法:前端编码面试大致能拆成 DOM 操作题、算法题、JS 工具函数题三类,考察的重点各不相同。这三类里,哪一类和你在 LeetCode 上刷到的题目最像?如果你的答案是"算法题",那接下来要面对的第一个问题就是:这类题不是前端发明的,前端岗位到底还要不要刷、刷到多深——这正是这节课要拆开讲的。

一、算法编码题是什么、为什么前端也躲不开

算法编码题就是你在 LeetCode 上能直接搜到的那类题。源材料把它的特征说得很直接:它们并非特定于前端领域,大多数主流编程语言都能拿来解;通常伴随不切实际的场景——现实开发里,谁会真的去翻转一棵二叉树,或者数一数字符串里有多少个回文子串?但代码的时间/空间效率很重要,想拿出高效解法,需要扎实的数据结构与算法功底。

既然算法题本身不特定于前端,为什么前端面试里还是会问?因为解这类题需要的能力——系统的分析思维、清楚的沟通、对常见数据结构和算法的扎实掌握、良好的代码卫生——本来就是一名合格软件工程师应该具备的基本功,前端工程师也不例外。而且这些能力不是"考完就没用了":熟悉数据结构与算法,同样能帮你解 JavaScript 编码题和 UI 编程题,这两类才是更贴近前端岗位本身的题型。

二、常见题型长什么样、语言怎么选

源材料举了三个具体例子,能代表这类题的典型长相:

  • 反转一个链表
  • 判断一个字符串里的括号是不是成对匹配(平衡括号)
  • 统计一个字符串里有多少个子字符串是回文

这些题目共同的特点是:题干本身完全看不出"前端"或"后端"的痕迹,换一个岗位面试,题目可能原样照搬。

解题语言怎么选,源材料给了一个务实的建议:如果想省准备时间,直接用 JavaScript 刷完大部分题也够用;但要留意 JavaScript 标准库缺一些常见又好用的结构——队列、堆、二分查找,Python、Java、C++ 这些语言里都有对应的现成实现。如果这一点让你在面试时卡住,一个被认可的应对方式是直接跟面试官说清楚:"假设这个数据结构/算法已经存在,我直接调用,不现场手写实现"——这不是偷懒,而是把有限的面试时间花在真正要考察的逻辑上。

三、深度差异:前端不用啃到后端那么深,但树是例外

源材料给了一句对判断"该刷多深"很关键的话:即便前端候选人仍然可能被问到任何算法问题,但公司通常会对前端候选人"放轻松",不太会问到动态规划或复杂图算法这类难题。换句话说,通用软件工程岗位可能把这两类当成常规考点,前端岗位命中的概率明显更低。

但这不代表可以跳过所有进阶内容——源材料专门提了一个例外:DOM 本身就是一棵树,所以树和各种树遍历算法(广度优先、深度优先、递归)反而应该优先学。用一张图表示这层判断逻辑:

四、要不要死磕 Hard 题:答案是 Blind 75,不是啃遍图论

把"深度差异"这个结论往前推一步,就是"要不要死磕 Hard 题"的答案。源材料给的准备方法是:先选一种语言,再按重要性规划时间,把学习和练习结合起来一个主题一个主题地过,配合一份编码面试备忘单内化。这套方法本身就意味着——时间是有限资源,不是每个主题都值得等量投入。

结合上一节的深度差异,一个合理的时间分配是:把动态规划、复杂图算法这类 Hard 题的优先级往后放,先把数组、映射、堆栈、树、图、矩阵、集合这些基础结构,和二分查找、BFS、DFS、拓扑排序、递归这些基础算法刷透。源材料推荐的具体清单是 Blind 75——由 Yangshun Tay 策展的一份著名且简洁的算法题清单,覆盖面广但数量克制,不是把 LeetCode 题库刷穿。

换句话说:不必把前端候选人的算法准备,刷到和通用软件工程岗位同一个深度。Blind 75 加上树相关主题打底,通常已经覆盖大部分前端面试会问到的范围;如果刷完这些还有余力,再挑感兴趣的 Hard 题练手,而不必把这部分当成必答题。

五、关键定义

算法编码题(Algorithm Coding Question)
类似 LeetCode 风格的题目,不特定于任何技术领域,通常伴随不切实际的场景,考察的核心是代码的时间/空间效率,以及背后的数据结构与算法功底。避免把它和"前端编码题"划等号——DOM 操作题、UI 组件实现题不属于这一类,考察点也不一样。
Blind 75
由 Yangshun Tay 策展的一份精简高频算法题清单,覆盖面广但数量克制,适合作为准备时间有限时的主线刷题范围。避免把它当成"刷完就够、封顶"的考纲——它只是排好优先级的起点,不是上限。

现实中怎么用。选好语言(通常直接用 JavaScript 就够,除非你想更从容地用到队列/堆/二分查找这类 JS 标准库没有的结构,那可以考虑 Python)之后,别按目录从头到尾刷,先按"树/图/BFS/DFS"和"数组/哈希/双指针"这类前端面试更常出现的主题排优先级,再往后排动态规划和复杂图算法。边学一个主题边配套刷几道题,再拿一份编码面试备忘单把"必须做的事、必须记住的事"过一遍——具体的分步做法,可以直接照着 Tech Interview Handbook 的准备指南 走一遍,这门课不重复展开通用算法面试怎么复习。

常见误区:两个方向都容易失衡。一种是"前端不用刷算法,反正和业务不像",但源材料说得很直接——很多公司在前端面试里仍然会问算法编码题,而且练好数据结构与算法,对解 JavaScript 编码题、UI 编程题同样有帮助,不是一门孤立的技能。另一种是反过来,既然要考就"刷到和通用软件岗一样深",把动态规划、复杂图算法这类 Hard 题也啃遍——但源材料明确说公司对前端候选人通常放轻松,不太会深挖到这个程度,这部分时间投入前端系统设计或 UI 编程题,回报大概率更高。

今天就做的事:找一份 Blind 75 题目清单(策展人 Yangshun Tay,见文末链接),不按题号顺序刷,先把清单里"树、图、BFS/DFS、递归"相关的题挑出来单独标记,这些是 DOM 系考点、命中率更高;剩下的动态规划、复杂图算法类题目先标"时间富余再看"。30 分钟就能把接下来的刷题优先级定下来,而不是从第一题开始盲刷。

带走这一条:前端岗位的算法编码面试题目本身和其他岗位没有区别,但公司对深度的期待通常更低——动态规划、复杂图算法这类 Hard 题不必死磕到通用软件岗的程度;真正该优先打牢的是树与遍历算法,因为 DOM 本身就是一棵树,这部分投入还能反哺 JavaScript 编码题和 UI 编程题。

六、自测题

Q1:关于前端岗位算法编码面试和通用软件工程岗位的深度差异,下面哪个说法最准确? (A) 前端岗位基本不会被问到算法编码题,可以完全跳过不复习 (B) 公司对前端候选人的算法深度期待通常更低,不太会深挖动态规划或复杂图算法,但因为 DOM 是一棵树,树与遍历相关题反而值得优先打牢 (C) 前端岗位和通用软件岗的算法题深度完全一样,唯一区别只是把 JavaScript 换成了 Python

正确答案是 (B)。源材料明确说公司会对前端候选人"放轻松",较少深挖动态规划、复杂图算法,同时因为 DOM 是树结构,树与遍历算法的优先级反而更高。(A) 忽视了很多公司仍然会在前端面试里问算法编码题;(C) 把深度差异简化成了语言选择,但源材料里"是否深挖 DP/复杂图"这个深度问题,和"用 JS 还是 Python"这个语言选择问题是两件独立的事,不能互相替代。

Q2:关于"前端候选人要不要把动态规划、复杂图算法这类 Hard 题刷到和通用软件岗一样深",比较合理的态度是下面哪一个? (A) 应该刷到底,因为算法面试不区分岗位,通用软件岗考多深前端就该考多深 (B) 完全不用碰,因为这类题目"不切实际",前端项目里根本用不到 (C) 不必刷到通用软件岗的深度,优先用 Blind 75 之类的精简清单和树、BFS/DFS 等更贴近 DOM 的主题打底,时间富余再看 Hard 题

正确答案是 (C)。源材料建议按重要性规划时间,并指出公司对前端候选人通常放轻松,Blind 75 这类精简清单加上树相关主题足以覆盖大部分场景。(A) 忽视了源材料指出的深度差异,把两类岗位的期待混为一谈;(B) 把"题目场景不切实际"错误地理解成"不需要学"——源材料说的是这些题目在现实开发里不会遇到同样的场景,但考察的分析思维、数据结构与算法功底仍然是前端工程师的关键技能,不能因此完全跳过。

  • Tech Interview Handbook · 算法编码面试准备分步指南 —— 对应"如何准备"一节提到的分步指南,规划时间、边学边练、搭配备忘单的具体做法都在这里。
  • Yangshun Tay 的 LinkedIn —— Blind 75 精简题目清单的策展人,想了解这份清单的定位和边界,可以从这里的背景信息入手。
