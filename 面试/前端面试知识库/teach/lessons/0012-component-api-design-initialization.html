组件 Props 怎么设计:初始化原则

上一课说到,UI 编程面试的复杂性,很大一部分从"数据结构与算法"转移到了"组件状态与 API 设计"上。这节课就从最靠前的一步拆开这句话:一个 UI 组件从不存在到能跑起来,历史上出现过哪几种初始化方式;给它设计 props(有的框架里叫选项、参数)时,又有哪几条看似琐碎、却直接决定这个组件好不好用的原则。

先回忆一下上一课(0011)里的那张评估维度表格:"复杂性主要来自哪里"这一行,算法编码面试写的是"数据结构与算法本身",UI 编程面试写的是"组件状态与 API 设计"。当时只给了个结论,没有展开。这节课要把"API 设计"具体拆开——面对一个组件,第一个绕不开的问题是:别人要怎么把它"造出来"?如果现在让你设计一个 slider(滑块)组件的初始化方式,你会让调用者传几个参数、分别是什么?先想一个答案,再往下看。

一、为什么这是"基本功",不是可选技能

像 Bootstrap 和 Material UI 这样的用户界面组件库,提供按钮、选项卡、模态框这类常用组件,是为了让开发者不必在每个新项目里从头搭一遍同样的东西,免得重复造轮子。

手册说得很直接:前端面试里经常会要求候选人现场构建 UI 组件,并为它设计一套用来初始化的 API。设计好的组件 API,被列为前端工程师的基本功——这也是为什么这节课把"怎么初始化"单独拎出来讲一整节,而不是把它当成实现细节里一个可以顺手带过的小分支。

二、三种初始化风格:根元素怎么传,选项怎么传

按 UI 技术演进的时间线,手册列出了三种主流做法。它们的差别主要体现在两件事上:组件要不要一个"根元素"参数、自定义选项怎么传进去。

jQuery 风格根元素 + 选项对象构造函数两个参数,选项可省略
Vanilla JS 风格没有官方标准,但趋同推荐参照 jQuery,函数签名 (rootEl, options)
React 风格只有选项(props)组件不接受根元素,渲染要另一套 API

在 React、Angular 和 Vue 这些现代框架出现之前,jQuery(和 jQuery UI)是构建 UI 最流行的方式。jQuery UI 推广了通过"构造函数"初始化组件的做法,一行代码就能把一个 DOM 元素变成滑块:

<div id="gfe-slider"></div>
<script>
  $('#gfe-slider').slider({
    animate: true,
    max: 50,
    min: 10,
  });
</script>

slider() 方法本身不需要显式传入根元素参数,因为 $('#gfe-slider') 这一步已经先选中了元素,slider() 只是对着这个"选中结果"执行操作——jQuery 整套 API 都建立在"先选一个元素、再对它做点什么"这个模式上,this 关键字在方法内部就指向被选中的元素。完整的可选项列表可以在jQuery UI 官方文档里查到。

Vanilla JavaScript 不是标准或框架,所以没有官方规定的初始化写法。但手册指出,如果读过足够多 vanilla JS UI 编码题的参考解法,会发现推荐的 API 和 jQuery 很接近——构造函数同样接受根元素和选项两个参数:

function slider(rootEl, options) {
  // 对 rootEl 和 options 做一些事情。
}

到了 React(或其他类似的基于组件的库),情况变了一层。React 强制把 UI 写成组件,组件本质上是"描述自己该怎么渲染"的函数,它接收的 props 本质上就是这个组件的自定义选项:

function Slider({ min, max }) {
  // 使用 props 渲染自定义组件。
  return <div>...</div>;
}

<Slider max={50} min={10} />;

但组件函数本身不接受根元素——要把它渲染到页面里某个具体的 DOM 节点上,需要另外一套 API:

import { createRoot } from 'react-dom/client';
import Slider from './Slider';

const domNode = document.getElementById('#gfe-slider');
// React 将管理此元素中的 DOM。
const root = createRoot(domNode);
// 在元素中显示 Slider 组件。
root.render(<Slider max={50} min={10} />);

如果整个页面本身就是一个 React 应用,通常不需要自己手写这段 createRoot() 调用,因为在根/页面级别一般只有一处这样的调用。

风格根元素怎么传自定义选项怎么传
jQuery不作为构造函数参数,靠先用选择器选中元素纯 JS 对象,作为构造函数参数,可整体省略
Vanilla JS作为构造函数第一个参数显式传入作为构造函数第二个参数,同样是纯 JS 对象
React组件函数不接受,由 createRoot 这类单独的渲染 API 负责作为 props 传给组件函数

三、选项("props")有一条容易被忽略的性质:默认值

三种风格讲完,能看出一条共性:不管叫"选项"还是"props",本质上都是"给组件的自定义配置"。手册在描述 jQuery UI 的自定义选项时,专门用了"可选的、额外的"这两个词来形容它——这不是随口一说,而是直接决定了调用者用起来省不省心。

默认值。上面 jQuery UI 示例里传的 animate/max/min 都是可选的——不传就用组件内部的默认值。这意味着大多数自定义选项都应该配一个"够用"的默认值,调用者只需要覆盖自己真正关心的那几个字段,而不是每次初始化都要把全部选项抄一遍才能用。

四、关键定义

自定义选项(Options / Props)
除了根元素(如果这种初始化风格需要的话)之外,用来定制组件行为和外观的可选配置——jQuery 风格里是传给构造函数的纯 JS 对象,React 里是传给组件函数的 props。避免把每个选项都设计成必填参数:大多数选项应该有合理默认值,调用者用不到就不用传。

现实中怎么用。面试现场被要求设计一个组件(比如 slider、tabs)的 API 时,可以按这节课的顺序过一遍:先确定用哪种初始化风格(如果题目限定用 React,根元素这一步直接省掉);再对着自己列出来的选项,逐个问自己"这个字段有没有默认值"——像 jQuery UI 的 slider 文档那样,把每个选项的名字和默认值列成一张表讲给面试官听,比边写代码边临时决定命名,更能体现你在主动设计 API,而不是只在拼凑功能。

一个容易踩的误区:把"能跑起来"当成 API 设计已经过关。两个常见的翻车方向:一是把每个可选项都做成必填参数,调用者哪怕只想要个默认样子的组件,也要把所有字段抄一遍才能用起来,违背了上面 animate/max/min 都可以不传的初衷;二是把 jQuery/vanilla 的心智模型直接搬到 React 上,以为组件函数本身也要接收根元素——却忘了 React 组件不接受根元素参数,渲染到哪个 DOM 节点由 createRoot 这类单独的 API 负责,和组件的 props 是两件不同的事。

今天就做的一件事:打开 jQuery UI 的 slider 选项文档,挑 3~5 个选项,给它们各设计一版对应的 React props——写出对应的 prop 名字和默认值,并说清楚哪些字段可以直接省略。

带走这一条:不管用哪种技术,组件初始化本质上都在回答同一个问题——根元素(如果需要)怎么传、自定义选项(props)怎么传;而选项设计得好不好,至少要看有没有给出合理默认值,让调用者不必为每个字段都手动传参就能用起来。

五、自测题

Q1:关于 jQuery 风格和 React 风格初始化组件的核心区别,下面哪个说法最准确? (A) jQuery 风格和 React 风格都要求先手动创建根 DOM 元素,并把它作为组件本身的第一个参数传入 (B) React 组件函数本身不接受根元素参数,渲染到页面上的哪个 DOM 节点,由 createRoot 之类的单独 API 负责 (C) React 的 props 和 jQuery 构造函数里的自定义选项本质上互不相关,是两种没有共同点的设计

正确答案是 (B)。React 组件不接受根元素,渲染发生在单独的一步——先拿到 DOM 节点,再用 createRoot 包一层,最后 root.render() 把组件塞进去。(A) 混淆了两种风格:jQuery 的 .slider() 不是把根元素当参数传入构造函数,而是先用选择器选中元素,根元素是隐式的;(C) 恰好弄反了——React 的 props 本质上正是 jQuery 自定义选项思路的延续,都是"给组件的可选配置",只是载体和传递方式不同,不是互不相关。

Q2:关于 jQuery UI 的 slider() 方法和它的自定义选项(如 animate/max/min),下面哪个说法最准确? (A) 这些选项本质上是可选的,不传就使用组件内部默认值,调用者只需要覆盖自己真正关心的字段 (B) 这些选项一旦在文档里列出来,就必须在每次调用 slider() 时全部显式传入,否则组件无法初始化 (C) 这套"可选项 + 默认值"的设计只存在于 jQuery 风格里,和 React 的 props 没有任何相似之处

正确答案是 (A)。手册把这些自定义选项形容为"可选的、额外的",这正是这节课"默认值"这条原则的出处——调用者只覆盖自己关心的字段,其余交给组件内部默认值兜底。(B) 恰好说反了:如果每个选项都是必填,animate/max/min 就不该被称为"可选";(C) 混淆了载体和思路——jQuery 构造函数的选项对象、React 的 props,都是"给组件的自定义配置",只是传递方式不同,思路是相通的,不是互不相关。

六、主推资源

本节内容对应综合面试手册这篇文章"初始化"一节里点名的几个组件库和文档,建议按下面顺序看:

  • jQuery UI · Slider —— 本节 jQuery 示例背后的完整选项文档,对照它的命名和默认值,练习给同一个组件设计一版 props。
  • jQuery UI —— 手册举例时引用的组件库官网,可以翻翻其他组件的构造函数怎么设计选项。
  • React —— 理解 props 作为"组件自定义选项"这套机制的官方文档。
  • Bootstrap —— 本节开篇提到的组件库范例之一,可以对照它公开的组件配置项,看成熟项目里命名和默认值长什么样。

有任何不清楚的,回到会话里问你的 AI 老师——可以让老师用 ELI5 讲清"props 和 jQuery 选项到底是不是一回事",也可以现场挑一个组件,让老师陪你把选项表和默认值走一遍。
