# 前端面试精读课建成并全量核验(46 节)

`面试/前端面试知识库/teach/` 从只有 SKILL.md + 4×FORMAT.md 的空脚手架,建成完整课程:46 节自成一体 HTML 微课(0001-0046)+ 门户 `index.html` + 自包含 `assets/style.css` + MISSION/NOTES/GLOSSARY(约 20 词)/RESOURCES。真实源是仓库本体自带的完整讲义——`前端系统设计/`(6篇)、`综合面试手册/`(10篇)、`行为面试手册/`(10篇)、`React面试手册/`(12篇)、`quiz题库/`(40道 h5bp 经典问答题)——不是像姊妹课程「工程领导力资源」那样只有一份扁平资源链接清单,而是可以直接读的完整正文,拆分密度按各源文件真实行数决定(如 `React面试手册/react-forms` 近 800 行,拆成 3 课)。

**这改变未来会话的什么**:教「前端工程师面试准备」走这门课,不要重建;它以仓库本体的五个目录为源(每节锚定具体源文件的具体行号区间),与 [[interview-prep-course]](编程面试大全,通用 DS&A + 系统设计面试)明确分工——通用算法刷题、通用系统设计方法论去那门课,本课只补前端特有的 HTML/CSS/浏览器 trivia、前端系统设计(RADIO 框架)、React 专题、前端向简历与行为面试。MISSION.md 的 Why 是首次生成时基于仓库自身内容起草的第一版草案,不是与用户当面访谈得出,下次真正开课时应先确认是否贴合用户本人处境(准备具体哪场面试、目标岗位、剩余时间)。

**建法(与 [[interview-prep-course]]、[[eng-leadership-course]] 相同的可复用套路,但引用密度更高)**:① 逐个探查五个源目录,实测每篇 mdx 的行数、h2 大纲、外链清单,而不是凭标题猜内容;② 手写并结构核验金标准 0001(锁定房屋风格:七件套装置沿用姊妹课程,新增一个本课专属的 `.codecompare` 代码并排对照装置,因为这门课比姊妹课程多得多真实代码示例);③ 46 课的精确 spec(brief+源文件+该课专属 URL 白名单+术语+prev/next)写进 Workflow 脚本 → 45 个 agent 走 build→verify 两阶段流水线(不设屏障,每课写完立刻被独立 agent 核验,不等其他课写完)。

**新教训 · Workflow 里单个 agent 的 API 中断不会自动重试,得手动补**:45 个 agent 的 pipeline 跑完后,`[build:0031] failed: API Error: Server error mid-response` ——第 31 课(受控/非受控表单)因为一次流式响应中断,build 阶段直接失败,对应的 verify 阶段也随之跳过,最终 44/45 完成、0031 文件从未落盘。这和之前记录的 [[workflow-resume-replays-writes]]是同一个工具的不同故障模式:那次是 resume 重放覆盖已有文件,这次是单个 agent 因外部 API 抖动直接失败、流水线不会自动补跑。**处理方式**:不需要对整个 45-agent 的 workflow 做 resume(避免重蹈 resume 覆盖已核验文件的覆辙),而是直接单独起两个前台 Agent(先 build 后 verify),严格复用同一份 build/verify prompt 模板,手动补齐这一课,再跑一遍全量结构核验确认它和其余 44 课在文件系统层面完全一致。

**新教训 · 局部修复容易漏改"引用它的邻居"**:0002 课在 verify 阶段被独立 agent 发现"标题写四道关卡、正文按五道关卡展开"的自相矛盾,已经修好了 0002 自身的 `<title>`/`<h1>` 和 `index.html` 里的锚文本,但漏改了 0001 课 footer 里指向 0002 的"下一课"链接文案、以及 0003 课 footer 里指向 0002 的"上一课"链接文案——这两处仍停留在旧的"四道关卡"措辞。这类 bug 的特点是:被改的文件本身没有问题,问题出在两个没被直接编辑、但内容里硬编码引用了它的邻居文件里。**教训**:凡是"改一个词条的规范说法"这类修改,必须在全量核验阶段专门跑一次 prev/next 链的文本一致性检查(不能只查文件名对不对,还要逐字比对链接文案是否和目标文件当前的真实标题一致),不能假设"改哪个文件就只影响哪个文件"。

**Evidence(核验结论)**:46/46 结构齐全(单样式表、`lang="zh-CN"`、favicon、div/dl/details 等全部标签配对、七件套装置各恰好 1 次、quiz 恰好 2 题且每题 3 个选项);prev/next 链 0001↔0046 首尾相连,逐节核对一开始有 2 处文本不一致(见上一条教训),已修复并二次核验全部清零;`<title>`/`<h1>` 与 `index.html` 锚文本逐字一致;全部 46 课的外部链接(总计约 200+ 条,含重复)逐条比对各自课程专属的 URL 白名单,零越界,零编造;MISSION/NOTES/GLOSSARY/RESOURCES 里的外链另行核对——RESOURCES.md 引用的 `patterns.dev`/`developer.mozilla.org` 根域名虽未在语料库里逐字出现,但语料库里大量子页面确实来自这两个真实域名,注释文本本身也如实说明是"具体页面均来自这两个域名"而非声称根链接本身出现过,判定为合理的编辑性引用而非幻觉;「唯一/总是/永远/绝对」等绝对措辞全语料库扫描,命中的全部落在 CSS 术语("绝对定位")、quiz 错误选项(被答案解析明确否定)、或否定句/场景描述里,未发现违规断言。

**已知限制,不要假装做过**:Playwright 浏览器连接在这次建课过程中仍是 `ECONNREFUSED`(和上一次建「工程领导力资源」课时同样的环境限制),只有金标准课 0001 做过结构性/标签配对核验,没有任何一课拿到过真实浏览器截图确认。下次接手,如果要做视觉核验,先确认 Playwright MCP 连接是否恢复。
