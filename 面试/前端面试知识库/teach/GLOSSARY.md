# 前端工程师面试 Glossary

覆盖前端面试的几种形式,以及 CSS/React/行为面试里反复出现的核心术语。术语只在对应课讲透之后才收进来。

## 面试形式

**Trivia 问答**:
不要求写代码、只考口头/文字问答的一类前端面试题,考察对 HTML/CSS/JS/浏览器底层知识的熟悉程度,常见于电话面或第一轮筛选。
_Avoid_: 八股文、基础知识题(本课固定用"trivia 问答")

**UI 编程面试**:
要求现场实现一个组件或页面片段的一类面试,考察点包括还原设计稿的准确度、状态管理、可访问性、边缘情况处理,不是纯算法题。
_Avoid_: 手写代码题(容易和算法编码面试混淆)

**前端系统设计面试**:
要求设计一个前端产品/应用整体架构的一类面试,侧重组件划分、数据模型、组件间接口、性能优化,和后端系统设计侧重的可用性/一致性/分布式取舍不同。
_Avoid_: 前端架构设计(本课固定用"前端系统设计")

**RADIO 框架**:
回答前端系统设计题的结构化框架,五步依次是需求探索(Requirements)、架构/高层设计(Architecture)、数据模型(Data Model)、接口定义(Interfaces)、优化与深入研究(Optimizations)。建议需求探索控制在整场时间的 15% 以内。
_Avoid_: 记完整单词全称(面试时按缩写 RADIO 记忆和推进即可)

## CSS 核心概念

**盒模型(Box Model)**:
浏览器计算一个元素占用空间的方式,由内容(content)、内边距(padding)、边框(border)、外边距(margin)四层组成。默认的 `content-box` 只把 `width`/`height` 用于内容大小;`border-box` 把 padding 和 border 也计入 `width`/`height`。
_Avoid_: CSS 盒子模型

**BFC(Block Formatting Context,块格式化上下文)**:
页面中一块独立的渲染区域,内部元素的布局(尤其是浮动元素的高度计算、外边距折叠)不会影响区域外部,常用来解决浮动元素撑不开父容器的问题。
_Avoid_: 块级格式化环境

**堆叠上下文(Stacking Context)**:
一组图层的容器,内部子元素的 `z-index` 是相对该容器计算的,而不是相对文档根元素;`opacity < 1`、非 `none` 的 `filter`/`transform` 等属性会触发新的堆叠上下文。`z-index` 只对非 `static` 定位的元素生效。
_Avoid_: z-index 层级(z-index 只是操作堆叠上下文内顺序的手段,不等于堆叠上下文本身)

**选择器特异性(Selector Specificity)**:
浏览器决定同一元素上多条冲突 CSS 规则谁生效的计算规则,按 `ID - CLASS - TYPE` 三档从左到右比较,`!important` 和内联样式的优先级高于特异性本身。
_Avoid_: CSS 优先级(优先级是更大的概念,特异性只是其中一环,`!important`/内联样式/源码顺序都在特异性之外起作用)

**移动优先(Mobile-First)**:
先为小屏幕设计和编写基础样式,再用媒体查询逐步为大屏幕叠加样式的策略,和"先做桌面版、再用媒体查询适配移动端"的响应式思路方向相反。
_Avoid_: 响应式设计(响应式是结果,移动优先是其中一种实现路径,二者不是同义词)

## React 核心概念

**受控组件(Controlled Component)**:
表单元素的值由 React state 持有并通过 props 传入,每次变化都经过 `onChange` 回调更新 state 再渲染回元素;与之相对的非受控组件让 DOM 自己持有值,通过 ref 在需要时读取。
_Avoid_: 双向绑定(那是 Vue 的术语,React 里受控组件的数据流是单向的)

**合成事件(SyntheticEvent)**:
React 包装原生 DOM 事件后传给事件处理函数的对象,跨浏览器行为一致,并且 React 用事件委托的方式统一在根节点监听,而不是给每个元素单独绑定原生事件。
_Avoid_: React 事件对象

**useEffect 依赖数组**:
`useEffect` 第二个参数,决定副作用函数在哪些值变化后重新执行;数组遗漏依赖是面试里最常被追问的错误来源之一。
_Avoid_: useEffect 的第二个参数(依赖数组是标准叫法)

**自定义 Hook(Custom Hook)**:
以 `use` 开头、内部调用其他 hook 的普通函数,用来把多个组件里重复的状态逻辑抽出来复用,但不共享 state 本身——每个调用它的组件仍各自拥有独立的状态。
_Avoid_: 自己封装的 Hook

**声明式 UI(Declarative UI)**:
描述"UI 在每种状态下应该长什么样",由框架负责计算如何从上一个状态过渡到下一个状态;与之相对的命令式 UI 要手动写"一步步怎么改 DOM"。React 组件的写法是声明式的。
_Avoid_: 响应式 UI(和"声明式"不是同一个维度的概念,不要混用)

## 行为面试

**STAR 法则**:
组织行为面试回答的结构:Situation(情境)、Task(任务)、Action(行动)、Result(结果),用来把"我做过什么"讲成一个具体、可验证的故事,而不是空泛的自我评价。
_Avoid_: STAR 原则、STAR 模型(本课固定用"STAR 法则")
