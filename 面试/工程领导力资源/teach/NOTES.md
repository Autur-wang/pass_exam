# NOTES · 教学偏好与工作区约定

## 学习者画像与授课方式
- 本课与 `../../编程面试大全/teach/` 同批建成,授课方式沿用仓库教学人设**交互式推进**:先让学习者复述当前理解 → 补缺 → 用 AskUserQuestion 出选择题校验(打乱正确项位置,答前不公布答案)。
- 难度基线=**均衡**:每节前半建场景直觉,后半落到「现实中怎么用」。不假设读者已带过团队,但也不从「什么是经理」讲起。
- **不要一次讲满**:一节课只攻一个窄主题;讲课时按阶段确认掌握再推进,不要把整节 HTML 一口气念完。
- 首次生成时 `MISSION.md` 的 Why/Success 是基于 README.md 自述的宗旨(「投资自己,成为 2026 年及以后的优秀工程领导者」)起草的**第一版草案**,不是与学习者本人访谈得出——下次真正开课时,应先确认这份 Mission 是否贴合学习者本人的实际处境(是在准备晋升?正带团队卡在某个具体问题?还是单纯的职业规划?),据实修订并补一条学习记录。

## 房屋风格(House Style)—— 每节课必须遵守
- 每节是**自成一体的 HTML**,放 `./lessons/`,命名 `NNNN-dash-case-topic.html`,编号递增。
- `<head>` 只 link **一个**样式表:`../assets/style.css`(自包含,零外部依赖);另加 `<link rel="icon" href="data:,">` 抑制 favicon 请求;`<html lang="zh-CN">`。
- **零外部资源**:不引 CDN、外部字体、远程图片、YouTube 内嵌。图示一律用内联 SVG 或 CSS 组件(见 style.css 的 `.pipeline`/`.flow`/`.bars`/`.trio`/`.dgm-*`)。外部一手资源只以**正文超链接**形式出现。
- 每节结构:`.meta` 页眉 → `h1` → `.lede` → `.recall`(先回忆,承上一课)→ 场景直觉+图 → `.keydef` 关键定义 → `.apply` 现实中怎么用 → `.pitfall` 常见误区 → `.practice` 今天就做的事 → `.good` 带走这一条 → `.quiz`(≥2 题,答案打乱位置)→ 主推资源(引 README 里**真实收录**的书/文章/newsletter)→ `footer.lesson-footer` + `.lesson-nav` 上下课导航。
- 本课的装置命名与「编程面试大全」不同(`.apply` 替代 `.interview`,`.pitfall` 替代 `.gotcha`,`.practice` 替代 `.implement`,`table.compare` 替代 `table.bigo`)——因为本课教的是判断力与框架,不是可判定对错的算法性质。装置背后的学习科学原理相同(retrieval practice / 对抗 fluency 错觉的动手环节 / 跨课锚点实现 interleaving),见 SKILL.md「Fluency vs Storage Strength」。

## 反幻觉纪律(本课的具体形态)
- 领导力判断没有「唯一正确答案」,更容易出现「听起来很有道理但是编的」——**每个具体建议都要能挂到 `RESOURCES.md` 里的真实书目/文章**,挂不上就不要写成断言,改写成「一种视角」并注明这是常识性框架而非该来源原话。
- 引用的文章标题/链接必须是 `../README.md` 里**真实收录**的那条,不要编造 URL、不要编造未收录的书名。
- 「唯一/永远/最好」这类绝对措辞是幻觉指纹——管理没有银弹,写下前想一个反例(例:「倍增器」框架不是对所有团队都适用,初创团队和成熟团队的最优管理方式不同)。

## 与其他 workspace 的边界
- 本课以 `../README.md` 的资源清单为源,教「如何成为工程领导者」这条主线。与 `../../编程面试大全/teach/`(通用 DS&A + 系统设计面试)互不共用装置与术语——系统设计的具体解题去那门课,本课只讲「领导者为什么要懂」。
- 与 `operating_systems/`(OS 期末)、`agent开发/` 三门课也互不共用装置与术语,别混。
