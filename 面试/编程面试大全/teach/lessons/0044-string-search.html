字符串搜索:朴素到 KMP

「在文本 T 里找模式串 P 第一次出现的位置」——这是 strStr / indexOf 背后的问题。朴素法一眼就会写,但它把主串指针反复往回拉,做了大量重复比较。这节课讲清朴素法浪费在哪,以及 KMP 凭什么能让主串指针「只进不退」,把最坏 O(nm) 压到 O(n+m)。

先回忆哈希表那节:哈希函数把任意数据压成一个整数指纹,让「相等判断」变得极快。等下你会看到,同一个想法可以用来做子串匹配——把一个窗口的字符串滚成一个哈希值,这就是 Rabin-Karp。先想想:如果两个窗口哈希值相等,能直接断定字符串相等吗?

一、问题:子串匹配到底在算什么

给定长度为 n 的文本 T 和长度为 m 的模式 P(通常 m ≤ n),要找出 P 在 T 里出现的位置。朴素做法:把 P 对齐到 T 的每一个起点,逐字符比对;一处不匹配,就把 P 整体右移一格,从头再比。

失配处的信息其实被浪费了:我们已经知道文本这一段是 ABAB。朴素法却装作没见过,退回去逐格重比。当文本和模式充满重复前缀时(如 AAAA…A 找 AAAB),这种重比在每个起点都发生,总代价逼近 O(nm)。

二、KMP:主串指针只进不退

KMP(Knuth-Morris-Pratt)的洞察是:失配时,不该把主串指针 i 往回拉,而该只挪动模式指针 j。挪到哪?挪到「已匹配的那段前缀里,最长的、既是前缀又是后缀的那部分」的末尾——这个长度由预先算好的 next 数组(也叫失配函数 / LPS,最长公共前后缀)给出。

为什么 i 可以不退?因为失配前那段文本我们完全掌握——它等于模式的前 j 个字符。模式右移后要重新对齐的部分,答案早就藏在「前缀=后缀」的重叠里。next 数组把这个重叠预计算出来,查表就能跳,不用回头再看文本。主串每个字符至多被「命中前进」一次、被「回跳触发比较」常数次,于是匹配阶段是 O(n),加上构建 next 的 O(m),合计 O(n+m)。

顺带认识两个亲戚:Rabin-Karp 用滚动哈希,把每个长度 m 的窗口 O(1) 更新出哈希值,哈希相等再逐字符确认,平均 O(n+m),擅长多模式匹配和「最长重复子串」;Boyer-Moore 从模式尾部往前比、失配时能一次跳过很多字符,实际文本里常常亚线性,是 grep 等工具的底子。

三、关键定义

模式 / 文本(pattern / text)
要找的短串叫模式 P(长 m),被搜索的长串叫文本 T(长 n)。子串匹配即求 P 在 T 中的出现位置。
next 数组 / 失配函数(LPS)
对模式的每个前缀,预计算「最长的、既是它真前缀又是它真后缀的子串」的长度。失配时模式指针据此回跳,是 KMP 免于回退主串的核心。避免把它和「跳表」「后缀数组」混为一谈。
滚动哈希(rolling hash)
把定长窗口的字符串映射成整数,窗口右移一位时用 O(1) 增量更新,而非重算整段。Rabin-Karp 用它做候选筛选。

四、复杂度

算法预处理匹配 平均匹配 最坏
朴素法(brute force)无O(n+m)~O(nm)O(nm)
KMPO(m)O(n)O(n) (+m 预处理)
Rabin-KarpO(m)O(n+m)O(nm) (哈希全冲突)
Boyer-MooreO(m+σ)亚线性(常见)O(nm) (经典版)

空间上 KMP 需要 O(m) 存 next 数组。注意最坏栏:朴素法与 Rabin-Karp 在极端输入下都会退化到 O(nm),别把它们当成稳定 O(n)。KMP 是唯一在最坏情况也保证线性的常见算法。

面试怎么考。直接考「手写 strStr/indexOf」的机会其实不多,但相关套路很密集:

  • 让你实现子串查找:先写朴素法讲清 O(nm),再说「可以用 KMP 优化到 O(n+m)」——能讲出「主串指针不回退」这一句,就赢过大多数只会背名字的人。
  • 滚动哈希题:「最长重复子串」「判断字符串旋转」「多模式匹配」常用 Rabin-Karp;哈希相等后必须逐字符复核以排除碰撞,这是加分点。
  • 被追问原理:面试官爱问「KMP 为什么快」。答:朴素法丢掉了已匹配信息,KMP 用 next 数组把这段信息复用,使主串每个字符只被扫常数次。

「朴素法是 O(n)」——错。它最坏是 O(nm),典型触发输入是大量重复字符(如 T="AAAA…A"、P="AAA…B")。面试里说朴素法复杂度时务必带上「最坏 O(nm)」。

next 数组构建极易写错。它本质是「模式自己和自己做一次 KMP」:边界(next[0] 通常记 0 或 -1,取决于约定)、回跳条件、下标是「已匹配长度」还是「当前位置」——这些细节一处不一致就死循环或漏匹配。写之前先把约定钉死,再在纸上跑 ABABC 验证。

动手清单:

1. 写朴素 strStr(T, P),返回首次出现下标或 -1。用 T="mississippi"、P="issip" 验证,并打印总比较次数。

2. 写 buildNext(P) 生成 next 数组,对 P="ababc" 手算一遍再和程序对照。

3. 用 next 数组写完整 KMP,喂它一个「全 A + 尾部一个 B」的对抗输入,对比朴素法的比较次数——亲眼看 O(nm) 塌成 O(n)。

4. 选做:写 Rabin-Karp,记得哈希命中后逐字符复核。

带走这一条:字符串匹配的一切加速,本质都在「不重复扫已经看过的文本」。KMP 用 next 数组记住已匹配前缀,让主串指针只进不退,于是 O(nm) → O(n+m)。

五、自测题

Q1:KMP 相比朴素法,把复杂度从 O(nm) 降到 O(n+m),最核心的原因是下面哪一个?

失配时主串指针 i 从不回退,只回跳模式指针 j。朴素法每次失配都把 i 拉回起点附近重扫,浪费了「已匹配前缀」这一信息;KMP 用预计算的 next 数组把这段信息复用,使文本每个字符只被扫常数次。干扰项「因为用了哈希」说的是 Rabin-Karp;「因为从尾部比」说的是 Boyer-Moore——都不是 KMP 的机制。

Q2:用 Rabin-Karp 做子串查找,某个窗口的滚动哈希和模式的哈希相等。下一步应该?

逐字符复核这个窗口是否真的等于模式。哈希相等只说明「可能相等」,不同字符串可能碰撞到同一哈希(假阳性)。不复核就直接报命中,遇到碰撞会给出错误答案;正因为存在碰撞,Rabin-Karp 最坏可退化到 O(nm)。这与后面布隆过滤器「可能存在需复核、一定不存在可信」的思路同源。
