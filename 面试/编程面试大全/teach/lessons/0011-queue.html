队列与环形缓冲区

队列和栈是一对反义词:栈后进先出,队列先进先出(FIFO),像排队买票,先来的先走。规矩变一个字,应用场景就全换了——BFS、生产者消费者、任务调度都是它的地盘。这节课的重点是它的高效实现:用数组做队列,如果每次出队都往前搬一格就退化成 O(n),环形缓冲区正是绕开这个坑、把入队出队都钉在 O(1) 的关键设计。

先回忆:上一课栈是「一摞盘子」,只在同一端进出(LIFO)。队列反过来——一端进、另一端出。先想想:如果拿数组实现队列,把「队尾」放在数组末尾、「队头」放在数组开头,那么出队一个元素后,剩下的元素要不要整体往前挪?这一挪是多少复杂度?

一、直觉:排队的两头

队列有两个操作端:队尾入队(enqueue)、队头出队(dequeue)。最先入队的元素最先出队。用带尾指针的链表实现最直接:head 指队头(出队),tail 指队尾(入队),两头各改几个指针,都是 O(1)。仓库特意提醒:如果用链表却没有尾指针,每次入队都要从 head 走到末尾找插入点,就退化成 O(n)。

二、用数组做队列:为什么需要「环形」

数组实现的天真做法:队头固定在下标 0,出队后把后面所有元素往前搬一格——这一搬就是 O(n),队列越长越慢。环形缓冲区(circular buffer)的思路是:不搬元素,搬指针。用两个下标 head(读)和 tail(写)在固定大小的数组里游走,走到末尾就用取模绕回开头 (i + 1) % capacity,把这块线性内存当成首尾相接的环来用。入队、出队都只动一个下标,恒 O(1)。

三、关键定义

队列(Queue)
先进先出(FIFO)的线性结构,一端入(enqueue)另一端出(dequeue)。避免:用「栈」泛指所有线性容器。
环形缓冲区(Circular Buffer / Ring Buffer)
用固定大小数组 + head/tail 两个下标取模绕回实现的队列,入队出队 O(1) 且不搬移元素。避免:与「会扩容的动态数组队列」混同。
FIFO(First In, First Out)
队列的核心序:最先进入的最先离开——与栈的 LIFO 相对。

四、复杂度:两种好实现都是 O(1)

操作平均 / 摊还最坏
enqueue (带尾指针链表 / 环形数组)O(1)O(1)
dequeueO(1)O(1)
front / peek · emptyO(1)O(1)
enqueue (朴素链表,无尾指针)O(n)O(n)

关键在「怎么实现」:带尾指针的链表、或环形数组,入队出队都 O(1);而「无尾指针的链表」或「出队后整体前移的数组」都会滑到 O(n)。仓库大纲白纸黑字地写了这条对比,面试也常拿它区分「记住结论」和「懂原理」的人。

面试怎么考。队列本身是很多算法的载体,考点常藏在它承载的算法里:

  • BFS 的骨架:图/树的广度优先遍历、无权图最短路径,全靠一个队列「逐层扩展」——把当前层出队、把下一层入队。看到「逐层」「最短步数」就该想到队列。
  • 用两个栈实现队列:一个栈管入、一个栈管出,出栈空了就把入栈整批倒过去。均摊分析下每个元素最多被搬两次,摊还 O(1)——经典追问题。
  • 环形队列的判满 / 判空:当 head == tail 时,到底是空还是满?两种标准解法:留一格不用(牺牲一个槽,满的条件是 (tail+1)%cap == head),或额外维护一个计数 count。答不清这个,就说明没真正实现过环形队列。

数组队列不用环形,就会 O(n)。「队头固定在 0、出队后所有元素前移」是初学者最常写的错法,每次出队都搬一遍,退化成 O(n)。正解是环形缓冲区——移动下标而非移动数据。

判满 / 判空条件极易写错。空队列 head == tail,可写满后head 又会追上 tail,同样 head == tail,两种状态撞在一起。必须靠「留一格」或「count 计数」来区分,否则会出现「以为空其实满」的隐蔽 bug。

带走这一条:队列 = FIFO。用数组实现时,记住四个字——搬指针,别搬数据:环形缓冲区靠 head/tail 取模绕回,把入队出队都锁死在 O(1)。而只要看到「逐层 / 最短步数 / 先到先服务」,答案里多半就站着一个队列。

照仓库大纲把队列的两种实现都写一遍,亲手对比:

① 带尾指针的链表版:enqueue(v)(尾部加)· dequeue()(头部删)· empty(),确认都是 O(1);② 固定大小数组的环形版:enqueue / dequeue / empty / full,用取模绕回,并用「留一格」或「count」解决判满/判空。

进阶:用两个栈实现一个队列,并说清为什么它是摊还 O(1)。

五、自测题

Q1:环形队列里,head == tail 既可能表示「空」又可能表示「满」。怎么区分这两种状态?

两种标准做法。(a) 留一格不用:规定队列最多存 capacity − 1 个元素,于是「空」是 head == tail,「满」是 (tail + 1) % capacity == head——两者不再重合,代价是浪费一个槽。(b) 额外维护 count:记录当前元素个数,count == 0 为空、count == capacity 为满,不浪费槽但多存一个变量。二选一即可,关键是别让「空」和「满」共用同一个判据。

Q2:为什么 BFS 用队列、DFS 用栈?换过来会怎样?

因为两种遍历的「下一个该访问谁」的策略正好对应两种容器。BFS 要逐层扩展:先访问的节点,其邻居也该先被访问——这是先进先出,正是队列。DFS 要一条路探到底再回退:最后发现的节点最先深入——这是后进先出,正是栈(递归则用系统调用栈)。如果 BFS 错用栈,遍历顺序就变成了 DFS 的深度优先;容器选错,算法的性质就变了——这也呼应术语表那句「BFS 和 DFS 不只是顺序不同」。
