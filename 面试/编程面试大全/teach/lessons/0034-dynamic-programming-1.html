动态规划(上):状态与递推

很多人怕 DP,是因为它被讲得太玄。其实 DP 只是「把重复计算的递归,改成算一次就记下来」。这节课用斐波那契和爬楼梯,把一条最重要的路走通:暴力递归 O(2ⁿ) → 记忆化 → 递推表 O(n),并交给你一套「定义状态 → 写递推 → 定 base → 定顺序」的四步流水线。

先回忆:上上课递归里,朴素递归斐波那契是 O(2ⁿ),慢的根源是递归树里同一个 fib(k) 被反复重算——也就是重叠子问题。这节课要做的,本质就是「把那棵树里重复的节点,只算一次」。试着先自己说:如果每个 fib(k) 只算一次,总共要算多少次?

一、DP 的两个前提:缺一个都不能用

不是所有问题都能上 DP。必须同时满足两条:

  • 重叠子问题:递归展开时,同一个子问题被反复求解(斐波那契就是)。这决定了「缓存」有意义——不重叠就没东西可省(那是分治)。
  • 最优子结构:大问题的最优解,可以由子问题的最优解拼出来。这决定了「递推」成立——否则子问题的解拼不出父问题。

记住这句判据:重叠子问题 → 值得缓存;最优子结构 → 能写递推。两者都有,才是 DP 的地盘。

二、一条主线:同一个斐波那契,三种写法

② 记忆化(自顶向下,memoization):代码形态还是递归,只加一个缓存——进函数先查「这个子问题算过没?算过直接返回」。它是「递归 + 缓存」,写起来最接近你已有的递归直觉。

③ 递推表(自底向上,tabulation):干脆不用递归,开一个数组 dp[],从最小的子问题开始顺着填,填到目标。以爬楼梯为例(每次走 1 或 2 阶,问到第 n 阶有几种走法),dp[i] = dp[i-1] + dp[i-2]:

三、四步流水线:任何 DP 都这么想

① 定义状态:dp[i] 到底表示什么?(如「到第 i 阶的走法数」)——定义必须无歧义、含全部维度。
↓
② 写递推关系(状态转移方程):dp[i] 怎么由更小的状态算出?(dp[i]=dp[i-1]+dp[i-2])
↓
③ 定 base case:最小状态的值是多少?(dp[0]=1, dp[1]=1)
↓
④ 定遍历顺序:按什么顺序填,才能保证算 dp[i] 时它依赖的状态都已算好。

README 反复强调的一句忠告:先看足够多的例子,建立「模式感」,再谈套路。第 ① 步「定义状态」是最难也最关键的一步——状态定错,后面全错。

四、关键定义

动态规划(DP, Dynamic Programming)
把有重叠子问题且满足最优子结构的问题,通过定义状态与递推关系、缓存子问题解来求解。避免把任何用了数组缓存的做法都叫 DP;避免把 DP 与「分治」混同(分治子问题不重叠)。
状态(State)
用来唯一刻画一个子问题的变量组合,即 dp[...] 的下标含义。维度不全会导致递推写不出或写错。
状态转移方程(Recurrence)
把当前状态的解用更小状态的解表达出来的等式,是 DP 的核心。
记忆化 vs 递推(Top-down vs Bottom-up)
记忆化=递归 + 缓存,自顶向下、按需计算;递推=开表自底向上填。两者复杂度同级,取舍看代码习惯与是否需要全部子问题。

五、复杂度:斐波那契的三种写法对比

做法时间空间
① 朴素递归O(2ⁿ)O(n) (栈)
② 记忆化(自顶向下)O(n)O(n) (缓存 + 栈)
③ 递推表(自底向上)O(n)O(n) (dp 数组)
③′ 递推 + 滚动变量O(n)O(1)

一般规律:DP 的时间 = 状态总数 × 每个状态的转移代价。斐波那契有 n 个状态、每个转移是常数,所以 O(n)。空间上,如果 dp[i] 只依赖最近几个状态,就能用几个变量替代整张表——这就是③′的滚动思想,下一课会正式讲滚动数组。

面试怎么考。正如 README 所说:面试不一定真让你写出 DP,但能识别「这题该用 DP」比会套模板更重要:

  • 信号词:「求方案数」「求最大/最小值」「能否达到某目标」,并且当前决策会影响后续、子问题明显重叠——大概率是 DP。(对比:「列出所有…」是回溯。)
  • 标准答题顺序:先口述「我定义 dp[i] 为…」,再写状态转移方程,再定 base 和遍历顺序,最后才敲代码。先方程后代码能让面试官看到你的思路,也大幅降低写错的概率。
  • 先暴力再优化的展示法:主动说「朴素递归是 O(2ⁿ),因为子问题重叠;加记忆化降到 O(n)」——这条演化叙事几乎是加分固定项。

坑一:把「用了数组」都叫 DP。DP 的判据是重叠子问题 + 最优子结构 + 状态转移,不是「开了个数组」。前缀和、双指针也用数组,但它们不是 DP。术语用错会被认为概念不清。

坑二:状态定义漏维度。如果子问题其实还取决于「已经用了几次」「上一个选的是什么」,而你只用了一维 dp[i],递推就会算错却很难发现。状态必须包含决定子问题结果的所有信息。

坑三:base case 和边界错。爬楼梯 dp[0] 该是 1(什么都不走算一种)还是 0?数组开多大、从哪个下标起填、循环边界是 <n 还是 <=n——这些一步错、满盘错。写完拿最小样例手动跑一遍是必须的。

就用这三道把「暴力→记忆化→递推」走通,亲手看复杂度塌下来:

斐波那契:先写朴素递归并计数调用次数 → 加缓存的记忆化版 → 自底向上递推版 → 滚动变量 O(1) 空间版,四版跑同一个 n,对比耗时。

爬楼梯(LeetCode 70):写出 dp[i]=dp[i-1]+dp[i-2],注意 base。零钱兑换 · 求最少硬币数(322):体会「多维选择的转移」——dp[amount]=min(dp[amount-coin]+1),并想清「凑不出」怎么表示。

带走这一条:DP = 有重叠子问题的递归 + 把每个子问题只算一次。解题永远按「定义状态 → 写状态转移方程 → 定 base → 定顺序」四步走,先写出方程再写代码。

六、自测题

Q1:一个问题满足什么条件,才「值得」用动态规划?

同时满足「重叠子问题」和「最优子结构」。

重叠子问题(同一子问题被反复求解)让缓存变得有意义——若子问题互不重叠,缓存省不下任何东西,那属于分治。最优子结构(大问题最优解可由子问题最优解拼出)让状态转移方程成立——否则子问题的解拼不出父问题。缺任何一条,DP 都不适用。注意:「能写成递归」或「用了数组」都不是 DP 的充分条件。

Q2:记忆化(自顶向下)和递推表(自底向上)相比,下面哪个说法正确?

正确的是:「两者时间复杂度同级,都把每个子问题只算一次;记忆化是递归 + 缓存,递推是开表顺着填。」

常见错误说法:「递推一定比记忆化快一个量级」——不对,两者同级,递推通常只是省掉递归调用的常数开销、且更容易改成滚动数组省空间。另一个错误:「记忆化不算 DP」——记忆化就是 DP 的自顶向下形态。选哪种多是代码习惯和「是否需要全部子问题解」的问题。

Q3:朴素递归斐波那契 O(2ⁿ),加了记忆化后为什么变成 O(n)?

因为加缓存后,每个不同的子问题 fib(0)…fib(n) 只被真正计算一次,共 n+1 个,之后所有对同一子问题的调用都直接命中缓存 O(1) 返回。递归树里原本指数级的重复节点,被缓存「短路」掉了,实际计算的节点数从 ~2ⁿ 降到 ~n。这正是「重叠子问题」被消除的直接效果——代码形态没变(还是递归),只是不再重复劳动。
