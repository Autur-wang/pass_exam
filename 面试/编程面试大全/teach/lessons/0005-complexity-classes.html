常见复杂度类:从 O(1) 到 O(2ⁿ)

上一课你学会了「只看增长率」的思维方式。这节把它落成一张可以背下来的清单：面试里真正常见的六七个复杂度类各自长什么样、从哪来、能扛多大的 n。学完你能做一件很值钱的事——看一眼输入规模，就反推出面试官期望的复杂度。

先回忆：上一课的「翻倍测试」——n 变 2 倍，工作量变几倍，就落在哪条曲线上。先自己填：n 翻倍工作量不变是 ____ 类；翻倍就翻倍是 ____ 类；翻倍变 4 倍是 ____ 类。填得出来，这节就是给这几类配上「从哪来」和「能扛多大」。

一、七个类,各有各的典型来源

复杂度类不是凭空记的——每一类都对应一批你一眼能认出的代码形状。看到那个形状，复杂度就出来了：

  • O(1) 常数：不随 n 变。哈希表查一个键、按下标取数组第 i 个、算术运算。
  • O(log n) 对数：每一步把问题砍掉一半。二分查找、在平衡二叉搜索树里查找、堆的插入/弹出。
  • O(n) 线性：把每个元素看一遍。一重循环扫数组、遍历链表。
  • O(n log n) 线性对数：好排序的门槛。归并排序、堆排序、快排（平均），以及「排序 + 一遍扫描」的套路。
  • O(n²) 平方：双重循环、每个元素和其余每个元素两两比。朴素排序（冒泡/选择/插入）、朴素两两配对。
  • O(2ⁿ) 指数：枚举所有子集——每个元素「选或不选」。朴素求幂集、不剪枝的回溯。
  • O(n!) 阶乘：枚举所有排列——朴素解旅行商、生成全排列。

「可承受 n」是经验数量级，不是硬阈值——它假设每次操作是常数时间、机器每秒约做 10⁸ 次。重点不在记死数字，而在建立一种反射：题目给的 n 一出来，脑子里就该跳出「哪些复杂度还活着、哪些已经出局」。

四、关键定义

复杂度类(Complexity Class)
一组增长率相同的算法的归类，如 O(n)、O(n log n)。面试里你选算法，本质就是在选让自己落进哪个类。
O(n log n) 门槛
比较排序的理论下界是 Ω(n log n)——只靠两两比较，没法比这更快。所以「先排序」这一步的成本天然是 O(n log n)，是很多解法的基准线。
指数级(O(2ⁿ) / O(n!))
随 n 爆炸式增长、n 稍大就跑不动的一类。只有当输入很小（n 约 ≤ 20），或题目本质无多项式解时，它才是可接受的答案。

面试怎么考。这节最实用的产出，是把「输入规模」当成面试官悄悄给的提示来读:

  • n ≤ 20 左右：指数级 / 阶乘可接受——大概率是回溯、状压 DP、子集/排列枚举类问题。
  • n ≤ 1000~2000：O(n²) 能过——放心用双重循环、区间 DP 这类平方解法。
  • n ≥ 10⁵：必须 O(n log n) 以内——排序、二分、哈希、单调栈/双指针，把 O(n²) 的暴力砍掉。
  • n ≥ 10⁷~10⁸：基本只剩 O(n) 或 O(log n)——一遍扫描、哈希、前缀和。

面试时把这个反推说出声：「n 到 10⁵，O(n²) 会超时，所以我要找 O(n log n) 的做法」——这句话本身就是加分项。

坑一:纠结对数的底。O(log₂n)、O(log₁₀n)、O(ln n) 在大 O 里是同一个 O(log n)——换底只差一个常数因子（logₐn = log_b n / log_b a），而常数在大 O 里一律抹掉。所以别在面试里认真区分「以 2 为底还是以 10 为底」，那说明没抓住大 O 的要点。

坑二:把 O(n log n) 当成 O(n)。那个 log n 因子是实打实的额外一档——n=10⁶ 时它约是 20 倍。「排序后再扫一遍」是 O(n log n)，不是 O(n)；只有当你能用哈希或计数把排序省掉，才真降到 O(n)。混淆这两类，等于把一道题的目标复杂度记错了一档。

动手核对：给自己出五道「看规模猜复杂度」的闪卡，正面写一个约束、背面写目标复杂度与典型手段，反复抽背——① n≤18；② n≤500；③ n≤2000；④ n≤2×10⁵；⑤ n≤5×10⁷。抽到能脱口而出「哪些复杂度出局、该往哪个方向想」才算过关。再挑一道你做过的题，回看它的 n 约束，验证当初的解法复杂度是否正好卡在容许线内。

带走这一条：每个复杂度类都对应一种能一眼认出的代码形状；而题目给的 n，就是面试官在告诉你「答案该落在哪个类里」。看规模、反推复杂度，再选算法。

五、自测题

Q1:一道题 n 最大到 2×10⁵，时限 1 秒。下面哪种复杂度最可能超时?

正确答案是 O(n²)。n=2×10⁵ 时 n² = 4×10¹⁰，远超 1 秒能做的约 10⁸ 次操作，必然超时。O(n log n) 约 2×10⁵×18 ≈ 4×10⁶、O(n) 约 2×10⁵，都轻松过。
这题的用意就是那条反推法：n≥10⁵ 时 O(n²) 出局，必须做到 O(n log n) 以内。看到这个规模，第一反应就该是排序、二分、哈希或双指针。

Q2:「因为我的二分用的是以 2 为底的对数，所以比别人以 10 为底的 O(log₁₀n) 更快。」这话对吗?

不对。对数的底在大 O 里不重要——log₂n 和 log₁₀n 只差一个常数因子（约 3.32 倍），而大 O 抹掉一切常数，两者都是 O(log n)、属于同一个复杂度类，谈不上谁「更快」。
会纠结底数，恰恰暴露了没吃透大 O 的核心：它比较的是增长率的量级，不是带系数的精确值。

Q3:题目说「n 最多 16，求所有满足条件的子集」。你该优先往哪个方向想?

优先想指数级枚举 / 回溯 / 状压——n=16 意味着子集只有 2¹⁶ = 65536 个，全枚举完全跑得动。这么小的 n + 「所有子集」的措辞，是在明示 O(2ⁿ) 这一档是被允许的。
反面提醒：如果你在 n=16 的题上死磕「怎么优化到多项式」，多半是想复杂了——小 n 常常就是让你放心暴力的信号。
