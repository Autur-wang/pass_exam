动态规划(下):经典模型与优化

上一课把「暴力递归 → DP」这条主线走通了。但面试里真正拉开差距的,是认出眼前这道题属于哪个经典模型——因为大多数 DP 题都是四五个母题的变形。这节课过四个必会模型(0/1 背包、LCS、编辑距离、LIS),讲清二维 DP 的表格思维,以及怎么用滚动数组把空间从 O(n²) 压到 O(n)。

先回忆:上一课动态规划(上)给了四步流水线——定义状态、写状态转移方程、定 base、定遍历顺序;还有一句「DP 时间 = 状态数 × 每状态转移代价」。这节的每个模型,你都可以拿这四步去套。先自己想:如果状态从「一维 dp[i]」变成「二维 dp[i][j]」,状态数变成多少?

一、二维 DP:从一条线到一张表

上一课的斐波那契只有一维状态。但很多问题要同时盯住两个下标——比如比较两个字符串时,得知道「word1 看到第 i 个、word2 看到第 j 个」这个组合的答案。于是状态变成 dp[i][j],填的不再是一行,而是一张二维表格。绝大多数字符串 DP(LCS、编辑距离、序列比对)都是这个套路。

二、编辑距离:二维表怎么填(README 明确点名)

编辑距离(Edit Distance / Levenshtein):把字符串 A 改成 B,最少需要几次「插入 / 删除 / 替换」。这是 README 里 Skiena 专门用两讲讲的模型。状态 dp[i][j] = 「A 的前 i 个字符」变成「B 的前 j 个字符」的最少操作数。转移只看三个邻居:

  • 若 A[i]==B[j]:不用操作,dp[i][j] = dp[i-1][j-1](左上角直接抄过来);
  • 否则 dp[i][j] = 1 + min( dp[i-1][j](删), dp[i][j-1](插), dp[i-1][j-1](替))。

三、其余三个必会模型

0/1 背包(0/1 Knapsack)
n 件物品各有重量和价值、每件只能选或不选,容量 W 下求最大价值。状态 dp[i][w]=前 i 件、容量 w 时的最大价值;转移 = 「不选第 i 件 dp[i-1][w]」与「选它 dp[i-1][w-wᵢ]+vᵢ」取大。是「选 / 不选」型 DP 的母题。
最长公共子序列(LCS, Longest Common Subsequence)
两串里都出现、且顺序一致(可不连续)的最长子序列长度。A[i]==B[j] 时 dp[i][j]=dp[i-1][j-1]+1,否则取 max(dp[i-1][j], dp[i][j-1])。与编辑距离是「亲戚」。避免把子序列(可不连续)和子串(必须连续)混为一谈。
最长递增子序列(LIS, Longest Increasing Subsequence)
一个序列里最长的严格递增子序列长度。基础 DP 是 O(n²);另有贪心 + 二分的 O(n log n) 经典优化。

四、优化:滚动数组把空间压下来

观察编辑距离的转移——dp[i][j] 只用到第 i 行和第 i-1 行,根本用不到更早的行。既然如此,没必要存整张 O(mn) 的表,只留「上一行 + 当前行」两行,甚至压成一行滚动更新,空间就从 O(mn) 降到 O(n)。这就是滚动数组(rolling array)。0/1 背包同理:把二维 dp[i][w] 压成一维 dp[w],但要倒序遍历容量,否则会把「同一件物品」重复选进去。

五、复杂度:四个模型一张表

模型时间空间(滚动优化后)
0/1 背包O(n·W)O(W)
最长公共子序列 LCSO(m·n)O(min(m,n))
编辑距离O(m·n)O(min(m,n))
最长递增子序列 LIS(基础 DP)O(n²)O(n)
最长递增子序列 LIS(贪心 + 二分)O(n log n)O(n)

注意 0/1 背包的 O(n·W) 是伪多项式——它随容量数值 W 增长,而 W 的编码长度是 log W,所以严格说不算多项式时间。这个细节在讲 NP 相关话题时会用到,先记住「背包快是因为 W 不大」。

面试怎么考。DP 题的胜负手在「认模型」:

  • 先归类,再动手:「两个字符串比来比去」→ 大概率 LCS / 编辑距离;「一堆物品选或不选、带容量约束」→ 背包;「一个序列里挑最长的递增段」→ LIS。认对模型,状态和转移基本是现成的。
  • 能默写状态转移方程:面试官常直接问「你的 dp[i][j] 表示什么、方程怎么写」。把编辑距离的「相等抄左上、不等 1 + 三者最小」讲利落,是硬功。
  • 主动提优化:写完二维版,补一句「因为只依赖上一行,可以用滚动数组把空间降到 O(n)」;遇到 LIS 补一句「还有 O(n log n) 的贪心 + 二分做法」。这两句几乎是标配加分项。

坑一:背包「恰好装满」vs「不超过容量」初始化不同。求「容量内最大价值」(不超过)时,dp 全初始化为 0;但求「恰好装满容量」的方案时,除 dp[0]=0 外其余要初始化为 -∞(表示「暂时无法恰好装满」),否则会把不可达状态误当作合法解。两种题面初始化不一样,张冠李戴必错。

坑二:一维背包遍历方向。0/1 背包压成一维后,容量必须从大到小倒序遍历;若正序,第 i 件物品会被在同一轮里重复选取,悄悄变成了「完全背包」。

坑三:子序列 ≠ 子串。LCS 求的是「可以不连续、但保持相对顺序」的子序列;最长公共子串要求连续,转移方程不同(不匹配就归零)。读题时先分清这两个词。

四个模型各写一遍,并都做一次空间优化:

0/1 背包:先写二维 dp[i][w],再压成一维并改倒序遍历,对拍两版结果一致。LCS(LeetCode 1143)· 编辑距离(72,照上面那张表把每格填出来验证)· LIS(300):先写 O(n²) DP,再实现 O(n log n) 的「维护一个可被二分替换的递增尾数组」版本,对拍。

带走这一条:DP 题先做「模型识别」——两字符串→LCS/编辑距离,选或不选带容量→背包,最长递增段→LIS。认出模型,状态转移方程就到手了;写完二维版顺手想「能不能滚动数组降空间」。

六、自测题

Q1:编辑距离中,当 A[i] == B[j](当前两字符相同)时,dp[i][j] 等于什么?

dp[i][j] = dp[i-1][j-1](直接取左上角的值,不加操作)。

因为这两个字符已经对齐、不需要任何编辑,当前这一格的代价就等于「去掉这对相同字符后」子问题的代价,即左上角 dp[i-1][j-1]。只有在字符不同时才是 1 + min(左, 上, 左上),分别对应插入、删除、替换。把「相等抄左上、不等 1 + 三者最小」记牢,编辑距离就稳了。

Q2:把 0/1 背包从二维 dp[i][w] 压成一维 dp[w] 后,为什么容量 w 必须倒序遍历?

为了保证计算 dp[w] 时,用到的 dp[w-wᵢ] 还是「上一件物品」的旧值,从而每件物品最多被选一次。

若正序遍历,dp[w-wᵢ] 在本轮可能已经被第 i 件物品更新过,于是第 i 件会被「叠加选取多次」,这恰好变成了完全背包(每件可选无限次)的语义,与 0/1 背包(每件只能选一次)不符。倒序遍历让每个 dp[w-wᵢ] 保持上一轮的值,才守住「0/1」。

Q3:有人说「LIS 的最优复杂度就是 O(n²),没法再快」。对吗?

不对。最长递增子序列除了朴素的 O(n²) DP,还有经典的 O(n log n) 做法:维护一个数组存「长度为 k 的递增子序列的最小可能结尾」,对每个新元素用二分查找找到它该替换/追加的位置。它求出的是 LIS 的长度(要还原具体序列需额外记录)。「某模型最快只能 X」这类绝对说法要警惕——LIS 就是反例。
