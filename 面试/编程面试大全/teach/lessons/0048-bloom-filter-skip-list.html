布隆过滤器与跳表

这一节收两个「加分项」结构:面试里不常作为主菜,但你能主动提起,立刻显得见过世面。布隆过滤器用极小的空间回答「一定不存在 / 可能存在」;跳表用随机的多层索引拿到期望 O(log n),却比红黑树好写得多。它们的共同气质:用一点点不确定性(误判 / 随机),换来简单与省空间。

先回忆两件事。哈希表那节:一个哈希函数把键映射到桶;等下布隆过滤器会用多个哈希函数映射到位数组。平衡查找树那节:红黑树保证 O(log n) 但实现繁琐;跳表是它的一个更好写的替代品。先想一个问题:如果只需要判断「元素肯定不在集合里」,还需要把元素本身完整存下来吗?

一、布隆过滤器:省空间的「概率型存在性判断」

布隆过滤器是一个长度为 m 的位数组(初始全 0)加上 k 个哈希函数。插入元素 x:用 k 个哈希函数各算一个位置,把这 k 个位置 1。查询 x:看那 k 个位是否全为 1——只要有一位是 0,就断定 x 一定不存在;若全为 1,则「可能存在」(也可能是别人的位凑巧把它们都填了)。

三条不可动摇的性质:有假阳性(说「有」可能其实没有)、无假阴性(说「没有」就一定没有)、标准版不支持删除。为什么不能删?因为某一位可能被多个元素共享,把它清 0 会误伤别人。典型用途:缓存穿透拦截(先问布隆「这个 key 可能存在吗」,答「不存在」就直接返回、不打数据库)、爬虫 URL 去重、大规模黑名单预筛。

二、跳表:随机索引撑起的有序表

跳表(skip list)是一条有序链表,外加若干层「快速通道」索引。底层是完整链表;每往上一层,节点数大约减半,像高速路的出入口一样让你「跳」着走。查找时从最高层往右冲,冲过头就下一层继续,平均只需 O(log n) 步。每个节点的层数由抛硬币随机决定,所以是期望 O(log n),不是最坏保证。

跳表最大的卖点是好写:没有旋转、没有着色规则,插入就是「抛硬币决定层高 + 改几个 next 指针」。这正是 Redis 的有序集合(zset)选它而非红黑树的原因——实现简单、范围查询(ZRANGE)天然顺着底层链表走、并发改造也容易。

三、关键定义

布隆过滤器(Bloom filter)
位数组 + k 个哈希函数的概率型集合。查询 O(k)。有假阳性、无假阴性、标准版不可删,不存元素本身故极省空间。避免说「布隆过滤器会漏判(假阴性)」——它只会误报「有」,不会漏报「没有」。
假阳性 / 假阴性(false positive / false negative)
假阳性=实际不在却报「可能在」(布隆会发生);假阴性=实际在却报「不在」(布隆不会发生)。
跳表(Skip list)
有序链表 + 随机多层索引,查找/插入/删除期望 O(log n),实现比平衡树简单。Redis zset 用它。避免把期望 O(log n) 说成「最坏 O(log n)」。

四、复杂度

结构 / 操作时间空间
布隆:插入 / 查询O(k)O(m) 位
跳表:查找(期望 / 最坏)O(log n)O(n) 期望
跳表:插入 / 删除(期望)O(log n)—
跳表:查找(最坏)O(n)O(n log n) 最坏

布隆的 k(哈希函数个数)是常数,故插入/查询是常数时间且省空间到位级。跳表的 O(log n) 是期望值——运气极差(所有节点都抽到最低层)时会退化到 O(n),但概率极低。这条「期望 vs 最坏」的区别是面试易错点。

面试怎么考。这两个结构常以「你还知道什么能解决 X 的结构」出现,主动提起就是加分:

  • 「海量数据判断是否见过、且能容忍少量误判」 → 布隆过滤器。经典追问:「误报了怎么办」——答「布隆说『可能在』时再去真库确认,说『不在』则可信直接跳过」。
  • 「缓存穿透怎么防」 → 布隆过滤器挡在缓存前,不存在的 key 直接被拦,不打到数据库。
  • 「想要 O(log n) 的有序结构,但不想手写红黑树」 → 跳表,实现简单、支持范围查询。
  • 「Redis 的 zset 底层」 → 跳表(配合哈希表)。这是高频八股。

布隆过滤器方向别搞反。它有假阳性、无假阴性:报「不存在」是 100% 可信的,报「存在」才可能是误报。说反了(以为它会漏掉真实存在的元素)是硬伤。还有:标准布隆不支持删除,想删得换计数布隆(Counting Bloom Filter,用计数器代替单个位)。

跳表是「期望」O(log n),不是「最坏」。层高靠随机决定,最坏(概率极小)可退化 O(n)。这点和红黑树不同——红黑树是最坏 O(log n) 的硬保证。面试里把跳表说成「保证 O(log n)」会被抓。

动手清单(任选其一深入):

1. 布隆:用一个 bitset + 2~3 个哈希函数(可用不同种子)实现 add 和 mightContain。插入一批词后,拿没插过的词测一测假阳性率,再调大位数组 m 观察误报下降。

2. 跳表:实现 search/insert,插入时用「抛硬币」(如 50% 概率再升一层)决定层高。打印每个节点的层数,确认大约每上一层数量减半。

3. 对比实验:同一份有序数据,用跳表和平衡树各查一遍,体会跳表代码短在哪。

带走这一条:布隆过滤器 = 省空间的概率集合,「不在」可信、「在」可能误报、不可删,用于缓存穿透/去重前置;跳表 = 随机多层索引,期望 O(log n)、比红黑树好写,Redis zset 的底层。两者都是「拿一点不确定换简单」。

五、自测题

Q1:一个布隆过滤器对某个查询返回「元素存在」。下面哪个结论是对的?

「元素可能存在,需要再去真实数据源确认。」布隆过滤器有假阳性——它报「存在」时,可能是别的元素把那几个位凑齐了。反过来,如果它报「不存在」,则 100% 可信(无假阴性)。干扰项「元素一定存在」正好把假阳性的方向搞反了;「元素一定不存在」更是彻底说反。记法:布隆帮你快速排除,不帮你最终确认。

Q2:跳表和红黑树都能提供 O(log n) 的有序查找。关于它们的复杂度保证,哪句准确?

「红黑树是最坏 O(log n) 的硬保证,跳表是期望 O(log n)、最坏可退化 O(n)。」跳表的层高由随机决定,运气极差时会退化,只是概率极低;红黑树靠旋转和着色规则强制平衡,最坏也保证 O(log n)。选跳表通常是因为它实现简单、易于范围查询和并发(如 Redis zset),而非因为它有更强的最坏保证。把跳表说成「最坏 O(log n)」是常见错误。
