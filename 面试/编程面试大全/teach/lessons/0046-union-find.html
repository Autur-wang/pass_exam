并查集:近乎 O(1) 的连通性

「这两个元素连通吗?」「把这两个集合并起来。」当连接关系动态、不断加入时,反复跑 DFS/BFS 太贵。并查集(Union-Find)用一片父指针森林 + 两个小优化,把 union 和 find 摊到近乎常数时间——这是一个「结构极简、复杂度分析极深」的经典结构。

先回忆图遍历那节:判断两点是否连通,可以从一点 BFS/DFS,看能否到达另一点,单次 O(V+E)。先想一个问题:如果要回答「成千上万次连通性查询」,而且图的边还在一条条动态加入,每次都重跑一遍遍历,代价受得了吗?并查集就是为这个场景生的。

一、直觉:每个集合选一个「代表」

把每个元素看成一个节点,给它一个「父指针」。同一集合里的节点最终都指向同一个根(代表元)。判断两元素是否同集合,就是各自往上找根,看根是否相同(find);合并两集合,就是把一个根挂到另一个根下(union)。整个结构是一片「孩子指向父亲」的森林,和树遍历里「父指向孩子」的方向正好相反。

朴素实现有个隐患:如果每次都把树越接越高,find 要顺着长链一路爬到根,最坏退化成 O(n)。两个优化联手根治这件事。

二、两个优化:让树永远又矮又胖

路径压缩(path compression):每次 find 爬到根之后,顺手把这一路上的节点直接改挂到根下。下次再查它们就一步到根。按秩/按大小合并(union by rank/size):union 时总是把「矮的/小的」树挂到「高的/大的」树下,避免把高树越叠越高。

神奇之处在复杂度:路径压缩 + 按秩合并合用时,每次操作的摊还代价是 O(α(n)),α 是反阿克曼函数(inverse Ackermann)——它增长得极其极其慢,对宇宙里任何可能的 n,α(n) 都不超过 4~5。所以工程上直接当作常数看待。

三、关键定义

并查集(Union-Find / Disjoint Set)
维护若干不相交集合、支持 union(合并)与 find(查代表元)的结构,配合路径压缩 + 按秩合并近似 O(1)。避免「联合查找」「不相交集」混称——本课统一叫并查集。
代表元 / 根(representative / root)
每个集合选出的唯一节点,父指针链的终点。「两元素同集合」等价于「两者的根相同」。
反阿克曼函数 α(n)
路径压缩 + 按秩合并后的摊还复杂度因子,增长慢到对一切实际 n 都 ≤ 5,故视为常数。避免把它说成「严格 O(1)」——严谨说法是「摊还 O(α(n))」。

四、复杂度

实现方式find 摊还union 摊还
朴素(无优化)O(n)O(n)
仅按秩合并O(log n)O(log n)
路径压缩 + 按秩合并O(α(n))≈O(1)O(α(n))≈O(1)

空间 O(n)(一个父指针数组,可再加一个秩/大小数组)。看清这张表的层次:两个优化各自单用都只到 O(log n),合用才近乎常数;不加优化则退化到 O(n)。这正是面试官爱挖的点。

面试怎么考。听到这些信号词,并查集应第一个跳进脑子:

  • 「动态连通性 / 朋友圈 / 省份数量」:边或关系一条条加入,反复问「连通吗」——并查集比每次重跑 DFS 高效得多。
  • 「岛屿合并 / 账户合并 / 等式方程可满足性」:本质都是「把有关系的元素并进同一集合,再查询」。
  • Kruskal 最小生成树:按边权从小到大加边,用并查集判「加这条边会不会成环」(两端已同集合就跳过)。
  • 无向图判环:遍历每条边,若两端已在同一集合,则出现环。

相比 DFS/BFS,并查集的优势正是边流式加入的场景——它不需要一开始就拿到整张图。

不加优化会退化成 O(n)。朴素并查集能把树接成一条长链,find 就成了顺链爬,最坏 O(n)。写并查集一定要带上路径压缩(通常还配按秩/按大小合并),否则在链式输入下和暴力没区别。

两个优化要一起用才近常数。只用其中一个是 O(log n),合用才是 O(α(n))。面试答题时把这个层次说清楚,比笼统说「并查集是 O(1)」专业得多。另外别把 α(n) 神化——它是反阿克曼函数,极小但严格来说复杂度是「摊还 O(α(n))」,不是「每次都 O(1)」。

动手清单:

1. 用一个 parent[] 数组实现最朴素的 find(顺父指针爬到根)和 union。

2. 给 find 加路径压缩(递归版:parent[x] = find(parent[x]))。

3. 给 union 加按秩(或按大小)合并,维护一个 rank[] 或 size[]。

4. 用它解 LeetCode 547「省份数量」或 200「岛屿数量」,并数一数「集合个数」= 有多少个 parent[i]==i 的根。

5. 构造一条链式合并输入,对比「有无路径压缩」时 find 的爬升步数。

带走这一条:并查集是一片「孩子指向父亲」的森林,靠路径压缩 + 按秩合并两招合用把 union/find 摊到近乎常数(O(α(n)))。见到「动态连通性/合并集合/判环/Kruskal」就想到它。

五、自测题

Q1:一个并查集只用了路径压缩,没用按秩合并。它单次操作的摊还复杂度大约是?

大约 O(log n)(更精确是 O(log n) 级,与只用按秩合并同量级)。达到 O(α(n))≈O(1) 需要两个优化合用。这道题就是在考「层次」:无优化 O(n)、单个优化 O(log n)、合用 O(α(n))。把这三档背清楚,面试里被追问就不会含糊。

Q2:下面哪个场景最适合用并查集,而不是每次都跑一遍 DFS/BFS?

「边一条条动态加入,期间要反复查询任意两点是否连通」。这种流式加边 + 大量连通性查询的场景,并查集每次操作近乎 O(1),而重跑遍历每次 O(V+E)。相反,若需要「求两点间最短路径长度」或「输出具体路径」,并查集做不到——它只回答「是否同一集合」,不保存路径。选「求最短路径」的话就用错了工具(那是 BFS/Dijkstra 的活)。
