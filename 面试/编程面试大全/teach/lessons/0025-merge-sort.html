归并排序:分治与稳定的代价

归并排序是「分治」范式最干净的教科书示例:把数组劈成两半,各自排好,再合并两个有序段。它的时间复杂度稳如泰山——最好、平均、最坏都是 O(n log n),还是稳定的。但天下没有免费的午餐,它的代价写在空间那一栏:数组版归并需要 O(n) 额外空间,不是原地排序。这节课把「稳定 + 稳定 O(n log n)」的红利和「非原地」的代价一并讲清,并揭示它一个特别的偏爱:链表。

回忆排序全景那张总表:归并在时间轴上稳站 O(n log n)、在稳定性轴上是「稳定」、但在空间轴上标了红色的 O(n)。这节就来解释这三个格子背后各自的机制——尤其是「为什么它能稳定,却要付出额外空间」。

一、分治三步:分、治、合

分治(Divide and Conquer)把一个大问题拆成互不重叠的同类子问题,分别解决再合并。归并排序的三步:

  1. 分(Divide):把数组从中间劈成左右两半。
  2. 治(Conquer):对左右两半各自递归调用归并排序。base case 是长度 ≤ 1 的段——它天然有序。
  3. 合(Merge):把两个已排好序的段,合并成一个有序段。这是全部的技术核心。

二、合并:两个有序段如何 O(n) 合一

合并是归并的灵魂。给定两个已排好序的段,各放一个指针在开头,比较两个指针指向的元素,把较小的那个取走、指针后移,如此往复直到一段耗尽,再把另一段剩下的接上。因为两段都已有序,每个元素只被看一次,合并一趟是 O(段长)。

合并稳定的秘诀藏在一个细节里:当两个指针指向的元素相等时,永远优先取左段那个。左段的元素在原数组里本来就在前面,先取它就保住了相等元素的原始相对顺序。这一行「<= 而非 <」的选择,就是归并稳定性的全部来源。

三、为什么要额外的 O(n) 空间

合并两个相邻段时,你没法在原数组里就地完成——一边比较一边写回会覆盖掉还没读的元素。标准做法是开一个和数组等长的辅助数组,把合并结果写进去再拷回。这就是 O(n) 额外空间的由来,也是归并不是原地排序的原因。有所谓「原地归并」的技巧,但要么把合并退化成 O(n²)、要么实现极其复杂,面试里不必深究——只要说清「数组版归并需要 O(n) 辅助空间」即可。

四、链表:归并的主场

数组归并要额外空间,但换到链表上,这个代价几乎消失。链表合并两个有序段只需改指针的指向,不需要辅助数组,额外空间降到 O(1)。而且链表天生只支持顺序访问——这正是归并唯一需要的访问模式(它从不随机跳下标)。所以对链表,归并是最自然、最优的选择;快排和堆排在链表上反而会因缺少 O(1) 随机访问而退化。这就是上一课那句「链表适合归并」的底层原因。

五、关键定义

分治(Divide and Conquer)
把问题分成互不重叠的子问题、分别求解再合并。避免与动态规划混同——DP 的子问题会重叠、需缓存,分治不重叠。
归并排序(Merge Sort)
分治排序:对半拆分、递归排序、合并两个有序段。稳定 O(n log n),数组版需 O(n) 辅助空间。
自底向上归并(Bottom-up Merge Sort)
不用递归,而是从段长 1 开始,一轮轮把相邻段两两合并(1→2→4→8…)的迭代版本,避免递归栈开销。

注意时间那一行——归并的三种情况完全一样,没有「最坏退化」。这是它相比快排最大的优势:性能可预测,永远 n log n,适合对最坏情况有硬性保证的场景。

面试怎么考。归并本身直接出题不多,但它的合并思想是一大批高频题的母题——看到「合并有序」「分治统计」就该想到它:

  • 合并 K 个有序链表——把归并的「合并两个」推广到 K 个,用两两归并或优先队列,是经典高频题。
  • 逆序对计数 / 数组中的翻转对——在归并的合并步里,当右段元素被取到左段元素前面时,顺带统计跨段逆序对,把 O(n²) 暴力降到 O(n log n)。
  • 外部排序(External Sort)——数据大到内存装不下时,分块排序后多路归并落盘,是归并「只需顺序访问」这一性质的工业级应用。
  • 会被追问:「归并和快排怎么选?」——要稳定、要最坏情况有保证、或排链表,选归并;内存紧张、要原地、平均更快,选快排。

「归并排序是原地的」——错。数组版归并需要 O(n) 辅助数组来完成合并,是典型的非原地排序。只有链表版靠改指针才做到 O(1) 额外空间。把数组归并说成原地是常见扣分点。

别把归并的「稳定」当成理所当然的偶然。它稳定是因为合并时相等元素优先取左段(left[i] <= right[j] 时取左)。如果你把条件写成 < 让右段优先,归并就变得不稳定了——稳定性是实现里那一行比较符的直接结果,不是天生的。

实现两个版本,对照理解:

1) 数组版:merge_sort(arr) 递归拆分 + merge(left, right) 用辅助数组合并。在 merge 里刻意用 <= 保证取左优先,再改成 <,用带标签的相等元素验证稳定性如何被破坏。

2) 自底向上迭代版:段长从 1 开始翻倍(1→2→4…),每轮扫一遍数组合并相邻段,不用递归。

进阶:实现链表版归并(快慢指针找中点拆分、合并只改 next 指针),观察它不需要辅助数组。

带走这一条:归并用「稳定 + 三种情况都 O(n log n)」的可预测性,换来了 O(n) 额外空间。要最坏情况有保证、要稳定、或者排链表——选它。

七、自测题

Q1:归并排序的最好情况时间复杂度是多少?为什么它和快排在这一点上有本质区别?

归并的最好情况仍是 O(n log n)——和平均、最坏完全一样。因为无论输入长什么样,它都要拆到底(log n 层)、每层合并处理全部 n 个元素,拆分和合并的工作量不随输入内容变化。快排则不同:它平均 O(n log n),但在最坏输入(如已排序 + 固定选 pivot)下会退化到 O(n²)。所以归并的卖点是性能可预测、最坏情况有保证,快排的卖点是平均更快且原地。

Q2:合并两个有序段时,若两个指针指向的元素相等,应该优先取哪一段的元素?取错了会有什么后果?

应优先取左段(实现里写成 left[i] <= right[j] 时取 left)。左段元素在原数组里本就排在右段前面,先取它就保住了相等元素的原始相对顺序,这正是归并稳定的来源。如果改成右段优先(把条件写成 <),相等元素的顺序会被颠倒,归并就不再稳定。稳定性完全由这一行比较符决定,不是天生的。

Q3:「数组中的逆序对个数」为什么能用归并排序在 O(n log n) 内求出,而不必 O(n²) 暴力两两比较?

关键在合并步:当合并左右两个已排序段时,如果右段的某个元素比左段当前指针指向的元素小、被提前取走,说明左段剩下的全部元素都与它构成逆序对——一次就能统计一批,而不是逐对比较。把每次合并统计到的跨段逆序对累加,再加上左右子段内部递归算出的逆序对,就是总数。整个过程搭在归并的骨架上,时间复杂度就是归并的 O(n log n)。这是「分治统计」这一大类题的范式。
