二叉搜索树:有序性即不变量

普通二叉树只是「能分叉」,没有任何秩序。给它加上一条铁律——左子树全部 < 根 < 右子树全部——它就升级成二叉搜索树(BST):一个把「有序数组的二分查找」和「链表的动态增删」揉在一起的结构。这节课只讲透这一条不变量,以及它如何一手推导出「查找/插入 O(h)」的红利,和「可能退化成链表」的代价。

先回忆:上一课(DFS 三种序)最重的结论是——对 BST 做中序遍历会得到升序序列。这节你会看到,那不是巧合,而是 BST 不变量的直接推论。先自己说说:如果「左 < 根 < 右」在每个节点都成立,为什么「左 → 根 → 右」地走一遍就一定是从小到大?

一、一条不变量,决定一切

BST 的定义只有一句话,但它是递归的:对每一个节点,它左子树里的所有值都比它小,右子树里的所有值都比它大。注意是「整棵子树」而不是「直接的那个孩子」——这个细节下一课会成为验证 BST 的关键陷阱。

二、查找 / 插入:沿着高度往下滑

查找:拿目标和当前节点比,小了走左、大了走右、相等即命中,直到走到空。每一步比较后只保留一半子树,所以走过的步数不超过树高 h——这就是 O(h)。插入同理:用查找的走法一路下滑,直到落到一个空位,把新节点挂上去,也是 O(h)。这正是 BST 相对有序数组的红利:有序数组二分查也是 O(log n),但插入要搬 O(n) 个元素;BST 的插入只改几个指针,依然是 O(h)。

三、为什么中序有序

把不变量和中序「左 → 根 → 右」摆一起看:递归到任意节点时,先访问完「全部比它小」的左子树,再访问它自己,最后访问「全部比它大」的右子树——每一层都严格「小的先出、大的后出」。层层如此,整体输出必然升序。这就是「BST + 中序 = 排序」的证明,不用背,推一遍就懂。

四、关键定义

二叉搜索树(BST, Binary Search Tree)
每个节点满足「左子树全部 < 本节点 < 右子树全部」的二叉树;操作复杂度取决于树高 h。避免默认 BST 就是平衡的。
树高 h(height)
决定 BST 一切操作快慢的量。平衡时 h≈log n,退化成链时 h=n。谈 BST 复杂度请说 O(h),而非武断的 O(log n)。

五、复杂度:平均漂亮,最坏危险

操作平均(随机/平衡)最坏(退化成链)
查找 searchO(log n)O(n)
插入 insertO(log n)O(n)
删除 deleteO(log n)O(n)
中序输出全部(有序)O(n)O(n)

三大操作本质都是 O(h)。表里写「平均 O(log n)、最坏 O(n)」,是因为 h 会随插入顺序波动:随机插入的树大致平衡 h≈log n;但若按有序序列插入,树就退化成一条只往一边长的链,h=n,BST 沦为链表。空间恒为 O(n)(每个值一个节点)。

面试怎么考。识别「该上 BST」的信号,和答对复杂度一样重要:

  • 题面同时要「保持有序」+「动态频繁增删」+「找第 k 小 / 范围查询 [a,b] / 前驱后继」 → 强烈指向 BST(或它的平衡变体、跳表)。纯静态有序数据用有序数组二分即可,不必上树。
  • 被问复杂度,先说 O(h),再补一句「平衡时 O(log n),退化时 O(n)」——这比张口就说 O(log n) 显专业得多。
  • 常见追问:「怎么保证不退化?」 → 引出自平衡树(AVL、红黑树),它们靠旋转把 h 强行压在 O(log n)(见后续「平衡树」一课,第 0047 课)。

BST 不会自动平衡——这是最常被忽视的致命点。「BST 查找 O(log n)」是有前提的近似说法,只在树大致平衡时成立。

最经典的翻车场景:按已经有序的序列插入(如 1,2,3,4,5)。每个新值都比现有全部大,永远挂到最右,树长成一条向右的链,h=n,查找退化成 O(n)——和链表一模一样,白白丢掉了树结构的意义。真实系统里的输入常常「近乎有序」,所以工业界用的几乎都是自平衡的变体,而不是裸 BST。

照仓库「二叉查找树」实现清单,先把最基础的一组写扎实:

insert(x)(下滑找空位)· is_in_tree(x) · get_min()(一路向左)· get_max()(一路向右)· print_values()(中序,验证升序)。

做个小实验:分别用随机顺序和严格递增顺序各插入 1..1000,打印两棵树的高度——你会亲眼看到前者约 10~20、后者恰好 1000(退化成链),复杂度差异一目了然。

带走这一条:BST 的一切都由那条不变量和树高 h 决定。答复杂度永远说 O(h)——平衡时 O(log n),退化时 O(n)。它不自动平衡,有序输入会把它打回链表。

六、自测题

Q1:为什么 BST 的查找准确说是 O(h) 而不是 O(log n)?

因为查找走过的步数等于树高 h,而 h 不一定等于 log n。只有当树平衡时 h≈log n;如果按有序序列插入,树退化成一条链,h=n,查找就退化成 O(n)。所以最严谨的说法是 O(h),「O(log n)」只是「树平衡」这个特例下的结果。把前提说出来,才说明你真的理解 BST 的软肋。

Q2:下面哪种插入顺序会让一棵 BST 退化成链表(最坏高度)?

严格递增的 1, 2, 3, 4, 5。每个新值都比树里现有的所有值大,于是一路走到最右、挂在最右下角,树只往右长,变成一条链,h=n。随机顺序或「先插中位数」会得到大致平衡的树(h≈log n);「5,3,8,1,4」这种也还算均匀。这也说明:BST 的性能取决于插入顺序,而它自己管不了这件事——所以才需要自平衡树。
