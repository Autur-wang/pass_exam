摊还分析:偶尔昂贵,平均便宜

有一类操作平时都很便宜，只是偶尔会突然做一次昂贵的活。如果按「最坏那一次」给它定复杂度，会严重高估它的真实成本。摊还分析就是修正这个偏差的工具——它问：把偶发的昂贵操作均摊到一长串便宜操作上，平均每次到底多贵？这节用动态数组扩容做主例讲透它，它正是下一课数组的直接前置。

先回忆：上一课你学会看输入规模反推复杂度。但那默认「每次操作代价固定」。这节要松动这个假设——先自己想一句：如果某个操作 99 次都是 O(1)、第 100 次却是 O(n)，你该说它是 O(1) 还是 O(n)？

一、问题:最坏情况会「冤枉」一个操作

想象你往一个动态数组末尾不停 push。大多数时候底层还有空位，直接写进去就行，是 O(1)。但每当容量用满，它得申请一块两倍大的新内存、把已有元素全搬过去——这一次是 O(n)。

如果只看「最坏单次」，你会说 push 是 O(n)。可这样定价太亏了：那次 O(n) 的搬家极少发生，绝大多数 push 依旧是 O(1)。用偶发峰值给整体定价，会把一个其实很便宜的操作说成很贵。摊还分析要算的是「一长串 push 平均下来每次多贵」，这才公道。

二、主例推导:翻倍扩容为什么摊还 O(1)

关键在按倍数扩容（×2），而不是按固定量（+1）。我们直接算「从空开始连续 push n 个元素」的总代价，再除以 n。

总代价分两块：① n 次写入本身，每次 1 个单位，共 n；② 各次扩容的搬运代价。扩容发生在容量 1、2、4、8… 被填满时，每次搬运的元素数正好是当时的容量：

触发扩容时的容量本次搬运元素数累计搬运
111
223
447
8815
………
n/2n/2< n

搬运总和是一个几何级数：1 + 2 + 4 + … + n/2。等比数列求和，它 < n（等价地，从大到小写就是 n + n/2 + n/4 + … < 2n）。所以:

总代价 = n(写入) + (<n)(搬运) < 2n = O(n)

n 次 push 总共花 O(n)，平均每次就是 O(n)/n = O(1)。换个更好记的说法——每个元素平均只被搬运常数次（翻倍策略下，一个元素被搬的次数不超过 2）。这就是「push 摊还 O(1)」的完整由来。

要是改成每次 +1 扩容呢？那每一次 push 都触发一次搬家，搬运总和变成 1 + 2 + 3 + … + n = O(n²)，平均每次 O(n)。同一个操作，扩容策略从「翻倍」换成「+1」，摊还复杂度就从 O(1) 崩到 O(n)——这正是翻倍如此关键的原因。

三、关键定义

摊还分析(Amortized Analysis)
把偶发的昂贵操作的代价均摊到一长串操作上，得出单次操作的平均代价。动态数组 push 的摊还复杂度是 O(1)。避免把摊还 O(1) 说成「每次都 O(1)」。
摊还 O(1) vs 最坏 O(n)
同一个操作可以同时是「摊还 O(1)」和「最坏单次 O(n)」——前者说长期平均，后者说某一次的峰值。完整表述要两句都给。
摊还 ≠ 平均情况(amortized ≠ average-case)
摊还是对任意一串操作序列的确定性保证，不依赖任何输入概率分布；平均情况则假设输入服从某个分布再求期望。两者是不同的分析框架。

面试怎么考。「动态数组的 push 为什么是摊还 O(1)?」是最高频的复杂度追问之一，几乎是数组/哈希表/栈题的标配。想答漂亮:

  • 先给完整定价：「摊还 O(1)，最坏单次 O(n)。」一句话把两面都说清，立刻区别于只会背「O(1)」的人。
  • 再给一句直觉证明：「因为按倍数扩容，每个元素平均只被搬运常数次，所以 n 次 push 总代价是 O(n)，摊到每次是 O(1)。」——能说出这句，面试官就知道你是懂的，不是背的。
  • 点破翻倍的必要性：如果被追问「为什么非要翻倍」，答「+1 扩容会让总代价退化成 O(n²)」，一句到位。
  • 同一套推理还会迁移到：哈希表的动态扩容（rehash）、栈基于动态数组的实现——都是摊还 O(1)。

坑一:把「摊还 O(1)」说成「每次都 O(1)」。这是漏掉「摊还」两字的典型错误。触发扩容的那一次实实在在是 O(n)，只是平均下来才是 O(1)。在对单次延迟敏感的场景（实时系统、低延迟服务），那次 O(n) 的抖动恰恰是要命的——这时说「O(1)」就暴露了理解不到位。

坑二:把摊还和平均情况混同。平均情况（如快排平均 O(n log n)）依赖「输入随机」的假设，遇到刻意构造的坏输入就失效；摊还是对任何操作序列都成立的确定性均摊，不赌输入分布。一个防不住恶意输入，一个防得住——别把它们当同义词。

动手核对：拿纸笔（或写段小代码打印）从空数组、容量 1 开始，模拟连续 push 16 个元素。每次 push 记下「本次是否触发扩容、搬了几个元素、本次总代价」，最后把 16 次代价加起来除以 16——看它是不是逼近一个常数（≈2）。再把扩容策略从「翻倍」改成「+1」重跑一遍，亲眼看总代价从 O(n) 变成 O(n²)。这个小实验做完，摊还 O(1) 就再也不会记错了。

带走这一条：摊还 O(1) = 「长期平均每次 O(1)，最坏单次可能 O(n)」。它靠翻倍扩容让每个元素只被搬运常数次；它是对操作序列的确定性均摊，不是依赖输入分布的平均情况。

四、自测题

Q1:一个同事说「动态数组的 push 是 O(1)」。作为面试官,你想追问一句让答案更严谨,该追问什么?

该追问：「是每次都 O(1)，还是摊还 O(1)?触发扩容那次呢?」严谨的答案是「摊还 O(1)，最坏单次 O(n)」——扩容时要搬走全部已有元素，那一次实实在在是 O(n)，只是均摊到一长串便宜 push 上平均才是常数。
只说「O(1)」不算错，但漏掉了「摊还」这个限定，也没提最坏峰值——在乎单次延迟的场景里这个疏漏会致命。

Q2:下面哪种说法准确区分了「摊还 O(1)」和「平均 O(1)」?

准确的是：摊还是对任意操作序列都成立的确定性保证，不依赖输入分布;平均情况则要先假设输入服从某个概率分布再求期望。
换句话说，摊还 O(1) 不怕你构造「最坏输入」——不管你怎么排 push 的顺序，n 次总代价都是 O(n)。而平均情况（比如哈希表在「均匀分布」假设下的 O(1)）一旦遇到刻意制造冲突的输入就可能退化。把两者说成一回事，是这节最需要避开的混淆。

Q3:如果把动态数组的扩容策略从「容量 ×2」改成「容量 +1」,连续 push n 个元素的总代价会变成多少?

变成 O(n²)，摊还退化到每次 O(n)。因为 +1 策略下，容量永远比当前元素数只多 1，几乎每次 push 都触发一次搬家，搬运总和是 1+2+3+…+n = n(n+1)/2 = O(n²)。
对比翻倍策略的搬运总和 1+2+4+…+n/2 < n（几何级数）——这一对照正说明：让摊还成立的不是「会扩容」，而是「按倍数扩容」，使昂贵操作越来越稀、稀到足以被中间的便宜操作稀释掉。
