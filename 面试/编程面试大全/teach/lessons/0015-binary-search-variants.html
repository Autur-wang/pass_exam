二分的变体:找边界与二分答案

上一课的二分只回答「在不在」。但面试里真正高频的是它的变体:找第一个满足条件的位置(边界),以及把一道最优化问题「二分」出答案。它们看着五花八门,内核却是同一句话——在一个「否否否是是是」的单调序列上,找那个从否翻到是的分界点。抓住这句,一堆题就通了。

先回忆:上一课我们背下了闭区间模板——while lo <= hi、mid = lo + (hi - lo)/2、收缩用 mid ± 1,靠不变量「目标若在必在 [lo, hi]」保证正确。请先自问:标准二分找到目标就 return 了;如果数组里有多个等于 target 的值,它返回的是第几个?(答案:不确定——这正是本课要治的病。)

一、把二分重新理解成「找分界点」

标准二分是「找等于 target 的那一个」。换个视角:给区间里每个位置贴一个布尔标签 predicate(i)(它满不满足某条件),如果这些标签是单调的——前面一段全 False、后面一段全 True,中间只翻一次——那么二分就能 O(log n) 找到第一个 True(或最后一个 False)。查找一个值,只是「predicate = (a[i] >= target)」的特例。

二、找左边界:lower_bound

lower_bound:找第一个 >= target 的位置(等价于「≥ target 的最左下标」)。谓词就是 a[i] >= target,前 False 后 True。找左边界的收缩要点是:命中条件时不要急着返回,而是把右端收过来,继续向左试探还有没有更早的。

def lower_bound(a, target):        # 第一个 a[i] >= target
    lo, hi = 0, len(a)             # 半开区间 [lo, hi),ans 落点可为 len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] >= target:       # mid 满足 → 答案在 mid 或更左
            hi = mid               # 不 -1:mid 本身可能就是答案
        else:
            lo = mid + 1           # mid 不满足,丢弃它及左侧
    return lo                      # lo == hi,即第一个 True 的位置

对称地,upper_bound(第一个 > target)只需把谓词换成 a[i] > target。有了这两个,「target 出现了几次」= upper_bound - lower_bound,「插入位置」= lower_bound。C++ 的 std::lower_bound/upper_bound、Python 的 bisect_left/bisect_right 就是它们——库函数背后正是这套。

三、旋转有序数组:被拧过一下的单调

把有序数组从某点旋转,如 [4,5,6,7,0,1,2],整体不再单调,但任意 mid 一劈,左右两半里至少有一半仍是有序的。于是每步先判断哪半有序、target 是否落在那半的范围内,据此决定往哪半走——依然 O(log n)。它是「局部单调也能二分」的代表。

四、二分答案:把「求最优」变成「问是否可行」

这是变体里最反直觉、也最高频的一招。很多最优化问题——「最小化最大值」「最大化最小值」「最少要几天/几台机器」——直接求很难,但改成判定问题就简单:「给定一个候选答案 x,可行吗?」如果可行性关于 x 单调(x 够大就一定可行、够小就一定不可行),那答案空间就是一条 F...F T...T,可以对答案本身二分。

套路固定:① 确认答案落在一个数值区间 [lo, hi];② 写一个 check(x) 判定 x 是否可行;③ 确认 check 关于 x 单调;④ 在数值区间上二分,找第一个可行的 x。经典例子:分割数组的最大值最小、Koko 吃香蕉的最小速度、船在 D 天内运完货的最小载重——全是同一个模子。

五、关键定义

lower_bound / upper_bound
第一个 >= target / 第一个 > target 的位置。是 C++ lower_bound、Python bisect_left/right 的原理。避免把「找边界」和「找任意一个等于 target」混为一谈。
谓词单调性(Monotone Predicate)
沿区间看 predicate 只从 False 翻到 True 一次(或反过来)。这是任何二分变体能成立的根本前提。
二分答案(Binary Search on the Answer)
把最优化问题转成「给定候选答案是否可行」的判定问题,当可行性单调时,对答案的取值范围二分。避免在可行性非单调时套用。

六、复杂度

变体时间空间
lower_bound / upper_boundO(log n)O(1)
旋转有序数组查找O(log n) (元素互异时)O(1)
二分答案O(log R × C) (R=答案范围,C=一次 check 代价)取决于 check

二分答案的时间是「二分次数 log R」乘「每次 check 的代价 C」——别只报 O(log R) 而忘了 check 本身通常是 O(n)。这类题的整体复杂度多为 O(n log R)。

面试怎么考。纯标准二分反而少见,变体才是主战场,记住两条触发信号:

  • 「有序数组里 target 的第一个/最后一个/出现次数/插入位置」→ lower/upper_bound。能说清「命中时为什么用 hi = mid 而不是 mid - 1」就到位了。
  • 「求满足某条件的最小/最大的那个值」且「答案越大越容易满足(或反之)」→ 二分答案。面试时先大声验证单调性,再写 check,最后套模板——这个顺序本身就是加分项。
  • 旋转数组、山脉数组峰值、在无限序列里定位,都是「局部单调 + 二分」,考的是你能不能把非全局单调的结构拆出可二分的方向。

找边界最容易在「命中后往哪缩、最后返回谁」上翻车。找左边界时,a[mid] >= target 命中后要 hi = mid(保留 mid,它可能就是最左的那个),而不是 hi = mid - 1——后者会把正确答案挤出区间。这也是为什么边界写法常用半开区间 [lo, hi) + while lo < hi与标准二分不同:两套模板的开闭、收缩、返回值必须整套配对,不能各取一半。

二分答案的前提是单调性,不确认就套模板 = 蒙。只有「x 可行 ⟹ 所有更大的 x 也可行」这种单调关系成立,答案空间才是 F...F T...T,二分才有意义。遇到可行性会「行→不行→又行」跳变的问题,二分答案直接失效,得换思路。

用同一份有序数组,把边界家族写全并互验:

① lower_bound 与 upper_bound;② 用它们求「target 出现次数」= upper - lower,并和暴力计数对拍;③ 旋转有序数组查找,专测 target 恰好是旋转点、在左半、在右半三种情况。

再挑一道二分答案练手(如「分割数组的最大值最小」或「Koko 吃香蕉」):先写 check(x),在纸上列几个 x 验证 check 确实单调,再套二分。打印每轮 (lo, mid, hi, check(mid)) 看它怎么逼近第一个可行值。

带走这一条:所有二分变体都是「在单调的 F...F T...T 上找那条分界线」。查值、找边界、二分答案的唯一区别是「谓词是什么」——写之前先说清谓词、并确认它单调,模板就那一个。

七、自测题

Q1:实现 lower_bound(第一个 >= target)时,当 a[mid] >= target,下一步应该怎么收缩?

hi = mid(保留 mid,不减 1)。因为 mid 本身满足 >= target,它有可能正是「最左的那个」,不能被排除;我们只是把范围收到「mid 及其左侧」继续找有没有更早的。若写成 hi = mid - 1,当 mid 恰好是答案时就把它挤出去了,返回值会偏右一位。这正是边界二分与标准二分收缩规则不同的核心点。

Q2:下面哪种问题最适合用「二分答案」?

「把货物在 D 天内运完,求船的最小载重」这类:求一个最优数值,且『能力越强(载重越大)越容易满足』的单调判定问题。它可以转成「载重 x 够不够 D 天运完?」的 check,且 x 越大越可行 → 单调 → 二分。干扰项里,「在有序数组找某个值」是标准二分而非二分答案;「求无序数组的中位数」「可行性会来回跳变的问题」都不满足单调性,套二分答案会出错。

Q3:在旋转有序数组 [4,5,6,7,0,1,2] 里用二分找 0,为什么整体不单调却还能 O(log n)?

因为任取 mid 把数组一劈,左右两半中至少有一半是完全有序的。每步先判断哪半有序(比较端点与 mid),再看 target 是否落在那个有序半的值域内:落在 → 去那半,不落在 → 去另一半。每步仍排除约一半元素,所以还是 O(log n)。它体现的通用思想是:即使全局不单调,只要每步都能确定性地砍掉一半,二分依旧成立。
