程序如何运行:从源码到内存布局

你写的 .c / .java 文件是一段文本,CPU 却只认机器码;程序跑起来时,变量、函数、动态分配的对象又各自躺在内存的哪一块?这节把两条链条讲清:源码怎么变成能执行的东西,以及运行时进程的内存怎么划分地盘。其中「栈 vs 堆」是所有系统类面试绕不开的高频概念题——搞清它,你才能解释清楚栈溢出、内存泄漏、为什么局部大数组会崩。

回忆栈那课:栈是「后进先出、只在一端 push/pop」的结构。当时我们把它当抽象数据结构讲;这节你会看到它在真实机器里最重要的化身——调用栈(call stack)。每次函数调用压入一个栈帧,返回时弹出,活生生就是 LIFO。数据结构不是纸上的,它就跑在你程序的内存里。

三、栈 vs 堆:面试必答的那道题

「栈和堆有什么区别」几乎是系统类面试的开胃菜。把这张表说清就稳了:

维度栈 Stack堆 Heap
存什么局部变量、函数参数、返回地址动态分配的对象(malloc/new)
谁来管编译器自动:进函数分配、出函数回收程序员手动 / 垃圾回收器(GC)
速度快:只移动栈指针一步慢:要找合适空闲块、可能加锁
大小小且有上限(典型几 MB)大,受可用内存限制
生命周期随函数返回自动消失手动释放 / 无引用后被回收前一直在
典型事故栈溢出(递归太深 / 局部数组太大)内存泄漏、碎片、悬空指针

一句话概括取舍:栈快、自动、但小且短命;堆大、灵活、但慢且要自己收拾。所以能放栈就放栈,需要「活得比当前函数久」或「大小运行时才知道」的数据才上堆。

面试怎么考。三条常见追问:

  • 「栈和堆区别?各存什么?」——上表就是标准答案。加一句「栈由编译器自动管理、堆要手动或 GC」立刻显专业。
  • 「栈溢出怎么发生的?」——递归太深(每层一个栈帧)或在栈上开了巨大的局部数组,把几 MB 的栈撑爆。对比堆溢出/OOM 是另一回事。
  • 「内存泄漏是什么?」——在堆上分配了却一直不释放、又丢了引用,内存只增不减。C/C++ 靠 free/delete,带 GC 的语言靠「没有引用可达」判定回收,但仍可能因意外持有引用而泄漏。

两个「堆」根本不是一回事。这节的堆是内存区(heap 内存区)——进程用来动态分配的那块地址空间;而数据结构那节的堆是优先队列——一棵满足堆序的完全二叉树。它们只是碰巧同名,毫无关系。面试里听到「堆」先确认对方指哪个,答题时也别串台(术语表专门标了这条)。

「栈是无限的」——错。栈空间通常只有几 MB 且有硬上限,这正是「用递归还是用迭代」有时要看栈深度的原因;把一个上百万元素的数组声明成函数里的局部变量(放栈上)大概率直接崩,得改成堆分配。

动手核对(把抽象变成看得见):① 写个无限递归函数跑起来,观察它报 StackOverflow / 段错误,估算你的栈能撑多少层。② 在 C 里分别用局部变量、static 全局、malloc 各建一个变量,打印它们的地址,看是不是分别落在栈(高地址)、数据/BSS 段、堆(低地址往上)三个区间。③ 故意 malloc 后不 free,用内存监控工具看进程内存持续上涨——亲眼看一次内存泄漏。

带走这一条:源码经「编译→汇编→链接→加载」变成 CPU 能执行的机器码;运行时进程内存分成代码/数据/BSS/堆/栈五段,栈向下长、堆向上长。栈快自动但小,堆大灵活但慢且要自己回收——「栈 vs 堆」几乎必考。

四、自测题

Q1:下面三个变量分别落在进程内存的哪个段?
(a) 函数里的 int i;　(b) 文件顶部的 int global = 42;　(c) int* p = malloc(100); 指向的那 100 字节

(a) 栈——局部变量随栈帧分配,函数返回即回收。(b) 数据段(Data)——已初始化的全局变量;若写成 int global;(未初始化)则落在 BSS 段并被清零。(c) 堆——malloc 动态分配的内存;注意指针 p 本身(那 8 字节地址)是局部变量,在栈上,而它指向的 100 字节在堆上,两者分属不同段。

Q2:一个函数里写 int arr[5000000];(约 20MB)一运行就崩,改成 malloc(5000000 * sizeof(int)) 就好了。为什么?

局部数组放在栈上,而栈空间通常只有几 MB 的硬上限,一次要 20MB 直接把栈撑爆 → 栈溢出崩溃。改用 malloc 是在堆上分配,堆的可用空间大得多(受整机内存限制),自然放得下。这也是「大块 / 大小运行时才定 / 要活得比函数久的数据,一律上堆」这条经验的由来。(用完记得 free,否则就变成 Q 里说的内存泄漏。)

Q3:「Java 是解释型语言,所以不用编译。」这句话准确吗?

不准确。Java 源码先被 javac 编译成字节码(.class),再由 JVM 执行;JVM 会解释字节码,并把热点代码用 JIT(即时编译)进一步编译成本地机器码以提速。所以 Java 既有编译(源码→字节码)也有运行时编译(字节码→机器码),不是「纯解释、不编译」。核心观念:任何真正在 CPU 上跑的东西,最终都要变成机器指令,区别只在「提前编译还是运行时编译」。
