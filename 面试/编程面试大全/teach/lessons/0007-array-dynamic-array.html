数组与动态数组:连续内存的代价与红利

数组是所有数据结构里最朴素的一个,也是面试里出现频率最高的底座——双指针、滑动窗口、原地操作,全都建立在它一个特性上:元素在内存里是连续排列的。这节课把这条特性的红利(O(1) 随机访问)和代价(中间插入要搬 n 个元素)讲透,并弄清面试最爱追问的那句:「动态数组的 push 为什么是摊还 O(1)?」

动手前先回忆:上一课摊还分析里,我们说「偶发的昂贵操作可以均摊到一长串便宜操作上」。这节你会看到它最经典的落地——动态数组扩容。先试着自己说出:为什么「偶尔一次 O(n) 的搬家」平均下来还是 O(1)?

一、直觉:一排编好号的连续格子

把数组想成内存里一排紧挨着的格子,每个格子大小相同、从地址 0 开始编号。因为格子等宽又连续,要拿第 i 个元素,不用一个个数——直接算 基址 + i × 元素大小 一步跳到,这就是 O(1) 随机访问的来源。

但连续也有代价:要在中间插一个元素,后面所有元素都得整体后移一格腾位置;删中间元素同理要前移填坑。这是 O(n)。数组的全部性格,都是「连续」这一个决定推导出来的。

二、动态数组:数组不够长了怎么办

原生数组容量是固定的。动态数组(C++ 的 vector、Java 的 ArrayList、Python 的 list)在容量用满时,做一件事:申请一块两倍大的新内存,把旧元素全搬过去,再释放旧的。这次操作是 O(n),但它不常发生。

为什么翻倍这么关键?因为翻倍后,下一次扩容前你能免费 push 掉的元素数,和这次搬家的代价成正比。把每次搬家的总代价摊到这中间的一长串 O(1) push 上,平均每次 push 仍是常数——这正是上一课摊还分析的结论。反之,如果每次只 +1 扩容,每次 push 都触发搬家,就退化成 O(n²) 建数组。

三、关键定义

动态数组(Dynamic Array)
底层是连续内存、容量满时按倍数扩容的可变长数组。随机访问 O(1),末尾 push 摊还 O(1)。避免与「链表」混用「数组」一词。
容量 vs 大小(capacity vs size)
size 是当前元素个数,capacity 是当前已申请、可容纳的格子数,capacity ≥ size。扩容改变的是 capacity。
摊还 O(1)(amortized O(1))
单次操作偶尔 O(n)(扩容),但均摊到一长串操作上平均是 O(1)。避免说成「每次都 O(1)」。

四、复杂度:一张必须背下来的表

操作平均 / 摊还最坏
随机访问 at(i) / 更新O(1)O(1)
末尾 push / popO(1)O(n) (push 触发扩容)
任意位置 insert / deleteO(n)O(n)
头部 prependO(n)O(n)
按值查找 find / removeO(n)O(n)

空间复杂度 O(n):即便预留容量让实际占用达到 2n,常数不影响量级。连续内存还带来一个表里看不见的红利——缓存友好,顺序遍历时 CPU 缓存命中率高,这也是后面缓存一课会回收的伏笔。

面试怎么考。数组本身很少单独出题,但它是这些高频套路的地基,看到就该联想:

  • 双指针 / 滑动窗口:靠 O(1) 随机访问在数组上移动指针,把很多 O(n²) 暴力解压到 O(n)。
  • 「原地(in-place)」要求:面试官说「不许开新数组」,考的就是你会不会用下标腾挪(如原地去重、旋转数组)。
  • 会被追问的证明题:「push 为什么摊还 O(1)?」——答:按倍数扩容,每个元素平均只被搬运常数次。能把这句话说清,面试官就知道你不是背的。

「动态数组 push 是 O(1)」——漏了「摊还」两个字就可能被扣分。准确说法是「摊还 O(1),最坏单次 O(n)」。有的场景(如实时系统、对单次延迟敏感)恰恰在乎那次 O(n) 的抖动,这时候答「O(1)」就暴露了理解不到位。

另一个坑:缩容不是「删一半就缩」,而是元素降到容量的 1/4 才缩到一半。为什么留这么大余量?防止在临界点反复「push 一个就扩、pop 一个就缩」的抖动(thrashing),否则又退化成每次 O(n)。

照仓库大纲徒手实现一个动态数组(别用语言自带的 vector/list 语法糖,自己管理一块原生数组 + capacity),把这些方法写全:

size() · capacity() · is_empty() · at(i)(越界要报错)· push(x) · insert(i, x) · prepend(x) · pop() · delete(i) · remove(x) · find(x) · 私有 resize(new_cap)(满则 ×2,降到 1/4 则 ÷2)。

从 capacity=16 起步,用 2 的幂。写完打印每次 push 时的 capacity,亲眼看它 16→32→64 跳变。

五、自测题

Q1:一个动态数组从空开始,连续 push 了 n 个元素(每次满就翻倍扩容)。这 n 次 push 的总时间复杂度是多少?

O(n)。虽然其中有若干次 O(k) 的扩容搬家,但翻倍策略下所有搬家的总代价是 n + n/2 + n/4 + … < 2n,即 O(n)。所以 n 次 push 总共 O(n),平均每次 摊还 O(1)。若改成每次 +1 扩容,总代价才会变成 1+2+…+n = O(n²)。

Q2:下面哪个操作在动态数组上是 O(n),但在(带头指针的)链表上是 O(1)?

头部插入 prepend。数组头插要把后面全部元素后移一格,是 O(n);链表头插只需改几个指针,是 O(1)。反过来,at(i) 随机访问在数组是 O(1)、在链表是 O(n)——这正是下一课链表要展开的取舍。
