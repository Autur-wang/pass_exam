补码与位技巧:计置位、交换、绝对值

上一课学了怎么拨单个位,这一课把它们串成几个面试常客:补码为什么能让减法变加法、怎么快速数一个数里有几个 1、怎么不用临时变量交换两数、怎么用位求绝对值。每一个都藏着一个漂亮的洞察,也各带一个能筛人的陷阱。

先回忆:上一课最后那条 idiom——n & (n - 1) 会「抹掉 n 最低位的那个 1」。请先自问:如果我反复对 n 做这一步,直到 n 变成 0,一共做了几次? 这次数意味着什么?(这就是本课「数 1 的个数」的钥匙。)

一、补码:让减法消失的设计

计算机只想造一种加法器,却要同时算加和减、还要表示负数。补码(two's complement)是那个统一方案:负数 -x 就用 ~x + 1 来表示(按位取反再加一)。这样一来,a - b 直接算成 a + (-b),同一个加法器搞定,连符号位都自动正确、进位溢出的自然丢弃恰好对应模运算。

n 位补码能表示 -2ⁿ⁻¹ 到 2ⁿ⁻¹ - 1。注意这个范围不对称:负数比正数多一个。以 8 位为例,能表示 -128 到 +127——有 -128,却没有 +128。这个不对称正是后面「绝对值溢出」陷阱的根。补码的最高位既是符号位、又参与数值,这也是为什么「有符号右移」要补符号位来保号(上一课的坑)。

二、数置位个数:Brian Kernighan 技巧

「一个整数的二进制里有几个 1?」(即 popcount / Hamming weight)。朴素法是逐位检查 32 次。Brian Kernighan 技巧更聪明:反复执行 n &= n - 1,每次抹掉一个最低位的 1,直到 n 归零——循环了几次,就有几个 1。

def popcount(n):
    count = 0
    while n:
        n &= n - 1     # 每次干掉最低位的一个 1
        count += 1
    return count

三、异或交换:不借临时变量

异或有两条黄金性质:自反(x ^ x = 0)和幺元(x ^ 0 = x)。据此可以不用临时变量交换两个值:

a ^= b     # a = a ^ b
b ^= a     # b = b ^ (a ^ b) = a   ← b 变成原来的 a
a ^= b     # a = (a ^ b) ^ a = b   ← a 变成原来的 b

这三行是面试和「炫技」里的常客,但它在真实代码里其实不推荐——现代编译器对普通的临时变量交换优化得更好,可读性也更高。它的价值在于考你对异或性质的理解,而非实用。

四、位求绝对值

用补码的符号位,可以无分支地求绝对值(以 32 位为例):

mask = x >> 31          # 算术右移:x 为负得全 1(=-1),为正得 0
abs  = (x ^ mask) - mask

x 为正时 mask=0,(x^0)-0 = x;x 为负时 mask=-1(全 1),x ^ (-1) = ~x,再 -(-1) 即 ~x + 1,正是补码取负 = |x|。无分支在某些场景下比 if 更快,也是「用补码性质做算术」的漂亮示范。

五、关键定义

补码(Two's Complement)
用 ~x + 1 表示 -x 的有符号整数编码,使加减法统一成加法。n 位范围 -2ⁿ⁻¹ ~ 2ⁿ⁻¹-1(负数多一个)。避免与「一补数(反码)」混为一谈。
置位计数 / popcount(Population Count)
一个整数二进制中 1 的个数。Brian Kernighan 技巧用 n &= n-1 逐个清最低位 1,复杂度 O(置位数)。
异或的自反性(x ^ x = 0)
任意数异或自身为 0、异或 0 不变。是异或交换、「只出现一次的数字」等技巧的根。避免在两操作数指向同一内存时用异或交换。

六、复杂度

操作时间空间
数 1 的个数 · KernighanO(置位数)O(1)
数 1 的个数 · 逐位O(w) (w=字长,如 32)O(1)
异或交换 / 位求绝对值O(1)O(1)

Kernighan 在稀疏(1 很少)时明显快;若几乎全是 1,它退化到接近 O(w),与逐位法持平。硬件层面还有专门的 POPCNT 指令能做到真正的一条指令,库函数(如 __builtin_popcount)通常走它。

面试怎么考。这几个技巧是位运算题的高频落点:

  • 「数 1 的个数 / 汉明距离」——直接考 Kernighan;能说出「O(置位数)而非 O(32)」就是加分。
  • 「只出现一次的数字」(其余都出现两次)——把全部元素异或起来,成对的互相抵消(x^x=0),剩下的就是答案,O(n) 时间 O(1) 空间。这是异或自反性最经典的应用。
  • 子集枚举 / 状态压缩——用整数的每一位表示「选没选某元素」,for mask in 0..(1<<n) 枚举全部 2ⁿ 个子集,配合 popcount 数子集大小。状压 DP 的基本功。

异或交换的致命陷阱:两个操作数是同一个变量 / 同一内存位置时,会被清零。比如数组内交换写成 swap(a[i], a[j]) 而恰好 i == j:第一步 a[i] ^= a[i] 直接把它变成 0,原值丢失,再也换不回来。普通的临时变量交换没有这个问题。这是面试官最爱用来「反杀」异或交换的边界。

补码最小负数取绝对值会溢出。32 位里 INT_MIN = -2³¹,它的绝对值 2³¹ 超出了正数上限 2³¹ - 1——无论用 if 还是位技巧,结果都会回绕(通常仍是 INT_MIN 本身)。根源是补码范围不对称(负数比正数多一个)。凡是「取绝对值 / 取负」的题,都要单独想一下 INT_MIN 会不会炸。

照 README「计算置位 / 交换 / 绝对值」三节,把技巧写全并对拍验证:

① popcount 两版(Kernighan 与逐位),对一批随机数断言结果一致;② 异或交换,专门写一个 i == j 的测试用例,亲眼看它把值清零,理解为什么要加 if (i != j) 保护;③ 位求绝对值,对 0, 5, -5, INT_MAX, INT_MIN 各测一遍,看 INT_MIN 怎么溢出;④(拓展)用异或解「只出现一次的数字」,和用哈希表的解法比空间。

带走这一条:补码让 -x = ~x + 1、减法变加法,代价是范围不对称(INT_MIN 无正对应,取绝对值会溢出);数 1 用 n &= n-1 循环(O(置位数));异或的 x^x=0 是「交换 / 找唯一数」的根,但同址会清零。

七、自测题

Q1:用 Brian Kernighan 技巧数整数 n 里 1 的个数,循环体是 n &= n - 1。它的时间复杂度是?

O(置位数),即 O(n 里 1 的个数),而不是 O(字长)。每次 n &= n-1 精确抹掉一个 1,循环次数正好等于 1 的个数。所以稀疏(1 少)时远快于逐位检查 32 次的做法;极端全 1 时才退化到接近 O(字长)。能主动区分「O(置位数)vs O(32)」,是这道题的加分点。

Q2:异或交换 a^=b; b^=a; a^=b; 在什么情况下会出错?

当 a 和 b 是同一个变量 / 同一块内存(例如数组内 i == j 的自交换)时。第一步 a ^= b 变成 a ^= a,由 x^x=0 直接把它清零,原值永久丢失,后两步再也恢复不了。普通用临时变量的交换没有这个问题。这也是为什么工程上更推荐临时变量法——异或交换主要用来考你对异或性质的理解。

Q3:8 位补码能表示 -128 到 +127。为什么对 -128 取绝对值会出问题?

因为 +128 超出了 8 位补码能表示的正数上限(最大只有 +127),绝对值「装不下」,结果会溢出回绕(通常仍得到 -128)。根源是补码范围不对称:负数比正数多一个(有 -128 却无 +128)。推广到 32 位就是 INT_MIN = -2³¹ 无法取绝对值。凡涉及取负 / 绝对值的题,都要单独检查最小负数这个边界——这是补码最经典的溢出陷阱。
