栈:后进先出与调用栈

栈只认一条规矩:只在一端进出。最后放进去的,最先被拿出来——后进先出(LIFO)。规矩简单到极致,用途却铺满整个计算机世界:括号匹配、表达式求值、DFS、撤销操作,乃至你写的每个函数调用背后那根「调用栈」。这节课把这条规矩和它的三个 O(1) 操作讲透,并弄清面试里那句口头禅:「递归都能改写成显式栈。」

先回忆:前两课我们看了数组(末尾 push/pop 摊还 O(1))和链表(头部 push/pop 恒 O(1))。栈其实不是一种新的底层结构,而是给它们加一条使用纪律。先想想:数组的哪一端、链表的哪一端,天然适合当栈顶?

一、直觉:一摞盘子

把栈想成一摞盘子:你只能往最上面放一个(push),或从最上面拿走一个(pop),想看最上面那个是什么就瞄一眼(peek/top)。你永远碰不到中间和底下的盘子。正因为只在一端操作、不涉及搬移,这三个操作全是 O(1)。

栈可以用数组实现(末尾当栈顶,push=末尾追加、pop=末尾删除),也可以用链表实现(头部当栈顶)。仓库大纲明说:「可以不实现,因为使用数组来实现是微不足道的事」——因为动态数组的末尾 push/pop 本来就是摊还 O(1),天然就是一个栈。

二、栈无处不在:调用栈

你写的每次函数调用,运行时都在一根调用栈(call stack)上压入一个「栈帧」(存局部变量、返回地址);函数返回就弹出栈帧。递归为什么会「栈溢出(stack overflow)」?就是压入的栈帧太多、把这根栈撑爆了。这也解释了那句面试口头禅——递归本质上是在用系统的隐式栈,你完全可以改用一个显式的栈手动模拟,把递归改成迭代。

三、关键定义

栈(Stack)
后进先出(LIFO)的线性结构,只在一端(栈顶)push/pop。避免:把「栈(数据结构)」和「调用栈」的语义混为一谈时不加说明。
peek / top
查看栈顶元素但不弹出。与 pop 的区别:pop 会移除并返回,peek 只看不动。
LIFO(Last In, First Out)
栈的核心序:最后进入的元素最先离开。与之相对的是下一课队列的 FIFO(先进先出)。

四、复杂度:三个操作都是常数

操作平均 / 摊还最坏
push(压栈)O(1)O(n) (数组实现触发扩容)
pop(弹栈)O(1)O(1)
peek / top(看栈顶)O(1)O(1)
按值查找(非核心操作)O(n)O(n)

唯一的「不平坦」处在 push:数组实现遇到扩容那次是 O(n),但摊还仍是 O(1)——这正是动态数组那一课的结论在栈上的复用。用链表实现则连这一下抖动都没有,push/pop 恒 O(1),代价是每节点多一根指针、缓存不如数组友好。

面试怎么考。栈是「用一个后进先出的容器化解嵌套/回溯」这类题的标配:

  • 括号匹配 / 有效括号:遇左括号压栈,遇右括号弹栈比对——最经典的栈入门题。表达式求值、解码嵌套字符串同理。
  • 最小栈(Min Stack):要求 push/pop/top/getMin 全 O(1)。技巧:再开一个辅助栈同步记录「当前最小值」。这道题考的就是你能不能用「额外的栈」换时间。
  • 用栈实现队列:两个栈倒来倒去,把 LIFO 拼成 FIFO(下一课会正面讲)。反向的「用队列实现栈」也常出。
  • 把递归改成迭代:DFS、树的遍历,面试官可能要求「不用递归」,考的就是你会不会用显式栈替代系统调用栈。

空栈还 pop / peek,是最常见的崩溃点。动手前一定先判空(或让 pop 在空栈时抛异常/返回哨兵),面试写代码时漏掉这个边界会直接被扣分。

另一个坑:用数组实现栈时,别忘了它背后有扩容——单次 push 最坏是 O(n)(触发 resize),正确说法是「push 摊还 O(1)」。若面试场景对单次延迟敏感,这一下抖动就值得点出来。

带走这一条:栈不是新结构,而是「只在一端进出」这条纪律。凡是问题带有嵌套、回溯、逆序、最近优先的味道(括号、递归、undo、DFS),先想栈——它几乎总是那个让 O(1) 成立的答案。

仓库说栈「可以不实现」,但为了吃透 LIFO,建议至少各写一版:

① 数组版:复用动态数组,末尾即栈顶,写 push / pop / peek / empty,并让 pop 空栈时报错;② 链表版:头部即栈顶。写完再做两道应用题:有效括号和最小栈(辅助栈让 getMin 也 O(1))。

五、自测题

Q1:要在 O(1) 内随时取到栈中最小值(getMin),同时 push/pop 也保持 O(1),该怎么做?

用一个辅助栈与主栈同步。每次 push 时,辅助栈压入「当前元素与辅助栈顶的较小者」;pop 时两个栈一起弹。这样辅助栈顶永远是当前主栈的最小值,getMin 只需 peek 辅助栈 → O(1)。核心思路:用额外空间(一个栈)换取查询时间,这是栈类题的常见套路。若只用一个栈,想找最小值就得遍历,退化成 O(n)。

Q2:为什么说「任何递归都能改写成用显式栈的迭代」?这背后的原理是什么?

因为递归本身就是在用系统的调用栈:每层递归 = 压入一个栈帧(保存局部状态与返回位置),返回 = 弹出栈帧。既然递归的控制流就是一根栈在进出,你完全可以拿一个自己维护的显式栈手动保存这些状态,把递归翻译成 while(栈非空){ ... } 的循环。好处:避开系统调用栈的深度上限(防止 stack overflow),且能更灵活地控制遍历。DFS 的递归版与栈版,正是同一件事的两种写法。
