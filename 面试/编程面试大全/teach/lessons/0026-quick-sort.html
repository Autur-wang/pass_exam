快速排序:分区与最坏退化

快速排序是实践中最常被采用的通用排序——不是因为它渐进最快(和归并、堆排一样都是 O(n log n)),而是因为它平均常数小、原地、缓存友好。但它有一个致命软肋:选错 pivot 时会退化到 O(n²)。面试官几乎必问那句:「快排最坏情况什么时候发生、你怎么避免?」这节课把分区机制、最坏退化的成因与规避手段,以及它的近亲快速选择讲清。

回忆上一课归并:它用 O(n) 额外空间换来了稳定和「三种情况都 O(n log n)」的可预测性。快排走的是相反的取舍——原地(几乎不费额外空间)、平均更快,但代价是不稳定、且最坏会退化。带着这个对比读,你会更清楚两者各自的适用场景。

一、分区:一次把数组劈成「小 | pivot | 大」

快排的核心动作叫分区(partition):选一个元素当 pivot(基准),然后重排数组,使得——所有比 pivot 小的排到它左边,所有比它大的排到右边。一趟分区结束后,pivot 落到了它最终的正确位置,再对左右两段分别递归快排即可。

分区在原数组上用交换完成,不需要辅助数组——这就是快排原地(仅 O(log n) 递归栈)的来源,也是它比归并省内存的根本。递归的结构和归并很像(都是分治),但重点不同:归并的重活在「合并」,快排的重活在「分区」;快排分完区就不用再合并了。

二、为什么平均 O(n log n):看 pivot 分得均不均

如果每次 pivot 都恰好把数组分成大致相等的两半,那么递归树高约 log n 层,每层分区总共处理 n 个元素——n × log n。平均而言,随机数据上的 pivot 大概率落在中间地带,所以平均是 O(n log n),而且分区只做比较和交换、内存访问局部性好,实测常数比归并、堆排都小。这就是它「快」的名字由来。

三、最坏 O(n²):当分区极度不均

但如果每次 pivot 都是当前段的最大或最小值,分区就把 n 个元素切成「0 个 + (n-1) 个」——一边空、一边几乎全留。这样递归深度变成 n 层,每层还要扫近 n 个元素,总代价退化成 O(n²)。

什么输入会触发?固定选第一个(或最后一个)元素当 pivot,遇上「已经有序(或完全逆序)」的数组——每次选到的都是极值,次次最坏。讽刺的是,对已排好序的数组,最朴素的快排反而最慢。

四、怎么规避最坏:随机化与三数取中

既然最坏来自「pivot 恰好是极值」,对策就是不让攻击者(或有序输入)能预测 pivot:

  • 随机化 pivot:每次从当前段里随机挑一个当 pivot。这样任何固定输入触发最坏的概率都极低,期望仍是 O(n log n)。
  • 三数取中(median-of-three):取首、中、尾三个元素的中位数当 pivot,能有效避开「已排序数组」这个常见陷阱。
  • 三路分区(3-way / 荷兰国旗):当数组含大量重复键时,把元素分成「< pivot | = pivot | > pivot」三段,等于 pivot 的一段直接就位不再递归,避免在重复元素上做无用功。

注意:这些手段把最坏情况变成概率极小,但理论上仍存在 O(n²) 的可能——所以「快排最坏 O(n²)」这句话永远成立,不能因为随机化就说它「总是 O(n log n)」。要绝对的最坏保证,该用归并或堆排。

五、关键定义

快速排序(Quicksort)
分治排序:选 pivot、分区、对左右段递归。平均 O(n log n)、原地、常数小;最坏 O(n²)、不稳定。
分区(Partition)
围绕 pivot 重排数组,使左边全 < pivot、右边全 > pivot,pivot 落到最终位置。快排的核心操作。
快速选择(Quickselect)
快排的近亲:只递归包含目标名次的那一侧,用于求第 K 大/小,平均 O(n)、最坏 O(n²)。

六、复杂度

项目平均最坏
时间O(n log n)O(n²) (pivot 每次取极值)
额外空间(递归栈)O(log n)O(n) (退化时栈深 n)
稳定性不稳定(分区的跨距离交换会打乱相等元素)
原地?是(分区在原数组上交换完成)

空间那一行值得留意:平均 O(log n) 是递归栈深度;最坏退化时栈深达 n,不仅慢还可能爆栈。工程上常对较小的一侧递归、较大的一侧改用循环(尾递归优化),把栈深压到 O(log n),规避栈溢出。

面试怎么考。快排是排序里的头号考点,几乎每轮算法面都可能碰到:

  • 「快排最坏什么时候发生、怎么避免?」——必答题。答:pivot 每次取到极值时退化 O(n²)(典型触发是固定选首/尾 pivot 遇上已排序数组);用随机化 pivot 或三数取中规避。能主动补一句「随机化只是把概率降到极低,理论最坏仍是 O(n²)」,就是加分。
  • 快速选择(quickselect)求第 K 大/小——高频。只对含目标名次的那一侧递归,平均把 O(n log n) 排序降到 O(n);要严格最坏 O(n) 需用「中位数的中位数」选 pivot(BFPRT),面试提到即可。
  • 手写分区——Lomuto 和 Hoare 两种分区方案要能写对边界(尤其含重复元素、指针越界)。
  • 「快排 vs 归并怎么选?」——快排:内存紧、要原地、平均更快;归并:要稳定、要最坏保证、排链表。

「快排总是 O(n log n)」——错,这是最典型的扣分说法。快排平均 O(n log n),最坏 O(n²)。即便用了随机化 pivot,理论最坏仍存在(只是概率极小)。要绝对的最坏保证,用归并或堆排。

「快排是稳定的」——错。分区时会把元素跨距离交换,相等元素的相对顺序会被打乱,所以默认不稳定。这一点和归并正好相反,常被放在一起考。

忽视递归栈深。最坏退化时递归深度达 n,可能栈溢出。对小侧递归、大侧转循环的尾递归优化能把栈深控制在 O(log n)。

实现一个健壮的快排,把这些都练到:

partition(arr, lo, hi)(先写 Lomuto 版,再挑战 Hoare 版)· quicksort(arr, lo, hi) 递归 · 用随机 pivot 或三数取中替换固定选尾,对比在「已排序输入」上的比较次数变化。

进阶:实现三路分区处理大量重复键(把 [2,2,2,2,2] 排序,看等于 pivot 的一段直接跳过);实现 quickselect(arr, k) 求第 K 小,验证平均只递归一侧、比全排序快。

实验:用固定选尾 pivot 排一个已升序的数组,统计比较次数——你会亲眼看到它退化成 O(n²)。

带走这一条:快排用「原地 + 平均更快 + 缓存友好」赢得了库里的位置,代价是不稳定和最坏 O(n²)。命门全在 pivot——随机化/三数取中把最坏压成极小概率,但它永远不是「总是 O(n log n)」。

七、自测题

Q1:用「固定选最后一个元素为 pivot」的朴素快排,去排一个已经升序排好的数组,时间复杂度是多少?为什么?

O(n²)。已升序时,末尾元素永远是当前段的最大值,每次分区都把它放到最右、左边留下 n-1 个,右边 0 个——分区极度不均。于是递归深度达 n 层,每层还要扫近 n 个元素,总代价退化到 O(n²)。这正是「最坏情况」的经典触发场景,讽刺的是对最有序的输入朴素快排反而最慢。规避办法:随机化 pivot 或三数取中,让 pivot 不再固定是极值。

Q2:要在一个未排序数组里找「第 K 小的元素」,下面哪种做法平均最快?(A)全排序后取第 K 个,O(n log n) (B)用大小为 K 的堆,O(n log K) (C)快速选择 quickselect,平均 O(n)

平均最快的是 (C)快速选择,平均 O(n)。它借用快排的分区,但每趟只需递归包含第 K 名的那一侧,另一侧整段丢弃——期望工作量是 n + n/2 + n/4 + … = O(n)。(A)全排序 O(n log n) 做了多余的工作;(B)堆做法 O(n log K) 在 K 较大时也不如 quickselect。注意 quickselect 最坏也是 O(n²)(pivot 次次取极值),要严格最坏 O(n) 需用「中位数的中位数」选 pivot。

Q3:一个数组里绝大多数元素都相等(如 [4,4,4,1,4,4,9,4])。为什么普通两路分区快排在这种输入上效率低,三路分区怎么解决?

普通两路分区只把元素分成「< pivot」和「≥ pivot」两堆,大量等于 pivot 的元素会被反复卷进递归、一次次参与分区,做了大量无用功(极端情况接近 O(n²))。三路分区(荷兰国旗划分)把数组分成「< pivot | = pivot | > pivot」三段,等于 pivot 的中段一次就位、不再递归,只对两侧递归。这样重复键越多反而越快,含大量重复键时能接近 O(n)。这也是 Sedgewick 课程「重复键」一讲的核心。
