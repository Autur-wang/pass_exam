拓扑排序与环检测

「学操作系统前得先学数据结构」「编译 A 模块前得先编译它依赖的 B」——这类有依赖关系、要排出一个合法执行顺序的问题,标准答案就是拓扑排序。这节课攻透:它解决什么问题、两种主流实现(Kahn 入度法 / DFS 后序法),以及一个漂亮的副产品——它天然就是有向图的环检测器。

先回忆上一课的 DFS(第 0029 课):一路探到底再回退,并且我们强调图必须记 visited 防环。这节你会看到 DFS 的一个精妙用法——它的回退顺序(后序)反过来,恰好就是一个拓扑序。先想想:如果 A 依赖 B,那 DFS 从 A 出发时,会先「完成」谁?

一、问题:给依赖关系排出执行顺序

把任务画成有向图:一条边 A → B 读作「A 必须排在 B 前面」(A 是 B 的前置)。拓扑排序就是把所有顶点排成一条线,使得每一条边都从前指向后——没有任何一条边往回指。这样从左到右执行,任何任务开工时它的前置都已完成。

但这有个前提:图里不能有环。如果 A 依赖 B、B 又依赖 A,那谁先谁后都自相矛盾——根本排不出来。所以拓扑排序只对 DAG(有向无环图)有意义,而「能不能排出拓扑序」正好等价于「这张图有没有环」。

二、法一:Kahn 算法(入度为 0 反复出队)

直觉:一个入度为 0 的顶点,表示「没有任何前置」,可以马上执行。执行掉它,就等于把它指出去的边全删掉,于是它的后继们入度各减 1——有些后继因此也变成入度 0,轮到它们了。反复这个过程:

  1. 算出每个顶点的入度,把所有入度 0 的顶点放进队列;
  2. 队列弹出一个顶点 u,加入结果序列,并把 u 的每个后继入度减 1,减到 0 的入队;
  3. 重复,直到队列空。

上图的入度初始为:0:0, 1:1, 2:1, 3:2, 4:1。只有顶点 0 入度为 0,先出。删 0 后 1、2 入度变 0……最终排出 0,1,2,3,4。

三、法二:DFS 后序逆序

对每个未访问顶点跑 DFS,在一个顶点的所有后继都递归完成、即将回退它时,把它压入一个栈(这叫记录「完成时间」/后序)。全部跑完后,把栈倒出来(后序的逆序),就是一个拓扑序。直觉:一个顶点只有在它所有下游都处理完后才被压栈,所以它在倒序里必然排在下游前面。检测环的话,DFS 过程中若遇到一个「正在递归栈上、尚未完成」的顶点,就发现了一条后向边,即存在环。

四、关键定义

拓扑排序(Topological Sort)
有向无环图(DAG)顶点的一种线性排列,使每条边都从前指向后。存在当且仅当图无环。避免在有环图上谈拓扑排序。
入度(In-degree)
指向某顶点的边数。Kahn 算法靠反复取「入度 0」的顶点推进。
DAG(有向无环图,Directed Acyclic Graph)
有向且没有任何有向环的图。依赖关系、任务调度、编译顺序建模出来的都是 DAG(前提是没有循环依赖)。

五、复杂度

方法时间额外空间
Kahn(入度 + 队列)O(V+E)O(V) (入度数组 + 队列)
DFS 后序逆序O(V+E)O(V) (递归栈 + 结果栈)

两种法都是 O(V+E)——每个顶点、每条边各处理一次,和一次普通遍历同量级。选哪种看手感:Kahn 更直观、天然给出「是否有环」和一种 BFS 式的分层顺序;DFS 法代码更短。

面试怎么考。拓扑排序的题面几乎都有固定「暗号」,听到就该联想:

  • 「有先修/依赖关系,求一个可行的完成顺序」(课程表 II、编译顺序、构建系统)→ 直接拓扑排序,返回排出的序列。
  • 「判断能否全部完成 / 有没有循环依赖」(课程表 I)→ 拓扑排序做环检测:能排出全部 V 个顶点就无环(可完成),否则有环(不可完成)。Kahn 版判据:最终出队顶点数 < V 即有环。
  • 追问「顺序唯一吗?」→ 一般不唯一(同一层的顶点先后可换)。若每一步入度 0 的顶点始终只有一个,则唯一。

「拓扑序是唯一的」——通常错。只要某一步有多个入度 0 的顶点可选,顺序就有多种合法排法。上图里 0 之后先排 1 还是先排 2 都对。面试官问唯一性,答「一般不唯一,除非每一步都恰好只有一个可选顶点」。

「有环也能拓扑排序」——错。环意味着循环依赖,排不出线性序。用 Kahn 判环最简单:算法结束时若出队的顶点数少于 V,说明有一批顶点因为互相牵制永远入度降不到 0,即存在环。别忘了这个「计数比对」的收尾检查——很多人写完 Kahn 却漏了它,于是环检测功能失灵。

还有个方向坑:边 A → B 到底是「A 依赖 B」还是「A 先于 B」?不同题设方向相反。动手前先明确边的语义,否则拓扑序会整个反过来。

照仓库大纲实现(大纲把「检查环」和「拓扑排序」列为基于 DFS 的算法,并注明先查环再排序):

topo_sort_kahn(graph):算入度 → 入度 0 入队 → 反复出队减度 → 结果长度 < V 则报告有环。topo_sort_dfs(graph):DFS 记后序 → 逆序输出;用「访问中 / 已完成」三色标记检测后向边(环)。

动手核对:先在无环 DAG 上验证两种法都产出合法序列(可写个校验函数确认每条边都前指后);再故意加一条制造环的边,确认两种法都能报出「有环」。

带走这一条:「依赖关系求执行顺序」用拓扑排序(Kahn 入度法 / DFS 后序逆序,均 O(V+E));它同时是有向图的环检测器——排不出全部顶点就说明有环,顺序一般不唯一。

六、自测题

Q1:有 n 门课和一组先修关系 [a, b](表示学 a 前必须先学 b)。只问「这些课能不能全部修完」,不要求给出顺序。核心在判断什么?

判断这张有向图有没有环(循环依赖)。把课程建成有向图跑拓扑排序:如果能把全部 n 门课都排进拓扑序(Kahn 版:出队数 == n),就无环、能修完;若排不全,说明存在循环依赖,修不完。这道题(LeetCode「课程表 I」)本质就是用拓扑排序做环检测,连顺序都不用输出。

Q2:用 Kahn 算法跑一张 5 顶点的图,算法正常结束,但结果序列里只有 3 个顶点。这说明什么?

图里有环。剩下的 2 个顶点因为处在一个环里、互相指着对方,入度永远降不到 0,所以从没被入队。Kahn 的环检测判据就是这条:最终出队(结果序列)的顶点数 < V,即有环。这也提醒你 Kahn 写完必须补一步「结果长度 vs V」的比对,否则检测不出环。

Q3:对上文那张 DAG(边 0→1、0→2、1→3、2→3、3→4),下面哪个不是合法拓扑序?

合法的有 0,1,2,3,4 和 0,2,1,3,4(1 和 2 谁先都行,因为它们之间没有边)。不合法的例子是 0,3,1,2,4——因为存在边 1→3、2→3,3 必须排在 1 和 2 之后,这里 3 却跑到了它俩前面,违反了「边从前指后」。判断合法性只需检查:每条边的起点在序列中是否都排在终点之前。
