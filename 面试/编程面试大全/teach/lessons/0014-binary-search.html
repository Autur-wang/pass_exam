二分查找:有序区间的对折

二分查找的想法一句话能说完:数据有序时,每看一次就能砍掉一半。但它是公认「一看就会、一写就错」的算法——边界写歪一格,轻则漏解,重则死循环。这节课的窄目标,是让你背下一个永不出错的模板,并说清它为什么对。

先回忆:在讲复杂度的那几课里,我们把 O(log n) 描述成「每一步把问题规模除以一个常数」的增长类。二分查找就是 O(log n) 最纯粹的样板。请先自问一句:n = 10 亿,二分最多看多少次就能定论?(答案在正文,提示是 2 的幂。)

一、直觉:猜数字游戏

「我心里想了 1 到 100 的一个数,你来猜,我只答『大了 / 小了 / 对了』。」聪明的猜法不是从 1 挨个试,而是先猜 50:一次就排除一半。二分查找就是把这套用在有序数组上——看正中间那个,比目标小就往右半找,比目标大就往左半找,每次搜索区间对折。

「每次砍一半」意味着,n 个元素最多对折 log₂ n 次就到底。所以 n = 10 亿(≈2³⁰)时,最多约 30 次比较——这就是 O(log n) 的威力:数据翻倍,只多看一次。

二、一个不出错的模板(闭区间写法)

最稳的写法是闭区间 [lo, hi]:两端都是有效候选。

def binary_search(a, target):
    lo, hi = 0, len(a) - 1          # 闭区间 [lo, hi]
    while lo <= hi:                  # 区间非空:注意是 <=
        mid = lo + (hi - lo) // 2    # 防溢出,别写 (lo+hi)//2
        if a[mid] == target:
            return mid
        elif a[mid] < target:
            lo = mid + 1            # 左半全 < target,丢弃
        else:
            hi = mid - 1            # 右半全 > target,丢弃
    return -1                       # 区间空了,没找到

三个决定它「对」的细节,面试官会逐个盯:

  1. while lo <= hi(带等号)。因为区间是闭的,lo == hi 时区间里还剩一个元素没查,必须进循环。写成 < 会漏掉这最后一个。
  2. mid = lo + (hi - lo) // 2。而不是 (lo + hi) // 2——后者在 C/C++/Java 这类定长整数里,lo + hi 可能溢出。Python 整数不溢出,但面试写这个模板是通用肌肉记忆。
  3. 收缩必须「跨过」mid:mid + 1 / mid - 1。因为 mid 已经比过、确认不是目标,把它排除掉区间才会真正变小。少了 ±1,区间可能不再收缩 → 死循环。

为什么这样一定对?靠一条循环不变量:如果目标存在,它一定落在当前的 [lo, hi] 里。初始区间是整个数组,不变量成立;每次收缩都只丢弃「已确认不含目标」的那半,不变量保持;当 lo > hi 区间为空,说明目标从不曾在里面,返回 -1。整个算法的正确性就锚在这一句上。

三、关键定义

二分查找(Binary Search)
在有序序列上,每次用中点把搜索区间对折的查找算法,时间 O(log n)。避免在无序数组上用二分。
循环不变量(Loop Invariant)
循环每轮开始时都成立的性质。二分的不变量是「目标若存在,必在 [lo, hi] 内」,它保证收缩不丢解、终止即定论。
闭区间 / 开区间(Closed / Half-open Interval)
[lo, hi] 两端都有效(用 lo <= hi、收缩到 mid±1);[lo, hi) 右端不含(用 lo < hi、hi=mid)。避免把两套写法的细节混着用。

四、复杂度:和线性查找摆一起看

操作平均最坏
线性查找(无序也能用)O(n)O(n)
二分查找(需有序)· 时间O(log n)O(log n)
二分查找 · 空间(迭代)O(1)O(1)
二分查找 · 空间(递归)O(log n) (调用栈)O(log n)

迭代写法空间 O(1),是它相对递归的一个小优势(没有调用栈深度)。但别忘了它的隐藏前提成本:数组得先有序。如果只查一次,排序要 O(n log n),不如直接线性扫;二分真正划算的是「一次排序、多次查询」,或者数据本来就有序。

面试怎么考。纯二分很少单独作为大题,但它是海量题目的内核,面试官在意的是你写不写得对、说不说得清:

  • 当场手写模板。能一次写对、并主动说出「闭区间 + <= + mid±1」三件套和防溢出的 lo+(hi-lo)/2,是基本功过关的信号。
  • 识别「有序 / 单调 → 二分」。看到「已排序数组」「单调函数上找临界点」就该条件反射地想二分,把 O(n) 压到 O(log n)。
  • 变形题引子。旋转有序数组找目标、在近乎无限的流里定位、「二分答案」——都是这套模板的延伸,是下一课的主线。

死循环几乎都出在「区间没真正变小」。如果你收缩时写成 lo = mid(而不是 mid + 1),当 lo 和 hi 只差 1、mid 恰好算成 lo 时,区间原地踏步,循环永不终止。规则:比过的 mid 一定要被排除在下一个区间之外。哪一半用 mid±1、循环条件用 < 还是 <=,必须和你选的区间开闭方式配套,不能东拼西凑。

另一个隐形前提:无序不能二分。二分的每一步都依赖「mid 比目标小 ⟹ 目标只可能在右半」,这个推断只有序才成立。数组没排序还硬套二分,结果是随机对错。

照 README 的实现清单,把二分写全并互相验证:

① 迭代式二分(上面的模板);② 递归式二分(体会调用栈带来的 O(log n) 空间);③ 用一个大数组做压力测试:随机生成有序数组,对每一个存在的元素和若干不存在的元素都查一遍,断言结果正确——专门盯 target 落在数组第一个、最后一个、比全体都小/都大这几个边界。

加一个探针:在循环里打印每次的 (lo, mid, hi),亲眼看区间怎么对折收敛,以及查不到时它是怎么收到 lo > hi 的。

带走这一条:背死一个模板——闭区间 [lo, hi]、while lo <= hi、mid = lo + (hi - lo)/2、收缩用 mid ± 1。它正确的唯一理由是循环不变量「目标若在,必在 [lo, hi]」始终成立。

五、自测题

Q1:有人把 mid 写成 mid = (lo + hi) / 2,在一个 Java int 数组上大规模运行时偶尔出错。最可能的原因是?

当 lo 和 hi 都很大时,lo + hi 整数溢出,变成负数,mid 就成了非法下标。lo + (hi - lo) / 2 先算差(不会溢出)再折半,数学上等于 (lo+hi)/2 但永不溢出。这是二分模板里一个经典的、只在大数据下暴露的 bug,面试官很爱借它考细节。

Q2:下面哪个是二分查找能工作的必要前提?

序列必须是有序的(按查找所依据的键单调排列)。二分的每一步都靠「和 mid 比较的结果」推断目标在左半还是右半,这个推断只有序时才成立。其余说法都是干扰:数组不必是 2 的幂长度,元素不必唯一(有重复也能二分,只是要小心返回哪一个),也不要求用递归实现(迭代同样可以)。

Q3:在一个长度为 n 的有序数组上,二分查找最坏情况下大约要比较多少次?为什么是这个量级?

约 ⌊log₂ n⌋ + 1 次,即 O(log n)。每次比较后候选区间至少减半:n → n/2 → n/4 → … → 1,能减半的次数就是 log₂ n。所以 n 从 10 亿(≈2³⁰)也只需约 30 次。直观记法:数据规模翻倍,只多比一次。这就是把 O(n) 换成 O(log n) 值得的地方。
