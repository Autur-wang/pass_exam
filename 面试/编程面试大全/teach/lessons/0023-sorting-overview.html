排序全景:稳定性、原地、下界

排序不是一个算法,而是一族算法。面试官很少让你「随便排个序」——他真正想听的是:你为什么选这一个。这节课先不钻进任何单个排序的细节,而是搭一张族谱地图:所有排序都可以沿三个互相独立的轴来定位——时间复杂度、稳定性、原地性。掌握了这三根轴,后面四节(平方阶、归并、快排、堆排/非比较)就都是往地图上填格子。

回忆复杂度那节:我们区分过 O(n²)、O(n log n)、O(n) 这几个增长档位,并说过「输入翻倍时,n² 变四倍、n log n 只多一点」。这节你会看到这些档位各对应哪一类排序——以及一个反直觉的事实:并非所有排序都被卡在 O(n log n) 这道墙上。

一、三根正交的轴

拿到任何一个排序,先问三个彼此独立的问题。它们不能互相推导——这正是「正交」的意思:知道时间复杂度,推不出它稳不稳定;知道它原地,也推不出它多快。

二、稳定性:相等元素会不会被打乱

稳定排序指:两个「相等」的元素(按你比较的那个键相等),排完后它们的先后顺序和排之前一致。听起来无关紧要,但它是多关键字排序的命根子。

设想一批订单,先按「金额」排好了,现在要再按「用户名」排一次。如果第二次排序是稳定的,那么同一个用户名下的订单仍然保持金额有序——你用两次简单排序就实现了「先按名、名内按额」的复合排序。若第二次不稳定,金额的顺序就被搅乱,前功尽弃。

三、比较排序的下界:那道 Ω(n log n) 的墙

为什么冒泡、归并、快排再怎么优化,平均都逃不过 O(n log n)?因为它们都是比较排序——只靠「两个元素谁大」这一种信息来决定顺序。n 个元素有 n! 种可能的排列,每做一次比较最多把候选排列砍掉一半;要从 n! 种里锁定唯一答案,至少需要 log₂(n!) 次比较,而 log₂(n!) ≈ n log n。这就是决策树论证:任何只靠比较的排序,最坏情况都需要 Ω(n log n) 次比较。

但这道墙有个前提——「只靠比较」。如果你能利用元素本身的结构(比如它们都是 0~1000 的小整数),就不必两两比较,可以直接按值归位,从而突破到 O(n)。这类非比较排序(计数、基数、桶)是下界的例外,我们在 0027 展开。记住这个例外,能拆穿面试里最常见的一句错话。

四、关键定义

稳定排序(Stable Sort)
相等元素的相对顺序在排序后保持不变。归并稳定;快排、堆排一般不稳定。避免说「快排是稳定的」。
原地(In-place)
只用 O(1)(或 O(log n) 递归栈)额外空间完成排序。快排、堆排、平方阶三兄弟都原地;归并(数组版)需 O(n) 额外空间,不原地。
比较排序(Comparison Sort)
只靠元素两两比较决定顺序的排序,下界 Ω(n log n)。避免说「所有排序最快都是 O(n log n)」——那漏了非比较排序。

面试怎么考。排序几乎不会孤立出现,但它是「你懂不懂取舍」的试金石。高频问法:

  • 「你会用哪个排序,为什么?」——标准答案不是报一个名字,而是先反问需求:数据量多大?要不要稳定?内存吃紧吗?已经近乎有序了吗?能问出这些,面试官就知道你理解「排序是选择题」。
  • 「稳定性在什么场景重要?」——答多关键字排序(先按 A 排、再按 B 排要保住 A 的序),这是最有说服力的例子。
  • 「链表适合哪种排序?」——归并。链表不支持 O(1) 随机访问,快排和堆排都依赖下标跳转会退化;归并只需顺序遍历,且合并两个有序链表可做到 O(1) 额外空间。

「快排是稳定的」——这是最常被扣分的一句。快排在分区时会把元素跨距离交换,相等元素的相对顺序会被打乱,所以默认不稳定。同理选择排序也不稳定(它把最小值和当前位交换,可能越过相等元素)。

「所有排序最快都是 O(n log n)」——漏了非比较排序。这句只对比较排序成立。计数/基数/桶排序不做两两比较,在值域有界时能做到 O(n)。加上「比较」这个限定词,答案才准确。

带走这一条:排序是三根正交轴上的选择题——快慢、稳不稳、费不费内存。没有全能选手,面试的正确姿势是先问清约束,再从这张地图上指出最合适的那一个。

六、自测题

Q1:一位面试官说「比较排序的最坏时间下界是 Ω(n log n),所以任何排序都不可能比 O(n log n) 更快」。这句话哪里错了?

错在把「比较排序」的结论扩大到了「任何排序」。Ω(n log n) 的下界只约束只靠两两比较的排序,论证来自决策树:n! 种排列需要至少 log₂(n!)≈n log n 次比较来区分。非比较排序(计数、基数、桶)利用元素值本身的结构直接归位,不受此下界约束,在值域有界时可达 O(n)。所以正确表述要加限定词:「比较排序的下界是 Ω(n log n)」。

Q2:你需要对一个只能顺序访问、不支持下标跳转的链表排序,且要求 O(n log n)。下面哪个排序最合适,为什么?(A)快排 (B)堆排 (C)归并排序

正确答案是 (C)归并排序。快排(A)和堆排(B)都严重依赖 O(1) 随机访问——快排要在分区时来回跳下标,堆排要靠 2i+1/2i+2 定位子节点,在链表上这些都退化成 O(n) 的遍历。归并只需顺序遍历来拆分和合并,与链表天然契合,而且合并两个有序链表可以只改指针、做到 O(1) 额外空间(数组版归并反而要 O(n) 辅助数组)。这也是为什么标准库对链表排序普遍用归并。

Q3:归并排序和快速排序平均时间都是 O(n log n)。仅凭这一点,能推断出它们的稳定性和空间占用相同吗?

不能。这正是「三根轴正交」的意义:时间复杂度推不出另外两根轴。归并稳定但需 O(n) 额外空间;快排不稳定但原地(仅 O(log n) 递归栈)。同为 n log n,取舍完全不同——这也是面试官爱把这两个放一起对比的原因。
