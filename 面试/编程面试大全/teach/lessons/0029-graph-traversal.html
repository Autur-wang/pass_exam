图的遍历:BFS 求最短、DFS 探连通

有了图的表示(上一课),现在要把图「走一遍」。图论里超过一半的面试题,内核都是两种遍历之一:BFS(广度优先,逐层扩散)和 DFS(深度优先,一条路走到黑)。这节课攻透它们的机制、复杂度,以及从树遍历跨到图遍历时那个绝不能忘的动作——记 visited。

先回忆树的 BFS 与 DFS(第 0018 课):BFS 靠一个队列逐层展开,DFS 靠递归(或栈)一路探到叶子再回退。图的遍历用的是同一套机制——但树是「没有环」的特例。先想一个问题:树遍历为什么从来不用记「这个节点访问过没有」?而图为什么非记不可?

一、和树遍历只差一件事:图有环

树里从根出发,每个节点只有一个父亲,你永远不会绕回来,所以「走过的就不会再走」是自动成立的。图不一样——图可以有环。A→B→C→A 这样一圈,如果你不记录「A 已经访问过」,遍历就会 A→B→C→A→B→C… 无限循环下去。

所以图遍历的模板比树遍历只多一样东西:一个 visited 集合(或布尔数组)。每到一个顶点,先问「来过没有?来过就跳过」,再标记为已访问。这一个改动,把树遍历升级成了图遍历。

二、BFS:一圈一圈往外扩

BFS 用队列(FIFO):从起点出发,先访问所有「距离 1」的邻居,再访问「距离 2」的,像水波纹一圈圈扩出去。正因为它严格按距离由近到远展开,在无权图上,第一次到达某个顶点时走过的边数,就是从起点到它的最短路径长度。

三、DFS:一条路走到底再回头

DFS 用栈(或递归调用栈):从起点冲进一个邻居,再冲进它的邻居,一路探到没有新顶点可走,才回退换另一条路。它不保证按距离展开,所以不能用来求无权最短路——但它天然适合「探到底」类问题:一张图里有几个连通块?两点之间存不存在一条路径?能不能检测出环?

四、关键定义

BFS(广度优先搜索,Breadth-First Search)
用队列逐层扩展的图遍历;在无权图上,首次到达一个顶点的层数即为最短路径长度。避免「BFS 和 DFS 只是顺序不同、效果一样」——只有 BFS 保证无权最短路。
DFS(深度优先搜索,Depth-First Search)
用栈/递归一路探到底再回退的图遍历;适合连通分量、路径存在性、环检测。不保证最短路。
visited(已访问标记)
图遍历中记录哪些顶点已处理过的集合。图有环,必须记 visited 才不会无限循环;树无环,可省。

五、复杂度:两者相同

遍历(邻接表)时间额外空间
BFS(队列)O(V+E)O(V) (队列 + visited)
DFS(栈 / 递归)O(V+E)O(V) (栈深最坏 V)

时间同为 O(V+E):每个顶点入队/入栈一次(V),每条边在遍历邻居时被看一次(无向图 2E,仍是 O(E))。若图用邻接矩阵存,遍历每个点的邻居要扫一整行,退化成 O(V²)——这又是上一课「表 vs 矩阵」取舍的回声。

面试怎么考。见到图题,先问自己一句「无权最短?还是探连通/路径?」,答案直接决定用哪个:

  • 无权图最短路 / 最少步数(迷宫最少几步、单词接龙、二叉树层序)→ BFS。看到「最少」「最短」「几步」且边无权,几乎就是它。
  • 连通分量 / 岛屿数量(数一数有几片相连的陆地)→ DFS 或 BFS 都行,或用并查集(第 0046 课)。做法:对每个还没 visited 的顶点发起一次遍历,发起了几次就有几个连通块。
  • 路径是否存在 / 全排列式搜索→ DFS(常配回溯)。
  • 网格题:把格子当顶点、上下左右当边,直接在二维数组上跑 BFS/DFS,visited 可以复用原数组(把访问过的格子改成特殊值)。

忘记 visited = 死循环。这是图遍历第一大坑。树遍历代码直接搬到图上、没加 visited,一旦图里有环(而图很容易有环)就会栈溢出或队列爆炸。记住这条因果:树无环所以不用记,图有环所以必须记。

「DFS 也能求最短路」——错。DFS 找到的是某一条路径,不是最短的那条。无权最短路必须用 BFS(靠逐层扩展的性质保证)。反过来,带权图连 BFS 都不够,得用下下课的 Dijkstra——BFS 只是「所有边权都为 1」的特例。

还有个细节:visited 要在入队时标记,而不是出队时。否则同一个顶点可能被多个邻居重复塞进队列,虽然结果仍对,但会浪费空间、在某些实现里还会错算距离。

照仓库大纲把这些遍历都手写一遍(大纲明确要求实现邻接表/邻接矩阵、递归/迭代的多种版本):

bfs(start)(队列 + visited,同时记录每个点的距离 dist[])· dfs_recursive(u)(递归 + visited)· dfs_iterative(start)(显式栈)· count_components()(对每个未访问点发起一次 DFS,计数)。

动手核对:造一张带环的图(比如 A-B-C-A),故意先不加 visited 跑一遍,亲眼看它死循环;再加上 visited,确认恢复正常。这个对比会让你永远记住这个坑。

带走这一条:无权图求最短路用 BFS(队列,逐层),探连通/路径存在用 DFS(栈/递归);两者都必须记 visited,因为图有环——这是它和树遍历唯一的本质差别。

六、自测题

Q1:在一个 m×n 的 0/1 网格里,1 表示陆地、0 表示水,上下左右相连的 1 算同一座岛。求岛屿数量。该用什么思路?

遍历 + 连通分量计数。把每个陆地格子当顶点,四个方向的相邻陆地当边。扫描整个网格,遇到一个还没访问过的 1,就从它发起一次 DFS(或 BFS),把这一整座岛全部标记为已访问;发起了几次遍历,就有几座岛。BFS、DFS 都可以;visited 可以直接把访问过的 1 改成 0 来省空间。这就是「隐式图 + 连通分量」的经典套路。

Q2:一张无权图,你要求从 s 到 t 的最短步数。有人用 DFS 找到了一条 s 到 t 的路径就返回长度。这样对吗?

不对。DFS 找到的是它恰好先探到的某一条路径,完全可能绕远,不保证最短。无权最短路必须用 BFS:它逐层扩展,第一次到达 t 时的层数就是最短步数,这由「按距离由近到远访问」的性质保证。这是 BFS 和 DFS 一个不可互换的关键区别。

Q3:BFS 遍历一张用邻接表存的图,V 个顶点、E 条边,时间复杂度是?如果这张图改用邻接矩阵存呢?

邻接表:O(V+E)——每个顶点入队一次、每条边被检查一次。邻接矩阵:O(V²)——遍历每个顶点的邻居时要扫矩阵的一整行(V 个格子,无论那里是否真有边)。所以稀疏图上邻接表快得多,这正是上一课选表不选矩阵的又一理由。
