堆排序与非比较排序

这节课收尾排序族谱,讲两类特别的排序。堆排序是三个 O(n log n) 里唯一「既原地又最坏有保证」的——听起来完美,却几乎没有库用它,为什么?非比较排序(计数、基数)则打破了上一节反复强调的 Ω(n log n) 下界,做到 O(n)——但这个「超能力」有严格的前提。理解「为什么堆排不受宠」和「非比较凭什么能突破下界」,你对排序的理解就真正立体了。

回忆堆那节:堆是存在数组里的完全二叉树,大顶堆的堆顶永远是最大值,取堆顶 O(1)、下沉 sift-down 是 O(log n)。也回忆排序全景里那道墙——比较排序下界 Ω(n log n)。这节两个主角,一个把堆变成排序,另一个则要翻过那道墙。

一、堆排序:反复取堆顶

堆排序就两步。第一步建堆:把无序数组原地整理成一个大顶堆。第二步反复取极值:把堆顶(当前最大值)和数组末尾交换,末尾就此固定为已排序区;然后堆大小减一、对新堆顶做一次 sift-down 恢复堆序;重复 n-1 次,整个数组就从小到大排好了。全程在原数组里交换完成,所以原地。

二、建堆是 O(n) 不是 O(n log n)

一个反直觉但极高频的考点:把无序数组整理成堆(heapify)是 O(n),不是 O(n log n)。

朴素想法是「插入 n 个元素,每次 O(log n)」得出 O(n log n)——但那是错的建堆方式。正确的建堆用自底向上:从最后一个非叶子节点往前,对每个节点做 sift-down。关键在于——绝大多数节点都靠近底层,下沉的高度很小。底层一半的节点高度为 0(不用动),上一层 1/4 的节点最多下沉 1 层……把「节点数 × 各自高度」求和,级数收敛到 O(n) 而非 O(n log n)。所以整个堆排序的 O(n log n) 是被第二阶段「n 次 O(log n) 下沉」主导的,建堆本身很便宜。

三、堆排序为什么不受库青睐

堆排序看似三全其美:O(n log n)、最坏也有保证、还原地。但主流标准库排序几乎都不用它,原因是缓存不友好。堆排序访问元素靠 2i+1/2i+2 这种下标跳转,在数组里是大跨步、无规律的访问,几乎每次都错过 CPU 缓存;而快排的分区是顺序扫描、局部性极好。同为 O(n log n),快排的实测常数因子明显更小。堆排还不稳定。所以它的位置很尴尬——真正需要「原地 + 最坏保证」时才轮到它(如 introsort 里作为快排退化时的兜底),常规场景快排更快、要稳定用归并。

四、非比较排序:翻过 Ω(n log n) 那道墙

上一节说过,只靠比较的排序逃不出 Ω(n log n)。非比较排序根本不做两两比较,而是利用元素值本身的结构直接把它归位,因此不受那道墙约束。

计数排序(Counting Sort):当元素都是范围 [0, k) 的小整数时,开一个大小 k 的桶,先统计每个值出现几次,再按值从小到大依次填回。全程不比较,时间 O(n + k)、稳定(从后往前填能保序)。前提是值域 k 有界且不太大——若 k 远大于 n(如对 32 位整数直接计数要开 40 亿个桶),就退化成灾难。

基数排序(Radix Sort):把「大值域」拆成「多位、每位小值域」。对多位数,从最低位到最高位逐位用稳定的计数排序排一遍(LSD)。d 位数就排 d 趟,时间 O(d·(n+k))。它依赖每一趟的稳定性来保住高位已排好的顺序——这正是稳定性在算法内部被用上的经典案例。

五、关键定义

堆排序(Heapsort)
建堆 O(n) + 反复取堆顶下沉。O(n log n)、原地、不稳定。缓存不友好,故实测常数大于快排。
建堆 / heapify
把无序数组自底向上整理成堆,O(n) 而非 O(n log n)——因大多数节点靠近底层、下沉高度小。
计数排序(Counting Sort)
对值域 [0,k) 小整数按值计数归位,O(n+k)、稳定。前提:值域 k 有界。
基数排序(Radix Sort)
按位(从低到高)反复用稳定排序,把大值域拆成多趟小值域,O(d·(n+k))。

计数/基数的时间不含 log n——这不违反下界,因为它们不是比较排序。代价写在空间(要额外的桶)和前提(值域/位数有界)上。天下没有免费的午餐,只是这次的账记在了别处。

面试怎么考。

  • 「建堆的复杂度是多少?」——陷阱题。答 O(n)(自底向上),并能一句话说明「大多数节点在底层、下沉高度小,级数收敛到 O(n)」。答成 O(n log n) 是常见失分。
  • 「既然堆排原地、最坏也 O(n log n),为什么库不用它?」——答缓存不友好(大跨步下标访问,缓存命中率低),实测常数大于快排;而且不稳定。
  • 「什么时候用计数/桶/基数排序?」——当值域已知且不大(如给年龄排序、给成绩 0~100 排序、给字符串按固定长度排序)时,用非比较排序可达 O(n),吊打任何比较排序。面试官想听你说出「前提」。
  • 「基数排序为什么必须用稳定的子排序?」——因为高位相同的元素要靠低位已排好的顺序,若子排序不稳定,前面几趟的成果会被打乱。

「建堆是 O(n log n)」——错,是 O(n)。逐个插入建堆才是 O(n log n);正确的自底向上 heapify 是 O(n)。堆排序整体的 O(n log n) 由第二阶段 n 次下沉主导,不是建堆。

「计数/基数排序总是 O(n),比快排强」——错,漏了前提。计数排序要求值域 k 有界且不太大:若 k ≫ n(如对任意 32 位/64 位整数),桶的空间和初始化开销爆炸,反而不如比较排序。基数排序也需要位数 d 可控。它们不是万能钥匙,只在特定值域下才划算。

别忘了堆排不稳定。取堆顶与末尾交换的动作会跨距离移动元素,打乱相等元素的相对顺序。

1) 堆排序:实现 heapify(arr)(自底向上,从最后一个非叶节点向前 sift-down)与 heap_sort(arr)(反复 swap 堆顶到末尾、缩小堆、下沉)。打印建堆时每个节点下沉的步数,亲眼验证总步数是 O(n) 量级而非 n log n。

2) 计数排序:对 [0,100] 内的整数排序,统计频次再归位。故意从后往前填回,验证它对带标签的相等元素保持稳定。

3) 基数排序:用计数排序作子过程,对多位整数从低位到高位逐位排,观察每趟如何保住高位顺序。

带走这一条:三个 O(n log n) 排序渐进相同、常数不同——快排缓存友好最快,堆排缓存不友好故库不用它。想更快只能换赛道:值域有界时用非比较排序(计数/基数)突破 Ω(n log n) 到 O(n),代价是额外空间和对值域的前提。

七、自测题

Q1:把一个无序数组用自底向上的方式整理成堆(heapify),时间复杂度是多少?为什么不是 O(n log n)?

是 O(n)。自底向上建堆时,每个节点做的是 sift-down,代价正比于它到叶子的高度。而堆里大多数节点都靠近底层、高度很小:约一半节点是叶子(高度 0,不用动),1/4 高度 1,1/8 高度 2……把「该高度的节点数 × 高度」求和,得到 Σ (n/2^(h+1))·h,这个级数收敛到 O(n)。反之,「逐个 insert n 个元素」每次 O(log n) 才是 O(n log n),那是另一种(更慢的)建堆方式。堆排序整体的 O(n log n) 来自第二阶段 n 次取顶下沉,不是建堆。

Q2:堆排序原地、最坏也是 O(n log n),看起来比快排还稳。为什么主流标准库排序几乎都不用它?

核心原因是缓存不友好。堆排序靠 2i+1/2i+2 的下标跳转访问元素,在数组里是大跨步、无规律的访问,CPU 缓存命中率低;快排的分区是顺序扫描,局部性极好。二者渐进都是 O(n log n),但堆排的实测常数因子明显更大,实际更慢。再加上堆排不稳定。所以它的实用位置很窄——通常只作为「需要原地又要防止快排退化」的兜底(如 introsort 在快排递归过深时切到堆排)。

Q3:一位候选人说「计数排序是 O(n),所以任何数据都该用它代替快排」。这句话在什么情况下站不住脚?

当值域 k 远大于元素个数 n 时站不住脚。计数排序的复杂度是 O(n + k),空间也要 O(k) 个桶。若元素是任意 32 位整数(k ≈ 40 亿)而 n 只有几千,那么开桶和遍历值域的开销 k 完全主导,既慢又爆内存,远不如 O(n log n) 的快排。计数排序只在值域有界且不大(如年龄、成绩、固定长度字符)时才划算。它不违反 Ω(n log n) 下界(因为不是比较排序),但把成本转嫁到了空间和「值域前提」上——没有免费的午餐。
