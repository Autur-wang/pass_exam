堆与优先队列:数组里的完全二叉树

前几课的 BST 追求「整体有序」,代价是可能退化、还得费劲平衡。但很多场景我们只关心极值——当前最大(或最小)的那一个。为此付出「全局有序」的代价太奢侈。堆(Heap)就是这个需求的精确答案:它只保证堆顶是极值,靠一棵完全二叉树做到取极值 O(1)、增删 O(log n),而且整棵树塞在一个数组里、连指针都不用。它就是「优先队列」最常见的底层实现。

先回忆两件事:上一课族里提过完全二叉树(第 0018 课——除最后一层外全填满、最后一层靠左连续);还有第 0007 课的数组(连续内存、O(1) 随机访问)。这节的魔法就是把这两者叠起来:先想想——如果一棵二叉树「没有空洞、逐层靠左填满」,是不是就能按层从左到右编号、直接摊平进数组,而不丢失父子关系?

一、堆是什么:完全二叉树 + 堆序

堆是一棵满足两条性质的树:①形状是完全二叉树(逐层填满、最后一层靠左);②堆序——大顶堆里每个节点都 ≥ 它的两个孩子(小顶堆则 ≤)。注意堆序只管父子、不管左右兄弟,所以堆不是排好序的,它只保证一件事:根(堆顶)是全局极值。

二、为什么能塞进数组:下标即指针

正因为是完全二叉树(没有空洞),按层从左到右给节点编号 0,1,2,…,就能直接摊进数组,父子关系用下标算出来,无需任何指针:

三、两个核心动作:上浮与下沉

堆的一切修改,都靠两个「把违反堆序的节点挪回正确层级」的操作:

插入 = 追加 + sift_up(上浮):新元素先放到数组末尾(树的最后一个位置,仍是完全二叉树),然后不断和父比较,比父大就交换、往上冒,直到不再比父大或到根。走过的路不超过树高,O(log n)。

弹出极值 = 取根 + 末尾补位 + sift_down(下沉):堆顶就是答案(O(1) 读到);删它时,把数组最后一个元素搬到根,再让它不断和较大的那个孩子比较、比孩子小就交换下沉,直到就位。同样 O(log n)。

四、建堆是 O(n),不是 O(n log n)

把一个乱序数组原地变成堆,叫 heapify。做法是自底向上:从最后一个非叶节点起、倒着对每个节点做一次 sift_down。直觉上「n 个节点 × 每个 log n = O(n log n)」,但这是高估——因为绝大多数节点在底层、下沉距离极短:一半是叶子(0 步),只有极少数靠近根的节点才走满 log n。把各层代价求和 Σ(节点数 × 该层最大下沉步数)是收敛级数,总和是 O(n)。这是面试高频的「反直觉复杂度」。

五、关键定义

堆 / 优先队列(Heap / Priority Queue)
用完全二叉树(通常存在数组里)实现、满足堆序的结构;取极值 O(1),插入/弹出 O(log n)。优先队列是抽象接口,堆是它最常见的实现。避免把「堆(数据结构)」和内存的「堆(heap 区)」混用而不说明。
堆序 vs 全序(heap order vs total order)
堆序只约束「父与子」,不约束兄弟,所以堆只保证堆顶是极值,避免误以为「堆是排好序的」。
sift_up / sift_down(上浮 / 下沉)
把一个暂时违反堆序的节点沿树高向上或向下移动到正确层级,是插入与弹出的引擎,单次 O(log n)。

六、复杂度:一张必须背下来的表

操作平均 / 摊还最坏
取极值 get_max(读堆顶)O(1)O(1)
插入 insert(sift_up)O(log n)O(log n)
弹出极值 extract_max(sift_down)O(log n)O(log n)
建堆 heapify(自底向上)O(n)O(n)
堆排序 heap_sortO(n log n)O(n log n)

空间 O(n)(就那一个数组,原地操作)。注意堆不支持 O(log n) 的「按值查找任意元素」——它只对极值高效,想查中间某个值仍是 O(n)。堆排序:先 heapify O(n),再反复弹出极值 n 次(每次 O(log n)),合计 O(n log n),且原地、但不稳定。

面试怎么考。看到这些信号,几乎就是在喊「上优先队列(堆)」:

  • Top-K / 第 K 大(小):维护一个大小为 K 的堆,O(n log K),比全排序 O(n log n) 更省。
  • 流式中位数(数据流不断来):一个大顶堆管左半、一个小顶堆管右半,两堆顶取中位数,每次插入 O(log n)。
  • 合并 K 个有序链表/数组:把每条的当前头塞进小顶堆,每次弹最小、再补该来源的下一个,O(N log K)。
  • 被追问建堆复杂度,答「自底向上 heapify 是 O(n),不是 O(n log n)」并能讲出「大多数节点在底层、下沉浅」的理由,是明显的加分项。

「堆是排好序的」——错。堆只保证堆顶是极值,兄弟节点、乃至不同分支之间毫无顺序可言。想拿到「从大到小的全序」,得一个一个弹出(那就是堆排序了)。

「建堆是 O(n log n)」——也错。逐个 insert 建堆才是 O(n log n);自底向上 heapify 是 O(n)。这是面试最爱设的坑,张口就说 O(n log n) 会直接暴露没推过那个求和。另外别忘了:堆排序虽然 O(n log n) 且原地,但它不稳定,相等元素的相对次序可能被打乱。

照仓库「实现一个大顶堆」清单,全部基于一个数组 + 下标运算(千万别真的建树节点):

insert(x) · sift_up(i) · get_max()(读堆顶不删)· extract_max() · sift_down(i) · heapify(arr)(自底向上建堆)· heap_sort(arr)(建堆后反复弹极值,原地)。

小实验:在 heapify 里数一下 sift_down 触发的总交换次数,对不同规模 n 打印出来,你会看到它大致线性增长(≈O(n)),而不是 n log n——亲手验证那个反直觉结论。

带走这一条:堆 = 塞进数组的完全二叉树,只保证堆顶是极值(取极值 O(1)、增删 O(log n))。看到「Top-K / 第 K 大 / 流式中位数 / 合并 K 路」就想优先队列。记牢:自底向上建堆是 O(n)。

七、自测题

Q1:为什么自底向上 heapify 建堆是 O(n),而不是 O(n log n)?

「n 个节点各下沉 log n」是高估:heapify 从最后一个非叶节点倒着做 sift_down,而节点的下沉距离等于「它到最深叶的高度」,不是整棵树高。底层节点占绝大多数、高度极小——一半是叶子(0 步),只有靠近根的极少数才走满 log n。把各层代价 Σ(该层节点数 × 该层高度)= Σ h·n/2^{h+1} 求和,这个级数收敛到 O(n)。相反,「逐个 insert 建堆」每次都可能上浮 log n,那才是 O(n log n)。

Q2:要在一个不断到来的数据流里实时维护「第 K 大」的元素,最合适的结构是?

一个大小为 K 的小顶堆。堆里始终只留当前最大的 K 个,堆顶是这 K 个里最小的——那正好就是「第 K 大」。新元素来时:若比堆顶大就弹掉堆顶、把它放进去(O(log K)),否则丢弃。排序数组每来一个要 O(n) 维护有序、哈希表管不了顺序、单调栈解决的是另一类「下一个更大元素」问题——都不对。这题也说明堆的杀手锏:只为极值买单,不为全局有序买单。
