组合与概率:面试要的那点数学

面试不会考你证明中心极限定理,但会以两种方式塞给你概率与组合:一是「把样本空间数清」的分析题(这台机器出故障的概率、抽到某组合的概率),二是「写一个等概率随机」的编码题(洗牌、抽样、用一个随机数造另一个)。这两类的失分点惊人地集中——区间写错一格、有序无序混淆。这节把面试真正用得上的那点数学收拢成一张可背的表和三个必会算法。

回忆回溯那课:我们在决策树上系统地枚举所有组合与排列。当时关心的是「怎么把它们一个不漏地生成出来」;这节换个问题——「一共有多少个?」以及「随机取一个,每个被取到的概率相等吗?」枚举和计数是同一枚硬币的两面。

一、排列 vs 组合:先问一句「顺序算不算」

这是全部组合数学的分水岭,也是面试最常混的地方。判据只有一句:取出来之后,顺序不同算不算不同的结果?

量公式直觉
阶乘 n!n·(n−1)···2·1n 个元素全排列的种数
排列 P(n,k)n! / (n−k)!取 k 个并排好序:第 1 位 n 选,第 2 位 n−1 选…
组合 C(n,k)n! / (k!(n−k)!)取 k 个不管序:排列数再除以 k! 消掉内部顺序

两个好用的等式:C(n,k) = C(n,n−k)(选 k 个留下 = 选 n−k 个丢掉);C(n,0) = C(n,n) = 1(一种都不选、全选,各一种)。杨辉三角的每一行就是 C(n,0)…C(n,n)。

二、概率的三块地基

面试概率题几乎只用到三样东西,把它们分清就够用:

独立事件(Independent)
一个发生与否不影响另一个。此时 P(A 且 B) = P(A)·P(B)(概率相乘)。掷两次骰子、连续抽后放回都是独立。
条件概率(Conditional)
P(A|B) = P(A 且 B) / P(B)——「已知 B 发生,A 的概率」。抽牌不放回、贝叶斯类题都靠它。避免把 P(A|B) 和 P(B|A) 当成一回事。
期望(Expectation)
E[X] = Σ x·P(X=x),即所有取值按概率的加权平均。杀手锏是期望的线性性:E[X+Y] = E[X]+E[Y],无论 X、Y 是否独立——很多看着吓人的期望题拆成一堆小指示变量相加就秒了。

还有两条互斥/加法的常识:互斥事件(不可能同时发生)P(A 或 B) = P(A)+P(B);一般情形要减去重叠 P(A)+P(B)−P(A 且 B)(容斥)。以及最省事的技巧:正难则反,「至少一个」用 1 − P(一个都没有) 往往比直接算简单得多。

三、面试三件套(等概率随机)

1. Fisher-Yates 洗牌——把数组原地打乱成均匀随机排列。从后往前,每一步把当前位置和「它及它之前」范围内随机挑的一个元素交换:

for i from n-1 downto 1:
    j = random_int(0, i)   // 闭区间 [0, i]，务必含 i 自己
    swap(a[i], a[j])

为什么均匀?第 i 步从 i+1 个候选里等概率选一个放到位置 i,乘下来恰好是 n! 种排列各 1/n!。区间一旦写成 random(0, n-1)(整个数组),就变成 nn 种等概率路径映射到 n! 种排列——不整除,必然有偏。

2. 蓄水池抽样(Reservoir Sampling)——从一个长度未知或超大的流里等概率抽 1 个(或 k 个),只用 O(1) 额外空间。先留住第 1 个,看到第 i 个元素时,以概率 1/i 用它替换当前保留者:

keep = stream[0]
for i from 1 to n-1:          // 0-indexed，i 是「第 i+1 个」
    if random_int(0, i) == 0: // 命中概率 1/(i+1)
        keep = stream[i]

归纳可证每个元素最终被留下的概率都是 1/n。它的美在于:你不需要事先知道 n,读到哪算到哪——处理日志流、大文件采样的标配。

3. 用 rand5 造 rand7——只有等概率 1~5 的随机源,要造等概率 1~7。核心思路:先合成一个更大的均匀范围,再拒绝掉多出来的尾巴(拒绝采样):

do {
    v = 5 * (rand5() - 1) + rand5();  // 均匀落在 1..25
} while (v > 21);                     // 拒绝 22..25，保持均匀
return (v - 1) % 7 + 1;               // 1..21 均匀 → 映射到 1..7

21 是 7 的倍数,所以 1..21 mod 7 后 7 个余数各出现 3 次、完全均匀;剩下的 22..25 不是整倍数,直接丢弃重来。丢弃看似浪费,但期望重试次数很小(21/25 一次成功)。

四、复杂度速记

算法时间额外空间
Fisher-Yates 洗牌O(n)O(1) (原地)
蓄水池抽样(抽 1)O(n)O(1)
rand5 造 rand7O(1) 期望O(1)

面试怎么考。三种形态:

  • 数样本空间:「一副牌抽 5 张是同花的概率」——分子是「有利结果数」,分母是「总结果数」,两个都用组合数数清,别数重也别数漏。
  • 等概率编码:直接让你写洗牌 / 抽样 / randM→randN,并要你证明均匀性。能讲清「为什么每种结果概率相等」比写对代码更关键。
  • 期望计算:抛硬币直到正面的期望次数、随机游走步数——先想能不能用期望线性性把它拆成小块相加。

Fisher-Yates 的区间只要错一格就不均匀。正确是从 [0, i](含 i 自己)里选;写成 [0, i-1] 或固定 [0, n-1] 都会引入偏差,而且这种偏差肉眼看不出来、只有统计几万次才现形——面试官专挑这里问「你确定含不含 i?为什么」。

有序无序别混。「密码锁 3 位」是排列(1-2-3 ≠ 3-2-1),「从 5 人选 3 人组队」是组合(顺序无关)。一句自检:换个顺序还是同一个结果吗?是 → 组合,否 → 排列。

拒绝采样别偷懒省掉拒绝。用 rand5()%7 之类直接取模而不合成大范围、不拒绝尾巴,余数分布必然不均——这是最常见的错解。

写代码 + 用统计验证均匀性(这一步才是重点):

① 实现 Fisher-Yates,对 [0,1,2] 洗牌一百万次,统计 6 种排列各出现的频率——应各约 1/6。再故意把区间改成 [0, n-1],看频率如何倾斜。② 实现单元素蓄水池抽样,对长度 10 的流跑百万次,验证每个元素约 1/10 被选中。③ 实现 rand7()(用一个假的均匀 rand5()),统计 1~7 的频率是否均匀,并数一下平均重试几次。

带走这一条:组合题先问「顺序算不算」定排列还是组合;随机题的正确性不在代码在证明——洗牌的区间必须含当前位、造随机数必须「合成大范围 + 拒绝尾巴」保持整除均匀。

五、自测题

Q1:一个班 30 人,要选出「班长、副班长、学习委员」各一名(一人一职)。这是排列还是组合?共几种?若改成「选 3 名普通委员」呢?

选三种不同职务:换个顺序(张当班长 vs 张当副班长)是不同结果 → 排列,P(30,3) = 30·29·28 = 24360 种。选 3 名不分职务的普通委员:{张,李,王} 无论谁先谁后都是同一组 → 组合,C(30,3) = 30·29·28 / 3! = 4060 种。两者正好差一个 3! = 6 倍,这个 6 就是三个人内部的排序数。

Q2:有人这样写洗牌:for i in 0..n-1: j = random(0, n-1); swap(a[i], a[j])。它错在哪?为什么结果不均匀?

每一步都从整个数组 [0, n-1] 里随机挑,共产生 nn 条等概率的执行路径。但排列只有 n! 种,而 nn 不能被 n! 整除(n≥3 时),所以必然有些排列被更多路径命中、概率偏高。正确的 Fisher-Yates 第 i 步只从 [0, i] 里挑,总路径数恰是 n·(n-1)···1 = n!,与排列一一对应,均匀。这题就是把「候选范围」写死成整段导致的经典 bug。

Q3:连续掷一枚均匀硬币,直到第一次出现正面。问「至少掷 2 次」的概率;再问期望掷几次。

至少掷 2 次等价于「第 1 次是反面」——正难则反,P = 1 − P(第一次就正面) = 1 − 1/2 = 1/2。期望次数:这是几何分布,成功概率 p = 1/2,期望 1/p = 2 次。也可用「首步分析」列方程 E = 1 + (1/2)·0 + (1/2)·E(一半概率这次成功、一半白掷一次重来),解得 E = 2。会用「1/p」或首步方程任一条都行。
