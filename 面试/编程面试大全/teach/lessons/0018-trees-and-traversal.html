树入门与遍历:BFS vs DFS

前面几课的线性结构(数组、链表、栈、队列)都是「一条线」。从这节起进入树——一个节点可以分叉出多个孩子的层级结构。树本身概念不难,难在面试里那道永恒的分岔:同一棵树,你是一层一层横着扫(BFS),还是一头扎到底再回头(DFS)?这节课把术语和两大遍历族一次讲清,后面所有树的题都建立在它之上。

先回忆:在「栈」(第 0010 课)里你学过 LIFO 后进先出、在「队列」(第 0011 课)里学过 FIFO 先进先出。这节你会看到它们各自的杀手级应用——队列驱动 BFS、栈(或递归调用栈)驱动 DFS。先自己想一想:为什么「先进先出」会让遍历按层推进,而「后进先出」会让遍历扎到底?

一、术语:先把家谱说清楚

树由节点(node)和连接它们的边(edge)组成,且没有环。最上面唯一的入口叫根(root);没有孩子的节点叫叶(leaf);一个节点指向的下层节点是它的孩子(child),反过来是父(parent)。本课只关心每个节点至多两个孩子的二叉树(binary tree)。

深度(depth)是某节点到根的边数(根深度 0);高度(height)是某节点到它最深叶的边数(整棵树的高度就是根的高度)。这两个词考试常被追问,务必分清方向:深度往上数到根,高度往下数到叶。

二、两大遍历族:横着走,还是扎到底

「遍历」就是不重不漏地访问每个节点一次。有且只有两种基本走法,区别只在下一个访问谁:

BFS(广度优先,又叫层序遍历):把根入队,然后循环「出队一个、把它的孩子全入队」。队列 FIFO 保证先被发现的节点先被展开,于是天然一层接一层推进。DFS(深度优先):从根出发,沿一个孩子一直往下探,到底了再回退换分支——递归写法最自然(隐式用了系统调用栈),迭代写法就用一个显式栈。

为什么是「队列 ↔ BFS、栈 ↔ DFS」?因为队列先进先出,让「离根近的先处理」;栈后进先出,让「最后发现的、也就是最深的先处理」。把 BFS 的队列换成栈,它立刻变成 DFS——数据结构的选择直接决定了搜索的形状。

三、关键定义

二叉树(Binary Tree)
每个节点至多有左、右两个孩子的树。避免把它和后面的「二叉搜索树」混为一谈——二叉树不要求任何大小顺序。
BFS / DFS(广度优先 / 深度优先)
树/图遍历的两种策略;BFS 用队列、逐层扩展,DFS 用栈或递归、探到底再回退。避免「BFS 和 DFS 只是顺序不同、效果一样」。
高度 vs 深度(height vs depth)
深度=节点到根的边数;高度=节点到最深叶的边数。整棵树的高度等于根的高度。避免把两者当同义词。

四、复杂度:遍历都是 O(n),差别在空间

操作平均最坏
遍历(BFS 或 DFS,每节点访问一次)O(n)O(n)
BFS 额外空间(队列存最宽一层 w)O(w)O(n)
DFS 额外空间(栈/递归 = 树高 h)O(h)O(n)

时间上两者没差:都要碰每个节点一次,共 n 个,O(n) 逃不掉。差别全在额外空间——BFS 的队列在最底层同时装下最宽一层(平衡树里约 n/2 个节点,故最坏 O(n));DFS 的栈只装「当前这条根到叶的路径」,即树高 h。平衡树 h≈log n,所以 DFS 空间可低至 O(log n);但退化成一条链时 h=n,两者都是 O(n)。

面试怎么考。树的题目几乎都以「你该用 BFS 还是 DFS」开场,信号词直接决定选型:

  • 题面出现「层」「每一层」「最短步数」「最近的」 → 首选 BFS + 队列(逐层扩展,第一次到达就是最短)。
  • 题面关心「一条路径」「子树的信息」「所有可能的走法」 → 首选 DFS + 递归(自然地把子树结果向上汇总)。
  • 被追问空间时,答得漂亮的关键:BFS 最坏 O(n)(最宽一层),DFS 最坏也是 O(n)(退化成链),但平衡树里 DFS 只要 O(log n)。

别把「二叉树」的几个近亲搞混——面试官很爱用定义卡人:

  • 满二叉树(full):每个节点要么 0 个孩子、要么 2 个孩子(没有只带一个孩子的节点)。
  • 完全二叉树(complete):除最后一层外都填满,且最后一层节点靠左连续排列(堆就靠它,见第 0022 课)。
  • 平衡二叉树(balanced):任意节点左右子树高度差有界,从而保证 h=O(log n)。

另一个坑:树高从 0 还是从 1 起算,不同教材不一样(本课按「边数」算,单节点高度 0;但仓库实现清单里 get_height 注明「单节点高度为 1」,按节点数算)。上手写题前先和面试官对齐口径,别默认对方和你一致。

定义一个二叉树节点(val / left / right),然后把两大遍历都写一遍:

bfs()(用队列,逐层输出)· dfs_recursive()(递归)· dfs_iterative()(显式栈)。跑同一棵树,打印三种输出的访问顺序;再顺手统计队列的最大长度与递归的最大深度,亲眼对比 BFS 与 DFS 的空间量级差异。

带走这一条:看到「层 / 最短步数」就想 BFS + 队列;看到「路径 / 子树 / 穷举走法」就想 DFS + 递归。两者时间都是 O(n),真正的取舍在空间——一个吃「最宽一层」,一个吃「树高」。

五、自测题

Q1:BFS 为什么必须用队列,换成栈会发生什么?

队列的 FIFO 保证「先被发现的节点先被展开」,于是同一层的节点会连续出队处理,遍历天然按层推进——这正是「广度优先」。如果换成栈(LIFO),最后压进去的(最深的)反而先弹出,遍历就会沿一条分支一头扎到底,那恰好变成了 DFS。换一个容器,搜索的形状就彻底变了,这也是为什么说「BFS 和 DFS 不只是顺序不同」。

Q2:一棵有 n 个节点的平衡二叉树,BFS 的额外空间(队列)最坏是多少?

O(n)。BFS 队列要同时装下「最宽的一层」,而平衡二叉树的最底层约有 n/2 个节点,故 O(n/2)=O(n)。干扰选项 O(log n) 是树高——那是 DFS 递归栈的量级,别张冠李戴。这也解释了一个反直觉的事实:在很宽的树上,想省内存反而该用 DFS。
