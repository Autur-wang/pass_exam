进程与线程:并发的两种单位

「进程和线程有什么区别」是面试的国民八股题,几乎躲不掉。但背下答案没用,考官一追问「那什么时候用多进程、什么时候用多线程」就露馅。这节把区别落到一件事上——它们共享还是隔离地址空间——从这一个点,进程与线程的所有性格(隔离性、通信方式、切换代价、崩溃影响)全都能推导出来。

先回忆 程序如何运行那节:一个运行中的程序有自己的地址空间——代码段、数据段、堆(向上长)、栈(向下长)。那节讲的其实就是「一个进程」的内存长相。现在把问题推进一步:如果想让同一个程序里几件事同时进行,是该再开一个这样完整的地址空间,还是在同一个地址空间里多拉几条执行线?——这就是进程与线程的分岔口。

一、直觉:公司与工位

把进程想成一家独立的公司:有自己独门独户的办公楼(地址空间)、自己的文件柜(内存、文件描述符)。两家公司要合作,只能靠打电话、寄快递(进程间通信 IPC)——安全,但麻烦、慢。

把线程想成公司里的员工:同一栋楼、共用同一批文件柜(共享代码、数据、堆),沟通只要扭头喊一声(直接读写共享内存)——快,但也危险:两个人同时改同一份文件就乱套了(数据竞争,下一课的主题)。每个员工只有自己的办公桌是私有的:线程各有独立的栈、程序计数器、寄存器。

二、一张表把区别钉死

维度进程(Process)线程(Thread)
地址空间独立、互相隔离同进程内共享
通信方式IPC:管道、消息队列、共享内存、socket直接读写共享内存(需加锁)
创建/切换代价重(要建/换整套地址空间与页表)轻(共享地址空间,只换栈和寄存器)
崩溃影响一个进程崩了,不拖累其它进程一个线程崩(如段错误)常拖垮整个进程
私有的东西全套内存 + 资源仅栈、程序计数器、寄存器

这张表不用死背——只要记住「进程隔离、线程共享」这一句,每一行都能现场推出来。隔离所以要 IPC、所以切换重、所以崩溃不互相牵连;共享所以通信快、切换轻,但也所以一崩全崩、所以必须同步。

三、上下文切换:并发的隐藏成本

单核 CPU 同一时刻只能跑一条执行流。看起来「同时」运行,靠的是操作系统飞快地在多个进程/线程间来回切换——每次切换要保存当前的寄存器、程序计数器等状态,再载入下一个的状态,这叫上下文切换(context switch)。进程切换还要额外换页表、刷新 TLB,所以比线程切换贵得多。切换本身不干活,是纯开销;切得太频繁,CPU 时间都耗在搬家上了。

四、并发 ≠ 并行

这是两个最常被混淆的词,面试爱抠:

  • 并发(concurrency):多个任务在时间上重叠推进,但不一定同一时刻真的在跑——单核靠快速切换也能并发。是一种「结构」。
  • 并行(parallelism):多个任务同一时刻真的在同时执行,必须有多核/多处理器硬件。是一种「执行」。

一句话:并发是「同时应付很多事」(可以只有一个厨师在多道菜之间轮转),并行是「同时做很多事」(真有多个厨师)。并行一定并发,并发不一定并行。

进程(Process)
拥有独立地址空间的程序执行实例;进程间隔离,通信靠 IPC。
线程(Thread)
进程内的执行单位,与同进程其它线程共享地址空间(代码/数据/堆),但各有私有的栈、程序计数器、寄存器。
上下文切换(Context Switch)
CPU 从一个执行流切到另一个时,保存旧状态、载入新状态的过程;纯开销。进程切换含换页表,比线程切换贵。
并发 vs 并行(Concurrency vs Parallelism)
并发=多任务在时间上交错推进(单核亦可);并行=多任务同一时刻真正同时执行(需多核)。避免把两者当同义词。
写时复制(Copy-on-Write)
fork 出的子进程先与父共享只读页,直到某方写入才真正复制该页;省去无谓的整片内存拷贝。

面试怎么考。

  • 「进程和线程的区别?」——别只背表。用「隔离 vs 共享」这一根线串起来讲,再补一句「所以线程通信快但要同步,进程安全但通信慢」,层次立刻不一样。
  • 「什么时候用多进程,什么时候用多线程?」——要隔离性/稳定性(一个崩不拖累全局)、或要绕开某语言的全局锁(如 Python 的 GIL 让多线程做不了 CPU 并行,得用多进程),选多进程;要频繁共享大量数据、切换开销敏感,选多线程。
  • 协程 / 线程池:进阶会问协程(用户态调度,比线程更轻,一个线程里跑成千上万个)、以及为什么要线程池(复用线程、摊掉创建开销)。

「并发就是并行」——最常见的口误,直接暴露基础不牢。单核机器可以并发(靠切换)但无法并行。反过来,把 8 核机器上的程序说成「并发执行」不算错,但要能指出它此刻是真并行。

另一个坑:「多线程一定更快」是错的。线程切换、锁竞争、缓存失效都是成本;IO 密集型任务多线程收益大(线程等 IO 时让别人跑),CPU 密集型任务线程数超过核数反而更慢。而且在 Python 里,GIL 使多线程无法让多个线程同时执行 Python 字节码,CPU 密集要靠多进程。

用你熟悉的语言各写一个小实验,亲手感受区别:

① 共享的证据:开 2 个线程,各把同一个全局计数器自增一百万次(先不加锁),打印最终值——你会看到它小于两百万,这就是共享内存 + 数据竞争(下一课要治的病)。
② 隔离的证据:用 fork(或多进程 API)开子进程,让它修改一个变量,回到父进程打印同名变量——父进程的值没变,因为地址空间隔离(写时复制)。
③ 若用 Python,再拿一段纯计算跑「多线程」对比「多进程」耗时,观察 GIL 让多线程 CPU 任务几乎不提速。

带走这一条:进程隔离、线程共享——这一个区别推出全部其它区别。共享带来速度也带来数据竞争,于是有了下一课的同步原语;隔离带来安全也带来 IPC 的麻烦。并发是结构,并行是执行,别混。

五、自测题

Q1:同一进程里的多个线程,下面哪一组是每个线程私有、不共享的?
A. 代码段和全局变量
B. 堆上分配的对象
C. 栈、程序计数器、寄存器
D. 打开的文件描述符

C。线程共享代码段、全局/静态数据、堆、文件描述符(A、B、D 都是共享的),但各自拥有私有的栈、程序计数器、寄存器。栈必须私有,因为每个线程有独立的函数调用链;PC 和寄存器私有,因为每个线程执行到的位置和中间状态各不相同。正是「堆共享、栈私有」,让线程既能便捷共享数据,又能各跑各的调用流。

Q2:一个 Web 服务要处理大量并发连接,团队在「多进程」和「多线程」间纠结。仅从「一个连接的处理逻辑崩溃了会怎样」这个角度看,两者差别是什么?

多进程更抗崩。进程地址空间隔离,一个进程因某连接的 bug 崩溃(如段错误),其它进程照常服务,影响面被限制在那一个进程。多线程共享地址空间,一个线程触发段错误通常会让整个进程连同其上所有线程一起挂掉,影响面大得多。这就是为什么很多服务器(如早期 Apache prefork、以及浏览器把每个标签页放进独立进程)用多进程换稳定性和隔离性——代价是更重的创建/切换开销和更麻烦的 IPC。

Q3:「我的笔记本是单核的,所以它没法并发,只能一个一个来。」这句话对吗?

不对——混淆了并发与并行。单核确实无法并行(同一时刻只能真正执行一条指令流),但完全可以并发:操作系统靠快速的上下文切换,让多个任务在时间上交错推进,宏观上「同时在跑」。你单核电脑上一边放音乐一边编辑文档,就是并发。并行才需要多核;并发只是一种任务组织结构,单核也成立。并行一定并发,并发不一定并行。
