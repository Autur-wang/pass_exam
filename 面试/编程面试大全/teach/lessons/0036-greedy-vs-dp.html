贪心 vs 动态规划

贪心算法诱人——每步只拿眼前最优、不回头,又快又短。但它有个致命前提:只有在特定问题上,「步步局部最优」才真能拼出「全局最优」。这节课讲清贪心什么时候对、怎么一句话证明它对,以及面试里最经典的「贪心翻车」案例——好让你在该用贪心时敢用、不该用时能立刻举出反例。

先回忆:前两课DP(上)DP(下)里,动态规划的做法是考虑所有子问题、缓存下来再挑最优。贪心恰恰相反——它只沿一条路走,每步定了就不再回头。先想一个问题:既然贪心不回头看别的可能,凭什么保证结果最优?

一、直觉:每步都拿眼前最好的,绝不反悔

贪心(Greedy)就是:面对一连串决策,每一步都不做全局权衡,只挑当下看起来最优的那个,选完就锁死、绝不回溯。它和 DP 是两种世界观——DP 谨慎地把所有可能都算一遍再取最优,贪心赌「局部最优的累积就是全局最优」。这个赌注只在某些问题上成立。

典型能贪心的例子是区间调度(活动选择):给一堆有起止时间的活动,选最多的互不重叠的活动。贪心策略惊人地简单——按结束时间排序,每次选「结束最早且不与已选冲突」的那个。直觉:最早结束的活动给后面留下最多空间。这个贪心是可以严格证明最优的。

二、贪心正确的两个条件

怎么证明「贪心选择性质」?面试里最常用的是交换论证(exchange argument):假设存在一个最优解没选贪心的那一步,那么总能把它里面的某个选择「换成」贪心的选择,而结果不变差——于是贪心解至少和最优解一样好。能说出这一句,就说明你不是碰运气用贪心。

三、经典能贪心的问题

区间调度 / 活动选择
按结束时间排序、每次选最早结束且不冲突者,得到最多不重叠活动。可用交换论证证明最优。
Huffman 编码
反复把频率最小的两个节点合并成子树,得到带权路径最短的前缀编码。是贪心 + 优先队列的教科书案例。
找零(仅在规范币制下)
凑出目标金额用最少硬币。在像 {1,5,10,25} 这类「规范」币制下,「每次尽量取最大面额」的贪心正确;但换一种币制就可能失效(见下)。

五、贪心 vs DP:一张判别表

算法 / 问题时间保证最优?
区间调度(按结束时间贪心)O(n log n)是(可证)
Huffman 编码(贪心)O(n log n)是
找零 · 规范币制(贪心)O(n)是
找零 · 任意币制(贪心)O(n)否 ({1,3,4} 凑 6 翻车)
0/1 背包(按性价比贪心)O(n log n)否 (必须用 DP)
找零 · 任意币制(DP)O(n·amount)是

核心对照:贪心通常更快(主要开销是排序,约 O(n log n)),因为它不铺开所有子问题;DP 更稳,因为它考虑了所有子问题。速度换的是「是否保证最优」的风险。

六、关键定义

贪心(Greedy)
每步都取当前局部最优,期望得到全局最优——仅在问题具备贪心选择性质时才正确。避免「贪心一定比 DP 快所以更好」。
贪心选择性质(Greedy-choice Property)
每一步的局部最优选择都能通向一个全局最优解。这是贪心区别于 DP、也最需要证明的一条。
交换论证(Exchange Argument)
证明贪心最优的常用手法:把任一最优解里的选择「换成」贪心的选择而不使其变差,从而证明贪心不劣于最优。

面试怎么考。贪心是面试官最爱设的「陷阱题」——因为贪心解往往看起来对、跑起来快,却悄悄错:

  • 被问「这题能贪心吗」时,先验证再下结论:检查贪心选择性质是否成立,能就上、能顺带用交换论证说一句证明思路;拿不准就用 DP——DP 更稳,不会因为找不到反例就翻车。
  • 随身带一个「贪心失败」的反例:{1,3,4} 凑 6 是最顺手的一个。面试官说「用贪心找零吧」,你能当场举出它比 DP 差,立刻显出深度。
  • 识别真正的贪心题:区间调度、会议室安排、跳跃游戏、加油站、Huffman——这些有明确「每步安全选择」的题才是贪心的主场。

坑一(最常见):以为「贪心一定比 DP 好」。贪心快,但可能得不到最优解;DP 慢一点却保证最优。「更好」取决于问题是否满足贪心选择性质,不是速度说了算。

坑二:把 DP 题当贪心题做。找零(任意币制)、0/1 背包都是经典的「贪心会错、必须 DP」。用「按性价比排序然后贪」做 0/1 背包,是高频错误答案。

坑三:用贪心却给不出正确性理由。「我觉得每次取最大就行」不是证明。面试官会追问「为什么局部最优能保证全局最优」——答不出交换论证或反证,就说明你只是撞对了。

用几道题把「贪心该用 / 不该用」的边界摸清:

区间调度(会议室、活动选择):实现「按结束时间排序 + 扫描」,并在纸上用交换论证说服自己它最优。找零对拍:同时写贪心版和 DP 版,在币制 {1,3,4} 上跑金额 6,亲眼看两者结果不同(3 vs 2)。跳跃游戏(LeetCode 55):体会一个「贪心确实成立」的例子——维护「当前能到的最远位置」。

带走这一条:贪心 = 每步局部最优、不回头,只有在「贪心选择性质 + 最优子结构」都成立时才正确。它比 DP 快但更冒险;拿不准就用 DP,并随身记住 {1,3,4} 凑 6 这个贪心翻车的反例。

七、自测题

Q1:用币制 {1, 3, 4} 凑金额 6,「每次取最大面额」的贪心会给出几枚硬币?最优是几枚?这说明了什么?

贪心 3 枚(4 + 1 + 1),最优 2 枚(3 + 3)。

贪心一上来贪了最大的 4,把自己逼进「剩 2 只能拿两个 1」的死角;而放弃 4、改用两个 3 反而更省。这说明贪心不具普适性——在非规范币制下它不保证最优,找零因此在一般情况下是 DP 题。记住这个反例,面试里被问「能贪心吗」时就有据可依。

Q2:下面关于贪心和 DP 的比较,哪个说法正确?

正确的是:「贪心通常更快(主要是排序开销 O(n log n)),但只在满足贪心选择性质时才保证最优;DP 更慢却更稳。」

错误说法举例:「贪心一定比 DP 好」(快不等于对);「凡是求最优值的题都能贪心」(很多必须 DP,如 0/1 背包);「DP 和贪心的区别只是写法」(本质区别是 DP 考虑所有子问题、贪心只走一条不回头)。选算法看的是问题性质,不是谁跑得快。

Q3:面试官问「你怎么证明你这个贪心策略是对的」,一个有说服力的回答思路是什么?

交换论证(exchange argument)。思路:假设存在一个最优解,它在某一步没有采用贪心的选择;证明总能把这个选择「替换成」贪心的选择,而解不会变差(目标值不减少 / 不增加)。反复替换后,得到一个与贪心一致、且不劣于原最优解的解——于是贪心解就是最优的。能讲出这套「替换而不变差」的逻辑,比只说「我觉得每次取最大就行」强太多;讲不出来,通常意味着该改用 DP。
