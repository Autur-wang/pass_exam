链表:指针的舞蹈,与数组的取舍

数组把「连续」当信仰,链表则反着来:它让每个元素散落在内存各处,靠一根根指针把它们串成一条线。这一个决定,把数组的性格几乎全部翻转——头部增删从 O(n) 变成 O(1),随机访问从 O(1) 变成 O(n)。这节课把这笔「取舍」算清楚,并回答面试官最爱问的:「什么时候该用链表,什么时候用数组?」

先回忆:上一课数组与动态数组里,我们看到数组头部插入 prepend 是 O(n)——因为后面所有元素都得整体后移一格。先自己想一想:如果不要求元素在内存里连续,这个「后移」还需要吗?

一、直觉:一串用绳子系起来的珠子

把链表想成一串珠子,每颗珠子(节点 node)装两样东西:数据 + 一根指针(指向下一颗珠子的地址)。珠子本身可以扔在内存的任何角落,彼此并不相邻;只要每颗都记得「下一颗在哪」,整串就不会散。另有一个 head 指针记着第一颗珠子的位置——它是进入整条链的唯一入口。

头部插入为什么变 O(1)?因为只要:新节点的 next 指向原来的头,再把 head 改指向新节点——两三个指针赋值,和链表多长毫无关系。代价立刻显现在另一头:想拿第 i 个元素,没有「基址 + i × 大小」这种一步跳的公式了,只能从 head 一个个 next 数过去,这是 O(n)。

二、代价的另一面:缓存不友好

大 O 表看不见的一笔账:节点散落在内存各处,顺序遍历时 CPU 每跳一个节点几乎都是一次缓存未命中(cache miss)。数组连续存放,遍历时一次加载就把邻居一起拉进缓存,命中率高。所以现实里遍历一遍链表常常比同样长度的数组慢好几倍——即便两者都记 O(n)。仓库大纲专门收录了一条《为什么你需要避免使用链表》,讲的正是这件事:除非你确实需要 O(1) 的头部增删或稳定的节点地址,否则数组往往是更实际的默认选择。

「链表随机访问也是 O(1)」——这是最典型的错答。链表没有连续内存,拿不到「基址 + 偏移」的捷径,value_at(i) 必须从 head 顺着 next 走 i 步,是 O(n)。反过来,数组头插 O(n)、链表头插 O(1)——把这两组恰好相反的复杂度记牢,面试就不会答反。

还有一个进阶坑:仓库提到「指向指针的指针」。当你把 head 传进一个会修改它的函数(比如头部插入),传值传的是 head 的副本,函数内改的是副本、外面的 head 没变;要真正改动 head,得传指针的地址(二级指针)或返回新 head。

三、关键定义

链表(Linked List)
由节点通过指针串起的线性结构,节点在内存中不连续。头部插入删除 O(1),随机访问 O(n)。避免:「链表访问也是 O(1)」。
节点(Node)
链表的基本单元,含数据域与至少一个指针域(next)。单链表每节点一个指针,下一课的双向链表多一个 prev。
头指针 / 尾指针(head / tail)
head 是进入链表的唯一入口;可选的 tail 记住末节点,使 push_back 从 O(n) 降到 O(1)。避免:默认链表一定有尾指针。

四、复杂度:与数组恰好对照的一张表

下表是带 head 指针的单链表(无尾指针)。链表操作大多是确定性的,平均与最坏一致。

操作平均 / 摊还最坏
随机访问 value_at(i)O(n)O(n)
头部插入 / 删除 push_front / pop_frontO(1)O(1)
尾部插入 push_back (无尾指针)O(n)O(n)
按值查找 findO(n)O(n)
已知前驱节点处插入 / 删除O(1)O(1)

空间复杂度 O(n),但常数比数组大:每个元素额外背一根指针(64 位机上 8 字节)。如果加一个尾指针,push_back 也能降到 O(1)——仓库大纲要求你两种实现都写一遍,亲手感受尾指针带来的差别。

面试怎么考。链表是「指针操作」这类题的主战场,几乎必考:

  • 反转链表(reverse):面试第一梯队高频题。核心是三个指针 prev / curr / next 边走边掉头,一趟 O(n)、原地 O(1) 空间。能徒手写对,是链表过关的门槛。
  • 快慢指针:一个走一步、一个走两步。求中点、判断是否有环(Floyd 判环)、找环入口、找倒数第 k 个节点——都是它的变体。仓库列的 value_n_from_end(n) 就是快慢指针的经典应用。
  • 选型追问:「这里你会用数组还是链表?」——答题要落到具体操作:频繁头部增删、需要稳定的节点地址(如把节点挂进别的结构)→ 链表;需要随机访问、在乎遍历速度与缓存 → 数组。

带走这一条:数组和链表是一对镜像。数组用「连续」换来 O(1) 随机访问,代价是 O(n) 的头部增删;链表用「指针」换来 O(1) 的头部增删,代价是 O(n) 的随机访问和缓存不友好。没有谁更好,只有「你的操作更偏哪一头」。

照仓库大纲徒手实现单链表(分别写「有尾指针」和「无尾指针」两版,对比 push_back):

size() · empty() · value_at(i) · push_front(v) · pop_front() · push_back(v) · pop_back() · front() · back() · insert(i, v) · erase(i) · value_n_from_end(n)(快慢指针)· reverse()(三指针原地)· remove_value(v)。

重点练 reverse():在纸上画三个指针,一步步挪,直到闭着眼也能写对。

五、自测题

Q1:给定一个指向单链表中间某个节点的指针(不给 head),要「访问」它是 O(1),但要「删除」它却没那么直接。为什么删除会卡住?

因为删除一个节点,本质上要让它的前驱的 next 跳过它。单链表只能往后走,拿不到前驱指针,所以正常删除需要 O(n) 从 head 找前驱。经典技巧:把后继节点的值复制到当前节点,再删掉后继,伪装成删了自己——但这招在删末节点时失效。下一课双向链表因为有 prev,已知节点就能真正 O(1) 删除,正是它多那根指针换来的红利。

Q2:下面哪种场景,链表明显优于动态数组?

需要频繁在序列头部(或已知位置)插入/删除,且几乎不做随机访问。此时链表全程 O(1),而数组头插每次 O(n)。反例——若你需要频繁按下标读取、或顺序遍历要快,数组的 O(1) 随机访问与缓存友好会完胜。仓库那条《为什么要避免链表》提醒:很多人默认链表「插删快所以更优」,却忽略了缓存代价,现实中数组往往才是更快的默认选项。
