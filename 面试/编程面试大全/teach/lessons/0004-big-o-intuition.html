大 O 记号:只看增长率

从这一课起，我们练的是贯穿整套面试的第一样通用基本功：估算一段代码有多贵。大 O 不是让你数「跑了几毫秒」，而是回答一个更本质、也更可迁移的问题——当输入规模 n 翻倍、翻十倍时，工作量会怎么涨？这节课把这条「只看增长率」的思维方式讲透，它是后面每一节算法课的通用语言。

先回忆：开课这几节聊的都是「进面试前准备什么」——上一课刚定下你要用哪门语言刷题。现在换个方向：不管用什么语言，面试官都会盯着你的解法问「这个复杂度是多少」。先自己想一句：为什么他们不问「你这段代码跑几秒」，偏要问那个字母 O？

一、为什么用 Big-O，而不用「秒」

用秒数衡量算法，有三个致命毛病：换台机器就变（新 CPU 快一倍）、换个语言就变（C 比 Python 快几十倍）、换组数据就变（同一段代码喂 10 个数和喂 1000 万个数完全两回事）。这些都是环境噪声，掩盖了算法本身的好坏。

大 O 把噪声全部抹掉，只留下一件跟机器无关的事实：工作量随 n 增长的速度。它做两步简化——忽略常数系数（3n 和 100n 都算 O(n)），忽略低阶项（n² + n + 5 只看 n²）。因为当 n 足够大时，涨得最快的那一项会碾压其余一切。

二、增长率的直觉:n 翻倍时会发生什么

判断一段代码属于哪一类，有个不用背公式的土办法：想象 n 变成 2 倍，工作量变成几倍？

  • O(1)：n 翻倍，工作量不变——比如按下标取数组第 i 个元素。
  • O(log n)：n 翻倍，工作量只多做「一步」——二分查找每次砍一半。
  • O(n)：n 翻倍，工作量也翻倍——扫一遍数组。
  • O(n²)：n 翻倍，工作量变 4 倍——嵌套双重循环。
  • O(2ⁿ)：n 只加 1，工作量就翻倍——枚举所有子集。这类叫指数级，n 稍大就彻底跑不动。

这个「翻倍测试」比任何定义都好用。面试现场你不必推导极限，只要在脑子里把输入放大一档，看代价怎么跟着跳。

三、关键定义

大 O(Big-O)
描述算法在最坏情况下运行时间或空间随 n 增长的增长率，忽略常数与低阶项。避免说「跑了多少秒」或「大 O 就是平均情况」。
增长率(渐进行为)
只关心 n 趋大时的走势，不关心小 n 或具体系数。O(n) 和 O(100n) 增长率相同，都写作 O(n)。
Θ 与 Ω(一句话版)
O 是上界（不会更差），Ω 是下界（至少这么贵），Θ 是上下都卡死的紧确界。面试里通常口头说「O」，但心里指的往往是 Θ（增长率恰好是这个）。

盯住最后一列：n 只从 10 涨到 1000（100 倍），O(n²) 却从 100 涨到一百万（1 万倍），而 O(2ⁿ) 在 n=100 就已经超过宇宙里的原子数。这张表说明了一件事——系数和低阶项完全无关紧要，决定生死的只有那条增长曲线。

面试怎么考。大 O 几乎不单独出题，但它是每道题的「开场白」和「收尾语」，占分极重：

  • 先说复杂度，再写码：好的做法是开口先给暴力解的复杂度（如「朴素双循环是 O(n²)」），再说目标（「我想优化到 O(n)」），最后才动手。这让面试官看到你在用复杂度指导设计，而不是瞎写。
  • 写完必被追问「这段是几阶」：要能对自己刚写的代码逐段估：几层循环、每层跑几次、循环里调的函数又是几阶。
  • 时间和空间都要报：很多人只说时间复杂度，忘了空间。「我这个哈希表换来了 O(n) 时间，代价是 O(n) 额外空间」——把取舍说出来才完整。

坑一:「大 O 是平均情况」——错。大 O 默认刻画的是最坏情况的上界。平均情况有它专门的分析（比如快排平均 O(n log n)、最坏 O(n²)），别把两者混为一谈。你说「快排是 O(n log n)」严格讲说的是平均；它的大 O（最坏）其实是 O(n²)。

坑二:把 O(2n) 当成比 O(n) 差。O(2n)、O(n+5)、O(100n) 全都等于 O(n)——常数在大 O 里一律抹掉，它们是同一类。真正的降级是从 O(n) 掉到 O(n log n) 再到 O(n²)，那是量级之差，不是系数之差。

动手核对（不用写代码，拿纸笔或口述给自己听）：找 3 段你写过的循环代码，对每一段做这套流程——① 数清有几层循环、每层随 n 跑多少次；② 写出总操作数的表达式（如 n² + 2n + 1）；③ 只保留最高阶、抹掉系数，报出大 O；④ 做一次「翻倍测试」验证：n 变 2 倍，你报的复杂度预测代价变几倍，和表达式算出来的对不对得上。

带走这一条：大 O 只回答一个问题——「n 变大时代价涨多快」。忽略常数、忽略低阶、默认最坏。面试全程用它做通用语言：先估复杂度，再谈解法。

五、自测题

Q1:一段代码的精确操作数是 5n² + 100n + 3000。它的大 O 是下面哪个?

正确答案是 O(n²)。规则是「只留最高阶项、抹掉系数」：5n² 的系数 5 丢掉，100n 和 3000 是低阶/常数项，n 大了它们相对 n² 可忽略。
干扰点：有人看到 3000 这个大常数就慌，觉得「n 小的时候明明是常数占主导」——但大 O 只管 n 趋大时的走势，n=100 时 5n² 已经 5 万、远超 3000。也别写成 O(5n²)，系数在大 O 里没有意义。

Q2:面试官说「这个问题的输入 n 最多到 20」。这句话在暗示你什么?

暗示指数级解法（O(2ⁿ) 或 O(n!)）在这题里是可以接受的。n=20 时 2²⁰ ≈ 100 万，跑得动；很多组合/子集/排列类问题本身就没有多项式解，n 给得这么小正是在放行暴力枚举。
反过来记这个信号更有用：看到输入规模就能反推期望复杂度——n≤20 放行指数级，n≤1000 大约允许 O(n²)，n≥10⁵ 就必须做到 O(n log n) 以内。这条反推法下一课会展开。

Q3:「O(n) 一定比 O(n²) 快」这句话对吗?

不完全对——准确说是「当 n 足够大时」O(n) 才一定更快。大 O 描述的是渐进行为；在 n 很小时，一个系数巨大的 O(n)（比如 1000n）可能反而慢过系数很小的 O(n²)（比如 n²，n<1000 时更小）。
但面试和工程都关心 n 变大后的可扩展性，所以默认按大 O 排序选算法是对的——只是要清楚这个「默认」建立在「n 大」的前提上，这也是为什么大 O 叫「渐进」分析。
