位运算基础:& | ^ ~ << >>

整数在机器里就是一排 0/1。位运算让你绕过算术、直接拨动这些开关——判奇偶、判 2 的幂、取出最低位的 1,都是常数时间的一行代码。这节课把六个运算符和几个必背 idiom 讲清,它们是「O(1) 空间技巧」「状态压缩」「位图」这些面试套路的字母表。

开课前先想想:前面讲复杂度时,我们把「常数时间 O(1)」当作最理想的一档。位运算正是把很多操作压进 O(1) 的利器——在机器字长(如 32/64 位)之内,一次 & 或 << 就是一条指令。先自问:你能不用取模、只用位运算判断一个数是不是偶数吗?

一、六个运算符,先建立画面

把一个整数看成一排灯(bit),从低位(右)到高位(左)。六个运算符就是操作这排灯的手法:

运算符名称逐位规则一句话记忆
&与 AND两个都是 1 才 1取交集 / 掩码取位
|或 OR有一个是 1 就 1取并集 / 置位
^异或 XOR不同才 1,相同为 0找不同 / 翻位 / 自反
~取反 NOT0↔1 每位翻转逐位反转(得到补码相关值)
<<左移整体左移,右边补 0× 2ᵏ
>>右移整体右移÷ 2ᵏ(向下取整)

二、移位 = 乘除 2 的幂

十进制里在末尾添个 0 就是 ×10;二进制里 左移一位就是 ×2,补 0 在最右。所以 x << 3 == x × 8,x >> 1 == x ÷ 2(向下取整)。这也是为什么位运算里「2 的幂」无处不在——README 特意提醒你要背下 2¹ 到 2¹⁶ 乃至 2³² 的数值。1 << k 就是「第 k 位是 1、其余是 0」的那个数,是构造掩码的基本零件。

三、掩码:精准操作某一位

掩码(mask)是一个「只在关心的位上是 1」的辅助数,配合位运算能精准拨动单个比特。四件套(设第 i 位):

目的写法为什么
取第 i 位(n >> i) & 1把第 i 位挪到最低位,再用 & 1 只留它
置第 i 位为 1n | (1 << i)掩码那一位是 1,| 强制点亮
清第 i 位为 0n & ~(1 << i)掩码那一位是 0、其余 1,& 只熄这一盏
翻转第 i 位n ^ (1 << i)与 1 异或 = 翻转,与 0 异或 = 不变

四、必背 idiom

面试里出现频率极高、几乎默认你会的三条:

  • 判奇偶:n & 1。最低位是 1 就是奇数。比 n % 2 更直接,且对负数也是看最低位。
  • 判 2 的幂:n > 0 && (n & (n - 1)) == 0。2 的幂在二进制里只有一个 1;n - 1 会把那个 1 变 0、后面全变 1,两者相与得 0。注意必须先判 n > 0——n = 0 时 n&(n-1) 也是 0,但 0 不是 2 的幂。
  • 取最低位的 1:n & (-n)。在补码下 -n = ~n + 1,与 n 相与恰好只留下最低的那个 1(如 n=1100 → n&-n=0100)。这是树状数组(Fenwick)的核心零件。

五、关键定义

位(Bit)与字(Word)
bit 是 0/1 的最小单位;word 是 CPU 一次处理的位数(如 32/64 位),位运算在字长内是 O(1)。避免忽略字长谈「无限位整数」。
掩码(Mask)
只在关心的位上为 1 的辅助整数,配合 &/|/^ 精准取位、置位、清位、翻位。
算术右移 / 逻辑右移(Arithmetic / Logical Shift)
算术右移高位补符号位(保号),逻辑右移高位补 0。有符号数右移多为算术右移。避免默认所有右移都补 0。

六、复杂度

关键红利在空间:用一个整数当「位图」,能把「某元素在不在集合里」压进单个 bit,32 位整数就是一个 32 元素集合的状态——这就是位运算作为「O(1) 空间技巧」被反复使用的原因。

面试怎么考。位运算很少单独成大题,更多是作为「让你的解法更省」的手段冒出来:

  • 「不用额外空间 / O(1) 空间」的暗示。面试官这么说时,常常在等你用位来压状态:用一个 int 当访问标记(位图)、用位掩码表示「已选了哪些元素」。
  • 状态压缩。子集枚举、状压 DP 里,一个整数的每一位代表一个元素在不在——直接掌握了这套字母表才写得出。
  • 数值直觉。能秒答 1 << 10 = 1024、1 << 20 ≈ 1e6,以及「32 位整数最多表示多大」,会让面试官相信你对机器有感觉。README 也专门要求背 2 的幂数值。

运算符优先级的坑:& | ^ 比 == < > 还低。写 a & 1 == 0,C/C++/Java 会先算 1 == 0(得 0)再 a & 0,结果恒为 0——和你想的完全不同。凡是位运算和比较混在一起,一律加括号:(a & 1) == 0。这是最常见、最隐蔽的位运算 bug。

有符号右移不是补 0。负数在多数语言里右移是算术右移(高位补符号位 1,保持负号),而不是逻辑右移(补 0)。想要补 0 的逻辑右移,Java 要用 >>>,C/C++ 里对有符号数右移是实现相关行为,处理无符号量时应先转 unsigned。把两者当一回事,负数移位就会得到意外结果。

照 README「好好理解位操作符」的要求,写一组小工具函数并逐位打印验证:

get_bit(n, i) · set_bit(n, i) · clear_bit(n, i) · toggle_bit(n, i) · is_even(n) · is_power_of_two(n) · lowest_set_bit(n)(即 n & -n)。

写一个把整数按 32 位二进制打印的小函数当「显微镜」,对 5, 0, 1, 8, -1, INT_MIN 各跑一遍上面的函数,亲眼核对每一位。特别测一下负数右移,看你的语言到底是算术还是逻辑右移。

带走这一条:位运算是「拨开关」——& 取位、| 置位、^ 翻位、1<<i 造掩码;三条 idiom(n&1 判奇偶、n&(n-1)==0 判 2 的幂、n&-n 取最低位 1)背死。混用比较时永远加括号。

七、自测题

Q1:表达式 n & (n - 1) 对结果做了什么?它常被用来做什么判断?

它把 n 最低位的那个 1 清成 0(其余位不变)。因为 n - 1 会把最低位的 1 翻成 0、并把它右边原本的 0 全翻成 1,再与 n 相与,只有那一位及右侧发生变化,净效果是「抹掉最低位的 1」。因此当 n > 0 且 n & (n-1) == 0 时,说明 n 只有一个 1,即 n 是 2 的幂。它还是下一课「Brian Kernighan 数 1 的个数」的核心一步。

Q2:在 C/Java 里写 if (flags & MASK == MASK) 想判断某些标志位是否都置上,却发现结果不对。为什么?

运算符优先级:== 高于 &,实际被解析成 flags & (MASK == MASK) = flags & 1,完全不是你要的语义。正确写法是 (flags & MASK) == MASK。位运算(& | ^)的优先级低于比较运算,这是位运算最经典的隐蔽 bug,规则很简单:位运算和比较混用,一律加括号。

Q3:下面哪个表达式能正确判断整数 n 是不是 2 的幂?

n > 0 && (n & (n - 1)) == 0。2 的幂在二进制里恰好只有一个 1,n&(n-1) 抹掉它后为 0。关键干扰项是漏掉 n > 0:因为 n = 0 时 n&(n-1) 也等于 0,会被误判成 2 的幂——但 0 不是。负数在补码下也可能凑巧,所以必须先要求 n > 0。这类「边界值 0」正是面试官最爱设的陷阱。
