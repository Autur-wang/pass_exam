# Ch10: 系统设计流程(System Design Flow)

**来源**: `cheat-sheets/system-design.pdf`(1 页,内容较薄,像是更完整指南的开头摘录)

## Core Idea
系统设计面试的三步走流程框架:理解问题与范围 → 估算约束条件 → 抽象设计。这份速查表只覆盖了流程的前三步(原文到"抽象设计"处戛然而止),更像一份提纲摘录而非完整指南——不做扩写,如实反映源文件的薄厚。

## Reference Tables

### System Design Flow(原文三步)
| 步骤 | 要点 |
|---|---|
| **1. 理解问题与范围** | 和面试官一起定义用例;主动建议额外功能;把面试官认为超出范围的需求砍掉;默认假设高可用是一个用例,主动提出 |
| **2. 思考约束条件** | 每月请求量;每秒请求量(可能需要自己心算出来);读写比例;记住二八法则(80/20 rule);每秒写入数据量;5 年总存储需求;每秒读取数据量 |
| **3. 抽象设计** | 分层(服务层、数据层、缓存层);基础设施(负载均衡、消息队列);概述驱动该服务的关键算法 |

## Key Takeaways
1. 系统设计面试的第一步永远是**对齐范围**,不是立刻画架构图——面试官故意留白就是想看你会不会主动追问、主动砍需求。
2. 第二步的估算(QPS、读写比、存储量)决定了后面架构选型的依据(要不要分库分表、要不要加缓存),不是走过场的数学题。
3. "二八法则"在这里指请求负载/数据访问往往集中在少数用户或少数数据上——缓存策略、热点数据识别都建立在这个假设上。
