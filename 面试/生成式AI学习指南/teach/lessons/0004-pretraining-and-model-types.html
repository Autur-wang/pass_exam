预训练机制与模型类型:MLM/CLM、GPT vs BERT、base/instruct/reasoning

前两课把 Transformer 这块「积木」拆到了螺丝。这节课回答:拿到积木后,怎么用海量无标注文本把它「喂大」,喂出来的又分哪几种模型?一口气答清五道高频基础题:「LLM 有哪些预训练机制?」「GPT 与 BERT 的关键区别?」「NLP 里的迁移学习/预训练+微调是什么?」「编码器-解码器的信息流与交叉注意力的作用?」「base / instruction-tuned / reasoning 三类模型有何不同?」(源:60 题·LLM 第 8、2、1、12、15 题;AI 工程师题库 Q7)。

回忆一下:自注意力让序列里任意两个位置「一步」互相看到,位置编码又给它补上了顺序感——积木已经搭好。但一个刚随机初始化的 Transformer 对语言一无所知。先别往下看:手上只有海量网页文本、一条人工标注都没有,你要怎么设计一个「自动出题、自动判分」的任务,逼模型把语言规律学进去?

一、预训练机制:没有标注,怎么学语言?

核心思路叫自监督:不用人标注,而是从文本自身「挖一块出来」当答案,让模型去补——文本自己就是标准答案。挖法不同,就有了不同的预训练机制。三种主流机制,举例记住即可:

MLM(Masked Language Modeling,掩码语言建模)——BERT
随机遮住句子里一部分 token(BERT 论文里约 15%),让模型看着左右两边的上下文去还原被遮的词,即建模 $P(x_i \mid x_{\setminus i})$。因为能同时看前后,得到的是双向表示,特别适合「理解」类任务。BERT 预训练时还搭了一个 NSP(Next Sentence Prediction,判断两句是否相邻)辅助任务。
CLM / 自回归(Causal / Autoregressive LM)——GPT
只看前文预测下一个 token,即最大化 $\prod_t P(x_t \mid x_{<t})$。注意 $x_{<t}$ 表示「$t$ 之前的所有 token」——它单向(左→右),天生就是「续写」,所以天然适合生成。
PLM(Permutation Language Modeling,排列语言建模)——XLNet
把预测顺序随机打乱后再做自回归,试图「既拿到双向上下文,又保留自回归的生成能力」,是对 MLM 与 CLM 各自短板的一种折中。

一句话串起来:MLM 完形填空(看两边)、CLM 写作文(只看前面)、PLM 打乱顺序做填空。

二、三种架构:GPT 与 BERT 只是同一块积木的两种搭法

Transformer 原论文本是「编码器 + 解码器」双塔。后人发现:很多任务只需要其中半边,于是分化出三个架构家族。GPT 与 BERT 的区别,本质就是「用哪半边 + 配哪种预训练目标」:

Encoder-only
编码器堆叠 · 双向
BERT · 擅长理解
Decoder-only
解码器堆叠 · 单向因果
GPT · 擅长生成
Encoder-Decoder
双塔 · 编码后解码
T5 · 擅长序列到序列

把 GPT 与 BERT 摊开对比,面试答这张表就够:

维度BERTGPT
用哪半边Transformer 编码器堆叠Transformer 解码器堆叠
注意力方向双向(能看左右)单向 / 因果(只看前文)
预训练目标MLM + NSPCLM(自回归)
天生擅长理解:分类、NER、抽取式 QA生成:续写、对话、开放式问答

为什么 BERT 更适合「理解」?因为分类、命名实体识别(NER)、抽取式问答这类任务,判断一个词要同时依赖它左右两边——双向刚好对口。为什么 GPT 更适合「生成」?因为「预测下一个词」必须只能看前文(否则就作弊看到了答案),这条因果约束反而让它学成了一台强大的续写引擎。

编码器-解码器与交叉注意力(信息流)

当输入和输出是两段不同序列时(翻译、摘要、生成式 QA),双塔结构最自然。信息流是这样走的:

交叉注意力(Cross-Attention)
解码每一步时,用当前解码器状态当 Query,去和编码器输出(当 Key/Value)算注意力——动态地「回头看」输入里当下最相关的部分。这正是第 0002 课自注意力的 Q、K、V 不再全来自同一段序列:Q 来自解码器、K/V 来自编码器。翻译时对齐原文哪个词、摘要时抓原文哪句、QA 时定位证据段,靠的都是它。

三、迁移学习:预训练 + 微调,两阶段范式

把上面的机制放进一个更大的框架,就是 NLP 里说的迁移学习——它是「预训练机制」之所以值钱的原因。分两阶段:

这套范式为什么赢了?三条价值,面试点这三条:

  • 省任务数据:通用能力已在预训练阶段学好,下游只需少量标注就能拿到高性能。
  • 省资源:昂贵的预训练只做一次,不必为每个任务从零训练。
  • 一模多用:同一个底座微调到分类、抽取、翻译……复用性极高。

四、base / instruct / reasoning:同一底座的三级「成熟度」

预训练出来的原始模型叫 base。但它并不「听话」——你问它问题,它可能只是接着你的话往下续写。要变成能对话、能解难题的产品,还要在 base 之上再加工。这就是 AI 工程师最常被问的三类模型区别:

base(基座)
只做一件事:预测下一个 token
不可靠听指令,续写机器
instruction-tuned / chat
base + SFT + 偏好优化
能听指令、能对话——产品默认
reasoning(推理型)
再进一步训练(常用可验证奖励 RL)
答前先花算力做内部思维链

三者递进关系说清楚:

  • base:纯预训练产物,目标只是「预测下一个 token」,不保证按你的指令行事——给它一句问题,它可能续成更多问题。
  • instruction-tuned / chat:在 base 上用指令数据做 SFT(监督微调)、再用偏好优化对齐人类偏好,于是学会「听懂指令、给出有用回答、多轮对话」。面向用户的产品默认用它。
  • reasoning:再往上,常用「可验证奖励」的强化学习(答案对不对可以自动判定,如数学、代码)训练模型在给出最终答案之前先花 test-time compute 做一段内部思维链。难的多步问题更强,代价是更慢、更贵。

选型口诀:常规任务用 instruct(快又够用);难的、多步的推理任务再上 reasoning(强但慢且贵)。

面试官会顺着往下追(高频链):

  • 「MLM 和 CLM 分别适合什么任务、为什么?」——MLM 双向→理解;CLM 单向→生成。答不出「方向」这个根因就是背书。
  • 「BERT 能做文本生成吗?」——不擅长。它是双向编码器、没有因果约束,天生做的是理解;硬做生成要额外改造。别答「一定不能」,要说「架构上不对口」。
  • 「decoder-only 的 GPT 里有交叉注意力吗?」——没有。交叉注意力只存在于「编-解码器」结构里(解码器看编码器);decoder-only 只有带因果 mask 的自注意力。这是极易混的坑。
  • 「预训练和微调的数据量、监督方式各是什么?」——预训练:海量、自监督/无标注;微调:小规模、有标注。
  • 「reasoning 模型是不是永远比 instruct 好,应该默认用?」——不是。它更慢更贵,简单任务上性价比反而低;按任务难度选。
  • 「instruct 模型是怎么从 base 来的?」——SFT + 偏好优化(如 RLHF 一类)。引出对齐话题。

易错点(绝对化措辞是扣分点):

  • 别把方向搞反:MLM 双向、CLM 单向。说「GPT 双向」或「BERT 单向」直接判死。
  • 交叉注意力 ≠ 自注意力。交叉注意力在编-解码器里(Q 来自解码器、K/V 来自编码器);decoder-only 的 GPT 没有交叉注意力,只有因果自注意力。
  • 别说「BERT 一定不能生成、GPT 一定不能理解」。是「架构各有所长」:BERT 不擅长自由生成、GPT 也能做理解类任务,只是各自的天生对口方向不同。
  • reasoning 不是「更高级所以永远该用」。它更慢更贵,简单问题用它是浪费;产品默认仍是 instruct。
  • base 模型不等于「没训练好」。它训得很充分,只是没做指令对齐——它本来就不以「听指令」为目标。

自测 1:关于 MLM 与 CLM 两种预训练机制,下列哪句最准确?

A. MLM 单向、适合生成;CLM 双向、适合理解方向和用途都反了。MLM 双向适合理解,CLM 单向适合生成。
B. MLM 双向掩码还原、BERT 用它;CLM 据前文预测下一 token、单向、GPT 用它 ✅正确。这正是 BERT 擅长理解、GPT 擅长生成的根因。
C. 两者都必须依赖大量人工标注数据才能完成预训练都是自监督,答案从文本自身挖出来,不需要人工标注。
D. CLM 因为是双向的,所以比 MLM 更适合做文本分类任务CLM 是单向的;适合分类的是双向的 MLM/BERT。

自测 2:关于 base / instruction-tuned / reasoning 三类模型,哪句最准确?

A. base 模型已经过 SFT,所以能可靠地听从指令、进行多轮对话listen 指令是 instruct 模型的能力;base 只会预测下一个 token,不保证听指令。
B. reasoning 模型比 instruct 更快也更便宜,理应作为产品的默认选择恰恰相反——它更慢更贵,产品默认是 instruct,难题才上 reasoning。
C. instruct 经 SFT+偏好优化能听指令对话、是产品默认;reasoning 再用 RL 训成答前先做内部思维链,难题更强但更慢更贵 ✅正确。三者是「同一底座」上逐级加工出来的成熟度。
D. 三者底层架构完全不同:base 是编码器、instruct 是解码器、reasoning 是编-解码器架构没变,都是同一底座;区别在训练阶段,不在架构。

一手出处与深挖方向:

  • Attention Is All You Need(Vaswani et al., 2017)——原始编-解码器与交叉注意力的出处。
  • BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding(Devlin et al., 2018)——MLM + NSP 与「双向」的原论文。
  • Improving Language Understanding by Generative Pre-Training(Radford et al., 2018,即 GPT)——自回归 CLM 的「预训练 + 微调」范式。
  • XLNet(Yang et al., 2019)——排列语言建模 PLM。
  • T5 / "Exploring the Limits of Transfer Learning…"(Raffel et al.)——编-解码器 + 迁移学习的统一框架。
  • Training language models to follow instructions with human feedback(Ouyang et al., 2022,即 InstructGPT)——base 如何经 SFT + 人类反馈变成 instruct 模型。
  • 下一步:token 化与解码控制(第 0005 课)——GPT 那台「续写引擎」到底怎么把概率变成文字。

一句话记忆:MLM 双向填空(BERT/理解)、CLM 单向续写(GPT/生成)、PLM 打乱折中;迁移学习 = 预训练学通识 + 微调做专业课;交叉注意力只在编-解码器里(Q 来自解码器);base→instruct(听指令,默认)→reasoning(答前先思考,难题更强但更慢更贵)。
