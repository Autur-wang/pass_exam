位置编码与长上下文瓶颈:RoPE、ALiBi 与 O(n²)

这节课把四道常连在一起考的题一次串清:「位置编码为何关键、它解决自注意力的什么问题?」「为何相对位置在 Transformer 里更本质?」「vanilla Transformer 固定注意力跨度的挑战、为何不能简单加长上下文?」「生成时如何高效处理长上下文?」(源:60 题·LLM 第 13、4、5、6 题;60 题·训练与推理 第 3 题)。目标:让你答得出「为什么长上下文又慢又贵」,并把业界的救法排成一条答题线。

上节课我们把注意力写成对 $V$ 的加权求和,权重来自 $Q\cdot K$ 的相似度。这里藏着一个问题:加权求和只看内容、不看座位。先别往下看——如果把输入序列的 token 顺序完全打乱,注意力的输出会跟着乱、还是本质不变?

一、根问题:自注意力「看不见」顺序

答案是本质不变:打乱输入,输出只是跟着同样地被打乱,算出来的两两关系集合一模一样。原因就在上节课那个公式——权重完全由 $Q\cdot K$ 的内容相似度决定,和「谁排第几」无关。这叫位置无关(排列等变)。

可语言的意义高度依赖顺序:「狗咬人」和「人咬狗」用的词一模一样,注意力却分不出差别。所以顺序信息必须显式地喂进去——这就是位置编码存在的全部理由:它解决的正是「自注意力天生丢失位置」这个缺口。

正弦位置编码(Sinusoidal Positional Encoding)
原始 Transformer 的做法:为每个位置 $pos$ 造一个固定向量 $PE(pos)$(由不同频率的 $\sin/\cos$ 拼成),加到该位置的 token embedding 上,让模型能从向量里读出「我在第几个」。
这是一种绝对位置编码——直接把「第几个」编码进去。它无需学习、可外推一点点,但「第几个」并不是语言里最本质的信息。

二、为什么相对位置更本质:RoPE 与 ALiBi

绝对编码告诉模型「你是第 5 个」;但真正影响理解的,往往是「这个词在那个词前面 2 格」这类相对关系。相对位置还有一个工程好处:模型训练时只见过有限长度,面对更长序列时,绝对位置里那些「没见过的座位号」会让它发懵,而相对距离更容易泛化到更长序列。这就是为什么现代大模型多转向相对位置编码。

RoPE(Rotary Position Embedding,旋转位置编码)
不再往 embedding 上「加」,而是按位置把 $Q$、$K$ 向量旋转一个与位置成正比的角度。旋转后,位置 $m$ 的 query 与位置 $n$ 的 key 做点积,结果只依赖相对距离 $m-n$:
$$\langle f(q,m),\,f(k,n)\rangle = g\big(q,\,k,\,m-n\big)$$
相对位置就这样「自然」进了点积,而且仍保持标准点积形式,能和高效注意力实现兼容。
ALiBi(Attention with Linear Biases)
更省事:不动 $Q/K$,直接在注意力分数上加一个与两 token 距离成正比的线性偏置——离得越远,惩罚越大。它把「就近关注」的先验直接写进分数里,也更容易外推到更长序列。

三、长上下文的根因:O(n²) 这堵墙

vanilla Transformer 的注意力窗口在训练时是固定的:超出窗口的内容根本进不来(这就是「固定注意力跨度」的挑战)。那把窗口调大不就行了?——问题是它会直接撞上复杂度的墙。

每个 token 都要和所有 token 算一次注意力,于是产生一个 $n\times n$ 的分数矩阵:计算量约 $O(n^2 d)$、显存约 $O(n^2)$。关键在那个平方——序列翻倍,计算与显存翻四倍。

序列 $n$(基准)
1×
序列 $2n$
4×
序列 $4n$
16×

相对开销(计算与显存):长度翻倍,代价约变 4 倍;翻 4 倍,代价约 16 倍。

所以「简单增大上下文长度」不可行:成本不是线性上涨,而是平方级爆炸——换更大显卡、加大 batch 只能拖一会儿,很快又撞墙。这也是为什么长上下文既慢又贵。

四、业界怎么救:一条答题线

面试问「生成时如何高效处理长上下文」,把下面几手按「省搬运 → 省显存 → 撑窗口 → 降复杂度」串起来讲,层次就出来了(源·训练与推理 3):

FlashAttention
分块算、省显存搬运
→
MQA / GQA
K/V 共享、缩 KV cache
→
Positional Interpolation
插值撑长窗口
→
RoPE / ALiBi
相对编码更好外推
→
稀疏注意力
只算部分、近线性
  • FlashAttention:把注意力分块(tiling)计算,不把完整的 $n\times n$ 矩阵写进显存,靠减少 GPU 显存搬运来提速省显存。注意:结果精确、复杂度仍是 $O(n^2)$——它省的是 IO,不是算力。
  • MQA(Multi-Query Attention):让所有注意力头共享同一份 K/V,推理时 KV cache 显存大幅下降、解码更快。GQA 是「分组共享」的折中,在质量与速度间取平衡。
  • Positional Interpolation:把超出原窗口的位置索引压缩插值回已训练过的范围,配少量微调就能把上下文窗口撑长(常与 RoPE 搭配)。
  • RoPE / ALiBi:相对位置编码本身就比绝对编码更容易外推到更长序列——是「长上下文友好」的地基。
  • 稀疏注意力(Sparse Attention):每个 token 只和一部分 token 算注意力(如局部窗口 + 少量全局锚点),复杂度从 $O(n^2)$ 降到近线性。

再补一句「生成时」的关键:自回归解码会复用 KV cache,已经算过的 K/V 不重算,MQA/GQA 正是在压这块 cache 的显存。

面试官会顺着往下追(高频链):

  • 「自注意力为什么必须要位置编码?」——因为它位置无关,打乱输入输出本质不变,分不出语序。
  • 「绝对 vs 相对位置编码差别在哪?」——相对更贴合语言、外推更好;举 RoPE、ALiBi。
  • 「RoPE 凭什么能带相对位置?」——按位置旋转 $Q/K$,旋转后点积只依赖相对距离 $m-n$。
  • 「上下文为什么不能随便加长?」——$O(n^2)$ 的计算与显存,翻倍即翻四倍。
  • 「那业界怎么支持长上下文?」——FlashAttention、MQA/GQA、Positional Interpolation、RoPE/ALiBi 外推、稀疏注意力,按省搬运/省显存/撑窗口/降复杂度分层答。
  • 「窗口变长,模型就一定用得好吗?」——不一定,有「中间信息被忽略」的现象(Lost in the Middle),扩窗 ≠ 会用。

易错点(注意别把手段说满):

  • 别说「FlashAttention 把复杂度从 $O(n^2)$ 降到线性」——它不改复杂度,结果精确,省的是显存搬运;真正逼近线性的是稀疏 / 线性注意力。
  • 别说「RoPE / ALiBi 能无限外推」——外推能力有限,超出太多仍会退化;Positional Interpolation 等通常还要配微调。
  • 别把位置编码说成「只能加在 embedding 上」——那是正弦编码;RoPE 作用在 $Q/K$,ALiBi 作用在分数上,落点不同。
  • 别说「MQA 共享 K/V 不损质量」——共享通常有一定质量损失,GQA 才是折中方案。绝对化措辞是面试扣分点。
  • 别说「换更大 GPU 就能任意加长上下文」——$O(n^2)$ 增长太快,硬件只能拖延、拖不掉这堵墙。

自测 1:自注意力必须外加位置编码,最根本的原因是?

A. 注意力权重之和必须归一化到 1那是 softmax 的职责,和位置信息无关。
B. token embedding 维度太高,需要位置向量来压缩位置编码不做降维,和维度压缩无关。
C. 自注意力位置无关,打乱输入顺序输出本质不变,分不出语序 ✅正确。权重只由内容相似度决定,不含顺序,所以必须显式补上位置信息。
D. softmax 在长序列上会导致梯度消失这是缩放因子处理的问题(见第 0002 课),与位置编码无关。

自测 2:关于长上下文,下列哪句最准确?

A. 上下文长度只受显存限制,换更大显卡即可任意加长不对,平方级增长很快撞墙,硬件只能拖延。
B. 自注意力的计算与显存随序列长度平方增长,序列翻倍则翻四倍 ✅正确。$O(n^2)$ 正是「简单加长不可行」的根因。
C. FlashAttention 把注意力复杂度从 $O(n^2)$ 降到了 $O(n)$不对,它省的是显存搬运、结果精确,复杂度不变。
D. RoPE 可以让模型无损外推到任意长度的序列不对,外推能力有限,超出太多仍会退化。

一手出处与深挖方向(都是真实存在的论文/工作):

  • Attention Is All You Need(Vaswani et al., 2017)——正弦位置编码与 $O(n^2)$ 注意力的原始出处。
  • RoFormer: Enhanced Transformer with Rotary Position Embedding(Su et al., 2021)——RoPE 原论文,本课的旋转直觉与 $g(q,k,m-n)$ 即出自此。
  • Train Short, Test Long(ALiBi)(Press et al., 2022)——用线性距离偏置实现长度外推。
  • FlashAttention(Dao et al., 2022)——IO 感知的精确注意力,分块省显存搬运。
  • MQA(Shazeer, 2019)与 GQA(Ainslie et al., 2023)——K/V 共享与分组折中。
  • Extending Context Window via Positional Interpolation(Chen et al., 2023);Lost in the Middle(Liu et al., 2023)——扩窗方法,以及「扩窗 ≠ 会用」的实证。

一句话记忆:自注意力位置无关,故必须补位置编码;相对位置(RoPE 旋转 Q/K、ALiBi 加距离偏置)比绝对更本质、更好外推;长上下文的墙是 $O(n^2)$——翻倍即翻四倍,靠 FlashAttention/MQA/插值/稀疏注意力分层去救。
