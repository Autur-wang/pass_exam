幻觉:为什么产生、如何评估与缓解

这节课把面试里最扎手的一组「诚实性」问题一次答清:「LLM 为什么会幻觉,能根除吗?」「幻觉怎么评估、怎么检测?」「怎么从模型拿到置信度/不确定信号?」「判断生成质量看哪些指标、为什么不能只看 perplexity?」以及压轴的系统设计题「设计一个检测并降低幻觉的系统」。(源:AI 工程师题库 Q4、Q12、Q133;60 题·训练与推理 第 4、5、7 题)。答这几道题的底色只有一句:幻觉是要「界定并管理」的风险,不是能「修好」的 bug。

上一课(0026)讲部署与可观测——上线后靠监控、日志、trace 去发现问题。但幻觉是所有故障里最难被观测的一种:它不报错、不崩溃、延迟正常,输出还流畅自信。先别往下看:如果一段回答语法完美、语气笃定,你怎么判断它是不是在编?模型自己「知道」它错了吗?

一、为什么会幻觉,能不能根除

直觉先行:LLM 的训练目标是预测像样的下一个词,不是「说真话」。它没有内建的真值观(no built-in notion of truth),也没有一个「我不知道」的开关。当训练数据对某话题很薄、或 prompt 把它推到它所知之外时,它照样会产出流畅但虚假的文本——因为在它的目标函数看来,一段通顺合理的编造和一段通顺正确的事实,长得一模一样。

所以正确的框定是:幻觉无法根除,只能管理。三条管理路径,后面几节会逐一展开——

grounding(RAG)、约束输出、更好的上下文

幻觉(Hallucination)
模型生成的、看似合理却与事实或所给上下文不符的内容。注意区分两类:与世界事实冲突(factuality),与所给来源冲突(faithfulness / 不忠实)。RAG 系统里后者更可控,也更该优先测——因为你有明确的「来源」当裁判。

面试里如果对方追「那能不能靠更大的模型/更多数据彻底解决?」——软化作答:更强的模型和更干净的数据能降低发生率,但只要目标仍是「预测像样文本」,残留风险就不会归零。把它当成要 bound(界定上界)的风险,而不是要 fix 的缺陷。

二、先谈评估:判断生成质量看什么,perplexity 为何不够

要治幻觉,先得会「测」。面试常问「判断生成质量有哪些指标」——把常见的几类摆清楚,并说明各自量的是什么:

  • Perplexity(困惑度):模型预测下一个词有多好,越低越好。是语言建模的内在指标。
  • Human evaluation(人工评估):人读、人打分。贵、慢,但对连贯性、事实性这类维度最可靠。
  • BLEU:偏机器翻译,比对与参考译文的 n-gram 重叠。
  • ROUGE:偏摘要,比对与参考摘要的重叠(召回向)。
  • Diversity(多样性):输出是否重复、单调。
  • Truthfulness(真实性):如 TruthfulQA,专门测模型是否会重复常见误解、说假话。
Perplexity(困惑度)
$$\mathrm{PPL}(x)=\exp\!\left(-\frac{1}{N}\sum_{i=1}^{N}\log p\!\left(x_i \mid x_{<i}\right)\right)$$ 本质是模型在测试文本上平均每步「有多意外」。越低 = 预测越准。但请盯住它只量了「预测下一个词好不好」这一件事。

为什么过度依赖 perplexity 有问题?因为它主要测下一词预测的准度,可能忽略:整体连贯性、事实性、以及细微的含义/含意(nuance/implication)。一段 perplexity 很低的文本,完全可以是流畅、通顺、又在一本正经地胡说——低困惑度和「说真话」根本不是一回事。对需要深层理解或创造性的任务,perplexity 更不反映真实表现。所以它适合当训练/建模的健康度指标,不适合单独用来判断「这段回答对不对、好不好」。

三、怎么检测幻觉:五种技术

60 题里这道「幻觉如何检测」给出一套很实用的工具箱,按「有没有概率信号」「是不是黑箱」分档来记最省力:

1) Log Probability(序列对数概率 / Seq-Logprob)
用长度归一化的序列对数概率当置信度:$\frac{1}{L}\sum_{t=1}^{L}\log p\!\left(y_t \mid y_{<t}\right)$。整段生成的平均 logprob 越低,越可疑。前提是你能拿到 token 概率。
2) Sentence Similarity(源贡献占比)
评估输出与来源的语义相似/蕴含程度——源的贡献占比低,就怀疑是幻觉。工具如 LASER、LaBSE(跨语句嵌入)或 XNLI(自然语言推理判蕴含)。
3) SelfCheckGPT(采样一致性,黑箱可用)
当拿不到概率、只有一个黑箱 API 时:对同一问题多次采样,看几次回答彼此是否一致——不一致 = 大概率在编。一致性可用 BERTScore 或 QA 方式来度量。
4) GPT-4 Prompting(用强模型逐句核事实)
用一个强模型 + CoT / 逐句提示,去检查目标输出的事实一致性(fact consistency)。本质是「LLM 当裁判」的一种。
5) G-EVAL(结构化打分)
用 GPT-4 + CoT + form-filling(表单式打分)来评 NLG 生成质量,把「好不好」拆成可打分的维度,输出更稳定。

记忆锚:有概率信号→ 用 Seq-Logprob;有明确来源→ 用 Sentence Similarity / NLI 蕴含;黑箱无概率→ 用 SelfCheckGPT 采样一致性;要更强判据→ 用 GPT-4 Prompting / G-EVAL 当裁判。

四、怎么从模型拿到置信度/不确定信号

这是 AI 工程师 Q12。先破一个误区:LLM 没有一个内建的、可直接读出的「这句话是对的的概率」。你只能近似。几条常见近似路径,各有陷阱:

  • Token 对数概率(logprobs):API 暴露时,可聚合成每 token / 整段的粗略置信。陷阱:流畅却错的文本经常拿高分——模型对自己的编造一样很「自信」。
  • Self-consistency(自一致性):同题多次采样,看回答稳不稳。答案飘忽本身就暴露了不确定。
  • Verbalized confidence(让模型自评):显式要求「给出你的置信度,不确定就直说」。能拿到粗信号,但这个自报数必须拿真实结果去校准(calibrate)才可信。
  • RAG 检索分:在 RAG 系统里,检索器的相关性分往往比生成器自报的置信更诚实——检索没命中好文档,就是个直接的「我可能要编了」的预警。
核心纪律:先校准,再据此门禁
无论 verbalized confidence 还是 logprobs,都要在你自己的数据上验证它是否真的与「答对」相关,校准通过后才拿它做门禁(阈值以下就拒答/转人工)。直接信模型自报的数字,是新手常踩的坑。

五、把它做成系统:reduce → detect → contain

压轴题 Q133「设计一个检测并降低幻觉的系统」。别指望一个开关——答成分层的:源头减少 + 事后检测 + 兜底控制,并测残留率。

Reduce(减少)

grounding:先检索可信来源,把「只根据下面材料回答,材料没有就说不知道」写进指令;约束输出(schema / 受限选项);给干净、最小的上下文——上下文越杂、越长,越容易诱发跑偏(呼应 Lost in the Middle)。

Detect(检测)

忠实度 / 蕴含检查:把回答拆成一条条 claim,逐 claim 对引用材料核验——用 NLI(判蕴含/矛盾)或 LLM judge;再加引用覆盖检查(每个论断是否都挂到了来源)和置信信号。关键:offline eval(上线前跑测试集)和 online 抽样(线上抽查真实流量)都要跑,只做其一都会漏。

Contain(兜底)

显示来源让用户能自己核验;支持不足时拒答而不是硬编;高危场景 + 低置信 → 路由给人审核。把「测残留幻觉率」当成一个持续跟踪的线上指标,而不是上线前跑一次就完。

面试官会顺着往下追(高频链):

  • 「LLM 为什么会幻觉?」——目标是预测像样文本、无内建真值观;数据薄或被推到所知之外就产出流畅假话。
  • 「那能根除吗?」——不能,只能管理;答 reduce/detect/contain 三层,并强调「界定风险上界,不是修 bug」。
  • 「怎么检测?」——分档答:有概率用 Seq-Logprob、有来源用相似度/NLI、黑箱用 SelfCheckGPT 采样一致性、要强判据用 GPT-4 Prompting / G-EVAL。
  • 「怎么拿模型的置信度?」——logprobs / self-consistency / verbalized confidence / RAG 检索分,且都要在自己数据上校准;点出「流畅却错的文本常拿高分」这个坑。
  • 「评估生成质量用什么、为什么不能只看 perplexity?」——列 perplexity/人工/BLEU/ROUGE/diversity/truthfulness;perplexity 只测下一词预测,忽略连贯性、事实性、nuance。
  • 「给我设计一个降幻觉系统」——上面那张 reduce→detect→contain 图,强调 offline+online 都跑、持续测残留率。

易错点(绝对化措辞是扣分点):

  • 别说「用了 RAG 就不会幻觉」——RAG 显著降低幻觉,但检索错源、或模型无视上下文照编,依然会幻觉;所以才需要 Detect 层的引用核验。
  • 别说「logprob 高就代表答案对」——流畅的编造常拿高 logprob;置信信号必须校准后才可用。
  • 别说「perplexity 越低模型越好/回答越对」——它只量下一词预测,和事实正确性不是一回事。
  • 别说「幻觉能彻底根除」——只要目标是预测像样文本,残留风险就不归零;正确说法是「界定并管理」。
  • 别把 detection 只放在上线前——offline eval 抓不到真实分布的问题,必须配 online 抽样。

自测 1:面试官问「为什么不能只用 perplexity 判断一段回答的质量?」下列哪句最准确?

A. perplexity 计算太慢,不适合线上使用速度不是核心问题,它其实很好算。
B. perplexity 主要量「下一词预测有多准」,可能忽略连贯性、事实性和细微含意,低困惑度也能是流畅的胡说 ✅正确。低 perplexity ≠ 说真话,它测的是建模好坏而非正确性。
C. perplexity 只能用于翻译任务,不能用于摘要那是 BLEU 的偏向;perplexity 是通用的语言建模指标。
D. perplexity 越高说明模型越好反了,perplexity 越低越好。

自测 2:你在一个只能黑箱调用、拿不到 token 概率的 API 上做幻觉检测,下列哪种方法最对口?

A. Seq-Logprob:用长度归一化的序列对数概率当置信度需要 token 概率,黑箱拿不到,用不了。
B. 直接读模型内建的「正确概率」字段LLM 没有这种内建字段,这是常见误解。
C. SelfCheckGPT:对同一问题多次采样,看回答彼此是否一致 ✅正确。无概率、黑箱场景就靠采样一致性,不一致即大概率幻觉。
D. 降低温度到 0,输出稳定就说明没幻觉输出稳定只代表确定性,稳定地编造依然是幻觉。

一手出处与深挖方向:

  • SelfCheckGPT(Manakul et al., 2023)——黑箱、无概率场景下用采样一致性检测幻觉的方法。
  • G-EVAL(Liu et al., 2023)——用 GPT-4 + CoT + form-filling 评 NLG 质量。
  • TruthfulQA(Lin et al., 2022)——衡量模型是否重复常见误解、说假话的真实性基准。
  • Lost in the Middle(Liu et al., 2023)——长/杂上下文如何让模型「看不见」中间信息,呼应本课 Reduce 层「干净最小上下文」。
  • NLI 蕴含判断可参考 XNLI;跨句嵌入相似度可参考 LaBSE / LASER。RAG 忠实度评估延伸到第 0017 课(RAG evaluation & trust)。

一句话记忆:幻觉源于「预测像样文本、无真值观」,不能根除只能管理——reduce(grounding+约束) → detect(逐 claim 对引文核验+置信信号,offline+online) → contain(显来源/拒答/转人工);置信信号都要先校准,perplexity 只测下一词、别拿来判对错。
