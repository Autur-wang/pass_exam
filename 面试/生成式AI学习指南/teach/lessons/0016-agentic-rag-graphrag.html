Agentic RAG 与 GraphRAG:多跳与迭代检索

这节课一次讲清 RAG 的两条「进化线」,答住三道高频题:「什么是 agentic RAG,何时需要?」「什么是 GraphRAG,解决什么问题?」「agentic RAG 有哪些能力、单/多/分层三种拓扑、有哪些挑战?」(源:AI 工程师题库 Q40、Q41;资源库 agentic_rag_101)。核心一句话先记住:agentic RAG 升级的是「控制流」——谁来决定怎么检索;GraphRAG 升级的是「数据结构」——在什么结构上检索。两者正交,可组合。

上一课(0015)讲的 reranker、hybrid search、query 改写/HyDE,都是把「单次检索」这一枪打得更准。但有些问题,再准的一枪也打不下来。先别往下看:如果一个问题的证据散落在好几篇文档里,而且「该查哪一篇」得先查到前一篇才知道——再强的单次 top-k 检索,救得了吗?

一、Agentic RAG:把检索的「决定权」交给模型(Q40)

普通 RAG 是一条固定的直线管线:query 进来 → 向量检索 top-k → 拼进 prompt → 生成。检索发生一次、时机固定、查哪个源写死在代码里。它对「一段文档就能答」的问题又快又好。

但遇到多跳问题(一次检索凑不齐所有事实)或「该用哪个源取决于问题本身」的场景,固定管线就卡壳了。Agentic RAG 的思路是:不再固定地 retrieve-then-generate,而是让一个 agent(由 LLM 驱动)主导整个检索过程——它自己决定要不要检索、怎么改写 query、要不要迭代多轮、跨多个源/工具里挑哪个,并对拿回来的结果做推理再决定下一步。

Agentic RAG
把「检索策略」从写死的管线变成 agent 的运行时决策:是否检索、如何改写 query、迭代多少轮、从哪个源/工具取数、如何对结果推理,都由模型动态决定。
代价很实在:更多的模型调用、更高的延迟,以及一批新的失败模式——比如把 query 改写坏了、或陷入反复检索的死循环。所以原则是:固定 RAG 够用就用固定;只对确实需要多步收集证据的问题,才上 agentic。

二、能力清单与三种拓扑(agentic_rag_101)

面试若问「agentic RAG 有什么能力」,资源库给的标准清单是这七条,挑三四条讲透即可:动态检索(按问题实时选源取数)、自主决策(全流程无需人工干预)、上下文感知(按 query 语境调整检索)、可扩展(跨多源、多域调度负载)、降幻觉风险、可定制工作流(按业务调检索策略)、多步推理(把复杂问题拆成小步逐步求解)。

问「有哪几种类型」,按 agent 之间怎么组织分三档,复杂度递增:

① Single-Agent
一个 agent 包办全部检索与生成
简单、常规查询
② Multi-Agent
多个专职 agent 分工:有的负责某个源的检索,有的负责整合
需多源/可拆分的复杂任务
③ Hierarchical
高层 agent 监督、调度低层 agent 执行
需多层决策、处理优先级冲突

选型逻辑很朴素:越简单的任务越该用越简单的拓扑。Single-Agent 处理路由清晰的常规问答;Multi-Agent 适合「不同类型数据要从不同源取、任务能拆成专门子块」;Hierarchical 适合「要在多个层级做战略决策、要给数据源排优先级或平衡相互竞争的目标」的高复杂场景。

但能力越强,挑战越多。资源库列的四个挑战,正是面试想听你主动补的「阴影面」:

  • 协调复杂度:agent 越多,彼此同步越难,不同优先级容易撞车、形成瓶颈,拖慢甚至答不全。
  • 可扩展性:管理大量 agent 与数据源很吃资源,规模一大,实时性和准确性难两全。
  • 数据质量与可靠性:agent 从不可靠的源取数,就会把错误信息喂进答案。
  • 决策透明度:很难看清 agent「为什么这么决策」,容易变成难以调试的「黑箱」。

三、GraphRAG:换掉的是「数据结构」(Q41)

换个维度看问题。固定 RAG 把语料切成一堆扁平的文本块(chunk),检索时靠向量相似度捞 top-k。这对「答案就在某一段里」的问题很好用,但对全局型 / 关系型 / 多跳的问题会失灵——因为相关事实散落在很多块里,任何单块都不完整,top-k 也拼不出全貌。

典型问不出来的问题:「这批文档共同讲了哪些主题?」「A 是经由 B 怎样关联到 C 的?」——这类问题要的是「跨文档、把点连成线」的能力,而扁平块检索天生看不到这种结构。

GraphRAG(微软研究院提出)
先用 LLM 从语料里抽取实体与关系,建成一张知识图谱(knowledge graph)(有时再对图上的社区生成摘要);检索时在这张图结构上做,而不是只在扁平文本块上做。
因为图里显式存了「谁和谁有什么关系」,它天然擅长全局问题和多跳关联——顺着边就能把散落各处的事实连起来。代价是:要一条更重、更贵的摄入(ingestion)管线去抽实体、建图、维护图。什么时候用?当问题是关系型 / 语料级、而不是「单段就能答」的时候。

四、两条升级线正交,可组合

别把 agentic RAG 和 GraphRAG 摆成「二选一」——它们改的是完全不同的东西:

Agentic RAGGraphRAG
升级的是控制流(谁决定怎么检索)数据结构(在什么结构上检索)
核心动作模型运行时决定:是否/如何/迭代检索、选哪个源把语料建成实体-关系图,在图上检索
擅长多步收集、按问题动态选源全局/关系型/多跳、跨文档连线
主要代价更多调用/延迟、坏改写与死循环等新失败模式更重更贵的建图/维护摄入管线

因为一个管「控制流」、一个管「数据结构」,两者可以叠着用:让一个 agent 主导流程,而它检索时面对的正是一张知识图谱——多跳问题里「先查 A 才知道该查 B」的迭代,和图上「顺边连线」的能力,恰好互补。

面试官会顺着往下追(高频链):

  • 「固定 RAG 和 agentic RAG 到底差在哪?」——一句点破:控制流。固定=一次写死的 retrieve-then-generate;agentic=模型运行时决定是否/如何/迭代检索、选哪个源。
  • 「什么时候才该上 agentic?不能一律用吗?」——只对多跳 / 该查哪个源取决于问题的复杂查询上;简单单跳别上,否则白白加延迟、加调用、加新失败模式。
  • 「agentic RAG 有哪几种拓扑?怎么选?」——Single / Multi / Hierarchical,按任务复杂度从低到高选。
  • 「agentic RAG 能降幻觉吗?」——能降低风险,但有条件:取决于源的质量。坏源照样喂出错答案,在医疗/金融这类场景尤其危险。别把它说成「消除幻觉」。
  • 「GraphRAG 解决了固定 RAG 的什么短板?代价是什么?」——短板:全局/关系型/多跳问题,事实散落多块、扁平检索拼不齐;代价:更重更贵的建图摄入管线。
  • 「agentic RAG 和 GraphRAG 冲突吗?」——不冲突,正交且可组合:一个升级控制流,一个升级数据结构。答出这句,层次立刻拉开。

面试易错点(绝对化说法都要给反例):

  • 「agentic RAG 一定比固定 RAG 好」——错。对单段可答、追求低延迟的高频简单问答,agentic 只是白白多花调用与延迟,还引入坏改写、死循环等新失败模式。固定够用就别上。
  • 「agentic RAG 能消除幻觉」——软化。它只是降低风险,且效果依赖源质量;源不可靠时照样出错。降幻觉是「有条件的」,不是「必然的」。
  • 「GraphRAG 总比向量检索强」——错。对单段就能答的事实型问题,扁平向量检索又快又准;GraphRAG 那条重摄入管线在这类问题上是白花钱。它赢在关系型 / 语料级问题,不是全能。
  • 「多 agent 一定比单 agent 强」——错。Single-Agent 处理常规任务更省更稳;多/分层拓扑换来的是协调复杂度、可扩展性压力和「黑箱」透明度问题。

自测 1:下面哪种情况最适合把固定 RAG 升级成 agentic RAG?

A. 单段文档即可作答、只求最低延迟的高频简单问答恰恰相反。这种场景固定管线又快又好,上 agentic 只是白白加调用、加延迟、加新失败模式。
B. 语料完全静态、一次 top-k 就能凑齐全部证据的场景一枪就够的问题不需要 agent 迭代决策,固定 RAG 更合适。
C. 需要多跳收集、且「该查哪个源取决于问题本身」的复杂查询 ✅正确。一次检索凑不齐、数据源需按问题动态选择——这正是 agentic RAG 的主场。
D. 只需把已有答案重排成 JSON、不涉及新知识获取的任务这是格式化,不涉及检索决策,和 agentic RAG 无关。

自测 2:GraphRAG 最擅长、而扁平文本块检索最吃力的是哪类问题?

A. 「把这一段翻译成英文」这类单段就能完成的改写任务不涉及跨文档关联,扁平检索甚至根本不需要检索。
B. 「这些文档共同指向哪些主题」「A 经 B 如何关联到 C」这类全局/多跳关系问题 ✅正确。相关事实散落多块、需要顺着实体关系连线,正是 GraphRAG 在图结构上的强项。
C. 「文档第 3 页第 2 段写了什么」这种能定位到单块的精确检索答案就在某一块里,扁平向量检索反而更直接高效。
D. 「今天天气如何」这类需要实时 API 而非语料库的查询这靠的是工具/API 调用,与在语料图上检索是两码事。

一手出处与深挖方向:

  • From Local to Global: A Graph RAG Approach to Query-Focused Summarization(Edge et al., Microsoft Research, 2024)——GraphRAG 的原始论文,讲清「建实体-关系图 + 社区摘要」如何回答扁平检索答不好的全局问题。
  • Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection(Asai et al., 2023)——让模型自己决定何时检索、并对检索结果自评,是 agentic「模型主导检索」思想的代表作。
  • ReAct: Synergizing Reasoning and Acting in Language Models(Yao et al., 2022)——推理与行动交替的循环,是 agentic RAG 迭代检索环的底层范式。
  • Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks(Lewis et al., 2020)——固定 RAG 的原论文,理解「起点」才看得清这两条升级线在改什么。
  • 资源库 agentic_rag_101(awesome-generative-ai-guide)——本课的能力清单、三种拓扑与挑战即出自此。

一句话记忆:Agentic RAG 升级「控制流」(模型自己决定是否/如何/迭代检索、选哪个源,多跳才上);GraphRAG 升级「数据结构」(在实体-关系图上检索,专治全局/多跳);两者正交、可组合,降幻觉是有条件的。
