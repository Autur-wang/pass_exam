Lesson 0004 · 第 2 章 三层架构

项目骨骼:五个包各管各的

🎯 本课目标:上一课我们摸清了 Pi 怎么"跑起来"(运行模式 + models.json); 这一课往回退一步,先别管怎么跑,只看克隆下来的代码库长什么样—— packages/ 下五个包,每个包各自负责哪一摊活。这是本章"三层架构"的第一块砖, 只讲物理骨骼,不碰依赖方向和类型细节(那是下一课的事)。
⏮ 回忆上一课:0003 讲了 Pi 的四种运行模式和 models.json 怎么接第三方模型—— 但那节课里出现的 cli.ts、main.ts 这些名字,到底住在仓库的哪个角落? 这节课就带你去 ls 一下真实的目录。
这节课你将能做到一件事: 打开 Pi 的仓库,一眼认出 五个包各自的职责——不是背下名字,而是能说出 "pi-ai 只管调模型,pi-agent-core 只管跑循环,pi-coding-agent 才知道具体业务" 这条主线,以及 pi-tui、pi-orchestrator 两个"旁支"为什么不算在主线里。
🎯 贯穿全课的类比:先认识五个同事,再谈他们怎么协作 第一次克隆 Pi,在终端敲下 ls,看见 packages/ 下五个包整整齐齐排成一排—— 先别管它们怎么勾连、谁听谁的,先像认识五个同事一样,搞清楚每个人各自负责哪一摊活。 谁管模型、谁管循环、谁管业务、谁管显示、谁是新来的实习生——这节课只做这件事。

1 · 打开仓库:五个包排排站

假设你第一次克隆了 Pi 的代码库,ls 一下,看到的是标准的 npm workspaces monorepo——根目录 package.json 里声明了 "workspaces": ["packages/*"],packages/ 下每个子目录就是一个独立的包: 

1repo/
2├── packages/
3│   ├── ai/              ← @earendil-works/pi-ai
4│   ├── agent/           ← @earendil-works/pi-agent-core
5│   ├── coding-agent/    ← @earendil-works/pi-coding-agent
6│   ├── orchestrator/    ← @earendil-works/pi-orchestrator(实验性,多 Agent 编排)
7│   └── tui/             ← @earendil-works/pi-tui
8├── package.json         ← 根配置,npm workspaces
9└── tsconfig.json
为什么拆成多个包,而不是一个大文件? 用 npm workspaces 把职责切开,每个包只做一件事、 可以独立发布复用——理解了这一套"元结构",后面钻进任何一层都不会迷路。 这也是为什么这门课要先花一整节课"认人",再谈"协作"。

2 · 核心三件套:自底向上各管一摊

五个包里,真正构成主线的是核心三件套:pi-ai(管调模型)→ pi-agent-core(管跑循环)→ pi-coding-agent(管具体业务)。 先看最底层的 pi-ai——它的 index.ts 导出清单说明了一切: 

1// packages/ai/src/index.ts(v0.80.x 节选)
2// 顶部注释明确写:Core only, side-effect free: no generated catalogs,
3// no provider factories, no api-registry, no OAuth implementations, no compat.
4export type { Static, TSchema } from "typebox";
5export { Type } from "typebox";
6export * from "./api/lazy.ts"            // 各 Provider API 的懒加载入口
7export * from "./auth/context.ts"        // 认证上下文
8export * from "./auth/credential-store.ts"
9export * from "./auth/helpers.ts"
10export * from "./auth/types.ts"
11export * from "./images-models.ts"
12export * from "./models.ts"              // 模型定义(KnownProvider 35 个)
13export * from "./types.ts"               // 统一类型
14export * from "./utils/event-stream.ts"  // 事件流基类
15// 流式调用入口(stream / streamSimple)实际位于 ./compat.ts

数一数这份清单:没有 agent、没有 tool、没有 loop。 pi-ai 只承诺做一件事——抹平 30+ 提供商的差异,对外暴露统一类型和 streamSimple()。

再往上一层,pi-agent-core 是 general-purpose(通用)的——它不知道自己在做 编程 Agent 还是客服 Agent,只知道怎么维护状态(AgentState)、跑循环(agentLoop)、 发事件(AgentEvent)、做上下文压缩(compact)。最后,pi-coding-agent 是最厚的一层——上百个源文件,7 个编程工具、扩展系统、会话持久化、CLI 全在这里。

为什么 pi-ai 的 index.ts 里刻意没有 agent / tool / loop? 因为它把"调模型"这件事做纯, 才可能被上层无负担地复用。为什么 pi-agent-core 强调 general-purpose? 因为框架层不绑定任何领域, 客服 Agent、编程 Agent 都能复用同一套循环 / 状态 / 压缩——具体的 read / bash 工具,恰恰不住在这一层。

3 · pi-coding-agent:最厚的一层,启动链路从这里开始

用户在终端敲下 pi 命令,程序从 cli.ts 启动——一个极简的入口: 

1// packages/coding-agent/src/cli.ts
2#!/usr/bin/env node
3import { main } from "./main.js";
4main(process.argv.slice(2));

一个简单的入口,背后是一整条启动链路:

1你输入: pi "帮我改个 bug"
2│
3├── cli.ts          ← 解析命令行参数
4│   └── main.ts     ← 创建会话、选择运行模式(交互/打印/RPC)
5│       └── AgentSession    ← 组装工具、加载扩展
6│           └── Agent       ← 管理状态、跑循环
7│               └── agentLoop()  ← 核心循环开始
🔑 记住这条链的方向: cli.ts → main.ts → AgentSession → Agent → agentLoop()—— 从外到内,从"解析参数"逐层收窄到"核心循环开始"。这条链会在后续讲 Agent Loop 的章节被逐段拆开细讲, 这节课只需要认得这五个名字、记住谁在最外层。

4 · pi-tui 与 pi-orchestrator:两个不在主线上的"旁支"

剩下两个包,不属于核心三件套。pi-tui 是独立的终端 UI 层,运行时依赖只有两个包: 

1// packages/tui/package.json (dependencies,节选自教程 §2.4)
2{
3  "dependencies": {
4    "marked": "...",                    // Markdown 渲染
5    "get-east-asian-width": "..."     // 东亚字符宽度计算
6  }
7  // 不含任何 pi-xxx 包,也不含任何 AI 相关的包
8}

pi-tui 只管显示,和"Agent 怎么工作"没有直接关系。而 pi-orchestrator 是 v0.80.x 新增的实验性外围编排层,站在 coding-agent 之上,负责让多个 coding-agent 实例协同工作——学习主线暂不深入,留到进阶阶段再接触。

为什么 pi-tui 运行时不依赖任何 AI 包? 显示与 Agent 逻辑彻底解耦,UI 换不换都不影响内核—— 这也预告了下一课要讲的"依赖方向"规则:谁能依赖谁,是有硬边界的。
三层直觉分层图 —— 认完五个同事,先建立一个直觉画面 ┌─────────────────────────────────────────────┐ │ pi-coding-agent:我知道怎么写代码 │ ← 最懂业务 │ (工具、扩展、CLI、会话持久化) │ ├─────────────────────────────────────────────┤ │ pi-agent-core:我知道怎么跑 Agent │ ← 只懂框架 │ (循环、状态、事件、压缩) │ ├─────────────────────────────────────────────┤ │ pi-ai:我知道怎么调模型 │ ← 只懂模型 │ (统一 API、流式调用、30+ 提供商适配) │ └─────────────────────────────────────────────┘ 旁边还有一个独立的 UI 包,和一个实验性外围包: ┌──────────┐ ┌────────────────┐ │ pi-tui │ │ pi-orchestrator │ ← 站在 coding-agent 之上,实验性 │ 只管显示 │ │ 多 Agent 编排 │ └──────────┘ └────────────────┘
