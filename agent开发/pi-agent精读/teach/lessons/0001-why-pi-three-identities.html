Lesson 0001 · 第 1 章 开篇总览

为什么 Pi 值得你花时间
—— 三重身份与「减法」哲学

🎯 本课目标:这是整门课的第一课,不碰源码,只回答一个更根本的问题—— Pi 到底是什么、凭什么值得你逐行读它的源码?读完你会明白:我们接下来 30 多节要拆的, 是一个小到能被完整读完、且每一处「不做什么」都藏着设计智慧的生产级 Agent。
这节课你将能做到一件事: 向别人一句话讲清 Pi 的三重身份 ——编码工具 / 学习教材 / 开发 SDK,并说出 Pi「刻意不做 MCP、不做子 Agent、不做权限弹窗」 背后的共同理由。
🎯 贯穿全课的类比:从「满」开始,还是从「空」开始? 想象两家搬家公司。一家(Claude Code 路线)把卡车塞满你可能用到的一切工具, 你上车先花半天清空用不上的;另一家(Pi 路线)给你一辆干净的车和一套挂载点, 你按需把工具装上去。前者从「满」开始做减法,后者从「空」开始做加法。 Pi 赌的是:对于想搞懂「一次搬家到底需要哪几件工具」的人,从空开始才看得清。

1 · 一句话定义 + 三重身份

Pi 的官方定义是:一款极简、可扩展的终端编码 Agent 外壳(coding agent harness), 由 libGDX 作者 Mario Zechner 创建,全部用 TypeScript 编写,MIT 协议开源。 它住在终端里,没有 GUI、没有 IDE 插件——这个「终端外壳」的形态,决定了它后续的一切设计选择。

你可能因为三种不同的原因点开这门课,而它们恰好对应 Pi 的三重身份:

你的诉求Pi 的身份这门课怎么喂你
想要个好用的编码 Agent🛠️ 编码工具本课讲清它的差异化(上下文干净、模型自由、树状会话)
想知道 Agent 到底怎么做的📖 学习教材后续 30 节逐层拆源码——这是本课的主线
要做自己的 Agent🧩 开发 SDK讲清三层堆栈怎么被你复用(0002 起)

三个诉求指向同一个项目,这本身就值得好奇——一个东西怎么能同时把这三件事做好?答案在它的「小」。

2 · 关键数字:小到能被「读完」

Pi 值得做教材的头号理由,是它足够小。很多 Agent 框架动辄几万行, 光搞清启动流程就要读几十个文件;Pi 的核心循环只有几百行。看几个数字(均按 v0.80.2 源码实际值):

指标数值含义
GitHub Stars64,000+十个月增长,社区验证了需求
内置工具4 核心 + 3 辅助核心 read / write / edit / bash;辅助 grep / find / ls
系统提示词静态模板 ~90 词运行时拼接 tools/skills 后约 200–400 词;对比 Claude Code 的数万字
核心包4 个pi-ai / pi-agent-core / pi-tui / pi-coding-agent
供应商30+ 家源码 KnownProvider 枚举 35 个(含区域变体),独立品牌约 27 个
运行模式4 种交互 / print-JSON / RPC / SDK
为什么「小」是一种功能,而不是缺陷? 因为它让「真正读完一个高质量 Agent 的全部核心代码」 这件事第一次变得可能——这对 Claude Code、对 LangChain 都是做不到的。而且 Pi 的小不等于弱: 它在 TerminalBench 基准测试中排名第二(使用 Claude Opus 4.5),仅次于 Terminus, 尽管它缺少 MCP、子 Agent、计划模式。小,是刻意设计出来的克制,不是没来得及做。

3 · 减法哲学:Pi「不做什么」清单

这是理解 Pi 最关键的一节。竞争对手在罗列功能,Pi 官网有一章叫 "What we didn't build"(我们没有构建什么)——一份倒过来的宣言。 每一次舍弃背后,都有清晰的工程理由:

Pi 不做的为什么不做替代方案
MCP 支持MCP 服务器(如 Playwright MCP)会在会话开始灌入 13,700+ token 的工具描述带 README 的 CLI 工具,Agent 按需读取
子 Agent增加复杂度,降低可观察性tmux 多实例,或专用扩展
权限弹窗导致「弹窗疲劳」,沦为安全表演(security theater)容器化隔离,或用扩展搭审批流程
计划模式计划写进 markdown 文件更持久、可复用写 plan.md 文件
后台 bashtmux 已经解决了这个问题用 tmux
内置待办TODO.md 文件更灵活用 markdown 文件或自建扩展
🔑 找出共同理由: 把这六行读两遍,你会发现它们指向同一条原则—— 凡是会污染上下文、降低可观察性、或制造虚假安全感的东西,都不进核心。 上下文窗口是 Agent 最稀缺的资源;可观察性是调试 Agent 的命脉;安全表演比没有安全更危险。 Pi 把这三条守得极死,缺的功能一律靠扩展补——这就是「从空开始」的落地方式。

4 · 尝一口代码:pi-ai 的极简调用

后面每节都会读真实源码,这里先尝一口,建立「Pi 的 API 长什么样」的直觉。 最底层的 pi-ai 包只管一件事——调模型。它不依赖任何 Agent 概念: 

1// 入口在 compat 子模块(不在主入口)
2import { getModel, stream } from '@earendil-works/pi-ai/compat';
3import type { Context } from '@earendil-works/pi-ai';
4
5const model = getModel('anthropic', 'claude-sonnet-4-5');
6// Context 是 interface(不是 class),用对象字面量构造
7const context: Context = {
8  systemPrompt: 'You are helpful.',
9  messages: [{ role: 'user', content: 'Hello!' }],
10};
11
12const eventStream = stream(model, context);  // ← 返回的是「事件流」,不是一坨字符串
13for await (const event of eventStream) {
14  if (event.type === 'text_delta') process.stdout.write(event.delta);
15}

注意第 12–14 行:调模型返回的是一个可以 for await 逐块消费的事件流, 而不是等它憋完一整段再返回。这个「流」的设计会一路贯穿到 Agent Loop、事件系统——记住这个画面。
