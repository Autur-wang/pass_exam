Lesson 0023 · 第 7 章 事件驱动

追踪一个 text_delta 的完整旅程

🎯 本课目标:上一课讲清了「10 种事件、4 层嵌套」和「内核 10 种 + Session 7 种」两层事件的划分。 这一课把它们串成一条真实的数据流——跟着一个字,看它怎么从 LLM 的网络响应, 一路跨过 5 层,最终出现在你的终端屏幕上。读完你会明白事件驱动架构真正厉害在哪:不是"通知",而是开放扩展。
🔁 回忆上一课:Agent 内核只定义 10 种 `AgentEvent`(4 层生命周期嵌套); AgentSession 又用联合类型加了 7 种产品级事件(队列、压缩、重试……)。 判断一个事件该放内核还是外层,标准是——去掉它内核还能不能正常跑。 今天要问的问题不一样:这些事件具体是怎么流动的?一个字从 LLM 嘴里"说"出来, 到你眼睛看见它,中间到底发生了什么?
这节课你将能做到一件事: 画出并讲清一个 text_delta 从 LLM SSE 流到终端屏幕的完整 5 步旅程,并说出为什么"层间只用事件通信"这条约束 能让"实时观测 / 工具拦截 / 上下文预处理 / 流式转发到 Web"这些功能零改 Agent 内核就能实现。
🎯 贯穿全课的类比:一件包裹的 4 个中转站 想象 LLM 正在生成"你好"两个字。其中一个"你"字,就像一件从工厂发出的包裹: 工厂(LLM 的 SSE 网络流)把它交给中转1(AI 层 EventStream.push()), 中转1 转手给中转2(Agent Loop 做事件转换),中转2 交给中转3 (Agent.processEvents() 的同步屏障),中转3 交给中转4 (AgentSession 分发与持久化),最后到终点(TUI)才被打开、显示在你眼前。 每一站只管自己那一道处理,不插手别的站在干什么。

1 · 一个"你"字的 5 步旅程

假设 LLM 正在生成"你好"。一个"你"字从产生到你在终端看见它,精确地经过 5 步—— 下面这张图逐字对应源码里真实存在的方法名和字段名: 

1触发端：LLM SSE 网络流
2  │  data: {"type":"text_delta","delta":"你",...}
3  │
4  ▼ 中转1：AI 层 EventStream.push()
5  │  异步队列，AssistantMessageEvent { type: "text_delta", delta: "你" }
6  │  （第4章讲过的12种事件之一）
7  │
8  ▼ 中转2：Agent Loop 事件转换
9  │  AI 层 text_delta → Agent 层 message_update
10  │  原始事件通过 assistantMessageEvent 字段透传
11  │
12  ▼ 中转3：Agent.processEvents()（同步屏障）
13  │  更新 streamingMessage 内部状态
14  │  await 所有 listeners
15  │
16  ▼ 中转4：AgentSession._handleAgentEvent()
17  │  通知扩展系统 → 分发给 Session 监听器 → 持久化
18  │
19  ▼ 终点：TUI 监听器
20  │  提取 delta "你" → 渲染到终端
21  │
22  ▼
23你看到了 "你" 字出现

整条链路上,每一层只关心自己的转换:AI 层只管解析 SSE 和构建消息; Agent Loop 只管 emit 事件和处理工具;Agent 只管更新状态和 await 监听器; Session 只管分发和持久化;TUI 只管渲染。

为什么层间只能用事件通信,不能直接调用? 源码里没有任何一层直接调用另一层的内部方法—— AI 层不知道 Agent Loop 怎么处理事件,Agent 不知道 TUI 长什么样,TUI 也不知道 Session 怎么持久化。 它们之间唯一的通信协议就是"事件"。这让 5 层各自独立演化、互不侵入: 你换掉 TUI 换成 Web 前端,AI 层、Agent Loop、Agent、Session 一行都不用改。

2 · 关键数据变换:统一映射 + 透传保留

中转2(Agent Loop 事件转换)藏着这条旅程里最值得琢磨的一步。AI 层其实有好几种 delta 事件—— text_delta(正文文字)、thinking_delta(思考过程)、toolcall_delta(工具调用参数)—— 但它们到了 Agent 层,全部被统一映射成同一个 message_update: 

1// AI 层的三种 delta，到了 Agent 层统一变成同一个事件类型
2export type AgentEvent =
3  // ……（第3层：Message 生命周期）
4  | { type: "message_update"; message: AgentMessage; assistantMessageEvent: AssistantMessageEvent }
5  //                                                    ^ 原始 delta（text_delta / thinking_delta / toolcall_delta）
6  //                                                      通过这个字段透传保留，而不是被丢弃

Agent Loop 拿到 AI 层的任何一种 delta,都只做一件事:「消息更新了」,打包成 message_update 往下传。它不关心 delta 具体是文字、思考还是工具参数。

为什么要统一映射? 因为 Agent Loop 只需要知道"消息更新了"这一件事就够了—— 统一映射把"三种不同的东西"简化成"一种事件",大大简化了 Agent Loop 自己的逻辑。
🔑 但原始类型信息不能丢: Agent Loop 不关心 delta 的具体类型, 但下游消费者可能关心——比如 TUI 要区分"思考过程"(灰色小字)和"正文"(正常显示)。 所以原始的 AssistantMessageEvent 被完整地挂在 assistantMessageEvent 字段上 透传保留,而不是在中转2 就地丢弃。这是"统一映射 + 透传保留"的典型取舍: 上层简化逻辑,细节留给真正需要它的人。
🔎 出处:教程第 7 章 §二「10 种事件,4 层嵌套」`AgentEvent` 类型定义 + §六 关于统一映射的说明(第7章-事件驱动-Agent的神经系统.md)。

3 · 开放扩展:同一套机制能干什么

理解了机制之后,真正有意思的问题是:你能拿这套事件系统做什么?下面两个场景, 都是只订阅、不改 Agent 内核一行代码就实现的:

场景1 · 实时观测 Agent 在干什么——监听工具执行的开始与结束:

1session.subscribe((event) => {
2    if (event.type === "tool_execution_start") {
3        console.log(`🔧 ${event.toolName}(${JSON.stringify(event.args).slice(0, 50)})`);
4    }
5    if (event.type === "tool_execution_end") {
6        console.log(`   └─ ${event.isError ? "❌ 失败" : "✅ 成功"}`);
7    }
8});

场景4 · 流式转发到 Web 前端——Agent 跑在服务器上,浏览器用户通过 SSE 看到实时输出:

1// 服务端
2session.subscribe((event) => {
3    if (event.type === "message_update") {
4        res.write(`data: ${JSON.stringify({ type: "delta", text: extractText(event.message) })}\n\n`);
5    }
6    if (event.type === "agent_end") {
7        res.end();
8    }
9});

除了这两个,教程还提到场景2 工具调用拦截(扩展在 tool_call 事件里返回 { block: true, reason: "…" } 就能挡下危险操作)和场景3 上下文预处理 (transformContext 钩子在 LLM 调用前注入时间、Git 状态)。

为什么说这是"开放扩展"而不只是"通知"? 观测、拦截、预处理、Web 转发—— 这四个功能共同的特点是:新增任何一个,都不需要修改 Agent 内核一行代码, 只需要 subscribe。事件驱动架构真正的威力,不是"把消息传出去"这件小事, 而是给了外部世界一个随时插入新能力的开放接口。
🔎 出处:教程第 7 章 §五「你能用事件系统做什么」场景1、场景4(第7章-事件驱动-Agent的神经系统.md)。
从"通知"到"开放扩展"—— 同一条事件流,不同的插入点 Agent 内核 ──emit(event)──→ 📡 事件流(唯一协议) ├──→ 观测:打印工具调用日志 ├──→ 拦截:beforeToolCall 挡危险操作 ├──→ 预处理:transformContext 注入上下文 └──→ 转发:res.write 推给浏览器 SSE 共同点：Agent 内核代码一行没变，新增能力 = 新增一个 subscribe
